LiveThing comes as a few separate packages. You install the client in the project that holds your UI. You install the server and one platform adapter in the project that holds your backend. A **platform adapter** is the package that runs your LiveThing server on one runtime, such as Node.js or Cloudflare. The client and the server both use `@livething/core`, and the commands below install it for you.

## The packages

| Package                        | Where it runs                                   | What it is                                                   |
| ------------------------------ | ----------------------------------------------- | ------------------------------------------------------------ |
| `@livething/client`            | Browser, React Native, Node, Bun, Deno, Workers | The typed client socket                                      |
| `@livething/server`            | Your backend                                    | The server framework (`server`, capabilities, `InferClient`) |
| `@livething/server-cloudflare` | Cloudflare Durable Objects                      | Platform adapter                                             |
| `@livething/server-bun`        | Bun                                             | Platform adapter                                             |
| `@livething/server-node`       | Node.js                                         | Platform adapter                                             |
| `@livething/core`              | Shared                                          | Wire protocol, errors, `CloseCodes`                          |

::note
`@livething/core` is a **peer dependency** of both `@livething/client` and `@livething/server`. A peer dependency is a package that another package needs, but that your own project must install. Some package managers install peer dependencies for you and some do not. The commands below name `@livething/core` directly, so the result is the same on npm, pnpm, Yarn, and Bun.
::

## Client

Install these packages in the project that holds your UI:

::code-group

```bash [npm]
npm install @livething/client @livething/core
```

```bash [pnpm]
pnpm add @livething/client @livething/core
```

```bash [bun]
bun add @livething/client @livething/core
```

```bash [yarn]
yarn add @livething/client @livething/core
```

::

## Server

Install `@livething/server` plus the adapter for your platform. Pick one adapter.

### Node.js and Bun

Install `@livething/server` plus the [adapter](/core/runtimes/adapters/overview) for your runtime: `@livething/server-node` or `@livething/server-bun`. Your server code is the same on every platform. Only the adapter package changes, together with the small file that passes your server to it. The adapter pages show how that file looks on each platform. `@livething/server-node` needs Node.js 22 or newer.

```bash [npm]
npm install @livething/server @livething/server-node @livething/core
```

`@livething/server-node` stores its data in SQLite through [better-sqlite3](https://github.com/WiseLibs/better-sqlite3), which is installed with it. better-sqlite3 is a **native module**: it contains compiled code, not only JavaScript. On most systems npm downloads a ready-made build. On other systems it builds the module during install, and then you need Python and a C++ compiler.

If you use a web framework, install that framework next to the adapter. Each framework has its own entry point in `@livething/server-node`:

| Entry point                      | Also install                                               |
| -------------------------------- | ---------------------------------------------------------- |
| `@livething/server-node`         | nothing (works with `node:http`, Express, Koa, and others) |
| `@livething/server-node/hono`    | `hono` and `@hono/node-server`                             |
| `@livething/server-node/fastify` | `fastify` and `@fastify/websocket`                         |
| `@livething/server-node/h3`      | `h3` (version 2) and `crossws`                             |
| `@livething/server-node/h3/v1`   | `h3` (version 1) and `crossws`                             |

For Bun, replace `@livething/server-node` with `@livething/server-bun`. You can also use Bun's own installer, `bun add`.

LiveThing has no Deno adapter. The Node.js adapter can run on Deno with a `node:sqlite` database, but Deno is not a supported runtime. [Deno](/core/runtimes/adapters/deno) has the setup.

### Cloudflare Durable Objects

```bash [npm]
npm install @livething/server @livething/server-cloudflare @livething/core
```

For pnpm, Bun, or Yarn, use `pnpm add`, `bun add`, or `yarn add` with the same packages. `wrangler.jsonc` is the config file of a Cloudflare Workers project. Its `compatibility_date` setting picks which version of the Workers runtime your code runs on. The Cloudflare adapter needs a `compatibility_date` of `2026-04-07` or later:

```jsonc [wrangler.jsonc]
{
  "compatibility_date": "2026-04-07",
}
```

## Schemas

LiveThing checks each payload against a schema. You can write schemas with any validator library that follows the [Standard Schema](https://standardschema.dev) spec, such as valibot, Zod, or ArkType. The examples in these docs use [valibot](https://valibot.dev). `@livething/server` already depends on valibot, but you still add it to your own project so that you can import it:

::code-group

```bash [npm]
npm install valibot
```

```bash [pnpm]
pnpm add valibot
```

```bash [bun]
bun add valibot
```

```bash [yarn]
yarn add valibot
```
