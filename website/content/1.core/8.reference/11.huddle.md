Every example in these docs comes from one app: **Huddle**, a team chat app. People talk in rooms and direct messages, send voice notes, share their screens, set a status and an avatar, share files, search the message history, and ask Scout, Huddle's AI assistant, questions. This page is the reference for its names and shapes. When an example uses an event, it has the payload shown here.

A page can show a smaller version of this server, with only the capabilities that page is about. The names and payloads stay the same.

## Features

Each feature uses the names below. Most send JSON. The ones that move pictures, files or audio send [bytes with JSON info](#info-and-bytes).

| Feature            | Where           | Names                                                                                                                                          |
| ------------------ | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Room messages      | `rooms` channel | `send-message` → `message`, `react` → `reaction`, `start-typing` → `typing`, `load-history` (request)                                          |
| Who is reading     | `rooms` channel | [awareness](/core/server/capabilities/awareness) state `{ viewingMessageId: string \| null; editingTopic: boolean }`, `list-viewers` (request) |
| Room topic         | `rooms` channel | `editingTopic` in the awareness state (a lock), `set-room-topic` → `room-topic`                                                                |
| Direct messages    | `dms` channel   | `send-message` → `message`, with `inbox()` and `readReceipts()`                                                                                |
| Voice notes        | `dms` channel   | `send-voice-note` → `voice-note` (bytes), `import-voice-notes`                                                                                 |
| Screen sharing     | `rooms` channel | `start-screen-share`, then `capture-screen` (server request, bytes), `share-screen-frame` → `screen-frame` (bytes), `resend-screen-frame`      |
| Profile and status | top level       | `rename` → `user-renamed`, `set-status` → `status-changed`, `get-profile` (request)                                                            |
| Avatar             | top level       | `upload-avatar` → `avatar-preview` (bytes)                                                                                                     |
| Attachments        | top level       | `upload-attachment` (upload), `get-thumbnail` (request, bytes), `download-attachment` (stream, bytes), `get-attachment-url` (request)          |
| Posting files      | both            | `post-files` → `files-posted` in `rooms`, and `post-attachment`, `post-photos` (uploads) at the top level                                      |
| Moderation         | top level       | `delete-message` (request) with `confirm-delete` (server request), `report-message` (request)                                                  |
| Search and export  | top level       | `search-messages`, `export-room` (streams), `export-room-pdf` (recorded stream, bytes)                                                         |
| Scout              | `rooms` channel | `ask-scout` (recorded broadcast stream), and `run-task` (stream) at the top level                                                              |
| Task boards        | Collaboration   | the `task-board` doc, one per room: see [Task boards](#task-boards)                                                                            |
| Admin              | top level       | `tail-audit-log` (stream), `send-digest` (scheduled task), `announcement` in the `announcements` channel                                       |

`a → b` means the client sends `a`, and its handler sends `b`.

## The server builder

`server/base.ts` holds the builder and the channels. Every handler file imports from here.

```typescript [server/base.ts]
import { emits, errors, server, t } from '@livething/server'
import { awareness } from '@livething/server/awareness'
import { binary } from '@livething/server/binary'
import { channels } from '@livething/server/channels'
import { clientRequests } from '@livething/server/client-requests'
import { dedup } from '@livething/server/dedup'
import { CloseCodes, RejectAuth } from '@livething/server/errors'
import { inbox, readReceipts } from '@livething/server/inbox'
import { keepalive } from '@livething/server/keepalive'
import { replay } from '@livething/server/replay'
import { scheduled } from '@livething/server/scheduled'
import { sequence } from '@livething/server/sequence'
import { serverRequests } from '@livething/server/server-requests'
import { recordedStream, stream } from '@livething/server/streams'
import { tags } from '@livething/server/tags'
import { uploads } from '@livething/server/uploads'
import * as v from 'valibot'
import { Forbidden, NotFound, RoomFull } from '../shared/errors'
import { verifySession } from './auth'
import { HuddleCollaboration } from './huddle-collaboration'

export const Message = v.object({
  id: v.string(),
  text: v.string(),
  from: v.string(),
  sentAt: v.number(),
})
export type Message = v.InferOutput<typeof Message>

export const Status = v.picklist(['active', 'away', 'busy'])
export type Status = v.InferOutput<typeof Status>

// One uploaded file in a room message.
export type PostedFile = {
  attachmentId: string
  fileName: string
  fileType: string
  size: number
}

export const base = server({
  async authenticate(request) {
    const token = request.headers
      .get('Authorization')
      ?.replace('Bearer ', '')
    const user = await verifySession(token)
    if (!user) {
      throw RejectAuth(CloseCodes.AUTH_INVALID, 'invalid session')
    }

    return {
      userId: user.id,
      // Other members see `meta`. `userId` lets a client group one person's tabs.
      meta: { userId: user.id, name: user.name, role: user.role },
    }
  },
  capabilities: [
    emits({
      notification: t<{ title: string; body: string }>(),
      announcement: t<{ text: string }>(),
      'user-renamed': t<{ userId: string; name: string }>(),
      'status-changed': t<{ userId: string; status: Status }>(),
      message: t<Message>(),
      reaction: t<{
        messageId: string
        emoji: string
        from: string
      }>(),
      'cursor-answer': t<{
        kind: 'received' | 'read'
        seq: number
        userIds: string[]
      }>(),
      health: t<{
        latencyMs: number | null
        quality: 'excellent' | 'good' | 'degraded' | 'poor' | null
      }>(),
      'room-topic': t<{ topic: string }>(),
      'online-users': t<{ userIds: string[] }>(),
      'reader-count': t<{ count: number }>(),
      'history-cleared': t<null>(),
      'digest-sent': t<{ userId: string }>(),
    }),
    errors([NotFound, Forbidden, RoomFull]),
    binary({
      emits: { 'avatar-preview': t<null>() },
      serverRequests: {
        'capture-screen': {
          out: t<{ maxWidth: number }>(),
          in: v.object({ fileType: v.literal('image/png') }),
        },
      },
    }),
    uploads(),
    channels(),
    keepalive(),
    scheduled({
      'send-digest': { data: t<{ userId: string }>() },
    }),
    tags((ephemeral) => [ephemeral('team', t<string>())]),
    clientRequests(),
    serverRequests({
      'confirm-delete': {
        out: t<{ preview: string }>(),
        in: v.object({ confirmed: v.boolean() }),
      },
    }),
    stream(),
    recordedStream(),
    dedup(),
    sequence({ persist: true }),
    replay.history(),
    HuddleCollaboration(),
  ],
})

// A room: everyone in it sees its messages, and which message each member is reading.
export const rooms = base.channel(['rooms', 'room:{roomId}'], {
  capabilities: [
    awareness(),
    emits({
      message: t<Message>(),
      reaction: t<{
        messageId: string
        emoji: string
        from: string
      }>(),
      typing: t<{ from: string }>(),
      'room-topic': t<{ topic: string }>(),
      roster: t<{ names: string[] }>(),
      'mention-result': t<{ delivered: number }>(),
      'ping-result': t<{ alive: boolean }>(),
      'files-posted': t<{
        id: string
        text: string
        files: PostedFile[]
        from: string
        sentAt: number
      }>(),
    }),
    binary({ emits: { 'screen-frame': t<{ from: string }>() } }),
  ],
  awareness: {
    state: v.object({
      viewingMessageId: v.nullable(v.string()),
      // A lock: true while this member edits the room topic.
      editingTopic: v.boolean(),
    }),
    // Guests can read a room, but other members do not see where they are.
    // Only one member at a time can hold the topic lock.
    check: (ctx, state) =>
      ctx.meta.role !== 'guest' &&
      (!state.editingTopic ||
        ctx.channel.awareness
          .list()
          .every(
            (entry) =>
              entry.connectionId === ctx.connection.id ||
              !entry.state.editingTopic,
          )),
  },
})

// A direct message: every member gets a stored copy until they acknowledge it.
export const dms = base.channel(['dms', 'dm:{pair}'], {
  membership: 'persistent',
  capabilities: [
    inbox(),
    readReceipts(),
    emits({ message: t<Message>() }),
    binary({
      emits: {
        'voice-note': t<{ from: string; durationMs: number }>(),
      },
    }),
  ],
})

// Announcements: one fixed channel. Only the server sends to it.
// Everyone joins it, so its members get no presence.
export const announcements = base.channel('announcements', {
  presence: false,
  capabilities: [
    emits({
      announcement: t<{ text: string }>(),
    }),
  ],
})
```

## The definition

`server/huddle-definition.ts` creates the handlers and passes them to `assemble()`. A handler only runs if it is passed. A larger app can keep each feature's handlers in its own file, export them as an `as const` list, and spread the lists here. With `as const`, using one event name twice in one scope is a compile error.

export const handleDownloadAttachment = base.binary.stream(
  'download-attachment',
  {
    input: v.object({
      attachmentId: v.string(),
      fromByte: v.number(),
    }),
    async *run(ctx, input) {
      if (
        !(await canReadAttachment(ctx.user.id, input.attachmentId))
      ) {
        throw NotFound({ id: input.attachmentId })
      }

      const file = await openAttachment(
        input.attachmentId,
        input.fromByte,
      )
      // The first chunk says what the file is. The others need no info.
      let info: { fileName: string; fileType: string } | null = {
        fileName: file.name,
        fileType: file.type,
      }

      for await (const piece of file.pieces(ctx.stream.signal)) {
        yield { info, bytes: piece }

        info = null
        await ctx.stream.drain()
      }
    },
  },
)

// A file, sent in pieces. A resumed upload continues from the last piece it saved.
export const handleUploadAttachment = base.binary.upload(
  'upload-attachment',
  {
    input: v.object({ fileName: v.string(), fileType: v.string() }),
    state: attachmentUploadState,
    maxBytes: 512 * 1024 * 1024,
    async run(ctx, input, pieces) {
      let attachmentId = ctx.upload.state?.attachmentId

      if (!attachmentId) {
        attachmentId = crypto.randomUUID()
        ctx.upload.saved(ctx.upload.savedThrough, {
          state: { attachmentId },
        })
      }

      const size = await writePieces(ctx.upload, attachmentId, pieces)

      await saveAttachment({
        attachmentId,
        ownerId: ctx.user.id,
        roomId: null,
        fileName: input.fileName,
        fileType: input.fileType,
        size,
      })

      return { info: { attachmentId } }
    },
    onDiscard(ctx) {
      return discardAttachment(ctx.upload)
    },
  },
)

// Posts files that the user uploaded with upload-attachment.
export const handlePostFiles = rooms.on('post-files', {
  input: v.object({
    text: v.string(),
    attachmentIds: v.array(v.string()),
  }),
  async run(ctx, input) {
    const attachmentIds = [...new Set(input.attachmentIds)]
    const files: PostedFile[] = []

    for (const attachmentId of attachmentIds) {
      const attachment = await loadAttachment(attachmentId)
      // A user posts only their own files, and each file only once.
      if (
        !attachment ||
        attachment.ownerId !== ctx.user.id ||
        attachment.roomId !== null
      ) {
        throw NotFound({ id: attachmentId })
      }

      const { fileName, fileType, size } = attachment
      files.push({ attachmentId, fileName, fileType, size })
    }

    await attachToRoom(attachmentIds, ctx.channel.params.roomId)
    ctx.channel.broadcast('files-posted', {
      id: crypto.randomUUID(),
      text: input.text,
      files,
      from: ctx.user.id,
      sentAt: Date.now(),
    })
  },
})

// A file and its message in one upload: run posts the message when the file is stored.
export const handlePostAttachment = base.binary.upload(
  'post-attachment',
  {
    input: v.object({
      roomId: v.string(),
      text: v.string(),
      fileName: v.string(),
      fileType: v.string(),
    }),
    state: attachmentUploadState,
    maxBytes: 512 * 1024 * 1024,
    async run(ctx, input, pieces) {
      if (!(await isRoomMember(ctx.user.id, input.roomId))) {
        throw Forbidden({ reason: 'not a member of this room' })
      }

      let attachmentId = ctx.upload.state?.attachmentId

      if (!attachmentId) {
        attachmentId = crypto.randomUUID()
        ctx.upload.saved(ctx.upload.savedThrough, {
          state: { attachmentId },
        })
      }

      const size = await writePieces(ctx.upload, attachmentId, pieces)

      // The user may have left the room while the file was still being sent.
      if (!(await isRoomMember(ctx.user.id, input.roomId))) {
        throw Forbidden({ reason: 'not a member of this room' })
      }

      const file = {
        attachmentId,
        fileName: input.fileName,
        fileType: input.fileType,
        size,
      }

      await saveAttachment({
        ...file,
        ownerId: ctx.user.id,
        roomId: input.roomId,
      })

      // A cancel stops run only through its signal: do not post a cancelled file.
      ctx.upload.signal.throwIfAborted()
      ctx.channels
        .get('rooms', `room:${input.roomId}`)
        .broadcast('files-posted', {
          id: crypto.randomUUID(),
          text: input.text,
          files: [file],
          from: ctx.user.id,
          sentAt: Date.now(),
        })

      return { info: { attachmentId } }
    },
    onDiscard(ctx) {
      return discardAttachment(ctx.upload)
    },
  },
)

const PHOTOS_MAX_BYTES = 50 * 1024 * 1024

// Several photos with one caption, as one upload: they are posted together, or not at all.
export const handlePostPhotos = base.binary.upload('post-photos', {
  input: v.object({
    roomId: v.string(),
    caption: v.string(),
    photos: v.array(
      v.object({
        fileName: v.string(),
        fileType: v.string(),
        size: v.pipe(v.number(), v.integer(), v.minValue(1)),
      }),
    ),
  }),
  // The attachment IDs, one for each photo.
  state: v.array(v.string()),
  maxBytes: PHOTOS_MAX_BYTES,
  async run(ctx, input, pieces) {
    if (!(await isRoomMember(ctx.user.id, input.roomId))) {
      throw Forbidden({ reason: 'not a member of this room' })
    }

    const wrongSize = ValidationFailed({
      event: 'post-photos',
      issues: [
        { message: 'The photo sizes do not match the bytes.' },
      ],
    })

    const total = input.photos.reduce(
      (sum, photo) => sum + photo.size,
      0,
    )
    if (total > PHOTOS_MAX_BYTES) throw wrongSize

    const bytes = await collectBytes(pieces, total)
    if (!bytes) throw wrongSize

    if (!(await isRoomMember(ctx.user.id, input.roomId))) {
      throw Forbidden({ reason: 'not a member of this room' })
    }

    // Keep the IDs before writing, so onDiscard can delete every file. A resumed
    // run finds them in the state, and writes the same files again.
    const attachmentIds =
      ctx.upload.state ?? input.photos.map(() => crypto.randomUUID())
    ctx.upload.saved(ctx.upload.savedThrough, {
      state: attachmentIds,
    })

    const files: PostedFile[] = []
    let start = 0

    for (const [index, photo] of input.photos.entries()) {
      ctx.upload.signal.throwIfAborted()
      const file = {
        attachmentId: attachmentIds[index]!,
        fileName: photo.fileName,
        fileType: photo.fileType,
        size: photo.size,
      }

      const photoBytes = bytes.subarray(start, start + photo.size)
      await writeAttachmentBytes(file.attachmentId, 0, photoBytes)
      await saveAttachment({
        ...file,
        ownerId: ctx.user.id,
        roomId: input.roomId,
      })

      files.push(file)
      start += photo.size
    }

    ctx.upload.signal.throwIfAborted()
    ctx.channels
      .get('rooms', `room:${input.roomId}`)
      .broadcast('files-posted', {
        id: crypto.randomUUID(),
        text: input.caption,
        files,
        from: ctx.user.id,
        sentAt: Date.now(),
      })

    return { info: { attachmentIds } }
  },
  async onDiscard(ctx) {
    for (const attachmentId of ctx.upload.state ?? []) {
      await deleteAttachment(attachmentId)
    }
  },
})

export const handleTailAuditLog = base.stream('tail-audit-log', {
  input: v.object({}),
  nudges: {
    stop: null,
    'set-level': v.object({
      level: v.picklist(['info', 'warn', 'error']),
    }),
  },
  async *run(ctx) {
    const levels = ['info', 'warn', 'error'] as const
    let minLevel = 0
    for await (const entry of auditLogEntries(ctx.stream.signal)) {
      if (levels.indexOf(entry.level) < minLevel) continue

      const recent = ctx.stream.nudges(yield { line: entry.line })
      for (const nudge of recent) {
        if (nudge.event === 'stop') return

        if (nudge.event === 'set-level') {
          minLevel = levels.indexOf(nudge.payload.level)
        }
      }
    }
  },
})

export const handleAskScout = rooms.recordedStream('ask-scout', {
  input: v.object({ prompt: v.string() }),
  nudges: {
    stop: null,
    redirect: v.object({ instruction: v.string() }),
  },
  broadcast: true, // every member of the room sees the reply
  async *run(ctx, input) {
    let messages = [{ role: 'user', text: input.prompt }]

    while (true) {
      const modelCall = new AbortController()
      let replySoFar = ''
      let redirectedTo: string | null = null

      for await (const piece of llm.stream({
        messages,
        signal: modelCall.signal,
      })) {
        replySoFar += piece
        const recent = ctx.stream.nudges(yield { text: piece })

        if (recent.some((n) => n.event === 'stop')) {
          modelCall.abort()
          return
        }

        const redirect = recent.find((n) => n.event === 'redirect')
        if (redirect) {
          modelCall.abort()
          redirectedTo = redirect.payload.instruction
          break
        }
      }

      if (!redirectedTo) return

      messages = [
        ...messages,
        { role: 'assistant', text: replySoFar },
        { role: 'user', text: redirectedTo },
      ]
    }
  },
})

## Info and bytes

Avatars, screen sharing, voice notes, attachments, uploads and the PDF export move pictures, audio and files. They send them as [binary messages](/core/server/binary/overview): each one has JSON **info** and raw **bytes**. These are the events. The client sends one name, and the server sends another:

| Event                | Who sends it | Where           | Info                                        | Bytes                                       |
| -------------------- | ------------ | --------------- | ------------------------------------------- | ------------------------------------------- |
| `upload-avatar`      | client       | top level       | `{ fileType: 'image/png' \| 'image/jpeg' }` | The new avatar picture, up to 2 MiB         |
| `avatar-preview`     | server       | top level       | `null`                                      | A small copy of the new avatar              |
| `share-screen-frame` | client       | `rooms` channel | `null`                                      | One picture of a shared screen, up to 1 MiB |
| `screen-frame`       | server       | `rooms` channel | `{ from: string }`, the sharer's user ID    | The same picture                            |
| `send-voice-note`    | client       | `dms` channel   | `{ durationMs: number }`                    | One recorded voice note, up to 1 MiB        |
| `voice-note`         | server       | `dms` channel   | `{ from: string; durationMs: number }`      | The same voice note                         |

The `dms` channel has `inbox()`, so a member who is away gets each `voice-note` when they come back, with its bytes. `import-voice-notes` is a JSON event with no input in the `dms` channel: it puts voice notes from an older app into the member's inbox with [`inbox.binary.backfill`](/core/server/inbox/delivery#backfilling-binary-messages).

`resend-screen-frame` is a JSON event in the `rooms` channel, `{ from: string }`. A member who opens the room late sends it to get the last picture shared by the member in `from`, as one `screen-frame` sent with [`binary.sendReplay`](/core/server/replay/history-and-snapshot#resending-a-binary-event).

These are the request, the two streams and the server request that carry bytes. The JSON events around them, such as `start-screen-share`, are normal text frames:

| Name                  | Kind            | Who starts it | Info sent                                    | Info back                                                                         | Bytes back                                     |
| --------------------- | --------------- | ------------- | -------------------------------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------- |
| `get-thumbnail`       | request         | client        | `{ attachmentId: string }`                   | `{ fileType: 'image/png' }`                                                       | A small picture of the attachment              |
| `download-attachment` | stream          | client        | `{ attachmentId: string; fromByte: number }` | `{ fileName: string; fileType: string }` on the first chunk, `null` on the others | One piece of the file per chunk                |
| `export-room-pdf`     | recorded stream | client        | `{ roomId: string }`                         | `{ fileName: string }` on the first chunk, `null` on the others                   | One piece of the PDF per chunk                 |
| `capture-screen`      | server request  | server        | `{ maxWidth: number }`                       | `{ fileType: 'image/png' }`                                                       | One full picture of the client's shared screen |

`download-attachment` takes a `fromByte`, so a client that loses its connection can start again where it stopped. `export-room-pdf` is a recorded stream instead: the PDF is made once, and its pieces are stored, so a client that loses its connection continues the stream and gets the pieces it missed. `capture-screen` sends no bytes. The server sends it when a member starts sharing their screen (`start-screen-share` in the `rooms` channel), and sends the answer to the room as a `screen-frame`, so members who joined late see a full picture at once.

`get-attachment-url` returns `{ url }`, a [signed URL](/core/server/binary/s3-and-r2#large-downloads-from-the-bucket) that downloads the attachment from the bucket for 5 minutes. `get-thumbnail`, `download-attachment` and `get-attachment-url` check that the user may read the attachment: the user who uploaded it can, and so can the members of the room it was posted in. Anyone else gets `NotFound`.

A file that is too big for one message is an [upload](/core/server/binary/uploads): the client sends it in pieces, and can resume it after a drop. Each upload has JSON input at the start, and its handler's `run` returns JSON info as the reply:

| Upload              | Input                                                                                                 | Reply info                    | What `run` does                                                                    |
| ------------------- | ----------------------------------------------------------------------------------------------------- | ----------------------------- | ---------------------------------------------------------------------------------- |
| `upload-attachment` | `{ fileName: string; fileType: string }`                                                              | `{ attachmentId: string }`    | Stores one file of up to 512 MiB. A `post-files` message in a room posts it later. |
| `post-attachment`   | `{ roomId: string; text: string; fileName: string; fileType: string }`                                | `{ attachmentId: string }`    | Stores one file, then posts it to the room as a `files-posted` message.            |
| `post-photos`       | `{ roomId: string; caption: string; photos: { fileName: string; fileType: string; size: number }[] }` | `{ attachmentIds: string[] }` | Stores several photos sent as one upload, then posts them with one caption.        |

`post-files` is a JSON event in the `rooms` channel: `{ text, attachmentIds }`, where `text` is a string and `attachmentIds` is an array of strings. Its handler and the two posting uploads send the room the same `files-posted` event: `{ id, text, files, from, sentAt }`, where each file is a `PostedFile` from `server/base.ts` above. The upload handlers store the bytes with the helpers in [`server/attachment-files.ts`](/core/server/binary/uploads#an-upload-handler).

On the client, [`binary()`](/core/client/primitives/binary) sends and receives the six binary events with `binary.send` and `binary.on`, such as `upload-avatar` and `avatar-preview`. It does this on the socket and on a `rooms` or `dms` channel handle. With the other primitives in the socket below, the socket also has `binary.request` for `get-thumbnail`, `binary.stream` for `download-attachment`, `binary.continueStream` for `export-room-pdf` and `binary.onRequest` for `capture-screen`. With [`uploads()`](/core/client/primitives/uploads), it has `binary.upload` for the three uploads. It takes the upload's name, the file, and the upload's input in `{ input }`:

```typescript
// After `socket` from the example below
export function makeAttachmentUpload(file: File) {
  return socket.binary.upload('upload-attachment', file, {
    input: { fileName: file.name, fileType: file.type },
  })
}
```

## The client socket

It connects over WebSocket first, and [moves to](/core/client/transports/overview#failover) `http()` on office networks that block WebSocket. ## Task boards

Each room has a task board that its members edit together, with the [Collaboration](/plugins/collaboration/overview) plugin. The doc is `task-board`, and its ID is the room ID, so the general room's board is `collab.doc('task-board', 'general')`. The server and the client share its description:

```typescript [shared/huddle-docs.ts]
import {
  doc,
  list,
  record,
  richText,
  text,
} from '@livething/plugin-collaboration'
import * as v from 'valibot'

export const taskBoard = doc(
  'task-board',
  {
    title: text(),
    archived: v.optional(v.boolean(), false),
    columns: list({ id: v.string(), name: text() }),
    tasks: list({
      id: v.string(),
      column: v.string(), // the ID of the column the task is in
      title: text(),
      done: v.boolean(),
      assignee: v.nullable(v.string()), // a user ID
      notes: richText(),
    }),
    // Each member's own view settings, by user ID.
    settings: record({ collapsed: v.array(v.string()) }),
  },
  {
    // Which task each member has open.
    awareness: v.object({ viewingTaskId: v.nullable(v.string()) }),
  },
)

// Every doc type Huddle has.
export const huddleDocs = [taskBoard] as const
```

The server plugin lets room members edit their room's board, and guests only read it. `server/base.ts` above lists it:

```typescript [server/huddle-collaboration.ts]
import { collaboration } from '@livething/plugin-collaboration/server'
import { huddleDocs } from '../shared/huddle-docs'
import { isRoomMember } from './helpers'

export const HuddleCollaboration = collaboration({
  docs: huddleDocs,
  async access(ctx, doc) {
    if (!ctx.user.id || !(await isRoomMember(ctx.user.id, doc.id))) {
      return false
    }

    return ctx.meta.role === 'guest' ? 'view' : 'edit'
  },
})
```

The client plugin keeps boards in IndexedDB, so an edit made offline survives a reload. `client/socket.ts` above lists it:

```typescript [client/huddle-collab.ts]
import {
  collaboration,
  indexedDbStorage,
} from '@livething/plugin-collaboration/client'
import { huddleDocs } from '../shared/huddle-docs'

export const HuddleCollaboration = collaboration({
  docs: huddleDocs,
  storage: indexedDbStorage(),
})
```

Task IDs look like `t_1042`, and column IDs are `todo`, `doing` and `done`. A lock key for a task is `task:<task ID>`.
