This page builds on [Uploads](/core/server/binary/uploads).

An upload often goes with a message: a file in a chat room, with some text. These are three ways to build it in Huddle, and one check that every way needs. In which order the app does things is its own choice: it can post the text first and show a spinner on the file, or post nothing until the file is stored. This page shows the first way. The other ways are [Post from `run`](/core/server/binary/post-from-run) and [Several files with one caption](/core/server/binary/several-files), and every way needs [Checking downloads](/core/server/binary/checking-downloads).

The client uploads the file with `upload-attachment`, and gets the attachment ID. Then it sends a normal JSON event to the room, `post-files`, with the text and the IDs. The `rooms` channel runs the handler only for its members, so the membership check happens when the message is sent. The handler has two steps:

::steps{level="3"}

### Check each file

`run` removes repeated IDs, then loads each attachment. A user posts only their own files, and each file only once, so any other ID gets `NotFound`:

<!-- docs-check: skip -->

```typescript [server/attachments.ts]
const attachmentIds = [...new Set(input.attachmentIds)]
const files: PostedFile[] = []

for (const attachmentId of attachmentIds) {
  const attachment = await loadAttachment(attachmentId)
  if (
    !attachment ||
    attachment.ownerId !== ctx.user.id ||
    attachment.roomId !== null
  ) {
    throw NotFound({ id: attachmentId })
  }

  const { fileName, fileType, size } = attachment
  files.push({ attachmentId, fileName, fileType, size })
}
```

### Post the files

`attachToRoom` puts the files in the room, so its members can download them. Then every member gets one `files-posted` event:

<!-- docs-check: skip -->

```typescript [server/attachments.ts]
await attachToRoom(attachmentIds, ctx.channel.params.roomId)
ctx.channel.broadcast('files-posted', {
  id: crypto.randomUUID(),
  text: input.text,
  files,
  from: ctx.user.id,
  sentAt: Date.now(),
})
```

::

::code-collapse

```typescript [server/attachments.ts]
import * as v from 'valibot'
import { NotFound } from '../shared/errors'
import { rooms } from './base'
import { attachToRoom, loadAttachment } from './helpers'
import type { PostedFile } from './base'

export const handlePostFiles = rooms.on('post-files', {
  input: v.object({
    text: v.string(),
    attachmentIds: v.array(v.string()),
  }),
  async run(ctx, input) {
    const attachmentIds = [...new Set(input.attachmentIds)]
    const files: PostedFile[] = []

    for (const attachmentId of attachmentIds) {
      const attachment = await loadAttachment(attachmentId)
      // A user posts only their own files, and each file only once.
      if (
        !attachment ||
        attachment.ownerId !== ctx.user.id ||
        attachment.roomId !== null
      ) {
        throw NotFound({ id: attachmentId })
      }

      const { fileName, fileType, size } = attachment
      files.push({ attachmentId, fileName, fileType, size })
    }

    await attachToRoom(attachmentIds, ctx.channel.params.roomId)
    ctx.channel.broadcast('files-posted', {
      id: crypto.randomUUID(),
      text: input.text,
      files,
      from: ctx.user.id,
      sentAt: Date.now(),
    })
  },
})
```

::

This keeps the upload simple, and the same file can be uploaded before the user picks a room. But a user can upload a file and never post it. So the app deletes old attachments that no message uses, for example with a [scheduled task](/core/server/handlers/scheduled) that deletes each attachment whose `roomId` is still `null` after a day.
