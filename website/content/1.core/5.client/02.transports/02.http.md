`http()` connects with server-sent events and POST requests. It can be your only transport, as below, or the one the client [moves to](/core/client/transports/overview#failover) when a network blocks WebSocket. The server must list [`http()`](/core/runtimes/transports/overview) too, and the server [`http()`](/core/runtimes/transports/http) page covers that side.

```typescript [client/socket.ts]
import { binary, client, connect, http } from '@livething/client'
import type { HuddleSocket } from '../server/huddle-definition'

const socket = client<HuddleSocket>()(
  connect('https://example.com/huddle', { transports: [http()] }),
  binary(),
)
```

On `http()`, the [`token`](/core/client/connecting/auth-and-query#token-auth-with-token) goes in an `Authorization: Bearer` header when the stream opens, and messages go up in POST batches, one at a time, in order. Each POST goes to the exact URL of the stream, query included. If the browser can stream a request body (today Chromium browsers), and the stream's connection uses HTTP/2 or HTTP/3, the client also tries [stream mode](/core/runtimes/transports/http#stream-mode) in the background: one long POST that carries messages as you send them. If the server does not answer its first probe within 2 seconds, the client stays on POST batches. A message that, with its 5-byte frame header, is bigger than the server's `maxPostBytes` (512 KiB by default) throws a `RangeError` when you send it. Nothing is sent and the connection stays open, so send large files with [uploads](/core/client/primitives/uploads), which work on `http()` too. Binary messages from the server arrive as base64 text, about a third bigger than on WebSocket. Messages are delivered at most once, as on WebSocket: a message can be lost when the connection drops, and the client does not send it again.

Every stream request carries a `LiveThing-Protocol: livething-v1` header. A browser page on another origin must send a preflight request for it, so the server always sees the `Origin`. A stream request without this header gets `426`. The [Origin check](/core/runtimes/transports/http#origins-cors-and-proxies) needs `allowedOrigins` for a page on another origin.

On Cloudflare, an open `http()` stream keeps the Durable Object in memory, so it does not hibernate. You get no hibernation savings for these connections.

`http()` needs a `fetch` that streams the response body. Browsers have one. React Native's own `fetch` does not stream, so install Expo's `expo/fetch`, which also works in a bare React Native app, and set it as the global `fetch`. `http()` has no option for a custom `fetch`: it uses the global one.

Serve the site over HTTP/2 or HTTP/3. HTTP/1.1 allows six connections per site, shared by all tabs, and one `http()` connection can use up to three of them: the stream and two POSTs. With [debug logging](/core/client/connecting/debug-logging) on, the client logs a warning when it sees HTTP/1.1. Browsers use HTTP/2 only over TLS, so plain `http://localhost` is HTTP/1.1. For local development of an app that lists only `http()`, serve it with a local certificate. LiveThing does not share one connection between tabs, so each tab opens its own.

With `http()`, [`reconnection()`](/core/client/primitives/reconnection#when-the-count-resets) resets its backoff only after the connection has stayed open for 30 seconds and one POST has gone through, so a connection that opens and then fails every POST still backs off.
