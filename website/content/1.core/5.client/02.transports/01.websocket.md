`websocket()` is the default transport. One WebSocket carries every message both ways. When you list no `transports` in `connect()`, the client uses `[websocket()]`. The server side is on the server [`websocket()`](/core/runtimes/transports/websocket) page.

```typescript [client/socket.ts]
import { binary, client, connect, websocket } from '@livething/client'
import type { HuddleSocket } from '../server/huddle-definition'

const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle', { transports: [websocket()] }),
  binary(),
)

socket.connect()
socket.ws // the native WebSocket, or null
```

## `socket.ws`

`socket.ws` is the native WebSocket while the socket is connecting or open over WebSocket, and `null` otherwise, for example on [`http()`](/core/client/transports/http) or when the socket is closed.

## The token

A browser cannot set headers on a WebSocket handshake. So the client sends the [`token`](/core/client/connecting/auth-and-query#token-auth-with-token) in the handshake's `Sec-WebSocket-Protocol` header, as a subprotocol, and the server moves it to `Authorization` before `authenticate` runs. You write no encoding and no header names. The server [`websocket()`](/core/runtimes/transports/websocket#the-token) page has the details.

## Subprotocols

To offer your own subprotocols, use the [`protocols`](/core/client/connecting/connect-options#protocols) option of `connect()`. Your names come first and the token goes last, so the token is never the name the server accepts.
