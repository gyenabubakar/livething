Every socket needs to know where to connect. You tell it with the `connect(...)` primitive. It is the one argument that every `client()` call needs. (When the server sends or takes binary messages, like Huddle's, the client also needs [`binary()`](/core/client/primitives/binary).) This chapter covers how connecting works: the options you can set, a URL that can change, how to send auth data, and how to create a socket safely in server-rendered (SSR) code.

## The `connect` primitive

`connect(url, options?)` takes the server URL and a few options. In the example, `HuddleSocket` is Huddle's contract type, inferred from the server definition (see [Creating a socket](/core/client/overview#creating-a-socket)):

```typescript [client/socket.ts]
import { binary, client, connect } from '@livething/client'
import type { HuddleSocket } from '../server/huddle-definition'

export const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle', { lazy: false }),
  binary(),
)

socket.connect()
```

`url` is a string, or a function that returns a string (sync or async). The function runs again on every connect and reconnect. So each attempt can use a different server. For example, you can move to a backup server when one is down (failover), or spread users across many servers (load balancing). This is called a [dynamic URL](/core/client/connecting/dynamic-url).

## What happens on connect

Calling `socket.connect()` moves the socket from `closed` to `connecting`. The socket moves to `open` when the server accepts the connection and sends its first frame, `__connected__`. Between `connecting` and `open`, the client does these steps:

1. **Resolves the URL.** If you passed a URL function, the client calls it. If the function is async, the client waits for its result. Then, if you passed a [`token`](/core/client/connecting/auth-and-query#token-auth-with-token) function, the client calls it the same way.
2. **Opens the first transport.** It takes the first transport in [`transports`](/core/client/transports/overview) that has not failed in the last 5 minutes. By default this is a WebSocket. It uses the URL, any subprotocols you set, and the token. On a WebSocket, the [handshake](/core/start/what-is-websocket) runs. On every transport, your server's [`authenticate`](/core/server/server/authenticate) function checks the connection.
3. **Waits for the first frame.** The wait is at most [`connectTimeoutMs`](/core/client/connecting/connect-options#connecttimeoutms). When the frame arrives, the socket is `open`. When the transport gets no answer and another transport is listed, the client goes back to step 2 with the next one (see [Failover](/core/client/transports/overview#failover)). When the server rejects the connection with a close code, the socket never shows `open`.

Calling `connect()` again while the socket is `open` or `connecting` does nothing. You can call `disconnect()` at any time to stop the connection on purpose. If you call it while the URL is still resolving, the client cancels that attempt and ignores its result.
