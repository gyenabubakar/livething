A socket can react to what happens on the device. It can close while the browser tab is hidden, stop reconnection tries while the device is offline, and connect again when the tab is shown or the network comes back. To do this, the socket needs two **signals** from the platform it runs on: is the app **visible**, and is the network **online**? The `platform()` primitive gives the socket these signals.

Platform signals are **opt-in**. Nothing reads visibility or network state unless you add `platform()` with an environment. The code for it is also not in your bundle until you import `platform()`.

```typescript [client/socket.ts]
import {
  binary,
  client,
  connect,
  platform,
  reconnection,
} from '@livething/client'
import { WebEnvironment } from '@livething/client/environment'
import type { HuddleSocket } from '../server/huddle-definition'

export const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle'),
  binary(),
  reconnection(),
  platform({
    environment: WebEnvironment, // where the signals come from
    backgroundDisconnectMs: 30_000, // close the socket 30s after the tab is hidden
  }),
)
```

## Two signals, two behaviors

An **environment** is the object that supplies the signals. It can report up to two signals, and each one turns on a different behavior:

| Signal         | Comes from           | Turns on                                                                                                                     |
| -------------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **visibility** | `onVisibilityChange` | [Background disconnect](/core/client/platform/background-disconnect): close the socket while hidden, open it again on return |
| **network**    | `onNetworkChange`    | [Network-aware reconnection](/core/client/platform/network-aware): pause retries while offline, retry as soon as it is back  |

Both signals are optional. An environment that reports only one signal turns on only that behavior, and the other behavior stays off. There is one exception. If you set `backgroundDisconnectMs` and the environment has no `onVisibilityChange`, `platform()` throws a `LiveThingConfigError` when `client()` creates the socket. This way the mistake does not go unnoticed.

## The online store

`platform()` also adds `socket.online` to the socket. It is a [reactive store](/core/client/overview#reactive-stores) of a `boolean` that holds the network signal, so you can show it in your UI. `socket.online.get()` reads the current value, and `socket.online.subscribe(...)` runs your listener each time the value changes. The value starts as `true`. It changes only when the environment's `onNetworkChange` reports a change, so with an environment that has no `onNetworkChange` it stays `true`.

```typescript [client/connection-status.ts]
import { showOfflineNotice, showToast } from './huddle-ui'
import { socket } from './socket'

if (!socket.online.get()) showOfflineNotice()

socket.online.subscribe((online) => {
  if (online) {
    showToast('Back online')
  } else {
    showOfflineNotice()
  }
})
```

Like every store on the socket, it connects to your UI framework with the same small [adapter](/core/recipes/framework-hooks/react).

## The pieces

- An **environment** supplies the signals. In a browser, use the ready-made [`WebEnvironment`](/core/client/platform/environments). For React Native, Electron or another platform, write your own.
- **`platform({ environment })`** passes those signals to the socket. With only `environment` set, it passes the signals on and does nothing else. Set `backgroundDisconnectMs` to turn on the hidden-tab disconnect.
- **`reconnection({ networkAware })`** uses the network signal when you add both `reconnection()` and `platform()`. `networkAware` is `true` by default, so you do not need to connect the two primitives yourself.
