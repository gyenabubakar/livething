This page builds on the [Node.js adapter](/core/runtimes/adapters/node). It shows only what is different with TanStack Start. The options, limits, origins, compression, client IP, storage, admin API and shutdown work as that page explains.

TanStack Start can run on Nitro 3, so LiveThing connects to it through the [H3 v2 binding](/core/runtimes/node-frameworks/h3#h3-v2). Read [Nitro apps](/core/runtimes/node-frameworks/overview#nitro-apps-nuxt-solidstart-and-tanstack-start) first for what each file does.

TanStack Start has no WebSocket route of its own. Its server functions handle normal HTTP requests and responses, so they cannot accept a WebSocket upgrade. Instead, you add a Nitro WebSocket route next to your TanStack Start app. The same route serves `/huddle` in development and in production.

```bash [pnpm]
pnpm add @livething/core @livething/server @livething/server-node h3@^2.0.1-rc.31 crossws@^0.4.12 nitro
```

Add the Nitro Vite plugin after the TanStack Start plugin and before the React plugin. Then enable WebSockets and choose the Node server preset:

```ts [vite.config.ts]
import { tanstackStart } from '@tanstack/react-start/plugin/vite'
import react from '@vitejs/plugin-react'
import { nitro } from 'nitro/vite'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [tanstackStart(), nitro(), react()],
  nitro: {
    serverDir: './server',
    preset: 'node_server',
    features: {
      websocket: true,
    },
  },
})
```

Keep any other Vite plugins and TanStack Start options that your project already has. The `nitro` options mean the same as in [SolidStart](/core/runtimes/node-frameworks/solidstart).

The endpoint file, the WebSocket route and the Nitro plugin are the same as in [SolidStart](/core/runtimes/node-frameworks/solidstart): `server/utils/huddle-endpoint.ts` binds Huddle with `@livething/server-node/h3`, `server/routes/huddle.ts` exports `huddleEndpoint.connect`, and `server/plugins/huddle.ts` uses `definePlugin` from `nitro`. Compression also works as on SolidStart: it depends on the WebSocket server options that TanStack Start and Nitro give you.

## Serve `http()`

TanStack Start runs on Nitro with H3 v2. Add `transports` to the endpoint file, the same file as on [SolidStart](/core/runtimes/node-frameworks/solidstart):

```ts [server/utils/huddle-endpoint.ts]
import { http, websocket } from '@livething/server-node'
import { setup } from '@livething/server-node/h3'
import { huddle } from '../huddle-definition'

export const huddleNode = setup()
export const huddleEndpoint = huddleNode.bind(huddle, {
  sql: './data/huddle.sqlite',
  transports: [websocket(), http()],
})
```

The route file `server/routes/huddle.ts` stays as it is. Nitro sends every method to `huddleEndpoint.connect`, and `connect` passes a request that is not a WebSocket upgrade to `handle`. As on [H3 v2](/core/runtimes/node-frameworks/h3#serve-http-on-h3-v2), `handle` needs the original Node request. The `node_server` preset runs on a Node server. A development server that gives the route only a Web API `Request` gets `500` from `handle`.

## Call the admin API from a TanStack Start route

Use a Nitro route, not a TanStack Start server function. A server function is called from your React code, and an admin endpoint is usually called by another system, such as an internal dashboard or a webhook. The route is the same as the [SolidStart admin route](/core/runtimes/node-frameworks/solidstart#call-the-admin-api-from-a-solidstart-route), in `server/routes/admin/announcements.post.ts`.
