This page builds on the [Node.js adapter](/core/runtimes/adapters/node). It shows only what is different with Fastify. The options, limits, origins, compression, client IP, storage, admin API and shutdown work as that page explains.

Use `@livething/server-node/fastify` with the [`@fastify/websocket`](https://github.com/fastify/fastify-websocket) plugin. Register the plugin before you add your routes. The plugin adds WebSocket support only to routes that are added after it.

```bash [pnpm]
pnpm add @livething/server @livething/server-node @livething/core fastify @fastify/websocket
```

```ts [huddle-server.ts]
import websocket from '@fastify/websocket'
import { setup } from '@livething/server-node/fastify'
import Fastify from 'fastify'
import { huddle } from './server/huddle-definition'

const app = Fastify()
await app.register(websocket)

const { bind, ready, shutdown } = setup()
const huddleEndpoint = bind(huddle, {
  sql: './data/huddle.sqlite',
})

app.get('/huddle', huddleEndpoint.connect)

await ready()
await app.listen({ port: 3000 })

process.once('SIGTERM', async () => {
  await shutdown()
  await app.close()
})
```

`huddleEndpoint.connect` is a Fastify route options object. It contains a `preHandler` hook, a normal HTTP `handler`, and a `wsHandler`. Fastify runs its normal lifecycle hooks for the route. After `@fastify/websocket` accepts the socket, LiveThing takes over the connection. Call `shutdown()` before you close the Fastify app.

Do not add `websocket: true` to this route. The route object already has the `wsHandler` and the HTTP handler it needs. Fastify's route parameters (`request.params`) do not reach LiveThing. When your definition needs a value from the path, read it from `new URL(request.url).pathname` inside the definition's [`authenticate(request)`](/core/server/server/authenticate) function.

A plain HTTP request to the route gets `426 Upgrade Required`, and your `authenticate` hook does not run. An upgrade request whose `Upgrade` header is not `websocket` gets `400`.

With [`http()`](#serve-http) turned on, a plain `GET` to the same route opens the stream instead, and a second route, `huddleEndpoint.handle`, takes the `POST` and `OPTIONS` requests. The `huddleEndpoint.handle` route answers the request in Fastify's `onRequest` step, so it can read the raw body. So your app's `onRequest` hooks run for these requests, but its `preParsing`, `preValidation` and `preHandler` hooks do not. Other routes and the `connect` route are not affected. If a hook must run for every request, for example a rate limit, add it with `onRequest`.

`authenticate(request)` can reject with an HTTP status or with a WebSocket close code:

```ts
import { CloseCodes, RejectAuth } from '@livething/server/errors'

// The preHandler sends this HTTP response. The socket is never accepted.
throw RejectAuth(401, 'Missing credentials')

// The socket is accepted first, then closed with this code and reason.
throw RejectAuth(CloseCodes.AUTH_INVALID, 'invalid session')
```

This binding passes Fastify's original Node request (`request.raw`) to LiveThing. So [`clientIp`](/core/runtimes/adapters/node#client-ip) works the same way as with `node:http`. LiveThing does not use Fastify's `request.ip` or Fastify's `trustProxy` setting. Set the endpoint option, so LiveThing follows one clear trust rule.

## Serve `http()`

With `http()` listed, a plain `GET` to the `connect` route opens the stream. Add `huddleEndpoint.handle` as a second route on the same path, for `POST` and `OPTIONS`. It answers in `onRequest`, before Fastify reads the body, so you need no content type parser:

```ts [huddle-server.ts]
import websocket from '@fastify/websocket'
import {
  http,
  websocket as websocketTransport,
} from '@livething/server-node'
import { setup } from '@livething/server-node/fastify'
import Fastify from 'fastify'
import { huddle } from './server/huddle-definition'

const app = Fastify()
await app.register(websocket)

const { bind } = setup()
const huddleEndpoint = bind(huddle, {
  sql: './data/huddle.sqlite',
  transports: [websocketTransport(), http()],
})

app.get('/huddle', huddleEndpoint.connect)
app.route({
  method: ['POST', 'OPTIONS'],
  url: '/huddle',
  ...huddleEndpoint.handle,
})
```

## Message size and compression on Fastify

`@fastify/websocket` creates the `ws` server, so LiveThing does not set its limit or its compression. The plugin's `options` go to the `ws` server. Set `maxPayload` there to the endpoint's `maxMessageBytes`, and turn on WebSocket compression (`permessage-deflate`) with `perMessageDeflate`:

```ts [huddle-server.ts]
import websocket from '@fastify/websocket'
import { setup } from '@livething/server-node/fastify'
import Fastify from 'fastify'
import { huddle } from './server/huddle-definition'

// Huddle's file uploads need room for messages up to 64 MiB.
const maxMessageBytes = 64 * 1024 * 1024

const app = Fastify()
await app.register(websocket, {
  options: { maxPayload: maxMessageBytes, perMessageDeflate: true },
})

const { bind } = setup()
const huddleEndpoint = bind(huddle, {
  sql: './data/huddle.sqlite',
  maxMessageBytes,
})
```

## Call the admin API from a Fastify route

```ts [admin-routes.ts]
import Fastify from 'fastify'
import { verifySession } from './auth'
import { huddleEndpoint } from './huddle-endpoint'

export function addAdminRoutes(app: ReturnType<typeof Fastify>) {
  app.post('/admin/announcements', async (request, reply) => {
    const token = request.headers.authorization?.replace(
      /^Bearer /i,
      '',
    )
    const user = await verifySession(token) // your auth
    if (user?.role !== 'admin') return reply.code(401).send()

    const { text } = request.body as { text: string }

    const admin = await huddleEndpoint.admin()
    await admin.announce(text)

    return reply.code(204).send()
  })
}
```

Call `addAdminRoutes(app)` with the same `app` that serves the WebSocket route.
