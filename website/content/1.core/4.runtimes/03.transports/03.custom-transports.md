LiveThing ships two [transports](/core/runtimes/transports/overview): WebSocket, and `http()` (server-sent events and POST requests). If your users are on a network that neither one reaches, you can build your own transport. A transport has two parts:

- **A client transport**, which you list in the [`transports`](/core/client/transports/overview) option of `connect()`, next to `websocket()` and `http()`.
- **A server transport**, which you list in the `transports` option of the adapter's `bind()`, next to `websocket()` and `http()`.

The engine does not change. It sends frames to a connection and gets frames from it, and it does not care how they travel. Your transport moves the same frames that WebSocket moves. This page covers the server half, and builds a long-polling transport, because long polling is the transport people ask about most. The client half is on the client [Custom Transports](/core/client/transports/custom-transports) page.

## Why LiveThing has no long polling

LiveThing has no built-in long polling, for these reasons:

- **`http()` reaches the same networks.** Both are plain HTTP requests, so a proxy that blocks WebSocket lets both through.
- **Long polling is slower and costs more.** After every answer the client must send a new request, and messages that arrive in between wait on the server. One open stream has no such gap.
- **The gap makes order and memory harder.** The server keeps the messages for each client between polls, and must keep them in order when a poll fails.

Long polling helps in one case: a proxy that holds back a whole response until it ends, so a stream never arrives. mitmproxy, a proxy for debugging, does this with its default settings: in our tests through it, WebSocket worked and no event of the stream arrived. We have not found data on how many networks do this. If yours does, build long polling as a custom transport with the example below.

## The server side

A server transport is a `ServerTransport` object with a `name`, a `handle()`, and an optional `check()`. The [complete example](#a-complete-long-polling-transport) at the end of this page has the server side. List it in `bind()` with the built-in transports. Its `name` must not be `websocket` or `http`, and two transports cannot share a name:

```ts [huddle-server.ts]
import { http, setup, websocket } from '@livething/server-node'
import { huddle } from './server/huddle-definition'
import { longPolling } from './server/long-polling'

const { bind } = setup()
const huddleEndpoint = bind(huddle, {
  sql: './data/huddle.sqlite',
  transports: [websocket(), http(), longPolling()],
})
```

### `handle(request, endpoint)`

The adapter calls `handle()` for every request to the endpoint that is not a WebSocket upgrade. It gives you a standard Web `Request` and returns your `Response`, on Node, on Cloudflare and in a custom adapter alike.

- **Return `null` for a request that is not yours.** The adapter then offers the request to the next custom transport, in list order, and then to `http()`. Without `http()`, a request that nobody takes gets `426`. Mark your requests in a way you can check cheaply, such as a header, and return `null` before you read the body: the body can be read only once.
- **The response can stream.** On Node, the adapter writes the body as your stream produces it. A slow client slows the writes, so your stream's `desiredSize` shows it.
- **Watch `request.signal`.** It aborts when the client goes away, and on Node when the endpoint shuts down. A request you hold open, such as a poll, must stop waiting then. On Node, the shutdown ends every request still open.
- **A thrown error answers `500`.** The adapter logs it.

### `endpoint.authenticate(request)`

It runs the endpoint's origin check, then the server's [`authenticate`](/core/server/server/authenticate), and returns its decision. A request from an origin that is not allowed gets `{ reject: true, code: 403 }`. Pass the request you got, so the adapter keeps the client's IP address.

A request with no `Origin` header passes the check, unless its `Sec-Fetch-Site` header says it came from another site. A browser leaves `Origin` out of a plain cross-site `GET`, such as an `<img>` or a `no-cors` fetch, so older browsers that do not send `Sec-Fetch-Site` let such a `GET` through with the user's cookies. Open a connection only for a request that carries your own header, as the example below does with `LiveThing-Transport`. A browser sends a custom header only after a CORS preflight, and that request carries `Origin`.

A decision with `reject: true` has a `code`. A code under `1000` is an HTTP status: answer with it. A code from `1000` is a close code: the client must get it as a close, as it would on a WebSocket.

### `endpoint.accept(connection, decision)`

It hands a connection to the engine and returns its `ConnectionHandle`. Call it only with a decision that is not a reject: a rejected decision makes it throw. The `connection` is how the engine sends:

| Field                   | What it does                                                                                                                                                                                                                                                                                    |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `send(frame)`           | Send one frame: `{ kind: 'text', text }` or `{ kind: 'bytes', bytes }`. A frame can also have `shared: true`, as on the [Custom adapters](/core/runtimes/adapters/custom-adapters) page. Return `false` when the frame was not sent, so the engine does not count it as delivered. Never throw. |
| `close(code, reason)`   | Close the connection. Tell the client the code and the reason.                                                                                                                                                                                                                                  |
| `bufferedAmount()`      | The bytes waiting to be sent.                                                                                                                                                                                                                                                                   |
| `backpressureSupported` | `true` only when `bufferedAmount()` is the real number. The engine then paces streams and closes a client that reads too slowly with `1013`.                                                                                                                                                    |
| `terminate()`           | Optional. Drop the connection at once, for a client that stopped reading.                                                                                                                                                                                                                       |
| `secret`                | Optional. A secret the client sends to name its connection. The engine puts it in the first frame, `__connected__`, so your client transport reads it there.                                                                                                                                    |
| `maxPostBytes`          | Optional. The largest request body you take, for the `__connected__` frame.                                                                                                                                                                                                                     |

Report what the client does to the handle: `handleMessage(text)` for a text frame, `handleBinaryMessage(bytes)` for a [binary](/core/server/binary/overview) frame, and `handleClose(code, reason)` once when the connection ends, whichever side ended it. Call `handleClose` after your own `close()` too, as a WebSocket close event would. A value that is not a string closes the connection with `1003`, so check what the client sent before you pass it on, and check its close code too: a browser lets a page close with `1000` or `3000` to `4999` only.

### `check(definition)`

Optional. `bind()` calls it once at startup with the server definition. Throw to stop a startup that cannot work. A transport that cannot see a dead client by itself needs [`keepalive()`](/core/server/capabilities/keepalive), whose pings find out:

```ts [server/long-polling.ts]
import { hasCapability } from '@livething/server/adapters'
import type { ServerDefinition } from '@livething/server/adapters'

// Inside the transport object.
function check(definition: ServerDefinition) {
  if (!hasCapability(definition, 'keepalive')) {
    throw new Error(
      'longPolling() needs keepalive() in the server definition.',
    )
  }
}
```

### On Cloudflare

The Worker forwards each request to its Durable Object, as for `http()`, and the object calls `handle()`. Every request of one connection must reach the same object, so route it by the URL, as the [Cloudflare setup](/core/runtimes/adapters/cloudflare#the-http-transport) does. One transport object serves every object of the class in that isolate, so keep your state per connection, such as in a map by secret. An open request keeps the object awake, as an `http()` stream does.

## A complete long-polling transport

LiveThing's own tests run this transport, without its CORS answers, with the real client against a Node server on the same origin: messages both ways, a broadcast to a client that is waiting, close codes from both sides, failover from a blocked WebSocket, and a shutdown while polls wait. It carries text frames only. Like WebSocket, it delivers each message at most once: a frame that was on its way when a poll failed is lost.

The client sends every request with a `LiveThing-Transport: long-polling` header. The first `GET` opens the connection. Each later `GET` carries the secret from `__connected__`, and waits up to 20 seconds for frames. A `POST` carries the client's frames, or its close.

When the page is on another origin, the browser first asks the server if it may send these headers. This is the CORS preflight: an `OPTIONS` request that only names the headers, so it does not carry the transport header itself. The `preflight` function in the example answers it:

- It takes only a preflight that names the transport header. Any other `OPTIONS` request belongs to `http()`, so it returns `null`.
- It answers `204`, with the CORS headers from `corsHeaders(origin)`, the methods the transport uses, and the headers the client sends.

Every other answer gets the CORS headers too, so the page can read it.

`corsHeaders` allows any origin you give it. The Origin check in `endpoint.authenticate()` still stops a page on a site you do not allow from connecting, but that page can still read your answers. To stop that too, check the origin against your own list before you add the CORS headers.

```ts [server/long-polling.ts]
import {
  corsHeaders,
  hasCapability,
  normalizeCloseReason,
} from '@livething/server/adapters'
import type {
  AuthDecision,
  ConnectionHandle,
  ServerTransport,
  TransportEndpoint,
} from '@livething/server/adapters'

const POLL_MS = 20_000
const CLIENT_HEADERS =
  'Authorization, Content-Type, LiveThing-Transport, LiveThing-Secret'

interface CloseInfo {
  code: number
  reason: string
}

interface Session {
  frames: string[]
  wake: (() => void) | null
  closed: CloseInfo | null
  handle: ConnectionHandle | null
}

interface ClientMessage {
  frames?: string[]
  close?: CloseInfo
}

const MAX_BODY_BYTES = 1024 * 1024

// A client may close with 1000 or an app code, as on a WebSocket.
function isClientClose(close: CloseInfo) {
  const { code } = close
  const allowed = code === 1000 || (code >= 3000 && code <= 4999)
  return (
    Number.isInteger(code) &&
    allowed &&
    typeof close.reason === 'string'
  )
}

export function longPolling(): ServerTransport {
  const sessions = new Map<string, Session>()

  function finish(secret: string, close: CloseInfo) {
    const session = sessions.get(secret)
    if (!session || session.closed) return

    session.closed = close
    session.wake?.()
    // Keep the session for one more poll, so the client reads the close.
    setTimeout(() => sessions.delete(secret), POLL_MS).unref?.()
    void session.handle?.handleClose(close.code, close.reason)
  }

  async function poll(
    secret: string,
    session: Session,
    signal: AbortSignal,
  ) {
    if (
      session.frames.length === 0 &&
      !session.closed &&
      !signal.aborted
    ) {
      await new Promise<void>((resolve) => {
        function wake() {
          clearTimeout(timer)
          signal.removeEventListener('abort', wake)
          resolve()
        }

        const timer = setTimeout(wake, POLL_MS)
        signal.addEventListener('abort', wake)
        session.wake = wake
      })
      session.wake = null
    }

    if (session.closed) sessions.delete(secret)

    return Response.json({
      frames: session.frames.splice(0),
      close: session.closed,
    })
  }

  async function open(request: Request, endpoint: TransportEndpoint) {
    const decision: AuthDecision =
      await endpoint.authenticate(request)
    if (decision.reject) {
      const code = decision.code ?? 401
      if (code < 1000) {
        return new Response(decision.reason ?? null, { status: code })
      }

      return Response.json({
        frames: [],
        close: { code, reason: decision.reason ?? '' },
      })
    }

    const secret = crypto.randomUUID()
    const session: Session = {
      frames: [],
      wake: null,
      closed: null,
      handle: null,
    }

    sessions.set(secret, session)
    session.handle = endpoint.accept(
      {
        send(frame) {
          if (session.closed || frame.kind !== 'text') return false

          session.frames.push(frame.text)
          session.wake?.()
          return true
        },
        close: (code = 1000, reason = '') =>
          finish(secret, { code, reason }),
        bufferedAmount: () =>
          session.frames.reduce(
            (total, frame) => total + frame.length,
            0,
          ),
        backpressureSupported: false,
        secret,
      },
      decision,
    )

    return poll(secret, session, request.signal)
  }

  async function receive(
    secret: string,
    session: Session,
    request: Request,
  ) {
    const length = request.headers.get('Content-Length')
    if (Number(length ?? Infinity) > MAX_BODY_BYTES) {
      return new Response(null, { status: 413 })
    }

    const message = (await request
      .json()
      .catch(() => null)) as ClientMessage | null
    const frames = message?.frames ?? []
    const close = message?.close
    const badFrames =
      !Array.isArray(frames) ||
      frames.some((frame) => typeof frame !== 'string')
    if (badFrames || (close && !isClientClose(close))) {
      return new Response(null, { status: 400 })
    }

    for (const frame of frames) {
      void session.handle?.handleMessage(frame)
    }

    if (close) {
      finish(secret, {
        code: close.code,
        reason: normalizeCloseReason(close.reason)!,
      })
    }

    return new Response(null, { status: 204 })
  }

  async function route(
    request: Request,
    endpoint: TransportEndpoint,
  ) {
    const secret = request.headers.get('LiveThing-Secret')
    if (secret === null) return open(request, endpoint)

    const session = sessions.get(secret)
    if (!session) return new Response(null, { status: 404 })

    return request.method === 'POST'
      ? receive(secret, session, request)
      : poll(secret, session, request.signal)
  }

  function preflight(request: Request, origin: string | null) {
    const asked =
      request.headers.get('Access-Control-Request-Headers') ?? ''
    if (origin === null || !/livething-transport/i.test(asked)) {
      return null
    }

    return new Response(null, {
      status: 204,
      headers: {
        ...corsHeaders(origin),
        'Access-Control-Allow-Methods': 'GET, POST',
        'Access-Control-Allow-Headers': CLIENT_HEADERS,
      },
    })
  }

  return {
    name: 'long-polling',
    check(definition) {
      if (!hasCapability(definition, 'keepalive')) {
        throw new Error(
          'longPolling() needs keepalive() in the server definition.',
        )
      }
    },
    async handle(request, endpoint) {
      const origin = request.headers.get('Origin')
      if (request.method === 'OPTIONS') {
        return preflight(request, origin)
      }

      const transport = request.headers.get('LiveThing-Transport')
      if (transport !== 'long-polling') return null

      const response = await route(request, endpoint)
      for (const [name, value] of Object.entries(
        corsHeaders(origin),
      )) {
        response.headers.set(name, value)
      }

      return response
    },
  }
}
```

The client half of this transport, the code that polls in a loop and sends its frames in order, is on the client [Custom Transports](/core/client/transports/custom-transports#a-complete-long-polling-transport) page.

To carry [binary messages](/core/server/binary/overview), send a `bytes` frame as base64 text with a mark, as [`http()` does](/core/learn/wire-protocol#over-http). The [client half](/core/client/transports/custom-transports) turns it back into bytes.
