`websocket()` is the default transport. One WebSocket carries every message in both directions, so it costs the least of the [transports](/core/runtimes/transports/overview). An endpoint offers it when you list no transports at all. When you list your own, add it next to [`http()`](/core/runtimes/transports/http):

```ts [huddle-server.ts]
import { http, setup, websocket } from '@livething/server-node'
import { huddle } from './server/huddle-definition'

const { bind } = setup()
// Clients use WebSocket, and move to `http()` on a network that blocks it.
const huddleEndpoint = bind(huddle, {
  transports: [websocket(), http()],
})
```

Import `websocket()` from your adapter package, as you do `setup()`. The adapter serves the socket.

## Settings

`websocket()` takes no options. The runtime adapter that runs the socket has the settings, because each platform handles WebSocket in its own way:

| Setting                | Node.js                                                                                 | Cloudflare                                                                                                                           |
| ---------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Largest message        | [`maxMessageBytes`](/core/runtimes/adapters/node#message-size-limit), 32 MiB by default | 32 MiB, set by Cloudflare                                                                                                            |
| Compression            | [`compression`](/core/runtimes/adapters/node#compression), off by default               | [On](/core/runtimes/adapters/cloudflare#compression) when the client asks for it, and browsers always ask                            |
| Pages on other origins | [`allowedOrigins`](/core/runtimes/adapters/node#allowed-origins)                        | [`allowedOrigins`](/core/runtimes/adapters/cloudflare#allowed-origins)                                                               |
| Idle sockets           | Stay in memory                                                                          | Can [hibernate](/core/runtimes/adapters/cloudflare#how-it-relates-to-hibernation): the instance leaves memory, the socket stays open |

A client message over the size limit closes the socket with `1009` ([`MESSAGE_TOO_BIG`](/core/core/close-codes)). With [Fastify](/core/runtimes/node-frameworks/fastify), [H3](/core/runtimes/node-frameworks/h3) and the [Nitro apps](/core/runtimes/node-frameworks/overview#nitro-apps-nuxt-solidstart-and-tanstack-start), the framework creates the WebSocket server, so you set its limit and compression there too. [Hono](/core/runtimes/node-frameworks/hono#message-size-and-compression-on-hono) sets them in `setup()`.

## The token

A browser cannot set headers on a WebSocket handshake. So the client sends the [`connect()` token](/core/client/connecting/auth-and-query) in the `Sec-WebSocket-Protocol` header, as the subprotocol `livething-v1.token.<token in base64url>`. The server moves it to `Authorization: Bearer <token>` before `authenticate` runs, so `authenticate` reads it the same way on every transport. The server never sends the token back. When the request already has a real `Authorization` header, that header wins.

## Slow clients

`ctx.send` does not wait for the client. To find a client that cannot keep up, read [`ctx.bufferedAmount`](/core/server/context-and-storage/ctx), the bytes still waiting to go to this socket. On Node it is the real size. For a WebSocket on Cloudflare it is always `0`, because Cloudflare does not report it.

## Behind a proxy

A reverse proxy must pass the WebSocket upgrade on. With nginx, add these lines to the `location` of your endpoint's path:

```nginx
location /huddle {
  proxy_pass http://127.0.0.1:3000;
  proxy_http_version 1.1;
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";
  proxy_set_header Host $http_host;
}
```

`Host $http_host` keeps the browser's host and port, so the [origin check](/core/runtimes/adapters/node#allowed-origins) still matches. nginx's `$host` drops the port, and the check would then refuse a page on a port such as `8080`. A proxy that changes `Host` needs your page's origin in `allowedOrigins`.

Proxies also close a connection that stays quiet for too long. nginx waits 60 seconds by default (`proxy_read_timeout`). The [`keepalive()`](/core/server/capabilities/keepalive) capability sends a ping every 30 seconds by default, so a quiet socket stays open. Without it, raise the proxy's timeout, or use the client's [`keepalive()`](/core/client/primitives/keepalive), which pings too.

When a network or proxy blocks WebSocket, the handshake fails, and the client moves to the next transport in its list. To keep those users connected, offer [`http()`](/core/runtimes/transports/http) too.
