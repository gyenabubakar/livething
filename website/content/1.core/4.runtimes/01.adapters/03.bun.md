`@livething/server-bun` runs a LiveThing server definition on [Bun](https://bun.sh). You write the definition with `server`, capabilities, handlers, and `assemble`, and this code is the same for every adapter. Only the entry file changes. The entry file is the small file that passes your definition to the adapter.

To see a full server definition, read the [server overview](/core/server/overview#a-minimal-server-end-to-end). The `server/huddle-definition.ts` file in that example works on Bun with no changes. Only the adapter file after it is different on Bun. To learn what an adapter does internally, see [Custom adapters](/core/runtimes/adapters/custom-adapters).

## The `http()` transport

The Bun adapter takes the same `transports` list as the other adapters. Import `websocket()` and `http()` from `@livething/server-bun`, and list them in the `transports` option of its `bind()`. `http()` needs `keepalive()` in the definition, and every rule on the [Transports](/core/runtimes/transports/overview) and [`http()`](/core/runtimes/transports/http) pages applies.
