the framework for building realtime apps in typescript

LiveThing is a WebSocket framework for TypeScript. Write your server, and your client gets its types from it, with no shared schema file and no code generation. Rooms, requests, durable streams, presence and reconnection come built in.

#headline
The Contract

#title
Types shared by :br client and server

#description
One source of truth for both sides of the connection. Describe your app once on the server, and the client gets its types from it automatically. Every event, request, channel, and stream is typed from the client's side: what the server sends, the client receives. If the client and server stop matching, your editor shows a type error before the code runs.
:::

#headline
Channels

#title
Channels with :br access control

#description
Rooms with real membership rules. You decide who can join, and a broadcast reaches only the members of that room. The rules run on your server, so a client cannot skip them. Presence (who is in a room and who is online) and dynamic rooms, such as one room for each chat, are included.
:::

#headline
Streaming

#title
Streaming responses, :br chunk by chunk

#description
Send data to the client as soon as it exists: token by token, event by event, with every chunk typed on both ends. Streams are built for LLM output and live feeds. The client can send nudges (small typed messages) to change a stream while it runs. Durable streams continue from the exact point where a disconnect stopped them.
:::

#headline
Requests

#title
Requests over :br one socket

#description
Real request and response over a WebSocket. Send the server a request and `await` a typed reply. You don't connect events together or track request IDs yourself. Send many requests at once on one connection, and each reply goes back to the call that made it, even when replies arrive out of order. It works in both directions: the server can send requests to the client too.
:::

#headline
Reliability

#title
Reconnection :br and replay

#description
Real networks drop connections: a laptop goes to sleep, a phone loses signal, you deploy a new version. LiveThing keeps the connection healthy and your data correct through each of these. It detects a dead socket, reconnects with backoff (a longer wait before each new try), holds the messages you send while offline, and replays the messages you missed without duplicates. Add only the parts you need.
:::

#headline
Opt-in & tiny

#title
A small core with :br opt-in features

#description
Small to start, and small as your app grows. A typed client socket is about `5.24 KB` minified and gzipped. Every feature is a separate module, so your bundler leaves out the features you don't import, and their code never reaches your users. Turn on every client feature and the client is still about `21 KB`.
:::

#headline
The Engine

#title
Runtime- and :br transport-agnostic

#description
The engine is the core of the LiveThing server. It holds your contract, sends every message to the right handler, and runs your channels, requests, streams, and presence. The engine does not open sockets. An adapter (a small layer for one runtime) gives it each message and sends its replies back. So the same app code runs over WebSocket, server-sent events, or long polling, on Cloudflare, Node, Bun, or Deno.
:::
