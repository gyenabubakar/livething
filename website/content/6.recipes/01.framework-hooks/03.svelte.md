A LiveThing [store](/client/overview#reactive-stores) maps almost one-to-one onto a Svelte `readable`: both have a start function that receives `set` and returns a stop function. So the adapter is a single line, and every socket value goes through it.

In every example on this page, `./socket` is Huddle's client socket, as defined on the [Huddle page](/reference/huddle#the-client-socket). It installs `keepalive()`, `reconnection()`, `platform()`, `channels()`, `inbox()` and `readReceipts()`, which the stores below need.

## The adapter

`toStore` turns any `ReadableStore` into a Svelte `readable`. Svelte's `readable(initial, start)` is `start(set) => stop`, which is exactly `store.get()` plus `store.subscribe`:

```ts [stores.ts]
import { readable } from 'svelte/store'
import type { ReadableStore } from '@livething/client'

export function toStore<T>(store: ReadableStore<T>) {
  return readable(store.get(), (set) => store.subscribe(set))
}
```

```ts [socket-stores.ts]
import { socket } from './socket'
import { toStore } from './stores'

export const connectionState = toStore(socket.state)
export const quality = toStore(socket.quality) // needs keepalive()
export const latency = toStore(socket.latency) // needs keepalive()
export const reconnection = toStore(socket.reconnection) // needs reconnection()
export const online = toStore(socket.online) // needs platform()
```

```svelte [StatusDot.svelte]
<script lang="ts">
  import { connectionState } from './socket-stores'
</script>

<span class={$connectionState === 'open' ? 'green' : 'grey'}>{$connectionState}</span>
```

Svelte starts the underlying `store.subscribe` when the first component reads `$connectionState` and stops it when the last one drops, so the socket subscription is tied to actual use. `channel.members` and `channel.status` wrap the same way — `toStore(room.members)`, `toStore(room.status)` — so a roster or a "joining…" state is one more line.

## With runes (Svelte 5)

For state local to one component, a `$state` variable plus a `$effect` that subscribes works without a shared store. Returning the store's unsubscribe from the effect makes it the cleanup:

```svelte [StatusDot.svelte]
<script lang="ts">
  import { socket } from './socket'

  let state = $state(socket.state.get())
  $effect(() => socket.state.subscribe((s) => { state = s }))
</script>

<span class={state === 'open' ? 'green' : 'grey'}>{state}</span>
```

## Connection quality

With [`keepalive()`](/client/primitives/keepalive), `quality` and `latency` are the same wrapped stores — read them with `$`:

```svelte [SignalBars.svelte]
<script lang="ts">
  import { Bars } from './huddle-ui'
  import { quality, latency } from './socket-stores'
</script>

<Bars tier={$quality} title={$latency === null ? 'measuring…' : `${$latency}ms`} />
```

## Reconnection status

With [`reconnection()`](/client/primitives/reconnection), `reconnection` is a store of `{ retrying, attempt, nextRetryAt }`:

```svelte [ReconnectBanner.svelte]
<script lang="ts">
  import { Banner } from './huddle-ui'
  import { reconnection } from './socket-stores'
</script>

{#if $reconnection.retrying}<Banner>Reconnecting… (attempt {$reconnection.attempt})</Banner>{/if}
```

## Network status

With [`platform()`](/client/platform/overview), `online` follows the environment's network signal:

```svelte [OfflineBanner.svelte]
<script lang="ts">
  import { Banner } from './huddle-ui'
  import { online } from './socket-stores'
</script>

{#if !$online}<Banner>You're offline</Banner>{/if}
```

## Channel presence

`channel.members` and `channel.status` are per-channel, so wrap them where you open the channel:

```svelte [Roster.svelte]
<script lang="ts">
  import { Spinner } from './huddle-ui'
  import { toStore } from './stores'
  import { socket } from './socket'

  const room = socket.channel('rooms', 'room:general')
  const members = toStore(room.members)
  const status = toStore(room.status)
</script>

{#if $status === 'subscribing'}
  <Spinner />
{:else}
  <ul>{#each [...$members] as [id, m] (id)}<li>{m.meta.name}</li>{/each}</ul>
{/if}
```

## Receipts

`dm.receivers` and `dm.readers` are channel stores too — each a `Map<userId, cursor>` of how far the other person has received (grey check) or read (blue check). `receivers` fills only because the `dms` family calls `inbox()` (for receivers) and `readReceipts()` (for readers). Wrap them with `toStore` and read with `$`:

```svelte [Ticks.svelte]
<script lang="ts">
  import { Check } from './huddle-ui'
  import { toStore } from './stores'
  import { socket } from './socket'

  let { pair, seq }: { pair: string; seq: number } = $props()
  const dm = socket.channel('dms', `dm:${pair}`)
  const receivers = toStore(dm.receivers)
  const readers = toStore(dm.readers)

  const read = $derived([...$readers.values()].some((mark) => mark >= seq))
  const received = $derived([...$receivers.values()].some((mark) => mark >= seq))
</script>

<Check state={read ? 'read' : received ? 'received' : 'sent'} />
```

## Incoming events

Incoming events aren't a store — they're `socket.on(...)`, which returns the unsubscribe an effect (or a `readable`) cleans up with. A `readable` factory keeps the payload typed from the contract:

```ts [client/incoming.ts]
import { readable } from 'svelte/store'
import { socket } from './socket'
import type { HuddleSocket } from '../server/huddle-definition'

type Incoming = HuddleSocket['incoming']

export function incoming<E extends keyof Incoming & string>(
  event: E,
) {
  return readable(undefined as Incoming[E] | undefined, (set) =>
    socket.on(event, set),
  )
}
```

`incoming(...)` is used like any store — call it once, then read it with the `$` prefix. The event name is checked and `$note` is typed from the contract:

```svelte [Notifications.svelte]
<script lang="ts">
  import { Toast } from './huddle-ui'
  import { incoming } from './incoming'

  const note = incoming('notification') // Readable<{ title: string; body: string } | undefined>
</script>

{#if $note}<Toast>{$note.title}</Toast>{/if}
```

## Requests

A request is an `await`, so an `{#await}` block or a small async handler covers it:

```svelte [Profile.svelte]
<script lang="ts">
  import { ErrorNotice, ProfileCard, Spinner } from './huddle-ui'
  import { socket } from './socket'

  let { userId }: { userId: string } = $props()
  const profile = $derived(socket.request('get-profile', { userId }))
</script>

{#await profile}
  <Spinner />
{:then p}
  <ProfileCard {...p} />
{:catch err}
  <ErrorNotice {err} />
{/await}
```

## Connecting and SSR

Open the socket on mount so it stays client-side — under SvelteKit, `onMount` only runs in the browser:

```svelte [+layout.svelte]
<script lang="ts">
  import { onMount } from 'svelte'
  import { socket } from './socket'

  onMount(() => {
    socket.connect()
    return () => socket.disconnect()
  })
</script>
```

The stores start from `socket.state.get()` (`'closed'` before connect), so server-rendered markup and the first client render agree. See [SSR Safety](/client/connecting/ssr-safety) for the details.
