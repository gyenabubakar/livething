React's `useSyncExternalStore` is built for exactly this — a value that lives outside React and changes over time. Every WSKit [store](/client/overview#reactive-stores) already has the shape it wants, so you write one adapter and reuse it for every value.

## The adapter

`useStore` takes any `ReadableStore<T>` and returns its current value, re-rendering when it changes. This is the only store binding you need — connection state, quality, roster, all of them go through it:

```tsx [use-store.ts]
import { useSyncExternalStore } from 'react'
import type { ReadableStore } from '@wskit/client'

export function useStore<T>(store: ReadableStore<T>, serverValue?: T): T {
  return useSyncExternalStore(
    (cb) => store.subscribe(cb),
    () => store.get(),
    () => (serverValue === undefined ? store.get() : serverValue),
  )
}
```

The third argument to `useSyncExternalStore` is the **server snapshot**, rendered during SSR when there's no connection. `serverValue` is optional — omit it and `useStore` falls back to the store's own `store.get()`, which is exactly right for a store that starts empty (like a receipts map). Pass one only when you want a nicer placeholder, such as `'closed'` for the connection state.

## Connection state

Point `useStore` at `socket.state`; `'closed'` is the right server value:

```tsx [StatusDot.tsx]
import { useStore } from './use-store'
import { socket } from './socket'

function StatusDot() {
  const state = useStore(socket.state, 'closed')
  return <span className={state === 'open' ? 'green' : 'grey'}>{state}</span>
}
```

## Connection quality

With [`keepalive()`](/client/primitives/keepalive) installed, `socket.quality` and `socket.latency` are stores too — the *same* `useStore`, no new hook:

```tsx [SignalBars.tsx]
import { useStore } from './use-store'
import { socket } from './socket'

function SignalBars() {
  const quality = useStore(socket.quality, 'disconnected')
  const latency = useStore(socket.latency, null)
  return <Bars tier={quality} title={latency === null ? 'measuring…' : `${latency}ms`} />
}
```

## Reconnection status

With [`reconnection()`](/client/primitives/reconnection) installed, `socket.reconnection` is a store of `{ retrying, attempt, nextRetryAt }` — the same `useStore` turns it into a live "reconnecting…" banner:

```tsx [ReconnectBanner.tsx]
import { useStore } from './use-store'
import { socket } from './socket'

const idle = { retrying: false, attempt: 0, nextRetryAt: null }

function ReconnectBanner() {
  const { retrying, attempt } = useStore(socket.reconnection, idle)
  return retrying ? <Banner>Reconnecting… (attempt {attempt})</Banner> : null
}
```

## Network status

With [`platform()`](/client/platform/overview) installed, `socket.online` reflects the environment's network signal — one more store, same adapter:

```tsx [OfflineBanner.tsx]
import { useStore } from './use-store'
import { socket } from './socket'

function OfflineBanner() {
  const online = useStore(socket.online, true)
  return online ? null : <Banner>You're offline</Banner>
}
```

## Channel presence

`channel.members` and `channel.status` are stores as well, so a roster and a "joining…" state come from the same adapter:

```tsx [Roster.tsx]
import { useStore } from './use-store'
import { socket } from './socket'

function Roster() {
  const room = socket.channel('rooms', 'room-42')
  const members = useStore(room.members, new Map())
  const status = useStore(room.status, 'unsubscribed')

  if (status === 'subscribing') return <Spinner />
  return <ul>{[...members.values()].map((m) => <li>{m.meta.username}</li>)}</ul>
}
```

## Receipts

`chat.receivers` and `chat.readers` are channel stores too — each a `Map<identity, cursor>` of how far every member has received (grey check) or read (blue check). `receivers` fills only when the server channel sets `broadcastReceipts: true`. The same `useStore` turns them into a per-message tick:

```tsx [Ticks.tsx]
import { useStore } from './use-store'
import { socket } from './socket'

// chat needs inbox() (for receivers) and readReceipts() (for readers)
function Ticks({ seq }: { seq: number }) {
  const chat = socket.channel('chat')
  const receivers = useStore(chat.receivers)
  const readers = useStore(chat.readers)

  const read = [...readers.values()].some((mark) => mark >= seq)
  const received = [...receivers.values()].some((mark) => mark >= seq)
  return <Check state={read ? 'read' : received ? 'received' : 'sent'} />
}
```

## Incoming events

`socket.on(event, handler)` is already typed from your contract — the event name is checked, and the handler's `data` is inferred. Keep that when you wrap it: type the hook over the contract's incoming events instead of a bare `string`, and there's no cast.

```tsx [use-incoming.ts]
import { useEffect, useState } from 'react'
import { socket } from './socket'
import type { ChatSocket } from '../server/chat'

type Incoming = ChatSocket['incoming']

export function useIncoming<E extends keyof Incoming & string>(event: E) {
  const [data, setData] = useState<Incoming[E]>()
  useEffect(() => socket.on(event, setData), [event])
  return data
}
```

```tsx [Notifications.tsx]
function Notifications() {
  const note = useIncoming('notification') // note: { title: string } | undefined — inferred
  return note ? <Toast>{note.title}</Toast> : null
}
```

`event` only accepts a real incoming event name, the return type comes from the contract, and `socket.on(event, setData)` hands the listener straight to React's cleanup — no leak, no `as`.

## Requests

A request is just an `await`, so handle it like any async call with local state:

```tsx [useProfile.ts]
import { useEffect, useState } from 'react'
import { socket } from './socket'

function useProfile(id: string) {
  const [profile, setProfile] = useState<Profile>()
  const [error, setError] = useState<unknown>()

  useEffect(() => {
    let active = true
    socket
      .request('get-profile', { id })
      .then((p) => active && setProfile(p))
      .catch((e) => active && setError(e))
    return () => { active = false }
  }, [id])

  return { profile, error }
}
```

The `active` flag drops a late response after the component unmounted or the `id` changed — the usual React async guard.

## Connecting and SSR

Build the socket once at module scope (see [Creating a socket](/client/overview#creating-a-socket)), and open it from an effect at the top of your tree:

```tsx [App.tsx]
import { useEffect } from 'react'
import { socket } from './socket'

function App() {
  useEffect(() => {
    socket.connect()         // safe to call repeatedly; idempotent while open
    return () => socket.disconnect()
  }, [])
  // ...
}
```

`connect()` is a no-op while already open or connecting, so React 18 StrictMode's double-invoke in development is harmless. In a server-rendered app (Next), keep the socket module client-only and rely on the `'closed'` server snapshots above — details in [SSR Safety](/client/connecting/ssr-safety).
