React's `useSyncExternalStore` is built for exactly this — a value that lives outside React and changes over time. Every LiveThing [store](/client/overview#reactive-stores) already has the shape it wants, so you write one adapter and reuse it for every value.

In every example on this page, `./socket` is Huddle's client socket, as defined on the [Huddle page](/reference/huddle#the-client-socket). It installs `keepalive()`, `reconnection()`, `platform()`, `channels()`, `inbox()` and `readReceipts()`, which the stores below need.

## The adapter

`useStore` takes any `ReadableStore<T>` and returns its current value, re-rendering when it changes. This is the only store binding you need — connection state, quality, roster, all of them go through it:

```ts [use-store.ts]
import { useSyncExternalStore } from 'react'
import type { ReadableStore } from '@livething/client'

export function useStore<T>(
  store: ReadableStore<T>,
  serverValue?: T,
): T {
  return useSyncExternalStore(
    (cb) => store.subscribe(cb),
    () => store.get(),
    () => (serverValue === undefined ? store.get() : serverValue),
  )
}
```

The third argument to `useSyncExternalStore` is the **server snapshot**, rendered during SSR when there's no connection. `serverValue` is optional — omit it and `useStore` falls back to the store's own `store.get()`, which is exactly right for a store that starts empty (like a receipts map). Pass one only when you want a better placeholder, such as `'closed'` for the connection state.

## Connection state

Point `useStore` at `socket.state`; `'closed'` is the right server value:

```tsx [StatusDot.tsx]
import { socket } from './socket'
import { useStore } from './use-store'

function StatusDot() {
  const state = useStore(socket.state, 'closed')
  return (
    <span className={state === 'open' ? 'green' : 'grey'}>
      {state}
    </span>
  )
}
```

## Connection quality

With [`keepalive()`](/client/primitives/keepalive) installed, `socket.quality` and `socket.latency` are stores too — the _same_ `useStore`, no new hook:

```tsx [SignalBars.tsx]
import { Bars } from './huddle-ui'
import { socket } from './socket'
import { useStore } from './use-store'

function SignalBars() {
  const quality = useStore(socket.quality, 'disconnected')
  const latency = useStore(socket.latency, null)
  return (
    <Bars
      tier={quality}
      title={latency === null ? 'measuring…' : `${latency}ms`}
    />
  )
}
```

## Reconnection status

With [`reconnection()`](/client/primitives/reconnection) installed, `socket.reconnection` is a store of `{ retrying, attempt, nextRetryAt }` — the same `useStore` turns it into a live "reconnecting…" banner:

```tsx [ReconnectBanner.tsx]
import { Banner } from './huddle-ui'
import { socket } from './socket'
import { useStore } from './use-store'

const idle = { retrying: false, attempt: 0, nextRetryAt: null }

function ReconnectBanner() {
  const { retrying, attempt } = useStore(socket.reconnection, idle)
  return retrying ? (
    <Banner>Reconnecting… (attempt {attempt})</Banner>
  ) : null
}
```

## Network status

With [`platform()`](/client/platform/overview) installed, `socket.online` reflects the environment's network signal — one more store, same adapter:

```tsx [OfflineBanner.tsx]
import { Banner } from './huddle-ui'
import { socket } from './socket'
import { useStore } from './use-store'

function OfflineBanner() {
  const online = useStore(socket.online, true)
  return online ? null : <Banner>You're offline</Banner>
}
```

## Channel presence

`channel.members` and `channel.status` are stores as well, so a roster and a "joining…" state come from the same adapter:

```tsx [Roster.tsx]
import { Spinner } from './huddle-ui'
import { socket } from './socket'
import { useStore } from './use-store'

function Roster() {
  const room = socket.channel('rooms', 'room:general')
  const members = useStore(room.members, new Map())
  const status = useStore(room.status, 'unsubscribed')

  if (status === 'subscribing') return <Spinner />

  return (
    <ul>
      {[...members].map(([memberId, m]) => (
        <li key={memberId}>{String(m.meta.name)}</li>
      ))}
    </ul>
  )
}
```

## Receipts

`dm.receivers` and `dm.readers` are channel stores too — each a `Map<userId, cursor>` of how far the other person has received (grey check) or read (blue check). `receivers` fills only because the `dms` family calls `inbox()` (for receivers) and `readReceipts()` (for readers). The same `useStore` turns them into a per-message tick:

```tsx [Ticks.tsx]
import { Check } from './huddle-ui'
import { socket } from './socket'
import { useStore } from './use-store'

function Ticks({ pair, seq }: { pair: string; seq: number }) {
  const dm = socket.channel('dms', `dm:${pair}`)
  const receivers = useStore(dm.receivers)
  const readers = useStore(dm.readers)

  const read = [...readers.values()].some((mark) => mark >= seq)
  const received = [...receivers.values()].some((mark) => mark >= seq)

  return (
    <Check state={read ? 'read' : received ? 'received' : 'sent'} />
  )
}
```

## Incoming events

`socket.on(event, handler)` is already typed from your contract — the event name is checked, and the handler's `data` is inferred. Keep that when you wrap it: type the hook over the contract's incoming events instead of a bare `string`, and there's no cast.

```ts [client/use-incoming.ts]
import { useEffect, useState } from 'react'
import { socket } from './socket'
import type { HuddleSocket } from '../server/huddle-definition'

type Incoming = HuddleSocket['incoming']

export function useIncoming<E extends keyof Incoming & string>(
  event: E,
) {
  const [data, setData] = useState<Incoming[E]>()
  useEffect(() => socket.on(event, setData), [event])
  return data
}
```

```tsx [Notifications.tsx]
import { Toast } from './huddle-ui'
import { useIncoming } from './use-incoming'

function Notifications() {
  const note = useIncoming('notification') // note: { title: string; body: string } | undefined — inferred
  return note ? <Toast>{note.title}</Toast> : null
}
```

`event` only accepts a real incoming event name, the return type comes from the contract, and `socket.on(event, setData)` hands the listener straight to React's cleanup — no leak, no `as`.

## Requests

A request is just an `await`, so handle it like any async call with local state:

```ts [useProfile.ts]
import { useEffect, useState } from 'react'
import { socket } from './socket'

const getProfile = (userId: string) =>
  socket.request('get-profile', { userId })
type Profile = Awaited<ReturnType<typeof getProfile>>

function useProfile(userId: string) {
  const [profile, setProfile] = useState<Profile>()
  const [error, setError] = useState<unknown>()

  useEffect(() => {
    let active = true
    getProfile(userId)
      .then((p) => active && setProfile(p))
      .catch((e) => active && setError(e))
    return () => {
      active = false
    }
  }, [userId])

  return { profile, error }
}
```

The `active` flag drops a late response after the component unmounted or the `userId` changed — the usual React async guard.

## Connecting and SSR

Build the socket once at module scope (see [Creating a socket](/client/overview#creating-a-socket)), and open it from an effect at the top of your tree:

```tsx [App.tsx]
import { useEffect } from 'react'
import { socket } from './socket'

function App() {
  useEffect(() => {
    socket.connect() // calling it again while open or connecting does nothing
    return () => socket.disconnect()
  }, [])
  // ...
}
```

In development, React 18 StrictMode runs the effect, then the cleanup, then the effect again. The cleanup calls `disconnect()`, so the socket is closed when `connect()` runs the second time. Disconnecting and then connecting again is safe, so this is harmless. In a server-rendered app (Next), keep the socket module client-only and rely on the `'closed'` server snapshots above — details in [SSR Safety](/client/connecting/ssr-safety).
