Solid's reactivity fits WSKit [stores](/client/overview#reactive-stores) cleanly. The `from()` helper turns any subscribe-style source into a signal, so one adapter covers every value, and `createSignal` + `onCleanup` covers incoming events.

## The adapter

`from()` takes a producer `(set) => unsubscribe`. `toSignal` seeds it with `store.get()` and updates on every change, giving back a Solid accessor:

```ts [to-signal.ts]
import { from } from 'solid-js'
import type { ReadableStore } from '@wskit/client'

export function toSignal<T>(store: ReadableStore<T>) {
  return from<T>((set) => {
    set(store.get())
    return store.subscribe(set)
  })
}
```

```tsx [StatusDot.tsx]
import { toSignal } from './to-signal'
import { socket } from './socket'

const connectionState = toSignal(socket.state)

function StatusDot() {
  return <span class={connectionState() === 'open' ? 'green' : 'grey'}>{connectionState()}</span>
}
```

`from` returns an accessor; seeding it with `store.get()` means it's defined from the first read. The same `toSignal` binds `socket.quality`, `channel.members`, `channel.status`, and every other store.

## Incoming events

`socket.on(...)` returns the unsubscribe, which you hand to `onCleanup`:

```ts [useIncoming.ts]
import { createSignal, onCleanup } from 'solid-js'
import { socket } from './socket'
import type { ChatSocket } from '../server/chat'

type Incoming = ChatSocket['incoming']

export function useIncoming<E extends keyof Incoming & string>(event: E) {
  const [data, setData] = createSignal<Incoming[E]>()
  onCleanup(socket.on(event, (d) => setData(() => d)))
  return data
}
```

The functional `setData(() => d)` form stores the value as-is, since Solid otherwise treats a function passed to a setter as an updater.

## Requests

A request is an async source, so `createResource` is the natural fit — it tracks loading and errors for you:

```tsx [Profile.tsx]
import { createResource } from 'solid-js'
import { socket } from './socket'

function Profile(props: { id: string }) {
  const [profile] = createResource(
    () => props.id,
    (id) => socket.request('get-profile', { id }),
  )

  return (
    <Show when={profile()} fallback={<Spinner />}>
      <ProfileCard {...profile()!} />
    </Show>
  )
}
```

`createResource` re-fetches when `props.id` changes and exposes `profile.loading` and `profile.error` if you want them.

## Connection quality

With [`keepalive()`](/client/primitives/keepalive), `socket.quality` and `socket.latency` are stores, so it's just `toSignal` again:

```ts [quality.ts]
import { toSignal } from './to-signal'
import { socket } from './socket'

export const quality = toSignal(socket.quality)
export const latency = toSignal(socket.latency)
```

## Reconnection status

With [`reconnection()`](/client/primitives/reconnection), `socket.reconnection` is a store of `{ retrying, attempt, nextRetryAt }` — `toSignal` again:

```tsx [ReconnectBanner.tsx]
import { toSignal } from './to-signal'
import { socket } from './socket'

const reconnection = toSignal(socket.reconnection)

function ReconnectBanner() {
  return (
    <Show when={reconnection()?.retrying}>
      <Banner>Reconnecting… (attempt {reconnection()!.attempt})</Banner>
    </Show>
  )
}
```

## Network status

With [`platform()`](/client/platform/overview), `socket.online` follows the environment's network signal:

```tsx [OfflineBanner.tsx]
import { toSignal } from './to-signal'
import { socket } from './socket'

const online = toSignal(socket.online)

function OfflineBanner() {
  return <Show when={online() === false}><Banner>You're offline</Banner></Show>
}
```

## Channel presence

`channel.members` and `channel.status` are stores too, so a roster and a "joining…" state are the same `toSignal`:

```tsx [Roster.tsx]
import { toSignal } from './to-signal'
import { socket } from './socket'

function Roster() {
  const room = socket.channel('rooms', 'room-42')
  const members = toSignal(room.members)
  const status = toSignal(room.status)

  return (
    <Show when={status() !== 'subscribing'} fallback={<Spinner />}>
      <ul>
        <For each={[...(members() ?? new Map()).values()]}>{(m) => <li>{m.meta.username}</li>}</For>
      </ul>
    </Show>
  )
}
```

## Connecting and SSR

Open the socket from `onMount`, which runs only in the browser — so it's skipped during SolidStart's server render:

```tsx [App.tsx]
import { onMount, onCleanup } from 'solid-js'
import { socket } from './socket'

function App() {
  onMount(() => {
    socket.connect()
    onCleanup(() => socket.disconnect())
  })
  // ...
}
```

The signals start from `socket.state.get()` / `socket.quality.get()`, which read `'closed'` / `'disconnected'` before connecting, so the server render and first client render match. See [SSR Safety](/client/connecting/ssr-safety).
