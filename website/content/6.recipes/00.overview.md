The rest of the docs teach the pieces: [Start](/start/overview) gets you running, [Learn](/learn/overview) walks each feature from both sides, and the [Server](/server/overview) and [Client](/client/overview) guides hold the per-package detail. **Recipes** put the pieces together — each one is a complete, real app, built end to end, so you can see how the features combine and lift the pattern straight into your own project.

## Why recipes

Learn shows one feature at a time, on its own. A real app is never one feature. A chat is rooms *and* presence *and* history *and* auth, all at once; an AI app is streaming *and* steering *and* surviving a dropped connection. The gap between "I understand channels" and "I've built a chat" is exactly what these pages fill.

So each recipe names the WSKit ingredients it leans on, then builds the whole thing — server and client — as code you can read top to bottom. When you want to go deeper on any one piece, the recipe links back to the Learn, Server, and Client pages that own it.

::note
These pages assume you've met the building blocks already. If a capability or primitive is new to you, follow its link into [Learn](/learn/overview) for the concept, then come back. Recipes are about *assembly*, not first contact.
::

## The recipes

::card-group
::card{title="Chat App" icon="i-ph-chat-circle-dots-duotone" to="/recipes/chat-app"}
The classic: auth-gated rooms, a live member list, and message history that catches up on reconnect. Channels, presence, and replay together.
::
::card{title="Notifications" icon="i-ph-bell-duotone" to="/recipes/notifications"}
Push to one user across every tab they have open. Address a user as a group with tags, delivered reliably even through a brief drop.
::
::card{title="LLM Streaming" icon="i-ph-robot-duotone" to="/recipes/llm-streaming"}
Stream tokens from a model, let the user pause or steer mid-generation with nudges, and resume the stream cleanly across a disconnect.
::
::card{title="Collaborative Editor" icon="i-ph-note-pencil-duotone" to="/recipes/collaborative-editor"}
Sync edits and live cursors in a shared document, scoped to one room, with replay so a returning editor catches up on what changed.
::
::card{title="Multiplayer Game" icon="i-ph-game-controller-duotone" to="/recipes/multiplayer-game"}
Broadcast game state to a room and take player input at speed, with rate limits to keep one client from flooding the rest.
::
::card{title="React Native App" icon="i-simple-icons-react" to="/recipes/react-native-app"}
Run WSKit on mobile — handle the app backgrounding, network changes, and reconnect cleanly when the phone wakes back up.
::
::card{title="Presence & Online List" icon="i-ph-users-duotone" to="/recipes/presence-online-list"}
A live who's-online list that updates as people join and leave, and dims an avatar the moment a connection drops without removing them.
::
::card{title="Better Auth" icon="i-ph-shield-check-duotone" to="/recipes/better-auth"}
Authenticate the socket at the handshake with a Better Auth session cookie, so the connection is tied to a real, verified user.
::
::

## How to read them

Every recipe is self-contained and follows the same shape: the use case, the ingredients it uses, the server, the client, and the contract flowing between them. Start with [Chat App](/recipes/chat-app) — it touches the most features in one place — or jump straight to whichever is closest to what you're building.
