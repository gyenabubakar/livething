A **request** is a question that waits for an answer. The `requests()` capability turns on two kinds:

- **Client to server** — the client asks, your handler answers. This is `base.on` with a reply: the client awaits a value back.
- **Server to client** — your server asks one connection (or many) a question and awaits the client's typed answer.

Import it from `@wskit/server/requests`:

```typescript [server.ts]
import { requests } from '@wskit/server/requests'
```

## Client-to-server requests

Calling `requests()` with no argument already enables client-to-server request handlers. List it, then register a handler with `base.request(event, { input, run })`:

```typescript [server.ts]
import { define, t } from '@wskit/server'
import { requests } from '@wskit/server/requests'
import * as v from 'valibot'

const base = define({
  env: t<Env>(),
  capabilities: [requests()],
})

export const handleGetUser = base.request('get-user', {
  input: v.object({ id: v.string() }),
  run(ctx, input) {
    return { id: input.id, name: 'Ada' }
  },
})
```

A request is like `base.on`, but the client awaits a reply. The reply type is inferred from what `run` returns — here `{ id: string; name: string }`.

::note
If `run` returns `undefined` (or nothing at all), the client's pending request is rejected with the code `request-no-response`. A returned `null` is a real answer — a nullable response, not a missing one. To answer with "nothing here", return `null`, not `undefined`.
::

For the deep handler-authoring detail — `run` versus an explicit `respond`, the acknowledgement shape, and how rejection works — see [base.request](/server/handlers/request).

### The contract slice

`requests()` fills the client contract's `requests` key. Each entry pairs the `payload` the client sends with the `response` it gets back:

```typescript [user-socket.ts]
interface UserSocket {
  requests: {
    'get-user': { payload: { id: string }; response: { id: string; name: string } }
  }
}
```

## Server-to-client requests

Pass a **declaration map** to `requests({...})` and you also enable server-to-client requests. Each key is an event the server can ask; the value declares its shape:

```typescript [server.ts]
import { define, t } from '@wskit/server'
import { requests } from '@wskit/server/requests'
import * as v from 'valibot'

const base = define({
  env: t<Env>(),
  capabilities: [
    requests({
      'ask-permission': { out: t<{ action: string }>(), in: v.object({ allowed: v.boolean() }) },
      'ping-ack': t<{ note: string }>(),
      volunteer: { out: t<{ turn: number }>(), in: v.object({ ready: v.boolean() }) },
    }),
  ],
})
```

Each declaration is one of two shapes.

| Declaration | Meaning |
|---|---|
| `t<T>()` | An **acknowledgement** request. The server sends `T`, the client confirms receipt, and `ctx.request(...)` resolves `Promise<void>`. Any payload the client returns is ignored. |
| `{ out: t<T>(), in: schema }` | A **two-way** request. The server sends `out`, the client answers with `in`. The `in` schema validates the client's reply; a reply that fails it rejects the server's promise with `request-invalid-response`. |

The `out` type is trusted and not validated on the way out — it originates on your server. Only the client's answer (`in`) is validated.

### The contract slice

A declaration map fills the client contract's `serverRequests` key. The declarations above produce one entry each — here are the first two:

```typescript [user-socket.ts]
interface UserSocket {
  serverRequests: {
    'ask-permission': { payload: { action: string }; response: { allowed: boolean } }
    'ping-ack': { payload: { note: string }; response: void }
    volunteer: { payload: { turn: number }; response: { ready: boolean } }
  }
}
```

The acknowledgement request `ping-ack` has a `void` response — the client confirms but answers with nothing.

### Asking one connection

Inside a handler, `ctx.request(event, payload)` asks the calling connection and awaits its answer:

```typescript [handlers.ts]
const handleTrigger = base.on('trigger', {
  input: v.object({ action: v.string() }),
  async run(ctx, input) {
    const answer = await ctx.request('ask-permission', { action: input.action })
    ctx.send('outcome', { allowed: answer.allowed })
  },
})
```

`answer` is typed `{ allowed: boolean }` from the `in` schema. You can pass a timeout as a third argument: `ctx.request('ask-permission', payload, { timeout: 500 })`. If the client never answers in time, the promise rejects.

To target a different connection, ask through a reference: `ctx.connection(ref).request(...)`. Inside a channel handler, `ctx.channel.request(...)` asks the channel's connection.

### Asking everyone — broadcast request

`ctx.broadcastRequest(event, payload)` fans the question out to the other connections on this instance — like `ctx.broadcast`, it skips the caller — and resolves with the **first valid answer**. It returns `{ response, from }`:

```typescript [broadcast.ts]
const handleElect = base.on('elect', {
  input: v.object({ turn: v.number() }),
  async run(ctx, input) {
    const { response, from } = await ctx.broadcastRequest('volunteer', { turn: input.turn })
    ctx.send('outcome', { from: from.identity, ready: response.ready })
  },
})
```

`response` is the winner's typed answer; `from` identifies who answered first. Pass a timeout as a third argument — `ctx.broadcastRequest('volunteer', payload, { timeout: 500 })`; if nobody gives a valid answer in time, the promise rejects with `timeout` (silence counts as "no"). A channel-scoped fan-out is `ctx.channels.get(ref).broadcastRequest(...)`, and a tag-scoped one is `ctx.tags.ephemeral(group).ref(key).broadcastRequest(...)`.

## Channels can declare their own requests

A channel can declare its own server-to-client requests under `outgoing.requests`. Those need `requests()` listed too — a channel declaring `outgoing.requests` without it is a build error:

```typescript [channel.ts]
const lobby = base.channel('lobby', {
  outgoing: {
    emits: {},
    requests: {
      volunteer: { out: t<{ turn: number }>(), in: v.object({ ready: v.boolean() }) },
    },
  },
})
```

The channel's declarations stay scoped to that channel, so two channels can declare a `volunteer` request without clashing. See [Channels](/server/channels/overview) for the full channel surface.
