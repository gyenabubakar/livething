`outgoing` is the outbound mirror of [`intercept`](/server/lifecycle-and-intercept/intercept). It runs for **every server-to-client frame** — `ctx.send`, `ctx.broadcast`, `ctx.channel.send`, stream chunks, server requests — right before the frame is serialized. Use it for cross-cutting outbound work: stamping a field onto every message, redacting before send, or dropping a frame on a condition.

It is a plain method on `base`. Unlike `intercept`, it needs **no** capability.

```typescript [enable.ts]
base.outgoing((ctx, frame) => {
  ctx.log.info('outgoing', { event: frame.event })
})
```

One `outgoing` hook per server.

## The frame

The handler receives `(ctx, frame)`. An `OutgoingFrame` is the outbound counterpart of an `InterceptFrame`, with a smaller shape — an outgoing frame is already routed, so there is no `kind` or `routing`:

::field-group
  ::field{name="event" type="string"}
  The event name as it will be sent to the client. Locked — you cannot change it.
  ::
  ::field{name="payload" type="unknown"}
  The payload value. Gate on `frame.event`, then read it with a cast (see [Reading the payload](#reading-the-payload)).
  ::
  ::field{name="owner" type="FrameOwner"}
  Whether the event is app-owned (`{ kind: 'app' }`) or plugin-owned (`{ kind: 'plugin', id }`).
  ::
::

The `ctx` is the **dispatching** connection — the one whose inbound message is being handled right now — not the recipient of the frame. For a plain `ctx.send(...)` inside a handler the two are the same socket, so `ctx` is the receiver. But on a `ctx.broadcast(...)`, `ctx` stays the sender for every fan-out copy, and on a frame sent outside any connection dispatch — a `schedule(...)` task, a `shutdown` broadcast — there is no active connection at all and **`ctx` is `undefined`**.

::caution
Because `ctx` can be `undefined`, guard it before you read a connection field. The type does not force the guard — `ctx` is typed as the connection context — so a hook that reads `ctx.env` or `ctx.log` will throw on a frame sent with no connection in scope. Read the `frame` (always present) for per-message logic, and null-check `ctx` before touching it.

```typescript [guard-ctx.ts]
base.outgoing((ctx, frame) => {
  // frame is always there; ctx may be undefined on a broadcast or task send
  if (ctx && frame.event === 'debug-trace' && !isDevEnv(ctx.env)) {
    throw Block
  }
})
```
::

## Inspect, rewrite, or block

Same contract as `intercept`:

- **Return nothing** — the frame goes out unchanged.
- **Return a value** — it **replaces** `frame.payload`. The event stays locked.
- **Throw `Block`** — the frame is dropped; nothing is sent.

```typescript [stamp.ts]
base.outgoing((ctx, frame) => {
  // Stamp a server timestamp onto every outbound payload
  const p = frame.payload as Record<string, unknown>
  return { ...p, sentAt: Date.now() }
})
```

```typescript [redact.ts]
import { Block } from '@wskit/server/errors'

base.outgoing((ctx, frame) => {
  if (frame.event === 'user-profile') {
    const p = frame.payload as { email?: string }
    const { email, ...safe } = p
    return safe // never let email leave the server
  }

  // `ctx` can be undefined on a broadcast/task send — guard before reading env
  if (frame.event === 'debug-trace' && ctx && !isDevEnv(ctx.env)) {
    throw Block // drop debug frames in production
  }
})
```

After the hook returns, the payload still has to be a plain object and the event must be a declared one — a rewrite that returns a non-object, or a frame for an event your server never declared with `emits(...)`, is rejected. So a rewrite changes the payload's contents, not its basic shape.

## Reading the payload

`frame.payload` is typed `unknown`. Gate on `frame.event`, then read it with a cast — the same boundary pattern as the inbound `intercept`:

```typescript [read-out.ts]
base.outgoing((ctx, frame) => {
  if (frame.event === 'message') {
    const p = frame.payload as { text: string }
    return { ...p, text: p.text.trimEnd() }
  }
})
```

The `ctx.matches` / `ctx.unsafeCast` helpers are **inbound-only** — they take an `InterceptFrame`, not an `OutgoingFrame`, so they do not apply here. On the outbound path you gate on `frame.event` and cast.

## Plugin ownership

Like an intercept, `frame.owner` says whether the frame is your app's or a plugin's, and an app `outgoing` hook sees every outbound frame. With plugins listed, `frame.owner.id` is typed to the union of installed plugin IDs. Authoring plugins and the host-observation grant are in [Plugins](/server/plugins/overview).

```typescript [owner.ts]
base.outgoing((ctx, frame) => {
  if (frame.owner.kind === 'plugin') {
    ctx.log.info('plugin send', { id: frame.owner.id, event: frame.event })
  }
})
```

## `base.outgoing` is not `outgoing()`

Two different things share the word **outgoing** — keep them apart:

| Name | What it is |
|---|---|
| `base.outgoing((ctx, frame) => ...)` | The hook on this page — runs on every outbound frame. |
| `outgoing(name, schema?)` from `@wskit/server` | A **contract declaration** — names one server→client event with its payload type so the type flows into the generated client. It is the standalone sibling of `emits({...})`, not a hook. |

If you are declaring what events the server can emit, you want `emits(...)` (see [emits](/server/capabilities/emits)) — not this hook. This hook is for processing those frames as they leave.

::note
`outgoing` is the outbound twin of `intercept`. If you understand one, you understand the other: same locked-event rule, same return-to-rewrite, same `Block` to drop, same `frame.owner`. The inbound side, with the extra `kind` and `routing`, is in [Intercept](/server/lifecycle-and-intercept/intercept). The full place of both in the message pipeline is in [Pipeline Order](/server/pipeline-order).
::
