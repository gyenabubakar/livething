A plugin's whole surface — events, channels, requests, scheduled tasks, storage keys, tags — is kept separate from the host's. You write **short names** inside the plugin, and WSKit adds the plugin's id around them so two plugins (or a plugin and the host) never collide.

## The wire name: `__<id>::<name>`

A plugin-owned event travels with the plugin's id baked into the event name. For a plugin with id `acme:presence`, the event `heartbeat` goes out as:

```text
__acme:presence::heartbeat
```

The shape is `__` + the plugin id + `::` + the short name. The `::` is **framework-reserved** — it can never appear in a name you declare (it is also what marks a channel in addressing), so the split back into `{ id, name }` is always unambiguous.

You never type that long form. Inside the plugin you write the short name, and the framework rewrites it on the way out and resolves it on the way in:

```typescript [presence.ts]
const h = define({
  scoped: true,
  capabilities: [emits({ 'user-online': t<{ id: string }>() })],
})

const heartbeat = h.on('heartbeat', {
  input: v.object({}),
  run(ctx) {
    // you write 'user-online'; the client receives __acme:presence::user-online,
    // matching this plugin's own emits(...) declaration
    ctx.send('user-online', { id: ctx.id })
  },
})

export const Presence = plugin('acme:presence', { handler: h.assemble(heartbeat) })
```

So `Presence`'s `user-online` never clashes with the host's own `user-online`, or with another plugin's.

## What gets namespaced

Every name a plugin declares or addresses by string is namespaced under its id. You always use the short form; the long form is what's on the wire or in storage.

| Surface | You write | On the wire / in storage |
|---|---|---|
| Events (`ctx.send`, `emits`, `outgoing`) | `'user-online'` | `__acme:presence::user-online` |
| Requests (`ctx.request`) | `'confirm'` | `__acme:presence::confirm` |
| Channels (`h.channel`, `ctx.channels.get`) | `'room'` | `__acme:presence::room` |
| Scheduled tasks (`ctx.schedule`) | `'cleanup'` | `__acme:presence::cleanup` |
| KV keys / prefixes (`ctx.kv.get/set/list`) | `'last-seen'` | namespaced key |
| Tag groups (`ctx.tags.<kind>`) | `'role'` | namespaced group |

The point is the same everywhere: a plugin reads and writes as if it were the only thing running, and the id keeps its slice private.

```typescript [storage.ts]
run(ctx) {
  // this key never collides with the host's 'last-seen' or another plugin's
  ctx.kv.set('last-seen', Date.now())
}
```

## Reading the owner back

Because the id is part of the event name, any frame can be traced back to its owner. A hook reads this off `frame.owner` — `{ kind: 'plugin', id }` for a `__<id>::<name>` event, `{ kind: 'app' }` for everything else. That is how a host-observing plugin tells its own frames from the app's. See [Observing host traffic](/server/plugins/observe-host).

For building the scoped slice these names belong to, see [Authoring](/server/plugins/authoring).
