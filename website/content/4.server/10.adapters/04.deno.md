::warning
The Deno adapter (`@wskit/server-deno`) is **planned** and does not exist yet. [Cloudflare Durable Objects](/server/adapters/cloudflare) is the adapter available today. This page is a placeholder so you know what to expect.
::

## What stays the same

A WSKit server is a platform-agnostic **definition** plus a platform-specific **adapter**. The definition — `define`, capabilities, handlers, `assemble` — does not change between platforms. So this much will be identical on Deno and on Cloudflare:

```ts [handler.ts]
import { define, emits, t } from '@wskit/server'
import * as v from 'valibot'

const base = define({
  env: t<Env>(),
  capabilities: [emits({ pong: t<{ text: string }>() })],
})

const handlePing = base.on('ping', {
  input: v.object({ text: v.string() }),
  run(ctx, input) {
    ctx.send('pong', { text: input.text })
  },
})

export const chat = base.assemble(handlePing)
```

## What will change

Only the adapter entry. On Cloudflare you call `server(chat)` and export a Durable Object class. The Deno adapter will expose its own `server(...)` entry that runs the same `chat` definition, likely through `Deno.serve`. The exact API is not settled, so this page will not show a placeholder one.

::note
Deno exposes live outbound buffer pressure, so `ctx.stream.drain()` will pace a stream generator against the real socket buffer once the adapter lands. On Cloudflare, which does not expose buffer fullness, `drain()` is a no-op. The definition stays the same; the adapter decides the runtime behavior.
::

Until the Deno adapter ships, build on [Cloudflare](/server/adapters/cloudflare) — your handler code carries over unchanged when the Deno entry arrives. See [Installation](/start/installation) for the current package list.
