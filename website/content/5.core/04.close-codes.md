When a connection closes, the close **code** says why. `CloseCodes` is the named set WSKit uses, so you don't pass raw numbers around. The server sends a code when it closes a connection; the client's `onClose` receives it, and the reconnection logic reads it to decide whether to retry.

```typescript [server.ts]
import { CloseCodes } from '@wskit/core'

ctx.close(CloseCodes.BANNED, 'You have been banned')
```

## The codes

`1000`–`1015` are standard WebSocket codes; `4000`–`4999` are application-defined, and WSKit claims a handful of those for common situations:

| Code   | Name               | Meaning                                                                        |
| ------ | ------------------ | ------------------------------------------------------------------------------ |
| `1000` | `NORMAL`           | Normal closure — the connection finished its purpose                           |
| `1001` | `GOING_AWAY`       | Server going away — restart, deploy, shutdown. Clients should reconnect        |
| `1002` | `PROTOCOL_ERROR`   | The peer sent data that violates the WebSocket protocol                        |
| `1003` | `UNSUPPORTED_DATA` | The peer sent a frame type this server does not accept                         |
| `1011` | `INTERNAL_ERROR`   | The server could not complete an operation                                     |
| `4001` | `AUTH_EXPIRED`     | Auth token expired — refresh and reconnect                                     |
| `4002` | `AUTH_INVALID`     | Auth token invalid — don't reconnect with the same token                       |
| `4003` | `DUPLICATE`        | Another connection for the same user replaced this one                         |
| `4004` | `IDLE`             | Idle timeout — no activity for too long; keepalive's missed pongs trigger this |
| `4005` | `RATE_LIMITED`     | Sending too fast — back off before reconnecting                                |
| `4009` | `BANNED`           | User is permanently blocked — do not reconnect                                 |
| `4010` | `CAPACITY`         | Server at capacity — retry with backoff                                        |

## How reconnection uses them

The [`reconnection()`](/client/primitives/reconnection) primitive reads the close code to decide whether a drop is worth retrying. Codes that mean "this won't get better by retrying" — like `AUTH_INVALID` or `BANNED` — are treated as non-retryable, so the client stops instead of hammering a connection that will keep failing. A transient code like `GOING_AWAY` or `CAPACITY` reconnects with backoff.

```typescript [app.ts]
import { CloseCodes } from '@wskit/core'

socket.onClose(({ code, reason }) => {
  if (code === CloseCodes.BANNED) showBannedScreen(reason)
})
```

## Reading them on the client

`onClose` gives you `{ code, reason, wasClean }`, so you can branch on the named code rather than a magic number — the same `CloseCodes` import works on both sides:

```typescript [app.ts]
socket.onClose(({ code }) => {
  if (code === CloseCodes.AUTH_EXPIRED) refreshTokenAndReconnect()
})
```

On the server, you pass a code when you deliberately close a connection — `ctx.close(code, reason)` or by throwing the server's `Disconnect(code, reason)` control-flow error.
