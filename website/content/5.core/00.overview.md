`@wskit/core` is the small, runtime-agnostic package both halves of WSKit are built on. The [Client](/client/overview) and [Server](/server/overview) packages depend on it, and a few things live here precisely because **both sides need them to agree** — your error definitions, the built-in errors, the WebSocket close codes. This section is the reference for that shared surface.

## A shared peer dependency

`@wskit/core` is a **peer dependency** of both `@wskit/client` and `@wskit/server`, so you install it explicitly alongside them — the [installation](/start/installation) commands include it for you (`npm install @wskit/client @wskit/core`). Once it's in, you import the shared pieces from it:

```typescript [errors.ts]
import { CloseCodes, error } from '@wskit/core'
```

It carries no client or server code — no DOM, no sockets, no storage — which is why it's safe to import from anywhere, including code that runs on both sides.

## What lives here

| Area                | What it is                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------- |
| **Errors**          | `WSKitError`, the `error()` factory, and `.matches()` — the one error model shared end to end |
| **Built-in errors** | the errors WSKit ships (`RateLimited`, `StreamAborted`, …) plus the client-side ones          |
| **Close codes**     | `CloseCodes` — the named WebSocket close codes the connection speaks                          |

The reason these are shared rather than living in one package is the contract idea: an error you `throw` on the server is an error you `.matches()` on the client, so its definition has to be the same object on both sides. The same goes for a close code the server sends and the client's reconnection logic reads.
