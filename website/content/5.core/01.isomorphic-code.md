Some of your code naturally belongs to **both** sides — the error a server throws is the same error a client catches, the type a server declares is the type a client consumes. *Isomorphic* code is code written once and imported on both sides, and `@wskit/core` is what makes it safe to do.

## Why it's safe to share

`@wskit/core` is runtime-agnostic. It pulls in no browser globals, no WebSocket, no storage — just plain TypeScript and your schema library. So anything that imports only from `@wskit/core` (and your schemas) can be imported from client code, server code, or a file shared by both, with nothing platform-specific leaking in:

```typescript [errors.ts]
// Safe on the server, in the browser, and in a shared file — core is neutral.
import { error } from '@wskit/core'
import * as v from 'valibot'

export const Forbidden = error('forbidden', v.object({ reason: v.string() }))
```

## Shared error definitions

The clearest case is errors. You define an error **once**, in a file both sides import. The server throws it; the client narrows it with `.matches()` — and because it's the same definition object, the `code` and the `detail` type line up automatically:

```typescript [errors.ts]
import { error } from '@wskit/core'
import * as v from 'valibot'

export const NotFound = error('not-found', v.object({ id: v.string() }))
```

```typescript [server.ts]
import { NotFound } from './errors'

run(ctx, input) {
  const post = lookup(input.id)
  if (!post) throw NotFound({ id: input.id }) // thrown on the server
  return post
}
```

```typescript [app.ts]
import { NotFound } from './errors'

try {
  await socket.request('get-post', { id })
} catch (err) {
  if (NotFound.matches(err)) showMissing(err.detail.id) // matched on the client
}
```

One definition, two uses, no drift. The error model itself is in [Error Model](/core/error-model).

## Shared types

The other shared thing is the **contract** — the single typed description of your API. You don't hand-write it twice: the server defines it, and the client imports the inferred type. That flow is its own topic — see [The Contract](/learn/core-model/the-contract) in Learn — but the principle is the same as errors: declare once, consume on both sides, and the compiler keeps them honest.

## Where to put shared files

A common layout is a shared module (or a small package) holding your error definitions and any plain types both sides use, importing only from `@wskit/core` and your schema library:

```text
shared/
  errors.ts     // error() definitions — imported by client and server
server/
  chat.ts       // throws those errors; exports the contract type
client/
  app.ts        // matches those errors; imports the contract type
```

Keep platform-specific code (DOM, storage, sockets) out of the shared files, and they stay importable from either side.
