A **plugin** is a reusable client feature you package up with `plugin()` — analytics, a metrics counter, a custom protocol shim — and drop into any socket. It hooks into the same message pipeline and lifecycle a built-in primitive does, but reaches its API a little differently.

## A plugin vs a primitive

A built-in primitive (like `channels()`) adds methods straight onto the socket — `socket.channel(...)`. A plugin **can't** do that. Instead its API is reached through `Plugin.use(socket)`:

```typescript [app.ts]
const socket = client<MySocket>()(connect('wss://example.com/ws'), Metrics())

const metrics = Metrics.use(socket) // the plugin's API, not a socket method
metrics.count('message')
```

The reason is type inference: every method a primitive adds widens the socket's type, and a third-party plugin doing that on every project would slow the compiler down. Keeping the API behind `.use()` means a plugin costs nothing in the socket's type — you still get full typing on `metrics`, just reached through the accessor.

## Defining a plugin

You author one with `plugin()`. Give it an `id` (a name for logs), a `key` (a `Symbol` that uniquely identifies it), and a `setup` that wires hooks and returns the API:

```typescript [metrics.ts]
import { plugin } from '@wskit/client'

const KEY = Symbol('acme:metrics')

export const Metrics = plugin<{ sampleRate?: number }>({
  id: 'acme:metrics',
  key: KEY,
  setup(args, hooks) {
    const counts = new Map<string, number>()

    hooks.onIncoming((message) => {
      counts.set(message.event, (counts.get(message.event) ?? 0) + 1)
      return message // pass it on unchanged
    })

    // returns the per-socket API, built on first .use()
    return () => ({ count: (event: string) => counts.get(event) ?? 0 })
  },
})
```

`plugin<TArgs, TApi>()` is typed from the args your factory takes and the API your `setup` returns. `Metrics({ sampleRate: 0.5 })` registers it, and `Metrics.use(socket)` returns that `{ count }` API, fully typed.

## What goes in `plugin()`

| Field | Required | What it is |
|---|---|---|
| `id` | yes | A human-readable name for logs and errors. A namespaced form like `'acme:metrics'` is recommended. Two plugins sharing an `id` only warn — it isn't the unique identifier. |
| `key` | yes | A `Symbol` that uniquely identifies the plugin. The socket stores and looks up the plugin's API by it. |
| `setup` | yes | `(args, hooks) => (socket) => api`. Wires the hooks and returns a builder for the per-socket API. |
| `registrationId` | no | Makes the plugin repeatable — see [below](#repeatable-plugins). |
| `dependencies` | no | Primitives this plugin needs — see [below](#declaring-primitive-dependencies). |

## The hooks

The `hooks` object passed to `setup` lets the plugin tap the pipeline and lifecycle. Each is the client-side mirror of a primitive's lifecycle:

| Hook | Fires | Return |
|---|---|---|
| `onIncoming(fn)` | an incoming message arrives | the message (maybe changed) to pass on; throw `Block` to drop it |
| `onOutgoing(fn)` | a message is about to be sent | the message (maybe changed) to send; throw `Block` to cancel it |
| `onOpen(fn)` | every open (first connect and reconnects) | `WireMessage[]` to send right away, or nothing |
| `onReconnect(fn)` | reconnects only | same as `onOpen` |
| `onClose(fn)` | the socket closes | — (receives `code` and `reason`) |
| `generateId(prefix?)` | — | a unique id sharing the socket's counter |
| `getState()` | — | the current [connection state](/client/overview#connection-states) |

```typescript [metrics.ts]
import { Block } from '@wskit/client/errors'

setup(args, hooks) {
  hooks.onIncoming((message) => {
    if (isSpam(message)) throw Block // drop it — nothing downstream sees it
    return message
  })

  hooks.onOpen(() => [{ event: 'hello', payload: { v: 1 } }]) // sent on connect

  return () => ({ /* api */ })
}
```

Each hook can be registered **once** — calling `hooks.onIncoming(...)` twice in the same plugin throws, so you can't accidentally clobber your own handler. A throw inside a hook (other than `Block`) is reported and isolated; it won't tear the socket down.

## Registering and using it

Pass the configured plugin to `client()` alongside your primitives. Order doesn't matter — plugins sort with primitives by dependency:

```typescript [app.ts]
import { client, connect } from '@wskit/client'
import { Metrics } from './metrics'

const socket = client<MySocket>()(
  connect('wss://example.com/ws'),
  Metrics({ sampleRate: 0.5 }),
)

const metrics = Metrics.use(socket)
metrics.count('order-update')
```

The hooks start running as soon as the plugin is registered — you don't have to call `.use()` for a plugin that only taps the pipeline. `.use()` is only how you read the plugin's **API**, and it builds that API lazily the first time you call it (and returns the same instance after).

## Repeatable plugins

By default a plugin is one-per-socket — registering the same one twice throws. Add `registrationId` to make it repeatable: it turns the args into a stable string, and each distinct string is a separate instance. You then pick an instance by passing that id to `.use()`:

```typescript [analytics.ts]
import { plugin } from '@wskit/client'

const ANALYTICS = Symbol('acme:analytics')

export const Analytics = plugin<{ tracker: string }>({
  id: 'acme:analytics',
  key: ANALYTICS,
  registrationId: (args) => args.tracker, // one instance per tracker
  setup(args) {
    return () => ({ tracker: args.tracker })
  },
})
```

```typescript [app.ts]
const socket = client<MySocket>()(
  connect('wss://example.com/ws'),
  Analytics({ tracker: 'ga' }),
  Analytics({ tracker: 'mixpanel' }),
)

Analytics.use(socket, 'ga').tracker       // 'ga'
Analytics.use(socket, 'mixpanel').tracker // 'mixpanel'
```

Registering two instances with the *same* computed `registrationId` throws — each id must be unique.

## Declaring primitive dependencies

If your plugin relies on a primitive being present, list it in `dependencies`. WSKit asserts those primitives are registered and orders them before the plugin. You pass the primitive **factory** (not a call), because its presence is checked by a static `tag` without running it:

```typescript [presence-plugin.ts]
import { plugin } from '@wskit/client'
import { channels } from '@wskit/client'

export const RoomPresence = plugin({
  id: 'acme:room-presence',
  key: Symbol('acme:room-presence'),
  dependencies: [channels], // the channels() primitive must be installed
  setup(args, hooks) {
    return () => ({ /* api that assumes channels exists */ })
  },
})
```

Leave out a required primitive and `client()` throws at build with a message naming what to add.

## Errors you might hit

- **`Plugin.use(socket)` on a socket where it wasn't registered** throws — pass the plugin to `client()` first.
- **`.use(socket, id)` with an unknown `registrationId`** throws — the id must match one you registered.
- **A throw in `setup`'s API builder** surfaces from `.use()` the first time you call it (the failure is remembered, so it throws consistently).

::note
The client `plugin()` mirrors the server's, minus the server-only parts (scheduling, migrations). If you're authoring a feature for both halves, the shapes line up — see the server plugins documentation for that side.
::
