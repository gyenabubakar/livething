`stream()` adds the methods for consuming server streams — progressive, chunked data like LLM tokens or query rows. For the concept and the server half, see [Streaming](/learn/streaming/overview); for the full client surface, the [Streams chapter](/client/streams/overview).

```typescript [app.ts]
import { client, connect, stream } from '@wskit/client'
import type { AiSocket } from '../server/ai'

const socket = client<AiSocket>()(
  connect('wss://example.com/ws'),
  stream(),
)
```

It adds three methods, all typed from your contract's `streams`:

## `stream(event, payload, options?)` — trigger and iterate

Starts a stream and returns a promise for a handle you iterate with `for await`. The promise resolves once the server accepts the stream, and rejects if the server refuses it before any chunk:

```typescript [app.ts]
const tokens = await socket.stream('ask-ai', { prompt: 'Explain WebSockets' })

for await (const chunk of tokens) {
  appendToken(chunk.text) // chunk is typed from the stream's `chunk`
}
// loop exits normally → the stream finished
```

The loop **exits** when the stream completes, and **throws** on a terminal error or a per-chunk timeout — wrap it in `try/catch` to handle those. **Breaking** out of the loop (or `return`ing) cancels the stream for you.

The optional third argument pins the stream id (`{ streamId: 'conversation-42' }`) instead of letting one be generated — useful as a stable resume handle across reloads.

### The handle

```typescript [app.ts]
const tokens = await socket.stream('ask-ai', { prompt })

tokens.nudge('add-context', { context: 'be brief' }) // mid-stream message
tokens.cancel()        // ask the server to stop; the loop exits without throwing
tokens.streamId        // the id grouping this stream's chunks
tokens.active          // whether it's still running
```

`nudge(event, payload, options?)` sends a message *into* the running server generator — to pause it, steer it, and so on. It returns a promise that resolves when the server confirms the nudge and rejects if the server refuses it or `nudgeTimeout` passes; a rejected nudge does **not** end the stream. Only the stream's creator can nudge. After a stream has finished, `nudge()` and `cancel()` are harmless no-ops (`nudge()` resolves without sending).

::note
Chunks are queued in order until your `for await` body consumes them, and there's no client-side cap on that queue — if your consumer is much slower than the server's output, chunks accumulate in memory. For a fast producer and a slow UI, do the heavy work outside the loop (or sample) so you keep up.
::

## `onStream(event, handlers)` — listen-only (broadcasts)

When the server broadcasts a stream to everyone, you didn't trigger it, so you consume it with callbacks instead of an iterator:

```typescript [app.ts]
const unsubscribe = socket.onStream('live-feed', {
  onChunk(chunk, streamId) { append(chunk) },
  onEnd(streamId, finalSeq) { markComplete() },
  onError(err, streamId) { showError(err) },
  onTimeout(streamId) { showStalled() },
})
```

It fires for every stream matching the event name, so concurrent runs are told apart by `streamId`. On a broadcast, a terminal error reaches every subscriber, so `onError` fires for all of them.

## `resumeStream(event, streamId, options?)` — manual resume

Re-attach to a **durable** stream by id — after a page reload, or to join a broadcast you were handed an id for. It's type-gated to streams whose `kind` is `'persistent'`; passing a plain (ephemeral) stream is a compile error.

```typescript [app.ts]
const resumed = socket.resumeStream('ask-ai', savedStreamId, { lastKnownSeq: 12 })
for await (const chunk of resumed) render(chunk)
```

`lastKnownSeq` is the highest chunk sequence you already saw; the server sends only what's after it.

## Durable streams resume automatically

A `'persistent'` stream (a server `resumableStream`/`recordedStream`) re-attaches itself when the socket reconnects — the **same `for await` loop keeps producing chunks**, picking up where it left off. You don't write any reconnect handling, and you don't call `resumeStream()`:

```typescript [app.ts]
// `ask-ai` is a persistent stream. If the socket drops mid-generation and
// reconnects, the loop simply keeps receiving — the gap is invisible here.
const answer = await socket.stream('ask-ai', { prompt })
for await (const chunk of answer) {
  appendToken(chunk.text)
}
markComplete()
```

For this to work, install [`reconnection()`](/client/primitives/reconnection) (so a drop reconnects) and [`keepalive()`](/client/primitives/keepalive) (so a half-open socket is noticed rather than the loop waiting forever). `resumeStream()` is only for a *cold* resume — when the in-memory handle is gone after a reload or in a second tab.

## Options

```typescript [app.ts]
stream({
  timeout: 30_000,     // wait for the NEXT chunk; resets on every chunk, not a total limit (default: 30_000)
  nudgeTimeout: 10_000, // how long nudge() waits for confirmation (default: 10_000)
})
```

Set `timeout: 0` to turn the per-chunk timeout off. The per-chunk `timeout` is set here on the primitive; the nudge timeout can be overridden per call through `nudge(event, payload, { timeout })`.

## On a channel

With [`channels()`](/client/primitives/channels), channel handles gain `stream(...)`, `onStream(...)`, and `resumeStream(...)`, scoped to the channel and typed from its contract.
