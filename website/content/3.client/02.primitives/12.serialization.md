`serialization()` is the opt-in surface for handling **binary** messages — Protocol Buffers, MessagePack, and the like. You set the delivery format and a decoder, and they go together.

::warning
**Binary support isn't built yet.** Today the client handles text (JSON) frames only. An incoming binary frame is rejected before this decoder ever runs — the socket won't quietly mishandle bytes that carry no `__wskit` envelope. This primitive is kept as the shape binary will take when it lands, and that shape will likely change then. There is no `sendBinary()`.
::

```typescript [app.ts]
import { client, connect, serialization } from '@wskit/client'
import type { GameSocket } from './socket-types'

const socket = client<GameSocket>()(
  connect('wss://example.com/ws'),
  serialization({
    binaryType: 'arraybuffer',
    parseBinary(data) {
      const decoded = GameStateProto.decode(new Uint8Array(data))
      return { event: 'game-state', payload: decoded }
    },
  }),
)
```

## Options

`binaryType` and `parseBinary` are a **linked pair** — TypeScript won't let you set one without the other, and `binaryType` decides the type `parseBinary` receives:

- `binaryType: 'arraybuffer'` → `parseBinary(data: ArrayBuffer)`
- `binaryType: 'blob'` → `parseBinary(data: Blob)`

`parseBinary` returns a `{ event, payload }` to route the frame like any other message, or `null` to ignore that frame:

```typescript [app.ts]
parseBinary(data) {
  const view = new DataView(data)
  if (view.getUint8(0) !== MAGIC) return null // not ours — skip it
  return { event: 'game-state', payload: GameStateProto.decode(new Uint8Array(data)) }
}
```

Text frames always use the built-in `{ event, payload }` JSON format — `serialization()` only governs binary. Until binary support is finished, this primitive type-checks the pair but the decoder doesn't run: an incoming binary frame surfaces a real error on `socket.onError` ("binary frames are not supported yet") rather than being silently dropped.
