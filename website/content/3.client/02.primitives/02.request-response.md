`requestResponse()` adds `socket.request(...)` — send a message and get a promise back that resolves with the server's reply to that exact message. It's the ask-and-wait counterpart to fire-and-forget `send()`. For the concept and the server half, see [Requests](/learn/messaging/requests).

```typescript [app.ts]
import { client, connect, requestResponse } from '@wskit/client'
import type { ApiSocket } from '../server/api'

const socket = client<ApiSocket>()(
  connect('wss://example.com/ws'),
  requestResponse(),
)
socket.connect()

const balance = await socket.request('get-balance', { userId: '123' })
// balance: { balance: number; currency: string } — typed from the contract
console.log(`${balance.balance} ${balance.currency}`)
```

Under the hood each request carries a unique `__wskit.correlationId`; the server echoes it on the reply, and the primitive matches the reply back to the right promise. Both the payload you send and the response you get are typed from your contract's `requests`.

## The contract side

`request()` is typed from the `requests` map in your socket contract. Each entry pairs the `payload` you send with the `response` you get back:

```typescript [socket-types.ts]
interface ApiSocket {
  requests: {
    'get-balance': {
      payload: { userId: string }
      response: { balance: number; currency: string }
    }
    'create-post': {
      payload: { title: string; body: string }
      response: { id: string }
    }
  }
}
```

With `@wskit/server`, this map is produced by `InferClient` — you don't hand-write it. `socket.request('get-balance', …)` then autocompletes the event name, checks the payload, and types the resolved value.

## How the promise settles

```typescript [app.ts]
import { Timeout } from '@wskit/client/errors'
import { Forbidden, QuotaExceeded } from '../server/errors'

try {
  const post = await socket.request('create-post', { title: 'Hi', body: '…' })
  // resolved — `post` is { id: string }
  router.push(`/posts/${post.id}`)
} catch (err) {
  if (Forbidden.matches(err)) showToast(err.detail.reason)      // typed server error
  else if (QuotaExceeded.matches(err)) showUpgrade(err.detail)  // another typed error
  else if (Timeout.matches(err)) showToast('Server took too long')
  else throw err
}
```

The promise settles one of these ways:

- **Resolves** with the typed response when the server replies.
- **Rejects with a typed `WSKitError`** if the server answers with one of your declared errors — narrow it with `.matches()` and read `err.detail`.
- **Rejects with `Timeout`** if no reply arrives in the timeout window.
- **Rejects with `Disconnected`** if you `disconnect()` while the request is in flight.
- **Rejects with `Dropped`** if the request was buffered (see below) and then evicted because the buffer filled, or its TTL expired before it could be sent. Like `Timeout` and `Disconnected`, it's importable from `@wskit/client/errors`.

## Acknowledgement requests

Sometimes you don't need a value back — you just want to know the server **received and handled** your message. That's an *acknowledgement* request: on the server it's declared with no response body, and on the client `request()` resolves `undefined`. You `await` it purely for the receipt.

```typescript [socket-types.ts]
interface ApiSocket {
  requests: {
    // No `response` field → an acknowledgement. There's nothing to read back.
    'mark-seen': { payload: { messageId: string }; response: void }
  }
}
```

```typescript [app.ts]
// Resolves once the server has processed it — your "delivered and handled" receipt.
await socket.request('mark-seen', { messageId: 'm-42' })
console.log('the server confirmed it marked the message seen')
```

This is the difference from `send()`. A `send()` returns `true` for "accepted" — handed to the socket or buffered — and never tells you the server got it. An acknowledgement request resolves only **after** the server's handler ran, so awaiting it is how you confirm delivery and processing without needing any data in return.

```typescript [app.ts]
socket.send('mark-seen', { messageId: 'm-42' })       // fire-and-forget: true = accepted, not delivered
await socket.request('mark-seen', { messageId: 'm-42' }) // await resolves = the server handled it
```

## Concurrent requests

Each request is matched by its own correlation id, so you can have many in flight at once and they resolve independently:

```typescript [app.ts]
const [profile, balance] = await Promise.all([
  socket.request('get-profile', { userId: '123' }),
  socket.request('get-balance', { userId: '123' }),
])
```

## Timeout

The default wait is 10 seconds. Change the default for all requests with the primitive option, or override it per call with the third argument:

```typescript [app.ts]
const socket = client<ApiSocket>()(
  connect('wss://example.com/ws'),
  requestResponse({ timeout: 5_000 }), // default for every request
)

// override for one slow call
const report = await socket.request('build-report', { range: '1y' }, { timeout: 30_000 })
```

## When the socket isn't open

`request()` needs a socket that's open or connecting:

- On a **lazy** socket, calling `request()` opens the connection and sends once it's up.
- While **connecting** or **reconnecting**, the frame is held and sent in order when the socket opens. With [`buffering()`](/client/primitives/buffering), it queues like any other send.
- On a **non-lazy** socket you haven't `connect()`ed yet (state `closed`), it rejects immediately with `Disconnected` rather than hanging until the timeout. Call `connect()` first, or use a lazy socket.

## On a channel

With [`channels()`](/client/primitives/channels) installed, channel handles gain their own `request()`, typed from that channel's contract and tagged to its scope:

```typescript [app.ts]
const room = socket.channel('rooms', 'room-1')
await room.subscribe()
const history = await room.request('get-history', { before: 'msg-100' })
```

The mirror direction — the server asking *you* — is [`serverRequest()`](/client/primitives/server-request).
