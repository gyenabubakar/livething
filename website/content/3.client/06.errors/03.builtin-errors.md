WSKit ships a set of errors you don't define yourself. They come in two groups by where they're minted — the **client** raises some locally, the **framework** sends others from the server — and that's also where you import each from. All are `WSKitError`s; match them with `.matches()` like any error.

## Client-side errors

Raised by the client itself, never sent over the wire. Import from `@wskit/client/errors`:

| Error | Code | When it fires | `detail` |
|---|---|---|---|
| `Timeout` | `timeout` | A `request()` (or stream `nudge()`) got no reply in time, or a stream's per-chunk timeout elapsed | — |
| `Disconnected` | `disconnected` | The socket dropped while a `request()` was waiting, `disconnect()` was called mid-request, or a stream can't resume because reconnection was abandoned | — |
| `Dropped` | `dropped` | A buffered `request()` was evicted before it could be sent — the buffer overflowed, or its TTL elapsed while offline | — |

```typescript [app.ts]
import { Timeout, Disconnected } from '@wskit/client/errors'

try {
  await socket.request('slow-thing', {})
} catch (err) {
  if (Timeout.matches(err)) retry()
  else if (Disconnected.matches(err)) waitForReconnect()
}
```

## Framework errors

Sent by the server or the engine. Import from `@wskit/core`:

| Error | Code | When it fires | `detail` |
|---|---|---|---|
| `ValidationFailed` | `validation-failed` | An incoming payload failed its schema | `{ event: string, issues: Issue[] }` |
| `RateLimited` | `rate-limited` | A frame was rejected for exceeding the rate cap; the handler never ran | `{ retryAfter: number }` (seconds) |
| `ChannelNotFound` | `channel-not-found` | You subscribed to a name that's no declared channel or family | — |
| `ChannelNotSubscribed` | `channel-not-subscribed` | You sent to, or unsubscribed from, a channel you aren't in | — |
| `RejoinRejected` | `rejoin-rejected` | A persistent channel's auto-rejoin was refused on reconnect | `{ message: string }` |
| `UnsupportedProtocol` | `unsupported-protocol` | The client used a protocol feature the server didn't enable | `{ event: '__replay__' \| '__resumeStream__' }` |
| `InternalError` | `internal-error` | An unclassified server error — real details are never leaked to the client | — |
| `RequestNoResponse` | `request-no-response` | A request handler returned without sending a response | — |
| `RequestNoCorrelation` | `request-no-correlation` | A request frame arrived with no correlation id (a hand-crafted or non-SDK client) | — |
| `RequestInvalidResponse` | `request-invalid-response` | A request handler's reply failed its declared response schema | `{ event: string, issues: Issue[] }` |
| `StreamAborted` | `stream-aborted` | An in-flight stream was terminated server-side | `{ reason: StreamAbortedReason }` |
| `NudgeOverflow` | `nudge-overflow` | A `nudge()` couldn't be buffered — non-terminal, only that nudge rejects | `{ cap: number }` |
| `StreamIdCollision` | `stream-id-collision` | A `streamId` you pinned is already in use on the connection | — |
| `StreamAlreadyActive` | `stream-already-active` | A second stream of the same event started while one is running | `{ event: string, streamId: string }` |

`Issue[]` is the Standard Schema issue array — each `{ message: string, path?: (string \| number)[] }`.

These codes are **reserved**: you can't define your own `error()` with any of them.

### A few in use

`RateLimited` carries how long to wait before retrying:

```typescript [app.ts]
import { RateLimited } from '@wskit/core'

socket.onError((err) => {
  if (RateLimited.matches(err)) {
    setTimeout(retry, err.detail.retryAfter * 1000)
  }
})
```

`ValidationFailed` tells you which event and what was wrong:

```typescript [app.ts]
import { ValidationFailed } from '@wskit/core'

if (ValidationFailed.matches(err)) {
  console.error('bad payload for', err.detail.event, err.detail.issues)
}
```

`StreamAborted` names *why* the stream ended, so you can react per reason:

```typescript [app.ts]
import { StreamAborted } from '@wskit/core'

try {
  for await (const chunk of tokens) render(chunk)
} catch (err) {
  if (StreamAborted.matches(err)) {
    if (err.detail.reason === 'hibernation-wake') restartStream()
    else if (err.detail.reason === 'buffer-full') showSlowDownToast()
  }
}
```

Its `reason` is one of: `cancelled`, `buffer-full`, `expired`, `not-found`, `hibernation-wake`, `unsubscribed`, `cursor-invalid`, `aborted`.

::note
Where each of these lands — rejecting a specific call versus surfacing on `onError` — follows the rules in [onError Routing](/client/errors/onerror-routing). For example, `RequestInvalidResponse` rejects the `request()` that caused it, while an `InternalError` thrown outside any request surfaces on `onError`.
::
