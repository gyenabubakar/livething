A channel handle tracks who's in the room. There's a live roster you can read at any time, and four listeners that fire as people come and go. The listeners split into **two pairs** that answer two different questions — getting that split right is what this page is about.

## The roster

`channel.members` is a `ReadonlyMap` keyed by connection id. Each value carries that connection's `meta` — the metadata the server set during `upgrade`:

```typescript [app.ts]
const room = socket.channel('rooms', 'room-42')
await room.subscribe()

for (const [connectionId, member] of room.members) {
  console.log(connectionId, member.meta) // meta is what the server attached at upgrade
}
```

The roster fills in from a single sync frame the server sends right after you subscribe — so `members` is populated by the time `subscribe()` resolves. If a member's connection had no metadata, its `meta` is an empty object, never missing.

### Resyncing

If you suspect the roster has drifted — say a leave that didn't land cleanly — `channel.resyncMembers()` asks the server to resend the full snapshot. It's fire-and-forget: it sends the request and returns immediately, with nothing to await. It's a no-op if the channel isn't active.

```typescript [app.ts]
room.resyncMembers() // request a fresh roster; the listeners below fire with any deltas
```

## Two pairs of listeners

```typescript [app.ts]
room.onMemberJoin((connectionId, member) => addAvatar(member.meta))
room.onMemberLeave((connectionId) => removeAvatar(connectionId))

room.onMemberOnline((connectionId, member) => showDot(connectionId))
room.onMemberOffline((connectionId) => hideDot(connectionId))
```

Each returns an unsubscribe function. The two pairs are **not** interchangeable:

### Join / leave — group membership

`onMemberJoin` and `onMemberLeave` track who *belongs to the room*. They fire only when membership genuinely changes: a first subscribe, a kick, a server-side removal. On a persistent channel, a member who drops and reconnects on a new socket does **not** fire these — they never left the group, so there's nothing to re-join. Use this pair to maintain the list of who's in the room (an avatar strip, a participant count).

### Online / offline — reachability right now

`onMemberOnline` and `onMemberOffline` track whether a specific connection is *reachable this instant*. They fire on every fresh subscribe — including a reconnect's automatic rejoin — and on every disconnect. Use this pair for "online dot" UIs: a member can be in the room (joined) but momentarily offline (reconnecting).

A short way to hold both ideas: **join/leave is about the guest list; online/offline is about who's currently in the building.**

## Across a reconnect

When the socket drops, the client clears the roster but remembers who was there. After it reconnects and the server resends the snapshot, the listeners fire only the real differences:

- a peer who's still there → `onMemberOnline` (reachable again), but **not** `onMemberJoin` (they never left the group)
- a peer who's genuinely new → `onMemberJoin` **and** `onMemberOnline`
- a peer who's gone → `onMemberLeave`

```typescript [app.ts]
// This stays correct across reconnects with no extra work:
room.onMemberJoin((id, m) => addAvatar(id, m.meta))   // only truly new members
room.onMemberLeave((id) => removeAvatar(id))           // only departed members
room.onMemberOnline((id) => showDot(id))               // everyone present, after every rejoin
room.onMemberOffline((id) => hideDot(id))              // on the drop
```

So an avatar list built on join/leave won't flicker every time the network blips, while the online dots correctly flip off on the drop and back on after the rejoin.

::note
A listener that throws is reported and swallowed — the other listeners for the same event still run, so one bad callback can't stop the rest of your presence UI from updating.
::
