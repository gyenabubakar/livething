WSKit's client is built so your bundler only ships the parts you import. Every primitive is a separate module, the packages are marked `sideEffects: false`, and the public API is plain ESM — so anything you don't pass to `client()` is tree-shaken away. The result: you pay for what you use, and nothing else.

## The two ends of the range

A **minimal client** — just `client` and `connect`, enough for a typed incoming/outgoing handler — is about **4.5 KB gzipped**. Pull in **every primitive** and it comes to about **16 KB gzipped**. The gap between them is exactly the primitives you chose to leave out.

| Build | Gzipped | Raw (minified) |
|---|---|---|
| Minimal (`client` + `connect`) | **4.5 KB** (4,617 B) | 14.7 KB |
| Every primitive | **16.0 KB** (16,382 B) | 53.4 KB |
| Every primitive + `plugin()` | **16.6 KB** (17,023 B) | 55.4 KB |

```ts [minimal.ts]
// ~4.5 KB gzip — a bare incoming/outgoing client
import { client, connect } from '@wskit/client'

interface ChatSocket {
  incoming: { message: { text: string } }
  outgoing: { say: { text: string } }
}

const socket = client<ChatSocket>()(connect('wss://example.com/ws'))
socket.on('message', (m) => console.log(m.text))
socket.send('say', { text: 'hi' })
```

That 4.5 KB already includes the connection state machine, the message pipeline, and `.on()`/`.send()`. Reconnection, keepalive, channels, streams, and the rest are not in it — because this client never imported them.

## What each primitive adds

Each row below is measured by adding that one primitive to the minimal client and taking the gzipped difference. It's the cost of reaching for that feature, on top of the 4.5 KB base:

| Primitive | Added (gzip) |
|---|---|
| `debug` | 14 B |
| `intercept` | 24 B |
| `quality` | 32 B |
| `serialization` | 56 B |
| `query` | 119 B |
| `dedup` | 150 B |
| `replay` | 351 B |
| `platform` | 387 B |
| `serverRequest` | 457 B |
| `reconnection` | 478 B |
| `keepalive` | 721 B |
| `buffering` | 1.5 KB |
| `requestResponse` | 2.6 KB |
| `stream` | 4.6 KB |
| `channels` | 5.2 KB |

The small ones are nearly free — `debug`, `intercept`, and `quality` each add well under 100 bytes. The heavy ones — `channels` and `stream` — are the features that carry the most logic (subscription routing, presence, durable resume, backpressure), so they cost the most. You only meet that cost if you import them.

::note
These deltas **don't simply add up** to the 16 KB full build. The per-primitive numbers sum to about 17 KB, but every primitive enabled at once is only ~11.5 KB on top of the base — because primitives share internal helpers (channels and streams reuse the same framing code, for example). Adding the second feature that pulls a shared module is cheaper than the first. Treat each row as "what this feature costs if it's the only one you add," not a line item to total.
::

## Measuring it yourself

The numbers above come from bundling a real consumer entry with esbuild and gzipping the output — the same thing a production build does. You can reproduce any of them:

```bash [measure.sh]
# bundle an entry that imports only what you use, then gzip it
esbuild app.ts --bundle --minify --format=esm --platform=browser \
  | gzip -9 | wc -c
```

What moves the number is what you `import` and pass to `client()` — not what the package contains. If your app only uses `reconnection` and `keepalive`, your client is about 4.5 KB + those two, not 16 KB. Import a primitive but never apply it and a good bundler still drops it, because the modules are side-effect free.

::callout{icon="i-ph-lightbulb-duotone"}
Want the smallest possible client? Start from `client` + `connect` and add primitives one at a time as you actually need them. The table above tells you the cost of each before you commit to it.
::
