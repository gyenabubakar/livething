WSKit doesn't ship a `@wskit/react` or `@wskit/vue` package. It doesn't need to — the socket already exposes a standard **external store** interface, so wiring it into any framework's reactivity is a few lines you write once. This chapter gives you those few lines for the popular ones.

## The socket is an external store

Two methods make the socket a reactive source:

- **`subscribe(callback)`** — runs `callback` on every connection-state change, and returns an unsubscribe function.
- **`getState()`** — reads the current state (`'closed'`, `'connecting'`, `'open'`, `'reconnecting'`).

That's exactly the shape React's `useSyncExternalStore` wants, and every other framework has an equivalent (a Vue `ref`, a Svelte store, a Solid signal). So "connection state in the UI" is the same idea everywhere: subscribe to changes, read the value.

| You want | Use |
|---|---|
| Connection state in the UI | `subscribe()` + `getState()` |
| React to an incoming event | `socket.on(event, handler)` (returns an unsubscribe) |
| Send / ask / stream | `socket.send(...)`, `await socket.request(...)`, `socket.stream(...)` |
| Connection quality | `keepalive()`'s `onQualityChange(...)` + `getQuality()` |

## Two rules that apply everywhere

**Create the socket once.** Build it at module scope (or in a context/provider), not inside a component that re-renders. Every component then subscribes to the same socket:

```typescript [socket.ts]
import { client, connect, reconnection } from '@wskit/client'
import type { ChatSocket } from '../server/chat'

export const socket = client<ChatSocket>()(
  connect('wss://example.com/ws'),
  reconnection(),
)
```

**Wrap the methods, don't pass them bare.** `subscribe` and `getState` are methods that use `this`, so pass `(cb) => socket.subscribe(cb)` and `() => socket.getState()` — a bare `socket.subscribe` loses its binding.

```typescript [example.ts]
// ✅ keeps `this`
useSyncExternalStore((cb) => socket.subscribe(cb), () => socket.getState())
// ❌ `this` is undefined inside subscribe/getState
useSyncExternalStore(socket.subscribe, socket.getState)
```

## A note on SSR

If your app server-renders (Next, Nuxt, SvelteKit, SolidStart), don't open the socket during SSR — there's no WebSocket on the server. Create it client-side (or lazily) and render a `'closed'` state on the server. The full pattern is in [SSR Safety](/client/connecting/ssr-safety); each page below points out where it matters.
