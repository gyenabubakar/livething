Svelte gives you two clean ways to bind the socket: **runes** (Svelte 5) for state local to a component, and a **readable store** that any component can import. The store maps almost one-to-one onto the socket's `subscribe()` + `getState()`.

## With runes (Svelte 5)

A `$state` variable plus a `$effect` that subscribes. Returning the socket's unsubscribe from the effect makes it the cleanup:

```svelte [StatusDot.svelte]
<script lang="ts">
  import { socket } from './socket'

  let state = $state(socket.getState())
  $effect(() => socket.subscribe(() => { state = socket.getState() }))
</script>

<span class={state === 'open' ? 'green' : 'grey'}>{state}</span>
```

Incoming events work the same way — `socket.on(...)` returns the unsubscribe the effect cleans up with:

```svelte [Notifications.svelte]
<script lang="ts">
  import { socket } from './socket'

  let note = $state<{ title: string }>()
  $effect(() => socket.on('notification', (d) => { note = d as { title: string } }))
</script>

{#if note}<Toast>{note.title}</Toast>{/if}
```

## With a readable store

For state shared across components, a `readable` store is the idiomatic fit and works on every Svelte version. Its start function receives `set` and returns a stop function — exactly the shape `socket.subscribe` already has:

```ts [stores.ts]
import { readable } from 'svelte/store'
import { socket } from './socket'

export const connectionState = readable(socket.getState(), (set) => {
  return socket.subscribe(() => set(socket.getState()))
})

export function incoming<T>(event: string) {
  return readable<T | undefined>(undefined, (set) => socket.on(event, (d) => set(d as T)))
}
```

```svelte [StatusDot.svelte]
<script lang="ts">
  import { connectionState } from './stores'
</script>

<span class={$connectionState === 'open' ? 'green' : 'grey'}>{$connectionState}</span>
```

Svelte starts the store's subscription when the first component uses `$connectionState` and stops it when the last one drops — so the socket subscription is tied to actual use.

## Requests

A request is an `await`, so an `{#await}` block or a small async handler covers it:

```svelte [Profile.svelte]
<script lang="ts">
  import { socket } from './socket'
  export let id: string
  const profile = socket.request('get-profile', { id })
</script>

{#await profile}
  <Spinner />
{:then p}
  <ProfileCard {...p} />
{:catch err}
  <Error {err} />
{/await}
```

## Connecting and SSR

Open the socket on mount so it stays client-side — under SvelteKit, `onMount` only runs in the browser:

```svelte [+layout.svelte]
<script lang="ts">
  import { onMount } from 'svelte'
  import { socket } from './socket'

  onMount(() => {
    socket.connect()
    return () => socket.disconnect()
  })
</script>
```

The stores start from `socket.getState()` (`'closed'` before connect), so server-rendered markup and the first client render agree. See [SSR Safety](/client/connecting/ssr-safety) for the details.
