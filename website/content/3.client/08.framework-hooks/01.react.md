React's `useSyncExternalStore` is built for exactly this — a value that lives outside React and changes over time. The socket's `subscribe()` + `getState()` plug straight in.

## Connection state

```tsx [use-connection-state.ts]
import { useSyncExternalStore } from 'react'
import { socket } from './socket'

export function useConnectionState() {
  return useSyncExternalStore(
    (cb) => socket.subscribe(cb),   // subscribe to changes
    () => socket.getState(),        // read the current value
    () => 'closed',                 // server snapshot (SSR)
  )
}
```

```tsx [StatusDot.tsx]
function StatusDot() {
  const state = useConnectionState()
  return <span className={state === 'open' ? 'green' : 'grey'}>{state}</span>
}
```

The third argument is the **server snapshot**: during SSR there's no connection, so it returns `'closed'`. Without it, `useSyncExternalStore` throws on the server.

## Incoming events

`socket.on(event, handler)` returns an unsubscribe function, which is exactly what a `useEffect` cleanup wants:

```tsx [use-latest.ts]
import { useEffect, useState } from 'react'
import { socket } from './socket'

export function useLatest<T>(event: string) {
  const [data, setData] = useState<T>()
  useEffect(() => socket.on(event, (d) => setData(d as T)), [event])
  return data
}
```

```tsx [Notifications.tsx]
function Notifications() {
  const note = useLatest<{ title: string }>('notification')
  return note ? <Toast>{note.title}</Toast> : null
}
```

Returning `socket.on(...)` directly from the effect means React removes the listener on unmount — no leak.

## Requests

A request is just an `await`, so handle it like any async call with local state:

```tsx [useProfile.ts]
import { useEffect, useState } from 'react'
import { socket } from './socket'

function useProfile(id: string) {
  const [profile, setProfile] = useState<Profile>()
  const [error, setError] = useState<unknown>()

  useEffect(() => {
    let active = true
    socket
      .request('get-profile', { id })
      .then((p) => active && setProfile(p))
      .catch((e) => active && setError(e))
    return () => { active = false }
  }, [id])

  return { profile, error }
}
```

The `active` flag drops a late response after the component unmounted or the `id` changed — the usual React async guard.

## Connection quality

With [`keepalive()`](/client/primitives/keepalive) installed, quality is another external store — subscribe with `onQualityChange`, read with `getQuality`:

```tsx [use-quality.ts]
import { useSyncExternalStore } from 'react'
import { socket } from './socket'

export function useQuality() {
  return useSyncExternalStore(
    (cb) => socket.onQualityChange(cb),
    () => socket.getQuality(),
    () => 'disconnected',
  )
}
```

## Connecting and SSR

Build the socket once at module scope (see [the overview](/client/framework-hooks/overview#two-rules-that-apply-everywhere)), and open it from an effect at the top of your tree:

```tsx [App.tsx]
import { useEffect } from 'react'
import { socket } from './socket'

function App() {
  useEffect(() => {
    socket.connect()         // safe to call repeatedly; idempotent while open
    return () => socket.disconnect()
  }, [])
  // ...
}
```

`connect()` is a no-op while already open or connecting, so React 18 StrictMode's double-invoke in development is harmless. In a server-rendered app (Next), keep the socket module client-only and rely on the `'closed'` server snapshots above — details in [SSR Safety](/client/connecting/ssr-safety).
