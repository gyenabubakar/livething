`@wskit/client` is the typed WebSocket client. You give it a contract type and a URL, and you get back a **socket** — an object with typed `on()` and `send()`, connection control, lifecycle callbacks, and whatever extra methods the primitives you added bring along.

The [Learn](/learn/core-model/the-contract) section teaches each feature from both sides at once. This **Client** section is the per-package reference: it goes deep on the client half — every connection option, every primitive, every method — for when you need the details.

## Creating a socket

You build a socket in two calls. The first names the contract; the second takes `connect(...)` and the primitives you want:

```typescript [app.ts]
import { client, connect, channels, reconnection } from '@wskit/client'
import type { ChatSocket } from '../server/chat'

const socket = client<ChatSocket>()(
  connect('wss://example.com/ws'),
  channels(),
  reconnection({ maxAttempts: Infinity }),
)
```

The split into two calls is deliberate. TypeScript can't infer some type arguments while you write others by hand, so naming the contract in the first call frees the second call to infer the primitives — that's what types `socket.channel(...)` from your contract. The order of the primitives doesn't matter; they're sorted by their dependencies before they run.

`connect(...)` is the one required argument. Everything else is opt-in: a primitive you don't pass simply isn't on the socket.

## What every socket has

These methods are on the socket no matter which primitives you add:

| Method | What it does |
|---|---|
| `connect()` | Opens the connection. Safe to call more than once — a no-op while already open or connecting. |
| `disconnect(code?, reason?)` | Closes on purpose. A full stop: no reconnection, the send buffer is cleared, pending requests reject. `code` defaults to `1000`, `reason` to `''`. |
| `getState()` | The current [connection state](#connection-states). |
| `subscribe(callback)` | Runs `callback` on every state change. Returns an unsubscribe function. Read the new value with `getState()`. |
| `onOpen(callback)` | Runs on every open — the first connect and every reconnect. |
| `onReconnect(callback)` | Runs only on reconnects, not the first connect. |
| `onReconnectFailed(callback)` | Runs once when reconnection gives up for good. |
| `onClose(callback)` | Runs on every close, including ones that lead to a reconnect. The callback gets `{ code, reason, wasClean }`. |
| `onError(callback)` | Runs on a WebSocket-level error, and on a typed server error no request or stream claimed. |
| `setDebug(enabled)` | Turns console logging on or off at runtime. |
| `protocol` | The subprotocol the server picked, or `null`. |
| `ws` | The native `WebSocket`, or `null` when not connected. |

Each `on*` callback returns an unsubscribe function. Note that `onError` is called with either a DOM `Event` (a WebSocket-level error) or a typed `WSKitError` (an unclaimed server error), so you narrow on the type — and if you register no `onError` at all, those errors are rethrown to the host's global handler rather than swallowed. The full error model is in the [Errors chapter](/client/errors/overview).

The socket also carries the **Messaging** methods — `on(event, handler)` to listen and `send(event, payload)` to send — which appear only when your contract declares `incoming` or `outgoing` events, respectively. See [the Messaging interface](#the-messaging-interface) below.

## Connection states

A socket is always in exactly one of four states:

- **`closed`** — not connected, and not trying to be.
- **`connecting`** — opening a connection (resolving the URL, then the handshake).
- **`open`** — connected and ready to send and receive.
- **`reconnecting`** — the connection dropped and the client is waiting to retry. Only reached when the [`reconnection()`](/client/primitives/reconnection) primitive is installed.

`subscribe(callback)` plus `getState()` is the standard external-store pattern, so it drops straight into framework state — see [Framework Hooks](/client/framework-hooks/overview).

## The Messaging interface

`on()` and `send()` make up the **Messaging** interface — the pair of methods for receiving and sending typed events:

```typescript [app.ts]
// Listen — returns an unsubscribe function
const stop = socket.on('notification', (data) => {
  // data is typed from your contract's `incoming`
})

// Send — returns true if sent or buffered, false if dropped
socket.send('mark-read', { id: '123' })
```

Which of the two you get depends on your contract: `on()` exists only when the contract has `incoming` events, and `send()` only when it has `outgoing` events. Try to `send()` on a contract that declares nothing outgoing and it's a compile error — there's nothing to send.

A `true` from `send()` means "accepted" — handed to the socket or placed in the buffer — not "the server got it." When you need delivery confirmation, use a [request](/client/primitives/request-response) instead.

Channel handles returned by the `channels` primitive are Messaging objects too, so the same `on()` / `send()` work scoped to a room.

## Primitives add the rest

Beyond the base above, each primitive you install adds its own methods, typed from your contract:

- [`channels()`](/client/primitives/channels) adds `socket.channel(...)`.
- [`requestResponse()`](/client/primitives/request-response) adds `socket.request(...)`.
- [`serverRequest()`](/client/primitives/server-request) adds `socket.onRequest(...)`.
- [`stream()`](/client/primitives/stream) adds `socket.stream(...)`, `socket.onStream(...)`, and `socket.resumeStream(...)`.
- [`keepalive()`](/client/primitives/keepalive) adds `socket.getQuality()`, `socket.getLatency()`, and `socket.onQualityChange(...)`.

If you don't install a primitive, its methods aren't on the socket — and if your contract declares the matching section, TypeScript points you at the primitive to add.
