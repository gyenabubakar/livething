The server definition you build with `server`, capabilities, handlers and `assemble` says what your server does. It does not say where it runs or how clients reach it. This section covers those choices:

- **The runtime.** A [runtime adapter](/runtimes/adapters/overview) runs the definition on one platform, such as Cloudflare or Node.js. You pass the definition to the adapter's `bind()`.
- **The Node.js framework.** On Node.js, you can serve LiveThing from the [framework](/runtimes/node-frameworks/overview) your app already uses, such as Express, Hono or Nuxt.
- **The transports.** A [transport](/runtimes/transports/overview) is how a client's messages travel. WebSocket is the default. `http()` (server-sent events and POST requests) can carry the whole app alone, or take over when a network blocks WebSocket. You list the transports in `bind()` on the server and in `connect()` on the client.

These choices leave your definition and your app code the same.

## Node.js Frameworks

The Node.js adapter works with Express, Koa, Hono, Fastify, H3, Nuxt, SolidStart, TanStack Start, React Router, SvelteKit and Astro. [Node.js Frameworks](/runtimes/node-frameworks/overview) shows which import each one uses, and each framework has its own page. To connect a framework that is not on the list, see [Build your own](/runtimes/node-frameworks/build-your-own).

## Transports

| Transport                           | Server        | Client        | Page                                                        |
| ----------------------------------- | ------------- | ------------- | ----------------------------------------------------------- |
| WebSocket                           | `websocket()` | `websocket()` | [`websocket()`](/runtimes/transports/websocket)             |
| Server-sent events and POST         | `http()`      | `http()`      | [`http()`](/runtimes/transports/http)                       |
| One you build, such as long polling | Your own      | Your own      | [Custom Transports](/runtimes/transports/custom-transports) |

Cloudflare, Node.js and Bun offer WebSocket and `http()`. Deno has no adapter of its own: it can run the Node.js adapter with a `node:sqlite` database, but it is not a supported runtime. When a client lists several transports, it tries them in order and moves on when one does not connect.
