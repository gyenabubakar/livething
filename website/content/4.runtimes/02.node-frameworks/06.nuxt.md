This page builds on the [Node.js adapter](/runtimes/adapters/node). It shows only what is different with Nuxt. The options, limits, origins, compression, client IP, storage, admin API and shutdown work as that page explains.

Nuxt 4 runs its server code on Nitro 2, which uses H3 v1 for routing and CrossWS 0.3 for WebSockets. Because of these versions, Nuxt uses the [`@livething/server-node/h3/v1`](/runtimes/node-frameworks/h3#h3-v1) binding, not the H3 v2 binding at `@livething/server-node/h3`. Read [Nitro apps](/runtimes/node-frameworks/overview#nitro-apps-nuxt-solidstart-and-tanstack-start) first for what each file does.

```bash [pnpm]
pnpm add @livething/core @livething/server @livething/server-node h3@^1.15.11 crossws@^0.3.5
```

Enable Nitro's WebSocket support in the Nuxt config:

```ts [nuxt.config.ts]
import { defineNuxtConfig } from 'nuxt/config'

export default defineNuxtConfig({
  nitro: {
    experimental: {
      websocket: true,
    },
  },
})
```

Create the endpoint. The example expects `server/huddle-definition.ts` to export `huddle`, the [server definition](/server/server/overview) that holds your event handlers. `setup()` creates the Node adapter. `bind()` connects your server definition to the adapter, opens the SQLite file, and starts LiveThing's startup work:

```ts [server/utils/huddle-endpoint.ts]
import { setup } from '@livething/server-node/h3/v1'
import { huddle } from '../huddle-definition'

export const huddleNode = setup()
export const huddleEndpoint = huddleNode.bind(huddle, {
  sql: './data/huddle.sqlite',
})
```

Export `huddleEndpoint.connect` as the WebSocket route. It is the route handler, and it handles the WebSocket handshake:

```ts [server/routes/huddle.ts]
import { huddleEndpoint } from '../utils/huddle-endpoint'

export default huddleEndpoint.connect
```

Add the Nitro plugin:

```ts [server/plugins/huddle.ts]
import { defineNitroPlugin } from 'nitropack/runtime'
import { huddleNode } from '../utils/huddle-endpoint'

export default defineNitroPlugin((nitroApp) => {
  nitroApp.hooks.hook('close', huddleNode.shutdown)

  huddleNode.ready().catch((error) => {
    console.error('LiveThing huddle server failed to start', error)
    process.exit(1)
  })
})
```

Nuxt also auto-imports `defineNitroPlugin`, so you can leave out that import in a Nuxt project.

In Nuxt 4, Nitro's Node server preset does not pass any options to its WebSocket server, so compression stays off.

## Serve `http()`

Nuxt runs on H3 v1. Add `transports` to the endpoint file from the setup above:

```ts [server/utils/huddle-endpoint.ts]
import { http, websocket } from '@livething/server-node'
import { setup } from '@livething/server-node/h3/v1'
import { huddle } from '../huddle-definition'

export const huddleNode = setup()
export const huddleEndpoint = huddleNode.bind(huddle, {
  sql: './data/huddle.sqlite',
  transports: [websocket(), http()],
})
```

The route file `server/routes/huddle.ts` stays as it is. Its name has no method suffix, so Nitro sends every method to `huddleEndpoint.connect`. `connect` serves a request that is not a WebSocket upgrade the same way as `handle`: the stream, the POSTs and the preflight.

## Call the admin API from a Nuxt route

A normal Nuxt server route can use the admin API:

```ts [server/api/admin/announcements.post.ts]
import {
  defineEventHandler,
  getHeader,
  readBody,
  setResponseStatus,
} from 'h3'
import { verifySession } from '../../utils/auth'
import { huddleEndpoint } from '../../utils/huddle-endpoint'

export default defineEventHandler(async (event) => {
  const token = getHeader(event, 'authorization')?.replace(
    'Bearer ',
    '',
  )
  const user = await verifySession(token) // your auth
  if (user?.role !== 'admin') {
    setResponseStatus(event, 401)
    return null
  }

  const { text } = (await readBody(event)) as { text: string }

  const admin = await huddleEndpoint.admin()
  await admin.announce(text)
  setResponseStatus(event, 204)

  return null
})
```

The route imports `huddleEndpoint` from the same shared file as the WebSocket route, so the admin call reaches the users connected to `/huddle`.
