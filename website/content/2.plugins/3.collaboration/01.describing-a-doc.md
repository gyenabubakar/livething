A **doc type** is a kind of shared document, such as Huddle's task board. You describe it once with `doc()`, in a file that the server and the client both import. Each doc of that type (each room's board) has an ID.

```typescript [shared/huddle-docs.ts]
import {
  doc,
  list,
  record,
  richText,
  text,
} from '@livething/plugin-collaboration'
import * as v from 'valibot'

export const taskBoard = doc(
  'task-board',
  {
    title: text(),
    archived: v.optional(v.boolean(), false),
    columns: list({ id: v.string(), name: text() }),
    tasks: list({
      id: v.string(),
      column: v.string(),
      title: text(),
      done: v.boolean(),
      assignee: v.nullable(v.string()),
      notes: richText(),
    }),
    settings: record({ collapsed: v.array(v.string()) }),
  },
  {
    awareness: v.object({ viewingTaskId: v.nullable(v.string()) }),
  },
)

// Every doc type the app has. The server and the client both get this list.
export const huddleDocs = [taskBoard] as const
```

## The fields

A doc is a [CRDT](/plugins/collaboration/overview#how-edits-merge-a-crdt), and each kind of field is a different Yjs type, so each one merges in its own way:

| You write                           | You read              | How edits from different people merge                                                                               |
| ----------------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------- |
| any Standard Schema (`v.boolean()`) | its value             | the value changes as a whole: if two people set it at once, one of them wins                                        |
| `text()`                            | `string`              | letter by letter: two people can type in the same field, and both edits stay                                        |
| `richText()`                        | `string` (plain text) | letter by letter, through an editor ([Rich text editors](/plugins/collaboration/rich-text-editors))                 |
| `list(item)`                        | `readonly item[]`     | adds, deletes and moves from different people all merge ([Lists and moves](/plugins/collaboration/lists-and-moves)) |
| `record(item)`                      | `{ [key]: item }`     | each key on its own. Use it when you choose the keys, such as user IDs.                                             |
| `{ ... }` (a plain object)          | an object             | each field on its own                                                                                               |

The rule of thumb: use the plugin's builders for what people edit **together**, and a schema for a value that changes **as a whole**. People type into a task's `title` together, so it is `text()`. A task is done or not, so `done` is `v.boolean()`.

Fields nest: a list item is a plain object of fields, a record can hold lists, and a list can hold lists.

## Values: any Standard Schema

A value is any [Standard Schema](https://standardschema.dev): valibot, zod, arktype and others work the same way. The plugin checks every value that `change()` writes, on the client and again on the server.

- A schema must check a value at once. A schema that checks asynchronously is refused when a change is checked.
- A value must be JSON, or bytes (`Uint8Array`). A `Date`, `Map`, `Set` or class instance is refused, because a Yjs update carries JSON. Keep a date as a number or an ISO string.

## Values at the top need a default

A new doc starts empty. So a value at the top of the doc (not inside a list or a record) needs a default, such as `v.optional(v.boolean(), false)`. Leaving it out is a type error, and `doc()` throws for it too.

```ts
import { doc } from '@livething/plugin-collaboration'
import * as v from 'valibot'

doc('task-board', {
  // @ts-expect-error a value at the top of a doc needs a default
  archived: v.boolean(),
})
```

Text, rich text, lists and records start empty on their own, so they need nothing.

## The awareness state

The third argument's `awareness` is the schema of each member's live state in this doc, such as the task each member has open. [Awareness and locks](/plugins/collaboration/awareness-and-locks) shows how to use it.

## Names

- A doc type name is 1 to 64 lowercase letters, digits and hyphens, starting with a letter: `'task-board'`.
- A field name is a JavaScript name: letters, digits, `_` and `$`, not starting with a digit. Names such as `constructor` and `toString` are refused.
- A doc ID is any string of at least 1 character, and the type, a `:` and the ID are at most 256 characters together. Huddle uses the room ID.

## Changing a doc type later

The fields of a doc are found by name, so you can add fields to a doc type that already has stored docs:

- At the top of the doc, a new text, rich text, list or record starts empty.
- A new value needs a default, such as `v.optional(v.boolean(), false)`, even inside a list item. Items stored before the field existed read the default.
- Inside a list item or a record value, don't add a new text, rich text, list or record. Items stored before it existed don't have it, and they can't be read. Add it at the top of the doc, or in a new list.
- Content that does not match the schema, such as an old item with no value for a new field, is not shown: `state` keeps its last good copy, and the client's [`onError`](/plugins/collaboration/client#errors) gets an `invalid-change` error.

Renaming or removing a field leaves the old content stored under the old name, unread. When an older app version sends content the new schema does not allow, the server undoes it, and the older client hears about it through [`onRefused`](/plugins/collaboration/client#when-the-server-undoes-a-change).

## What TypeScript works out

From one `doc()` and the `huddleDocs` list, you never write these types by hand:

- what `state`, `select()`, `versions.read()` and the server's `read()` give you;
- the draft in `change()`, and what `push()`, `insert()` and `set()` take;
- the Yjs type that `yjs.at()` returns for a field;
- the awareness state;
- the doc names that `collab.doc(name, id)` takes;
- the `doc` in the server's `access`, and the `state` in `onSave`.

The types `Snapshot`, `Draft`, `Input` and `PathOf` are exported if you need to name them, for example `Snapshot<typeof taskBoard.shape>`.
