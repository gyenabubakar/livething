**Collaboration** gives your app shared documents that many people edit at the same time, like a task board, a form or meeting notes. Each doc is a CRDT, built on [Yjs](https://yjs.dev), so edits from different people never conflict, and it runs on your own LiveThing server.

You describe a doc once, in code the server and the client share. Every type comes from that description: what you read, what you write, what the server checks.

- **Edits merge.** Two people can type in the same text, add tasks at the same spot, or move the same task, and every copy ends up the same.
- **The server checks every change** against the doc's schema. A bad change (from an old or a modified client) is undone for everyone.
- **Undo and redo** for each person: your undo takes back only your changes.
- **Real list moves.** A moved item is moved, never copied, so edits made to it during the move stay.
- **Awareness and locks**: see which task each member has open, and let one member at a time edit a part.
- **Anchors** that stay on their words or items as people edit, for highlights, bookmarks or comments.
- **Text inputs and rich text editors**: `bindText()` for a plain `<input>`, and Yjs bindings for ProseMirror, Tiptap, CodeMirror, Monaco and Quill.
- **Versions**: save the doc, read an old version, and restore it as one change you can undo.
- **Offline edits** go out when the socket is back, and with device storage they survive a reload.

## How edits merge: a CRDT

A **CRDT** (conflict-free replicated data type) is a data structure that many copies can change at the same time, with no lock and no server in the middle deciding the order. Each copy sends its changes to the others, and when every copy has every change, all copies hold the same content, whatever order the changes came in.

Yjs is a CRDT library, and each doc is a Yjs doc. So:

- every client keeps its own copy of the doc, and `change()` edits that copy at once, with no round trip to the server;
- the client sends the change as a small update, and the server passes it on to the others;
- a client that was offline sends its changes later, and they merge with what happened meanwhile;
- two people who edit at the same moment never get a "conflict" error: the CRDT has a rule for each case. Text merges letter by letter, list adds and moves merge, and for one value set by two people at once, one of them wins.

A plain CRDT accepts any change, which is a problem when the doc has a schema. So the plugin adds two things on top: [the server checks](/plugins/collaboration/server#the-server-checks-every-change) each change against the doc's schema and undoes a bad one for everyone, and [lists](/plugins/collaboration/lists-and-moves) get real moves, which plain Yjs does not have.

## A first look

Huddle, the team chat app in these docs, gives each room a task board. This is the board, described once in a file both sides import:

```typescript [shared/huddle-docs.ts]
import {
  doc,
  list,
  richText,
  text,
} from '@livething/plugin-collaboration'
import * as v from 'valibot'

export const taskBoard = doc('task-board', {
  title: text(),
  archived: v.optional(v.boolean(), false),
  tasks: list({
    id: v.string(),
    title: text(),
    done: v.boolean(),
    notes: richText(),
  }),
})

export const huddleDocs = [taskBoard] as const
```

The server lists the plugin and says who may open which board. The client opens a board, reads it, and changes it:

```typescript [client/task-board.ts]
import { HuddleCollaboration } from './huddle-collab'
import { socket } from './socket'

const board = HuddleCollaboration.use(socket).doc(
  'task-board',
  'general',
)
await board.open()

board.state.subscribe((state) => {
  console.info(state.title, state.tasks.length)
})

board.change((d) => {
  d.title = 'Launch plan'
  const task = d.tasks.find((t) => t.id === 't_1042')
  if (task) task.done = true
})
```

Everyone who has the board open sees the change at once. The [Huddle reference](/core/reference/huddle#task-boards) has the full task board, and these pages use it.

## Install

```bash
pnpm add @livething/plugin-collaboration yjs
```

`yjs` is a peer dependency, so your app and any editor binding share one copy of it. The package has three entry points:

| Import                                   | What it has                                                                 |
| ---------------------------------------- | --------------------------------------------------------------------------- |
| `@livething/plugin-collaboration`        | `doc()`, `text()`, `richText()`, `list()`, `record()`, and the shared types |
| `@livething/plugin-collaboration/server` | the server plugin, `sqlStorage()`                                           |
| `@livething/plugin-collaboration/client` | the client plugin, `indexedDbStorage()`                                     |
