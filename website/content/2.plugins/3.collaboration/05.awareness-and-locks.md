Each doc has its own [awareness](/core/client/primitives/awareness): the live state of each member who has it open, such as the task they are looking at. It is typed by the `awareness` option of the doc's description. Huddle's task board has `awareness: v.object({ viewingTaskId: v.nullable(v.string()) })` (see [Describing a doc](/plugins/collaboration/describing-a-doc)).

## Your state and the others'

```typescript [client/task-viewers.ts]
import { board } from './task-board'

export function viewTask(taskId: string | null) {
  board.awareness.update({ viewingTaskId: taskId })
}

// Log who has each task open, by task ID.
board.awareness.others.subscribe((others) => {
  const names = new Map<string, string[]>()
  for (const member of others.values()) {
    const taskId = member.state?.viewingTaskId
    if (!taskId) continue

    const list = names.get(taskId) ?? []
    names.set(taskId, [...list, String(member.meta.name)])
  }

  console.info('viewers', Object.fromEntries(names))
})
```

- `update(patch)` merges `patch` into your last state and sends it. You only send the fields that changed. But the server checks the whole state against the doc's `awareness` schema, so the first `update()` must set every field the schema needs. Until it does, the server refuses the state, with its cursor and locks, and `lock()` gives `false`.
- `others` is a [store](/core/client/overview#reactive-stores) of the other members, by connection ID. Each has its `connectionId`, its `meta` from the server's `authenticate`, and its `state`, or `null` before it set one. Your own other tabs are here too.
- `self` is a store of you as the server holds you, or `null` before you joined.

A member leaves `others` when it closes the doc or disconnects. The server checks each state against the schema, and refuses one that does not match.

The plugin keeps some fields of its own in each member's awareness: the Yjs client ID, a rich text editor's cursor or a [text input's caret](/plugins/collaboration/text-inputs#other-members-carets), and the member's locks. Your schema only describes your part, and `state` only shows your part.

## Locks

A lock is for "only one person edits this at a time": a form field, a table cell, a slide. Huddle locks a task while a member edits its notes:

```typescript [client/task-editor.ts]
import { showToast } from './huddle-ui'
import { board } from './task-board'

export async function startEditingNotes(taskId: string) {
  if (await board.lock(`task:${taskId}`)) return true

  showToast('Someone else is editing this task.')
  return false
}

export function stopEditingNotes(taskId: string) {
  board.unlock(`task:${taskId}`)
}
```

`lock(key)` resolves `true` once the server holds the lock for you, and `false` when another member has it, the client may only view the doc, the doc is not open, or the socket is down. The server decides, so two members who ask at the same moment never both get it.

A lock is freed when its holder calls `unlock()`, closes the doc, or disconnects. A reconnect does not take it back: someone else may hold it by then, so call `lock()` again. `unlock()` runs after any `lock()` still waiting for the server, so a `lock()` followed by an `unlock()` always ends unlocked.

`board.locks` is a store of every lock in the doc, by key, with who holds it (`connectionId` and `meta`). Use it to show who is editing what:

```ts
board.locks.subscribe((locks) => {
  const holder = locks.get('task:t_1042')
  render(holder ? `${String(holder.meta.name)} is editing` : '')
})
```

A lock is only a signal: it tells the UI who is editing, and the server refuses a second holder, but `change()` does not check locks. A member holds at most 32 locks, and a key is at most 128 bytes when written as JSON: a quote, a backslash or a control character takes 2 to 6 bytes there.
