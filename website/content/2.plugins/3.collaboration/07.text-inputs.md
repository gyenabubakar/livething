A normal "controlled" input (`value` plus an input handler) has a problem in a shared doc. When someone else edits the same text, the input gets a new value, and the browser moves your cursor to the end of it. You are typing in the middle of a word, and your next letter lands somewhere else.

`bindText()` links an `<input>` or a `<textarea>` to a `text()` field and fixes that. It updates the input itself, and keeps your cursor on the same character:

```typescript [client/task-title-input.ts]
import { board } from './task-board'

export function bindTaskTitle(
  input: HTMLInputElement,
  index: number,
) {
  return board.bindText(input, (p) => p.tasks[index]?.title)
}
```

- It sets the input's value from the doc right away.
- Each input event becomes one `change()`, and one undo step. Like any text assignment, it changes only the letters that differ, so others' typing in the same field stays. Half of an emoji alone (from a paste or a `maxlength` cut) becomes U+FFFD (`�`) in the doc and in the input, as every other copy would show it.
- When someone else edits the text, or an undo changes it, the input gets the new text, and the cursor and selection move with the characters they were on.
- While the user composes with an IME (for Japanese, Chinese or Korean), it leaves the input alone, because a new value would cancel the composition. When the composition ends, the composed text goes in as one `change()`, and the input gets the edits others made meanwhile.
- It returns a function that unbinds the input. Call it when the input goes away.

The path must end at a `text()` field: a path to `done` or to a `richText()` field is a type error. For rich text, use an [editor](/plugins/collaboration/rich-text-editors).

The path must also lead to something that exists when you bind, or `bindText()` throws. So bind after `open()` has resolved, and only to a task that is in the list. If the task is deleted, unbind the input.

In a doc the client may only view, typing throws a `read-only` error and puts the doc's text back in the input, so make the input read-only when `board.access` is `'view'`.

## In each framework

`bindText()` takes the DOM element, so it works through each framework's way of getting one:

- **React**: a `ref`, and the binding in `useEffect`, which returns the unbind function.
- **Vue**: a template `ref`, bound in `onMounted` and unbound in `onUnmounted`.
- **Svelte**: a two-line `use:` action, which returns `{ destroy }`.
- **Solid**: a `ref`, with the unbind function in `onCleanup`.

```tsx [TaskTitleInput.tsx]
import { useEffect, useRef } from 'react'
import { board } from './task-board'

export function TaskTitleInput({ index }: { index: number }) {
  const input = useRef<HTMLInputElement>(null)
  useEffect(() => {
    if (!input.current) return

    return board.bindText(input.current, (p) => p.tasks[index]?.title)
  }, [index])

  return <input ref={input} />
}
```

Don't also pass `value` to a bound input: the binding owns its value. [Framework recipes](/plugins/collaboration/frameworks) has the other frameworks.

## React Native

React Native's `TextInput` is not a DOM element, so `bindText()` does not apply. Use `change()` in `onChangeText`, and keep the cursor with the `selection` prop:

```tsx [TaskTitle.tsx]
import { useMemo, useState } from 'react'
import { TextInput } from 'react-native'
import { board } from './task-board'
import { useStore } from './use-store'

export function TaskTitle({ index }: { index: number }) {
  const selected = useMemo(
    () => board.select((s) => s.tasks[index]?.title ?? ''),
    [index],
  )
  const title = useStore(selected)
  const [selection, setSelection] = useState({ start: 0, end: 0 })

  return (
    <TextInput
      value={title}
      selection={selection}
      onSelectionChange={(event) =>
        setSelection(event.nativeEvent.selection)
      }
      onChangeText={(text) =>
        board.change((d) => {
          const task = d.tasks.at(index)
          if (task) task.title = text
        })
      }
    />
  )
}
```

The text still merges letter by letter. Only the cursor is your job here: when a remote edit lands before it, the cursor stays at the same index, not on the same character.
