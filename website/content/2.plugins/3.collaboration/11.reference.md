## Shared: `@livething/plugin-collaboration`

| Export                                                                                                                   | What it is                                                                                                           |
| ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| `doc(name, shape, options?)`                                                                                             | describes a doc type. `options.awareness` is the schema of each member's live state                                  |
| `text()`                                                                                                                 | text that people type into together. Reads as `string`                                                               |
| `richText()`                                                                                                             | rich text for an editor. Reads as plain text, one line per block                                                     |
| `list(item)`                                                                                                             | a list with real moves. Reads as a read-only array                                                                   |
| `record(item)`                                                                                                           | a map from your own keys to items. Reads as a read-only object                                                       |
| `Snapshot<F>`                                                                                                            | what reading a field gives: `Snapshot<typeof taskBoard.shape>` is the board's `state`                                |
| `Draft<F>`, `DraftList<I>`, `DraftRecord<I>`, `DraftShape<S>`                                                            | what `change()` hands you                                                                                            |
| `Input<F>`                                                                                                               | what writes a whole field: a new list item, a record value or a value                                                |
| `PathOf<F>`, `YRef<T>`, `ItemRef`, `YTypeOf<F>`                                                                          | the paths that `yjs.at()`, `bindText()` and anchors take                                                             |
| `Anchor`, `TextAnchor`, `ItemAnchor`, `TextRange`, `TextPlace`, `ItemPlace`                                              | anchors, and where they are now                                                                                      |
| `ReadonlyBytes`                                                                                                          | the type of bytes in a snapshot or a draft. It allows no writes. Pass `bytes.slice()` where a `Uint8Array` is needed |
| `CollaborationStorage`, `DocRef`                                                                                         | where a doc's updates are kept, and `{ type, id }`                                                                   |
| `VersionInfo`                                                                                                            | `{ id, label, createdAt, author }`                                                                                   |
| `InvalidChangeDetail`                                                                                                    | the `detail` of an `invalid-change` error: `{ path, reason }`                                                        |
| `DocDef`, `DocOptions`, `DocsByName`, `Field`, `Leaf`, `Shape`, `TextField`, `RichTextField`, `ListField`, `RecordField` | the types of a description                                                                                           |

## Server: `@livething/plugin-collaboration/server`

It exports `collaboration` and `sqlStorage`, and these types: `CollaborationOptions` (the options below), `AccessContext` (the `ctx` that `access` gets), `DocAccess` (what `access` returns), `SaveContext` and `SaveEvent` (what `onSave` gets), `CollaborationApi` (what `ctx.plugin('livething:collaboration')` gives), `DocOf` (the `{ type, id }` union of the doc types), `ServerDoc`, `ServerVersions` and `ServerStorage`.

### `collaboration(options)`

Returns a plugin factory. The host lists `HuddleCollaboration()` in its capabilities, with `channels()`.

| Option        | Type                                                    | Default               | What it does                                                         |
| ------------- | ------------------------------------------------------- | --------------------- | -------------------------------------------------------------------- |
| `docs`        | the doc types                                           | required              | every doc type, the same list the client gets                        |
| `access`      | `(ctx, doc) => 'edit' \| 'view' \| false`, or a promise | required              | runs on each open and rejoin. `ctx` has `user`, `meta`, `connection` |
| `onSave`      | `(ctx, { type, id, state }) => void`, or a promise      | none                  | runs once changes settle, and when the last member leaves            |
| `saveDelayMs` | `number`                                                | `2000`                | how long a doc stays unchanged before `onSave` runs                  |
| `storage`     | `ServerStorage`                                         | `sqlStorage(ctx.sql)` | where docs and versions are kept                                     |
| `maxVersions` | `number`                                                | no limit              | the most versions each doc keeps. A save past it deletes the oldest  |

`collaboration()` throws a `LiveThingConfigError` when a doc type is listed twice, `docs` is empty, `saveDelayMs` is not a whole number from 0 to 2147483647, or `maxVersions` is not a whole number of 1 or more.

### Server and admin code

`ctx.plugin('livething:collaboration')` in a handler, and `admin.plugin('livething:collaboration')` in admin code, give `doc(type, id)`, a `ServerDoc`:

| Member                              | What it does                                                                                         |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `read()`                            | resolves with the doc's snapshot                                                                     |
| `change(fn)`                        | edits the doc with a draft, sends it to every member, and stores it. Resolves with what `fn` returns |
| `versions.save(label, { author? })` | saves a version. `author` defaults to `null`                                                         |
| `versions.list()`                   | the versions, newest first                                                                           |
| `versions.read(id)`                 | one version's snapshot                                                                               |
| `versions.restore(id)`              | makes the doc hold what the version holds, in one change                                             |
| `versions.delete(id)`               | deletes the version                                                                                  |

### `sqlStorage(sql)`

The default storage, over any LiveThing `SQLProvider` such as `ctx.sql`. Its tables are `livething_collaboration_updates`, `livething_collaboration_versions` and `livething_collaboration_version_parts`, each with a `metadata` column.

### `ServerStorage`

Pass your own as `storage` to keep docs in another database. Each method may return a promise. The plugin calls the update methods one at a time for each doc, in order.

| Method                             | What it must do                                                                     |
| ---------------------------------- | ----------------------------------------------------------------------------------- |
| `load(doc)`                        | give every stored update of the doc, oldest first, or an empty list                 |
| `append(doc, update)`              | keep one more update                                                                |
| `compact(doc, state)`              | replace every stored update of the doc with `state`, one update that holds them all |
| `saveVersion(doc, version, state)` | keep a version: its `VersionInfo` and its state                                     |
| `listVersions(doc)`                | give the doc's `VersionInfo`s, newest first                                         |
| `readVersion(doc, id)`             | give one version's state, or `null` when there is none                              |
| `deleteVersion(doc, id)`           | delete one version, and give `false` when there was none                            |

`doc` is a `DocRef`: `{ type, id }`. Updates and states are Yjs bytes: keep them as they are.

## Client: `@livething/plugin-collaboration/client`

It exports `collaboration` and `indexedDbStorage`, and these types: `CollaborationClientOptions` (the options below), `CollaborationClient` (what `HuddleCollaboration.use(socket)` gives), `DocHandle`, `DocStatus`, `DocHistory`, `DocAwareness`, `DocMember`, `LockHolder`, `DocAnchors`, `DocVersions`, `Refusal` (what `onRefused` gets), `ReadOnlyDetail` and `UpdateNotSentDetail` (error details), `TextInput` (what `bindText` takes), `IndexedDbStorageOptions` and `ReadableStore`.

### `collaboration(options)`

Returns a client plugin factory. List `HuddleCollaboration()` in `client()` after `channels()`, `binary()`, `awareness()` and `clientRequests()`. `HuddleCollaboration.use(socket).doc(type, id)` gives a `DocHandle`.

| Option         | Type                   | Default     | What it does                                                |
| -------------- | ---------------------- | ----------- | ----------------------------------------------------------- |
| `docs`         | the doc types          | required    | every doc type, the same list the server gets               |
| `storage`      | `CollaborationStorage` | memory only | keeps docs on the device, so offline edits survive a reload |
| `closeDelayMs` | `number`               | `1000`      | how long a doc stays joined after its last `close()`        |
| `onError`      | `(error) => void`      | uncaught    | gets errors no call can throw                               |

`collaboration()` throws a `LiveThingConfigError` when a doc type is listed twice, `docs` is empty, or `closeDelayMs` is not a whole number from 0 to 2147483647.

### `DocHandle`

A store is a [`ReadableStore`](/core/client/overview#reactive-stores), with `get()` and `subscribe(listener)`. The stores are `status`, `access`, `state`, what `select()` returns, `history.canUndo`, `history.canRedo`, `awareness.others`, `awareness.self`, `locks`, and what `anchor.watch()` returns.

| Member                              | What it is                                                                                                                                                                     |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `type`, `id`                        | which doc                                                                                                                                                                      |
| `open()`, `close()`                 | join and leave, counted                                                                                                                                                        |
| `status`                            | store: `'closed'`, `'opening'`, `'synced'`, `'saving'` or `'offline'`                                                                                                          |
| `access`                            | store: `'edit'`, `'view'` or `null`                                                                                                                                            |
| `state`, `select(fn)`               | stores of the snapshot, and of one part of it                                                                                                                                  |
| `change(fn)`                        | edits the doc. Returns what `fn` returns                                                                                                                                       |
| `keyOf(item)`                       | a list item's internal ID                                                                                                                                                      |
| `history`                           | `undo()`, `redo()`, `canUndo`, `canRedo`, `pause()`, `resume()`                                                                                                                |
| `onRefused(fn)`                     | runs when the server undoes one of this client's changes, or when a `'view'` client joins with content or deletes the server does not have. Returns a function that removes it |
| `awareness`                         | `update(patch)`, `others`, `self`                                                                                                                                              |
| `lock(key)`, `unlock(key)`, `locks` | one member at a time holds a key                                                                                                                                               |
| `anchor`                            | `text(path, { from, to })`, `item(path)`, `watch(anchor)`                                                                                                                      |
| `bindText(input, path)`             | links an `<input>` or `<textarea>` to a `text()` field. Returns the unbind function                                                                                            |
| `yjs`                               | `doc`, `at(path)` and `awareness`, for editor bindings                                                                                                                         |
| `versions`                          | `save(label)`, `list()`, `read(id)`, `restore(id)`, `delete(id)`                                                                                                               |

### `indexedDbStorage(options?)`

A `CollaborationStorage` in the browser's IndexedDB. `name` is the database name (default `'livething-collaboration'`), and `indexedDB` is the IndexedDB to use (default the browser's).

### `CollaborationStorage`

The client's `storage`. Each method may return a promise, and the plugin calls them one at a time for each doc, in order: `load(doc)` gives every stored update oldest first, `append(doc, update)` keeps one more, and `compact(doc, state)` replaces them all with `state`. An edit made before the doc's first `open()` is appended before the load, so `append` must work on a doc that was never loaded.

## Error codes

| Code                | Detail                  | When                                                                                                                                         |
| ------------------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `access-denied`     | `{ type, id }`          | `access` refused the client, or a `'view'` client saved or deleted a version                                                                 |
| `doc-not-found`     | `{ type, id }`          | the server does not serve the doc type, or the doc ID is empty, too long or holds half of an emoji alone                                     |
| `read-only`         | `{ type, id }`          | `change()`, `history.undo()`, `history.redo()` or `versions.restore()` in a doc the client may only view                                     |
| `invalid-change`    | `{ path, reason }`      | a value fails its schema, in `change()` or `versions.restore()`, on the client or the server                                                 |
| `version-not-found` | `{ type, id, version }` | the doc has no version with that ID                                                                                                          |
| `invalid-message`   | `{ reason }`            | a client sent bytes the plugin can't read, such as parts out of order                                                                        |
| `update-not-sent`   | `{ type, id, reason }`  | the server can never get a change: over 32 MiB, or the open socket dropped it. Later changes from this client fail too. It goes to `onError` |
| `validation-failed` | the schema's issues     | a client sent a bad version request, such as a label over 200 characters                                                                     |

## Limits

| What                                         | Limit                                                                          |
| -------------------------------------------- | ------------------------------------------------------------------------------ |
| a doc type name                              | 1 to 64 lowercase letters, digits and hyphens, starting with a letter          |
| a doc's type, `:` and ID together            | 256 characters (UTF-16 units, so an emoji counts 2). No half of an emoji alone |
| one update from a client                     | 32 MiB, sent in parts of 256 KiB                                               |
| one member's awareness                       | 8 KiB, with room for every lock and a cursor                                   |
| locks                                        | 32 per member, each key up to 128 bytes as JSON                                |
| a version label                              | 1 to 200 characters, with no half of an emoji alone                            |
| a rich text attribute or a format mark       | 1 KB. An attribute is a plain value, not a Yjs type                            |
| how deep rich text elements nest             | 100                                                                            |
| how deep Yjs types nest, from the doc's root | 200                                                                            |
| stored updates before the log is compacted   | 200 updates, or 4 MiB                                                          |

The plugin's ID is `livething:collaboration`. The plugin has one channel family, `docs`, and each doc is a room in it, named `<type>:<id>`.
