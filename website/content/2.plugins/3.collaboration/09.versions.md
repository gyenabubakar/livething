A **version** is a copy of the whole doc at one moment, with a label, kept on the server. Save one before a big change, show the list, read an old one, and restore it.

```typescript [client/board-versions.ts]
import { board } from './task-board'

export async function saveBeforeReview() {
  return board.versions.save('Before the launch review')
}

export async function restoreLatest() {
  const [latest] = await board.versions.list()
  if (!latest) return

  const old = await board.versions.read(latest.id)
  console.info(
    `Restoring "${latest.label}": ${old.tasks.length} tasks`,
  )
  await board.versions.restore(latest.id)
}
```

The doc must be open. Each method returns a promise.

| Method        | What it does                                                             | Access   |
| ------------- | ------------------------------------------------------------------------ | -------- |
| `save(label)` | saves the doc as the server has it now, and gives the new version's info | `'edit'` |
| `list()`      | every version of the doc, newest first                                   | any      |
| `read(id)`    | one version's content, typed like `state`                                | any      |
| `restore(id)` | makes the doc hold what the version holds, as one change                 | `'edit'` |

A version's info is `{ id, label, createdAt, author }`. `createdAt` is a time in ms since 1970, and `author` is the user ID of the member who saved it (or `null` from server code). A label is 1 to 200 characters.

## Saving waits for your changes

`save()` first waits until the server has confirmed the changes this client sent, so a version saved right after a `change()` has that change in it:

```ts
board.change((d) => {
  d.title = 'Launch plan, final'
})
await board.versions.save('Final plan') // has the new title
```

## Restoring is one change

`restore(id)` changes only what differs between the doc now and the version, as one `change()`:

- Every member who has the doc open gets it, like any other change.
- `board.history.undo()` takes it back, so a restore by mistake is one undo away.
- Text changes letter by letter, so anchors on words that are in both stay on them.
- List items that are in both keep their IDs, so [item anchors](/plugins/collaboration/anchors) and `keyOf()` keys stay. Items added since are deleted, and items deleted since come back.

A client that may only view the doc gets a `read-only` error from `restore()`, and an `access-denied` error from `save()`. An ID the doc has no version for gives `version-not-found`.

## From server code

The server's doc has the same methods, with an `author` option on `save()`:

```typescript [server/nightly-versions.ts]
import { huddleEndpoint } from './huddle-endpoint'

export async function saveNightlyVersion(roomId: string) {
  const admin = await huddleEndpoint.admin()
  const board = admin
    .plugin('livething:collaboration')
    .doc('task-board', roomId)

  await board.versions.save('Nightly', { author: null })
}
```

`restore()` from server code is one change too, and every member who has the doc open gets it.

## Storage

A version is kept as the doc's whole Yjs state, in two tables of the server's SQL: `livething_collaboration_versions` (the info) and `livething_collaboration_version_parts` (the bytes, split across rows when it is big). A custom [`storage`](/plugins/collaboration/server#storage) keeps them with its `saveVersion`, `listVersions` and `readVersion` methods.

The plugin does not delete versions, and it has no limit on how many a doc keeps. If your app saves versions often, delete old ones from the tables yourself.
