A **version** is a copy of the whole doc at one moment, with a label, kept on the server. Save one before a big change, show the list, read an old one, and restore it.

```typescript [client/board-versions.ts]
import { board } from './task-board'

export async function saveBeforeReview() {
  return board.versions.save('Before the launch review')
}

export async function restoreLatest() {
  const [latest] = await board.versions.list()
  if (!latest) return

  const old = await board.versions.read(latest.id)
  console.info(
    `Restoring "${latest.label}": ${old.tasks.length} tasks`,
  )
  await board.versions.restore(latest.id)
}
```

The doc must be open, and the socket connected: versions live on the server, so while the network is down each method rejects with `disconnected`. After `socket.disconnect()`, or while the doc is closed, it rejects with `channel-not-subscribed`. Each method returns a promise.

| Method        | What it does                                                             | Access   |
| ------------- | ------------------------------------------------------------------------ | -------- |
| `save(label)` | saves the doc as the server has it now, and gives the new version's info | `'edit'` |
| `list()`      | every version of the doc, newest first                                   | any      |
| `read(id)`    | one version's content, typed like `state`                                | any      |
| `restore(id)` | makes the doc hold what the version holds, as one change                 | `'edit'` |
| `delete(id)`  | deletes the version. The doc and its other versions stay as they are     | `'edit'` |

A version's info is `{ id, label, createdAt, author }`. `createdAt` is a time in ms since 1970, and `author` is the user ID of the member who saved it (or `null` from server code). A label is 1 to 200 characters, with no half of an emoji alone.

## Saving waits for your changes

`save()` first waits until the server has confirmed the changes this client sent, so a version saved right after a `change()` has that change in it:

```ts
board.change((d) => {
  d.title = 'Launch plan, final'
})
await board.versions.save('Final plan') // has the new title
```

## Restoring is one change

`restore(id)` changes only what differs between the doc now and the version, as one `change()`:

- Every member who has the doc open gets it, like any other change.
- `board.history.undo()` takes it back, so a restore by mistake is one undo away.
- Text changes letter by letter, so anchors on words that are in both stay on them. Format marks on the text, such as bold, come back too.
- List items that are in both keep their IDs, so [item anchors](/plugins/collaboration/anchors) and `keyOf()` keys stay. Items added since are deleted, and items deleted since come back.

A client that may only view the doc gets a `read-only` error from `restore()`, and an `access-denied` error from `save()` and `delete()`. An ID the doc has no version for gives `version-not-found`. A version that the doc type's schema now refuses (the schema changed after the save) gives `invalid-change`, and the doc stays as it was. A version saved before a field with a default was added restores fine: the field gets its default, and a text, list or record added since starts empty, as in the version.

## From server code

The server's doc has the same methods, with an `author` option on `save()`:

```typescript [server/nightly-versions.ts]
import { huddleEndpoint } from './huddle-endpoint'

export async function saveNightlyVersion(roomId: string) {
  const admin = await huddleEndpoint.admin()
  const board = admin
    .plugin('livething:collaboration')
    .doc('task-board', roomId)

  await board.versions.save('Nightly', { author: null })
}
```

`restore()` from server code is one change too, and every member who has the doc open gets it.

## Keeping fewer versions

Each version is a full copy of the doc, so a doc saved every night grows its versions every night. Set `maxVersions` on the server plugin, and a save that goes past it deletes that doc's oldest versions:

```typescript [server/huddle-collaboration.ts]
import { collaboration } from '@livething/plugin-collaboration/server'
import { huddleDocs } from '../shared/huddle-docs'
import { isRoomMember } from './helpers'

export const HuddleCollaboration = collaboration({
  docs: huddleDocs,
  maxVersions: 30,
  async access(ctx, doc) {
    if (!ctx.user.id || !(await isRoomMember(ctx.user.id, doc.id))) {
      return false
    }

    return ctx.meta.role === 'guest' ? 'view' : 'edit'
  },
})
```

With no `maxVersions`, a doc keeps every version until you `delete()` it. The limit counts every version of the doc, saved by members and by server code alike.

## Storage

A version is kept as the doc's whole Yjs state, in two tables of the server's SQL: `livething_collaboration_versions` (the info) and `livething_collaboration_version_parts` (the bytes, split across rows when it is big). A custom [`storage`](/plugins/collaboration/server#storage) keeps them with its `saveVersion`, `listVersions`, `readVersion` and `deleteVersion` methods.
