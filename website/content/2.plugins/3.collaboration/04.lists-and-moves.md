A `list(item)` holds items that people add, delete and move at the same time. A `record(item)` maps keys you choose, such as user IDs, to items. In `change()`, both change through their methods.

## List methods

```typescript [client/task-actions.ts]
import { board } from './task-board'

export function addTask(id: string, title: string) {
  board.change((d) => {
    d.tasks.push({
      id,
      column: 'todo',
      title,
      done: false,
      assignee: null,
      notes: '',
    })
  })
}

export function moveTaskToTop(taskId: string) {
  board.change((d) => {
    const from = d.tasks.findIndex((t) => t.id === taskId)
    if (from > 0) d.tasks.move(from, 0)
  })
}
```

| Method                      | What it does                                                               |
| --------------------------- | -------------------------------------------------------------------------- |
| `push(...items)`            | adds items at the end                                                      |
| `insert(index, ...items)`   | adds items before `index`                                                  |
| `set(index, item)`          | replaces the content of the item at `index`. It keeps its place and its ID |
| `delete(index, count = 1)`  | deletes `count` items from `index`                                         |
| `move(from, to)`            | moves the item at `from` so it ends up at `to`                             |
| `at(index)`                 | the item at `index`, as a draft you can write to, or `undefined`           |
| `find(fn)`, `findIndex(fn)` | the first item, or its index, that `fn` accepts                            |
| `length`, `for ... of`      | the number of items, and each item as a draft                              |

`find` and `findIndex` give `fn` each item as it was when the `change()` began, so they don't see what the same change wrote to it. An item the same change added, or replaced with `set()`, is given as the change wrote it. An index is a whole number of 0 or more. A new item is checked against the item's schema, and a field with a default may be left out. A `richText()` field of a new item takes a string: each line becomes a paragraph.

## Moves are real moves

Yjs has no "move". In plain Yjs, a move is a delete plus an insert, which **copies** the item. When two people move the same item at once, it ends up in the list twice, and an edit someone made to it during the move is lost with the old copy.

So a `list()` keeps its items and their order apart. The items live in a map by an internal ID, and the order is a separate list of those IDs. A move changes only the order, so the item is never copied:

- Two people move the same task at once: it shows up once, in the same place for everyone.
- Someone edits a task while someone else moves it: both changes stay.
- Someone deletes a task while someone else moves it: it stays deleted.
- Two people add several tasks at the same spot: each person's tasks stay together, in the same order for everyone.
- An undo puts a moved task back where it was.

The internal ID is what `board.keyOf(task)` gives, and what an [item anchor](/plugins/collaboration/anchors) stays on. It does not change when the item moves.

## A column is a field, not a list

Huddle keeps every task in one `tasks` list, with a `column` field, not one list per column. Moving a task to another column is then a field change, which merges like any other:

```ts
board.change((d) => {
  const task = d.tasks.find((t) => t.id === 't_1042')
  if (task) task.column = 'done'
})
```

With one list per column, the move would be a delete from one list and an insert into another: a copy, with the problems above.

## Records

A `record()` is for values you look up by your own key. Huddle keeps each member's board settings by user ID:

```typescript [client/board-settings.ts]
import { board } from './task-board'

export function collapseColumn(userId: string, columnId: string) {
  board.change((d) => {
    const mine = d.settings.get(userId)
    const collapsed = [...(mine?.collapsed ?? []), columnId]
    d.settings.set(userId, { collapsed })
  })
}
```

A record has `get(key)`, `set(key, item)`, `has(key)`, `delete(key)`, `keys()` and `size`. Each key merges on its own, so two members who change their own settings at the same time both keep them. If two people `set()` the same key at once, one of them wins.

`collapsed` is a value (`v.array(v.string())`), so it changes as a whole: you set a new array, you don't push to it. When people need to edit a list's items together, make it a `list()`.
