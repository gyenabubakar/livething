Rich text needs a real editor, and many editors already have a [Yjs](https://yjs.dev) binding. A binding needs two things: the Yjs container to edit, and a y-protocols `Awareness` object for live cursors. `board.yjs` gives both:

```ts
board.yjs.doc // the Y.Doc
board.yjs.at((p) => p.tasks[0]?.notes) // typed: Y.XmlFragment
board.yjs.awareness // a y-protocols Awareness object
```

`yjs.at(path)` gives the Yjs type behind a field: a `Y.XmlFragment` for `richText()`, and a `Y.Text` for `text()`. A path to any other field, such as `done`, is a type error. The path must lead to something that exists, so open the doc first, and bind an editor to a task that is there.

`yjs.awareness` is a real instance of y-protocols' `Awareness` class, the one every Yjs editor binding is written against. The plugin keeps it in step with the doc's [LiveThing awareness](/plugins/collaboration/awareness-and-locks) both ways, so cursors travel with the rest of each member's state, and leave when the member leaves. Cursors are not dropped by y-protocols' 30-second timeout while their owner is still in the doc.

## Which editors work

These editors are tested end to end: two browsers type through the editor, and each sees the other's text and cursor.

| Editor      | Binding                                                                       | Field        |
| ----------- | ----------------------------------------------------------------------------- | ------------ |
| ProseMirror | `y-prosemirror`                                                               | `richText()` |
| Tiptap      | `@tiptap/extension-collaboration` and `@tiptap/extension-collaboration-caret` | `richText()` |
| BlockNote   | `CollaborationExtension` from `@blocknote/core/yjs`                           | `richText()` |
| CodeMirror  | `y-codemirror.next`                                                           | `text()`     |
| Quill       | `y-quill` and `quill-cursors`                                                 | `text()`     |
| Monaco      | `y-monaco`                                                                    | `text()`     |

- **Lexical is not supported.** Its Yjs binding edits a different Yjs type than `richText()` uses, and it stores node data that the server's rich text check refuses.
- **Monaco**: use `monaco-editor` 0.54 or older. The package's exports in newer versions stop y-monaco from loading it.

## ProseMirror

A ProseMirror editor takes a list of plugins, and y-prosemirror provides three:

```typescript [client/task-notes-editor.ts]
import { schema } from 'prosemirror-schema-basic'
import { EditorState } from 'prosemirror-state'
import { EditorView } from 'prosemirror-view'
import {
  yCursorPlugin,
  ySyncPlugin,
  yUndoPlugin,
} from 'y-prosemirror'
import { board } from './task-board'

export function mountTaskNotes(host: HTMLElement, index: number) {
  const notes = board.yjs.at((p) => p.tasks[index]?.notes)

  return new EditorView(host, {
    state: EditorState.create({
      schema,
      plugins: [
        ySyncPlugin(notes), // keeps the editor and the doc in step
        yCursorPlugin(board.yjs.awareness), // shows the others' cursors
        yUndoPlugin(), // Ctrl+Z for typing in this editor
      ],
    }),
  })
}
```

## Tiptap

Tiptap 3's collaboration extensions take the fragment and an object with the awareness. Turn off StarterKit's own undo, since the collaboration extension brings its own:

```typescript [client/task-notes-tiptap.ts]
import { Editor } from '@tiptap/core'
import { Collaboration } from '@tiptap/extension-collaboration'
import { CollaborationCaret } from '@tiptap/extension-collaboration-caret'
import { StarterKit } from '@tiptap/starter-kit'
import { board } from './task-board'

export function mountTaskNotes(
  host: HTMLElement,
  index: number,
  name: string,
) {
  return new Editor({
    element: host,
    extensions: [
      StarterKit.configure({ undoRedo: false }),
      Collaboration.configure({
        fragment: board.yjs.at((p) => p.tasks[index]?.notes),
      }),
      CollaborationCaret.configure({
        provider: { awareness: board.yjs.awareness },
        user: { name, color: '#c0392b' },
      }),
    ],
  })
}
```

## BlockNote

BlockNote takes the fragment through its collaboration extension. Import it from `@blocknote/core/yjs`, the build for the Yjs that LiveThing uses (`@blocknote/core/y` is for the Yjs 14 preview). `mount()` makes the element you give it the editor itself:

```typescript [client/task-notes-blocknote.ts]
import { BlockNoteEditor } from '@blocknote/core'
import { CollaborationExtension } from '@blocknote/core/yjs'
import { board } from './task-board'

export function mountTaskNotes(
  editable: HTMLElement,
  index: number,
  name: string,
) {
  const editor = BlockNoteEditor.create({
    extensions: [
      CollaborationExtension({
        fragment: board.yjs.at((p) => p.tasks[index]?.notes),
        user: { name, color: '#c0392b' },
        provider: { awareness: board.yjs.awareness },
      }),
    ],
  })
  editor.mount(editable)

  return editor
}
```

BlockNote keeps each block inside block nodes of its own. Text that a `change()` gives a new task's `richText()` field shows in BlockNote too.

## CodeMirror, Quill and Monaco

These edit a `text()` field's `Y.Text`. Huddle uses the task title here, but a code snippet or plain notes field works the same way:

```typescript [client/task-title-editors.ts]
import { EditorState } from '@codemirror/state'
import { EditorView } from '@codemirror/view'
import * as monaco from 'monaco-editor'
import Quill from 'quill'
import QuillCursors from 'quill-cursors'
import { yCollab } from 'y-codemirror.next'
import { MonacoBinding } from 'y-monaco'
import { QuillBinding } from 'y-quill'
import { board } from './task-board'

export function mountCodeMirror(parent: HTMLElement) {
  const title = board.yjs.at((p) => p.title)
  return new EditorView({
    parent,
    state: EditorState.create({
      doc: title.toString(),
      extensions: [yCollab(title, board.yjs.awareness)],
    }),
  })
}

export function mountQuill(host: HTMLElement) {
  Quill.register('modules/cursors', QuillCursors)
  const quill = new Quill(host, { modules: { cursors: true } })
  return new QuillBinding(
    board.yjs.at((p) => p.title),
    quill,
    board.yjs.awareness,
  )
}

export function mountMonaco(host: HTMLElement) {
  const editor = monaco.editor.create(host, { value: '' })
  return new MonacoBinding(
    board.yjs.at((p) => p.title),
    editor.getModel()!,
    new Set([editor]),
    board.yjs.awareness,
  )
}
```

## Undo in an editor

Ctrl+Z inside an editor undoes typing in that editor, through the binding's own undo. `board.history.undo()` undoes your [`change()` calls](/plugins/collaboration/client#undo-and-redo). The two don't mix: an editor's undo does not take back a `change()`, and `board.history` does not take back typing in an editor.

## What the server checks in rich text

The server checks rich text like everything else. It refuses an update that puts something other than elements and text in a `richText()` field, attributes bigger than 1 KB, or a format mark (such as a link) bigger than 1 KB. Normal editing in the editors above stays far below these limits.

A `text()` field holds characters and small format marks, so Quill's bold works, but not an embed such as an image. `state` shows only its characters.

## Reading rich text

`state` shows a `richText()` field as plain text, one line per block, for previews and search. To get the formatting, read the `Y.XmlFragment` from `yjs.at()`, or render it with the editor. `change()` can't assign rich text. When you create an item with a `richText()` field, you may give it a string, and each line becomes a paragraph.
