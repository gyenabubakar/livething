A **server plugin** is a bundled, namespaced slice of a server. It owns its own events, handlers, channels, streams, storage, and errors — all kept under its own ID so it never collides with the host or with another plugin. You author it like a tiny app, wrap it with `plugin(...)`, and the host lists it like any other capability.

Think of a plugin as a feature you build once and reuse: a presence tracker, a metrics counter, a chat-room engine. The host owns the platform, transport, and global engines, while the plugin brings only its own slice. If it needs configuration, accept that configuration as an explicit factory value.

::note
The client has its own plugins too. They package reusable client features (analytics, a protocol shim) and reach their API through `Plugin.use(socket)`. See [client Plugins](/client/plugins/overview). This chapter is about **server** plugins.
::

## The flow at a glance

A plugin goes through four steps from author to running host.

::steps

### Author the slice

Build a scoped slice with `server({ scope: 'plugin' })`. It has the same `base.on`, `base.request`, `base.channel`, and `ctx` as a top-level server — it just builds one slice instead of the whole thing.

```typescript [presence.ts]
import { emits, server, t } from '@wskit/server'
import * as v from 'valibot'

const h = server({
  scope: 'plugin',
  capabilities: [emits({ 'user-online': t<{ id: string }>() })],
})

const heartbeat = h.on('heartbeat', {
  input: v.object({}),
  run(ctx) {
    ctx.send('user-online', { id: ctx.connection.id })
  },
})
```

### Assemble it

Collect routed handler values with `assemble(...)`, exactly like a top-level server, and expose an optional `api` — the per-connection surface the host reaches with `ctx.plugin(id)`. Lifecycle hooks and scheduled task bodies register directly on the scoped builder. The result is a scoped server definition — not a runnable server.

```typescript [presence.ts]
const definition = h.assemble({
  handlers: [heartbeat],
  api(ctx) {
    return {
      ping() {
        ctx.send('user-online', { id: ctx.connection.id })
      },
    }
  },
})
```

### Wrap it with `plugin(...)`

Give the slice an ID and wrap it. The ID is `author:name` — lowercase letters, digits, and hyphens on each side of the colon. This is the value the host imports, reusing the server definition from the previous step.

```typescript [presence.ts]
import { plugin } from '@wskit/server/plugins'

export const Presence = plugin('acme:presence', { definition })
```

### The host lists `Plugin()`

The host calls the plugin like any other capability factory. Its events and handlers fold into the server under the plugin's namespace.

```typescript [host.ts]
import { server, t } from '@wskit/server'
import { Presence } from './presence'

const base = server({
  capabilities: [Presence()],
})
```
