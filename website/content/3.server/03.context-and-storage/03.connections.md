`ctx.send` sends to the connection that is running the handler (the caller). `ctx.broadcast` sends to the other connections on the server. This page covers the cases between these two: reading **who** is connected, and sending to **one specific** connection that is not the caller.

Two types do this work:

- **`ConnectionInfo`**: a read-only snapshot of one live connection. A snapshot is a copy of the data at one moment.
- **`ConnectionRef`** (a "ref" for short): an address for one connection. You get it from a snapshot and pass it to `ctx.connections.get(ref)` to send to that socket.

## Reading who is connected

`ctx.connections.all()` returns an array of snapshots, one for every live connection on this server instance. (An instance is one running copy of your server.) `ctx.connectionCount` is the number of those connections.

```typescript [server/huddle.ts]
base.on('who-is-here', {
  input: v.object({}),
  run(ctx) {
    const peers = ctx.connections.all()
    // Each peer's meta has the type your upgrade step returns.
    const names = peers.map((p) => p.meta.name)
    ctx.send('notification', {
      title: 'Online now',
      body: names.join(', '),
    })
  },
})
```

The snapshot does not update. It shows the connections at the moment you called it. Call `ctx.connections.all()` again when you need fresh data.

## `ConnectionInfo`

Each entry from `ctx.connections.all()` (and from channel `members()` and tag `connections()`) is a `ConnectionInfo`:

::field-group
::field{name="id" type="string"}
Unique ID of this connection. It has the same value as that connection's own `ctx.connection.id`.
::
::field{name="userId" type="string"}
The user ID the upgrade step returned for this connection. It is `''` (an empty string) for an anonymous connection, which is a connection whose upgrade step returned no user ID. LiveThing never makes up a user ID. Address an anonymous connection by its `ConnectionRef` (`ctx.connections.get(ref)`), not by `userId`. [Users](/server/context-and-storage/users) explains why an empty `userId` reaches nobody through `ctx.users`.
::
::field{name="meta" type="Meta"}
The metadata set during the upgrade step. `ctx.connections.all()` returns `ConnectionInfo<Meta>[]`, where `Meta` is the type your upgrade step returns, so you can read a field without a type cast.
::
::field{name="tags" type="readonly TagRef[]"}
The tags on this connection right now, as `TagRef` values. The array is empty when your server declares no tag groups. See [Tags](/server/capabilities/tags).
::
::field{name="channels" type="readonly string[]"}
The names of the channels this connection is subscribed to right now.
::
::field{name="latency" type="number | null"}
Round-trip latency in milliseconds. A round trip is the time a ping takes to reach the client and come back. The value is the average of the most recent round trips. It is `null` until it has been measured. The [`keepalive()`](/server/capabilities/keepalive) capability measures it.
::
::field{name="quality" type="'excellent' | 'good' | 'degraded' | 'poor' | null"}
A health label based on the average of the recent latency values. When a ping gets no answer before the next ping is sent, the label becomes `'poor'`. It is `null` when hibernation is enabled, or before the first latency has been measured.
::
::field{name="bufferedAmount" type="number"}
The number of bytes waiting to be sent to this connection. A high value means the client receives data more slowly than the server sends it.
::
::field{name="lastSeen" type="number | null | undefined"}
The last-seen time of this connection's user, as a timestamp in milliseconds. This field exists only when the [`lastSeen()`](/server/capabilities/last-seen) capability is listed. Without that capability, the object does not have this field at all. `null` means the capability is listed but no last-seen time has been saved for this user yet.
::
::field{name="ref()" type="() => ConnectionRef"}
Returns a `ConnectionRef` for this connection. Pass it to any API that addresses one socket.
::
::

This example reads the fields of a snapshot:

```typescript [server/huddle.ts]
base.on('inspect-peers', {
  input: v.object({}),
  run(ctx) {
    const conns = ctx.connections.all()
    const first = conns[0]
    if (first) {
      ctx.log.info('peer snapshot', {
        id: first.id,
        userId: first.userId,
        channels: first.channels.length,
        tags: first.tags.length,
        latency: first.latency,
        quality: first.quality,
      })
    }
  },
})
```

::note
`ctx.connections.all()`, channel `members()`, and tag `connections()` all return `ConnectionInfo<Meta>`, where `Meta` is the type your upgrade step returns. So `p.meta.name` has the same type as your own `ctx.meta.name`, and you need no type cast.
::

## `ConnectionRef`

A `ConnectionRef` is an address for one connection. You do not create it yourself from its fields. You get one from:

- **`ctx.connection`**: the ref of the current connection.
- **`someConnectionInfo.ref()`**: the ref of any snapshot from `ctx.connections.all()`, channel `members()`, or tag `connections()`.

A ref is a plain data object, and it has no methods. It holds the connection's `id`, its `userId`, and the server instance that owns the connection. Keep it and pass it to any API that addresses one socket, such as `ctx.connections.get(ref)` or `channelHandle.subscribe(ref)`.

```typescript [server/huddle.ts]
base.on('join-general', {
  input: v.object({}),
  async run(ctx) {
    // ctx.connection is this connection's ref.
    await ctx.channels
      .get('rooms', 'room:general')
      .subscribe(ctx.connection)
  },
})
```

## Addressing one socket with `ctx.connections.get(ref)`

`ctx.connections.get(ref)` returns a handle to one specific connection. A handle is an object you use to act on something. Its `send(event, payload)` sends to **only** that socket. It returns `false` when the connection is no longer live on this instance.

```typescript [server/huddle.ts]
base.on('notify-connection', {
  input: v.object({ toId: v.string(), text: v.string() }),
  run(ctx, input) {
    // Find the target snapshot, then address it by ref.
    const target = ctx.connections
      .all()
      .find((c) => c.id === input.toId)
    if (!target) return

    const delivered = ctx.connections
      .get(target.ref())
      .send('notification', { title: 'Message', body: input.text })
    ctx.send('notification', {
      title: 'Delivery',
      body: String(delivered),
    })
  },
})
```

The same handle has `close(code?, reason?)`. It closes **only the connection that the ref points to**. The user's other connections stay open. It does nothing when that connection is no longer live on this server instance. A ref that belongs to another server instance makes `send` and `close` throw a `CrossInstanceRef` error, because only the instance that owns a connection can address it.

```typescript [server/huddle.ts]
import { CloseCodes } from '@livething/core'

const target = ctx.connections.all().find((c) => c.id === input.toId)
if (target) {
  ctx.connections
    .get(target.ref())
    .close(CloseCodes.AUTH_EXPIRED, 'revoked')
}
```

Use `CloseCodes` from `@livething/core` instead of raw numbers. LiveThing checks the close code in the same way as for `ctx.close(...)`. If the code is not valid, it logs the mistake and sends `1011` instead. See [Close Codes](/core/close-codes).

### One connection vs broadcast

Each of these calls reaches a different set of connections:

| You want to…                   | Use                                              |
| ------------------------------ | ------------------------------------------------ |
| Send to the calling connection | `ctx.send(event, payload)`                       |
| Send to one other connection   | `ctx.connections.get(ref).send(event, payload)`  |
| Close one specific connection  | `ctx.connections.get(ref).close(code?, reason?)` |
| Send to every other connection | `ctx.broadcast(event, payload, options?)`        |

`ctx.broadcast` skips the calling connection unless you pass `{ includeSelf: true }`.

To send to a **group** of connections, use tags or channels. `ctx.tags.<kind>(group).ref(key).broadcast(...)` sends to every connection that has a tag, and a channel handle's `broadcast(...)` sends to that channel's members. See [Tags](/server/capabilities/tags) and [Channels](/server/channels/overview).

### Asking one connection a question

When the `serverRequests()` capability is listed, the handle from `ctx.connections.get(ref)` also has `request(...)`. It sends one of your declared server-to-client requests to that one connection and waits for its typed answer.

```typescript [server/huddle.ts]
base.on('delete-message', {
  input: v.object({ messageId: v.string(), toId: v.string() }),
  async run(ctx, input) {
    const target = ctx.connections
      .all()
      .find((c) => c.id === input.toId)
    if (!target) return

    const { response } = await ctx.connections
      .get(target.ref())
      .request(
        'confirm-delete',
        { preview: input.messageId },
        { timeout: 5_000 },
      )
    ctx.send('notification', {
      title: 'Confirmed',
      body: String(response.confirmed),
    })
  },
})
```

Without `serverRequests()`, the handle has only `send` and `close`. The type has no `request` method, so TypeScript reports an error if you call it. The [serverRequests](/server/capabilities/server-requests) page explains the full request and response model.

## In scheduled tasks

A scheduled task does not belong to one socket, so its `ctx` has no `ctx.send`. It still has `ctx.connections.get(ref)`, `ctx.connections.all()`, and `ctx.broadcast`. So a background job can read who is connected and send to one of them by ref. This example uses `quality`, so it needs the `keepalive()` capability:

```typescript [server/jobs.ts]
base.scheduled('flag-slow-connections', {
  run(ctx) {
    for (const conn of ctx.connections.all()) {
      if (conn.quality === 'poor') {
        ctx.connections.get(conn.ref()).send('notification', {
          title: 'Connection',
          body: 'Your connection looks slow.',
        })
      }
    }
  },
})
```

See [Scheduled](/server/capabilities/scheduled) for everything the task context has.
