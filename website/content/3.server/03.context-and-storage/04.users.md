A connection belongs to exactly one **user** when your `upgrade` step assigns it a real `userId` — an anonymous connection belongs to none. This page covers the user model in full: what a user is, the difference between a `ConnectionRef` (one socket) and a `UserRef` (one user, every socket), and `UserHandle` — the surface for acting on all of a user's live connections at once.

## Every connection has a user

Your `upgrade` step returns `{ userId, meta }` to accept a connection. That `userId` is the account this connection belongs to:

```typescript [server.ts]
export default server({
  upgrade: async (req) => {
    const userId = await verifySessionCookie(req)
    // No session → accept as anonymous (omit userId).
    if (!userId) return { meta: {} }
    return {
      userId,
      meta: { username: await lookupUsername(userId) },
    }
  },
})
```

If `upgrade` returns no `userId` (or you skip `upgrade` entirely), the connection is **anonymous** — it has no user identity at all. `ctx.user` is still present, so your handler code never has to check for it before using it — but for an anonymous connection it is honest about having nobody to address:

| Case                           | `ctx.user.id` | `ctx.user.broadcast(...)` reaches           |
| ------------------------------ | ------------- | ------------------------------------------- |
| `upgrade` returned a `userId`  | that `userId` | every live connection sharing that `userId` |
| `upgrade` returned no `userId` | `''` (empty)  | nobody — not even this connection           |

An anonymous connection is reached the same way any single socket is: `ctx.send(...)` for itself, or `ctx.connections.get(ref).send(...)` for another one — addressing by connection, not by user. Anything that needs to survive a reconnect — durable channel membership, a resumable stream — needs a real `userId`. See [the anonymous durable-stream guard](#anonymous-connections-and-durable-streams) below.

## One socket vs one user

Two addresses, two different reaches:

| Address         | Reaches                                                                 | Get one from                                                      |
| --------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `ConnectionRef` | Exactly one socket.                                                     | `ctx.connection`, or any `ConnectionInfo.ref()`.                  |
| `UserRef`       | Every **live** connection that user currently holds (all tabs/devices). | `ctx.user.ref()`, `UserInfo.ref()`, or `ctx.users.get(id).ref()`. |

The same person open in two browser tabs is two `ConnectionRef`s but one `UserRef`. Sending to a `UserRef` fans the event out to both tabs; sending to a `ConnectionRef` reaches only the one tab you addressed.

```typescript [refs.ts]
base.on('whoami', {
  input: v.object({}),
  run(ctx) {
    ctx.send('whoami-result', {
      connectionId: ctx.connection.id, // this one tab
      userId: ctx.user.id, // this account, however many tabs it has open
    })
  },
})
```

## `ctx.user` — the calling connection's user

`ctx.user` is a `UserHandle` — a handle to the account behind the connection you are currently handling. It carries `.id` plus actions that fan out to every live tab that user has open:

::field-group
::field{name="id" type="string"}
The user id. Same value as `ctx.connection.userId` — `''` (empty) for an anonymous connection.
::
::field{name="ref()" type="() => UserRef"}
Build a `UserRef` for this user — pass it to anything that addresses the whole user, such as `kick`.
::
::field{name="broadcast(event, payload)" type="(event, payload) => number"}
Broadcast an event to every live connection this user holds. Returns the number of sockets it reached.
::
::field{name="request(event, payload, opts?)" type="(event, payload, opts?) => Promise<{ response, from }>"}
Ask the user a question and await the first valid answer from any of their live connections. Present only when the contract declares `serverRequests({...})`.
::
::field{name="setMeta(patch)" type="(patch: Partial<Meta>) => void"}
Merge `patch` into **every** live connection's `meta` — the same patch fans out to all of the user's tabs/devices.
::
::field{name="connections()" type="() => ConnectionInfo<Meta>[]"}
A snapshot of this user's live connections.
::
::field{name="close(code?, reason?)" type="(code?, reason?) => void"}
Close every live connection this user holds.
::
::field{name="info()" type="() => UserInfo<Meta> | null"}
A snapshot of this user, or `null` when the user has no live connections right now.
::
::

```typescript [fan-out.ts]
base.on('rename', {
  input: v.object({ displayName: v.string() }),
  run(ctx, input) {
    // Every tab this user has open sees the new name and the toast.
    ctx.user.setMeta({ displayName: input.displayName })
    const delivered = ctx.user.broadcast('renamed', {
      displayName: input.displayName,
    })
    ctx.send('rename-ok', { tabsNotified: delivered })
  },
})
```

## `ctx.users` — reaching any user by id

`ctx.users` is a `UsersManager`. Its `.get(id)` returns a `UserHandle` for any user id, usable even when that user has no live connections right now (its `broadcast` simply reaches nobody and returns `0`). `ctx.users.get('')` also reaches nobody — `''` is never a real user id, so it can never match a live connection.

```typescript [nudge-user.ts]
base.on('nudge', {
  input: v.object({ targetUserId: v.string() }),
  run(ctx, input) {
    const delivered = ctx.users
      .get(input.targetUserId)
      .broadcast('nudged', {
        from: ctx.user.id,
      })
    ctx.send('nudge-result', { delivered })
  },
})
```

## `UserInfo` — a read-only snapshot

`ctx.user.info()` (or `ctx.users.get(id).info()`) returns a `UserInfo`, or `null` if the user has no live connections. Unlike `ConnectionInfo`, there is no flat `.meta` on `UserInfo` — metadata lives per connection, since the same user can have different meta on different sockets (a different device, a different session).

::field-group
::field{name="id" type="string"}
The user id.
::
::field{name="online" type="boolean"}
Whether this user has at least one live connection right now.
::
::field{name="connections()" type="() => ConnectionInfo<Meta>[]"}
Snapshot of this user's live connections.
::
::field{name="channels" type="readonly string[]"}
Union of channel names across this user's live connections.
::
::field{name="tags" type="readonly TagRef[]"}
Union of tag refs across this user's live connections.
::
::field{name="lastSeen" type="number | null | undefined"}
This user's last-seen timestamp (ms). Present only when the [`lastSeen()`](/server/capabilities/last-seen) capability is listed.
::
::field{name="ref()" type="() => UserRef"}
Build a `UserRef` for this user.
::
::

```typescript [presence-check.ts]
base.on('is-online', {
  input: v.object({ userId: v.string() }),
  run(ctx, input) {
    const info = ctx.users.get(input.userId).info()
    ctx.send('is-online-result', {
      online: info?.online ?? false,
      tabCount: info?.connections().length ?? 0,
    })
  },
})
```

## Capping connections per user

`server({ users: { maxConnections, onExceed } })` caps how many live connections one user may hold at once:

```typescript [server.ts]
export default server({
  upgrade: async (req) => ({
    userId: await verifySessionCookie(req),
    meta: {},
  }),
  users: { maxConnections: 3, onExceed: 'replace' },
})
```

| `onExceed`  | What happens to the connection **over** the cap                                                                            |
| ----------- | -------------------------------------------------------------------------------------------------------------------------- |
| `'replace'` | The user's **oldest** connection(s) are evicted (closed with `CloseCodes.DUPLICATE`, `4003`) to make room for the new one. |
| `'reject'`  | The **new** connection is refused — closed with `CloseCodes.CAPACITY` (`4010`) before `onConnect` runs.                    |

Omit `users.maxConnections` entirely for unlimited connections per user (today's default). Anonymous connections have no `userId`, so they are **never** capped by this setting — the cap only ever competes connections against each other when they share a real `userId`.

`maxConnections`, when given, must be a positive whole number. `0`, a negative number, and a fraction like `1.5` all throw at `server(...)` — the check runs at startup, not on the first connection.

## Anonymous connections and durable streams

A durable, resumable, or recorded stream keys its stored state by the connection's real user id, so a later reconnect can find and resume it. An anonymous connection has no user id to key that storage by. This is a storage detail only — it does not make an anonymous connection reachable through `ctx.user` or `ctx.users` — and starting one of these streams on an anonymous connection is rejected with `DurableStreamRequiresUser` from `@livething/core`:

```typescript [durable-guard.ts]
import { DurableStreamRequiresUser } from '@livething/core'

try {
  await socket.stream('start-tokens', { prompt })
} catch (err) {
  if (DurableStreamRequiresUser.matches(err)) {
    // Sign the connection in (assign a userId in upgrade) before retrying
    // with a resumable/recorded stream, or fall back to a plain stream.
  }
}
```

Give the connection a `userId` in `upgrade`, or use a plain (non-durable) stream instead. See [Durable, resumable streams](/server/streams/durable-resumable) and the [built-in error catalog](/core/builtin-errors) for the rest of the reserved errors.
