WSKit promises you pay only for the capabilities you list. This page is the mechanism behind that promise. The short version: the engine's frame dispatcher does not import any feature directly — it reaches each one through an optional **slot**, and a slot is filled only when its capability is listed.

## The dispatcher knows nothing about features

When a frame arrives, one dispatcher routes it. That dispatcher is built to know nothing about features: it never imports the stream runtime or the request runtime. (It does pull in one lightweight channel helper — the membership check — but the channel **runtime** itself, the subscribe/kick/leave protocol and broadcast routing, is slot-loaded like the rest.) Instead the engine carries a set of optional slots — one per feature — and the dispatcher reads the slot and calls it if it's there.

So the stream path is really "is there a stream trigger in the slot? if yes, call it." If you never listed `stream()`, the slot is empty, the dispatcher skips it, and **the stream runtime was never imported** — there is no code path that reaches it, so the bundler drops it.

Each slot maps to one capability:

| Capability                               | Fills the slot for                                                  |
| ---------------------------------------- | ------------------------------------------------------------------- |
| `stream()`                               | starting and nudging plain streams                                  |
| `resumableStream()` / `recordedStream()` | the durable-stream service                                          |
| `clientRequests()`                       | dispatching `request` handlers                                      |
| `channels()`                             | the subscribe / leave / kick runtime and the `ctx.channel` surface  |
| `intercepts()`                           | the intercept pipeline and `ctx.matches` / `ctx.unsafeCast`         |
| `scheduled()`                            | the task scheduler behind `ctx.schedule`                            |
| `tags()`                                 | the `ctx.tags` group handles                                        |
| `inbox()`                                | the per-member delivery fan-out, reconnect drain, and leave cleanup |
| `lastSeen()`                             | the `ctx.lastSeen` accessor's storage                               |

`inbox()` (and the related `readReceipts()`) also graft an extra member onto every channel handle `ctx.channel` and `ctx.channels.get(...)` produce — `handle.inbox()` and `handle.readReceipts()` — so any handle can reach them, not just the scope that declared them. It's the same rule either way: list the capability and the surface exists and ships; leave it out and it doesn't.

## Listing is what loads the code

The slots get filled during the boot **install** step — each capability you listed registers its runtime and sets its own slot. A capability you didn't list never runs that step, so nothing imports its runtime.

This is why the rule is "listing a capability pulls its code in." It isn't a build flag or a manual import you manage — the act of putting `channels()` in your `capabilities` list is the single reference that makes the channel runtime reachable. Take it out and the same code becomes unreachable and tree-shakes away.

```typescript [minimal.ts]
import { emits, server, t } from '@wskit/server'

// No channels(), no clientRequests(), no streams() — none of those runtimes
// are reachable from this engine, so none of them ship.
const base = server({
  capabilities: [emits({ tick: t<{ n: number }>() })],
})

const handleStart = base.on('start', {
  run(ctx) {
    ctx.send('tick', { n: 1 })
  },
})

export const definition = base.assemble({ handlers: [handleStart] })
```

Add `channels()` to that list and the channel runtime, its frame handlers, and the `ctx.channel` surface all become reachable and ship. Nothing else changes in your code — the list is the switch.

## The same idea, both sides of the wire

This is the server half of WSKit's opt-in design. The client works the same way: a primitive you don't pass to `client()` simply doesn't exist on the socket, and its code never loads — which is why the minimal client is a few kilobytes.

On the server it matters most for edge runtimes like Cloudflare Workers, where a smaller bundle means a faster cold start.
