Some engines are **host-owned**: `dedup`, `sequence`, `keepalive`, `persistence`, `rateLimit`, and the whole `replay` family — built-in `replay.history()` / `replay.snapshot()` **and** `replay.custom()`. They are global to the whole server, so a plugin can never list one in its scoped [`define`](/server/plugins/authoring) — doing so is a compile error. A plugin that _needs_ one declares a prerequisite instead, and the host must satisfy it.

```typescript [host-only.ts]
const h = define({
  scoped: true,
  capabilities: [
    resumableStream(), // OK — a plugin can own its own durable streams
    // persistence(),    // compile error: host-owned, a plugin can't list it
  ],
})
```

## Auto-derived requirements

The durable streams above _need_ persistence to work, but the plugin does not — and cannot — list it. That requirement is **auto-derived**: WSKit reads it off the plugin's own capabilities and passes it up to the host as a dependency. The host must list `persistence()`, or its `assemble` fails with a clear error. (This is the same requirement mechanism used in [Capabilities](/server/define/capabilities), applied across the plugin boundary.)

Auto-derivation isn't limited to a stream sitting at the top of the plugin, and it isn't limited to streams either:

```typescript [auto-derived-more.ts]
// A durable stream nested inside a plugin's own channel still needs
// persistence — the host must add it even though the stream lives inside a channel.
const rooms = h.channel('rooms', {})
const paginate = rooms.recordedStream('paginate', { async *run() {} })

// A persistent tag group needs persistence too — nothing to do with streams at all.
const withPersistentTags = define({
  scoped: true,
  capabilities: [
    tags((_ephemeral, persistent) => [persistent('favorite', t<string>())]),
  ],
})
```

Both fail the host's `assemble()` with the same "does not list" error until the host adds `persistence()` — the plugin never lists it itself.

::note
"Plugin-safe" is exactly "every capability except the host-owned engines listed above." Behavior capabilities a plugin _can_ own itself — `requests`, `channels`, the stream kinds, `emits`, `errors`, `tags`, `intercepts` — are all fine in a scoped list. Note `base.replay` is not among them: even `replay.custom()` is host-owned, so a plugin cannot register its own custom replay strategy.
::

## Stating a prerequisite explicitly

Auto-derivation covers anything the plugin's own capabilities imply. When a plugin's _code_ needs a **host-owned** capability that nothing in its config implies — it reads `ctx.latency`, which only `keepalive()` provides, say — state it directly with `dependsOn`, passing the host capability factory. (Only the host-owned engines are valid `dependsOn` targets; behavior capabilities like `requests()` a plugin simply lists itself, so they are never dependencies.)

```typescript [depends-on.ts]
import { persistence } from '@wskit/server/persistence'
import { plugin } from '@wskit/server/plugin'

export const Durable = plugin('acme:durable', {
  handler: h.assemble({ handlers: [] } /* ... */),
  dependsOn: [persistence], // the host must list persistence()
})
```

A missing prerequisite is a build error that names what to add, the same way a [capability requirement](/server/define/capabilities) does for a top-level server. Only host capability **factories** are accepted here — passing a plugin factory is a compile error.

::caution
Pass the capability **factory** itself, never a called capability: `dependsOn: [persistence]`, not `dependsOn: [persistence()]`. The check matches a `dependsOn` entry to a listed capability by reading an identity token off the factory — it never calls it. That is also why an arg-requiring factory like `keepalive` is a safe `dependsOn` target even though `keepalive({ pingIntervalMs, idleTimeoutMs })` needs a config object to run: the host is the one who calls it.
::
