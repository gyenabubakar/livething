On a bad network, a client may send the same message again because it did not get an answer in time. The same message can then arrive at the server twice. Without protection, the handler runs twice. For example, a payment is charged twice, or a chat post appears twice. **dedup** (short for deduplication) stops this. It gives every outgoing message an ID. It also remembers the most recent incoming IDs on each connection and drops any message whose ID it has already seen.

## How it works

dedup works in both directions:

- **Outgoing:** every application message from the server to a client gets a unique ID in `metadata.delivery.id`. A client can use this ID to drop copies that arrive twice, for example after a reconnect or a [replay](/server/capabilities/replay). Protocol frames do not get an ID, because they do not need one.
- **Incoming:** when a message arrives with a `metadata.delivery.id` that the connection has seen recently, dedup drops it before any handler runs.

Each connection keeps a short list of recent IDs. The list has a fixed size, called the `cap`. When the list is full, the oldest ID is removed to make room for the new one.

A message with **no delivery ID** is never treated as a duplicate. It always reaches its handler. So incoming deduplication is something the client chooses per message. The client puts an ID in `metadata.delivery.id` and sends the same ID again with each retry of that message. The [wire format](/reference/wire-format) page shows where this field sits in a frame.

dedup adds nothing to the client contract. The delivery ID is metadata, not part of your typed payloads, so `InferClient` does not change.

## Enable it

Import `dedup` from `@livething/server/dedup` and list it in `capabilities`. The options object is optional.

::code-group

```typescript [server/huddle-definition.ts]
import { server } from '@livething/server'
import { dedup } from '@livething/server/dedup'

const base = server({
  capabilities: [dedup()],
})
```

```typescript [server/huddle-definition.ts (custom list size)]
import { server } from '@livething/server'
import { dedup } from '@livething/server/dedup'

const base = server({
  capabilities: [dedup({ cap: 512 })],
})
```

::

## Configuration

| Option | Type     | Required | Default | What it is                                                       |
| ------ | -------- | -------- | ------- | ---------------------------------------------------------------- |
| `cap`  | `number` | no       | `256`   | How many recent incoming delivery IDs to remember per connection |

If you give `cap`, it must be a positive whole number. An invalid value throws a `LiveThingConfigError` at once, when you call `dedup()`, not later in `assemble()`. A larger list catches retries that are spread over a longer time, but it uses a little more memory for each connection. The default of `256` covers a few seconds of fast retries on a bad network.

## Host-only :badge[host-only]

dedup is a **host-only** capability. Only your app's own `server(...)` can list it. A plugin's scoped server definition (`server({ scope: 'plugin' })`) cannot list it, and trying to do so is a type error. If a plugin needs dedup, it [declares a dependency on the host](/server/plugins/depends-on) instead.

## Use with sequence and replay

dedup is often listed together with [sequence](/server/capabilities/sequence). sequence gives every outgoing message a number, so a client that reconnects can see which messages it missed. The two cover different problems: dedup drops messages that arrived twice, and sequence shows which messages never arrived.

[Replay](/server/capabilities/replay) needs `dedup()` and `sequence({ persist: true })`. Replay stores each message with its delivery ID. When a message is sent again, the client can use that ID to drop the copy it already has. A channel's `inbox()` needs `dedup()` for the same reason. These three are usually listed together:

```typescript [server/huddle-definition.ts]
import { server } from '@livething/server'
import { dedup } from '@livething/server/dedup'
import { replay } from '@livething/server/replay'
import { sequence } from '@livething/server/sequence'

const base = server({
  capabilities: [
    dedup(),
    sequence({ persist: true }),
    replay.history(), // replay needs both of the above
  ],
})
```
