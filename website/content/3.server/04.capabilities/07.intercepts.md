The `intercepts()` capability turns on the **inbound intercept hook**. This is a function that runs for every incoming frame (one message from a client), before validation and before your handler. Listing the capability adds `base.intercept(...)` and the channel-scoped `channel.intercept(...)`. Import it from `@livething/server/intercepts`:

```typescript [server/huddle.ts]
import { server } from '@livething/server'
import { intercepts } from '@livething/server/intercepts'

const base = server({
  capabilities: [intercepts()],
})
```

Without `intercepts()`, `base.intercept` and `channel.intercept` are not on the builder types, so calling them is a compile error.

## What it grants

| Surface                                | What it is                                                                                          |
| -------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `base.intercept((ctx, frame) => …)`    | The inbound hook. It runs before validation and the handler. It can read, rewrite, or drop a frame. |
| `channel.intercept((ctx, frame) => …)` | The same hook, but it runs only for frames sent to one channel.                                     |

This page covers how to **turn on** the capability. The [Intercept](/server/lifecycle-and-intercept/intercept) page explains how the hook works: the `frame` shape, how to rewrite or drop a frame, the order of the server and channel hooks, `frame.owner`, and how to handle nudges.

::note
The outgoing hook `base.onOutgoing(...)` does _not_ need `intercepts()`. It is always available. Only the inbound `intercept` needs this capability.
::

::note
The frame guards `ctx.matches` and `ctx.unsafeCast` (helpers that give a frame's payload a typed shape) do **not** need `intercepts()`. They are core `ctx` methods, available on every connection. Their full API is on the [Core Context](/server/context-and-storage/ctx#frame-guards) page. An intercept is the most common place to use them, because its `frame.payload` has the type `unknown`.
::

## The contract slice

`intercepts()` adds **nothing** to the client contract (the typed list of events the client can send and receive). Intercepts run only on the server, so `InferClient` stays the same.
