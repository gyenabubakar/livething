A **channel** is a server-managed room. Connections subscribe to it, and a channel carries its own scoped events, its own gate, and its own lifecycle hooks. A chat lobby, a game table, a per-document session — each is a channel.

The `channels()` capability enables `base.channel(name, config)` and the `ctx.channels` accessor. Import it from `@wskit/server/channels`:

```typescript [server.ts]
import { channels } from '@wskit/server/channels'
```

## Defining a channel

List `channels()`, then declare a channel with `base.channel(name, config)`. A channel object exposes handler methods you build on. Here is a static `lobby` with an outgoing event, an auth gate, and a message handler:

```typescript [server.ts]
import { define, emits, t } from '@wskit/server'
import { channels } from '@wskit/server/channels'
import * as v from 'valibot'

const base = define({
  capabilities: [channels()],
})

const lobby = base.channel('lobby', {
  capabilities: [emits({ message: t<{ text: string; from: string }>() })],
  check(ctx) {
    if (ctx.meta.username === 'blocked-user') {
      throw new Error('blocked-user may not subscribe')
    }
  },
})

export const handleSay = lobby.on('say', {
  input: v.object({ text: v.string() }),
  run(ctx, input) {
    ctx.channel.broadcast('message', {
      text: input.text,
      from: ctx.meta.username,
    })
  },
})
```

::note
`lobby.on(...)` creates a handler value. Include `handleSay` in `base.assemble({ handlers: [...] })` for it to run and enter `InferClient`; passing `lobby` itself includes its config and lifecycle hooks, but no routed handlers.
::

Inside a channel handler, `ctx.channel.broadcast(...)` pushes to every other member — the caller is excluded by default; pass `{ includeSelf: true }` to include the sender — and `ctx.channel.send(...)` pushes to the one connection. For the deep authoring detail, see [Defining Channels](/server/channels/defining).

## The contract slice

`channels()` fills the client contract's `channels` key. Each channel carries its own nested mini-contract — the same `incoming` and `outgoing` keys again, scoped to that room:

```typescript [chat-socket.ts]
interface ChatSocket {
  channels: {
    lobby: {
      incoming: {
        message: { text: string; from: string }
      }
      outgoing: {
        say: { text: string }
      }
    }
  }
}
```

The swap works the same way as the top-level contract: the channel's `emits(...)` capability becomes the client's `incoming`, and the channel's handlers become the client's `outgoing`.

## Config at a glance

`base.channel(name, config)` accepts these config fields:

| Field               | What it does                                                                         |
| ------------------- | ------------------------------------------------------------------------------------ |
| `subscribe`         | Input schema for the subscribe payload.                                              |
| `capabilities`      | `emits(...)`, `serverRequests(...)`, and channel-only capabilities for this channel. |
| `check(ctx, input)` | Auth gate. Throw to reject the subscribe.                                            |
| `commit(ctx)`       | Runs after a subscribe is accepted.                                                  |
| `revalidate(ctx)`   | Re-checks an existing membership.                                                    |
| `membership`        | `'persistent'` (default) or `'ephemeral'` — whether membership survives a reconnect. |
| `replay`            | `true` or `false` — re-send missed messages on reconnect.                            |
| `capabilities`      | This channel's own channel-only capabilities — `inbox()` and `readReceipts()`.       |
| `rateLimit`         | Throttle how fast a member can send to this channel.                                 |

On the returned channel object you bind handlers and lifecycle: `.on`, `.request`, `.stream` / `.resumableStream` / `.recordedStream`, `.subscribe`, `.unsubscribe`, `.sessionEnd`, `.intercept`, and `.replay`.

For the auth gate in depth, see [Auth Gate](/server/channels/auth-gate). For scoped streams and requests, see [Scoped Streams & Requests](/server/channels/scoped-streams-requests).

## Dynamic families

A channel can be a **family** — a pattern that spins up one channel per ID. Declare it with a `[family, template]` pair, then make a concrete reference with `.at(...)`:

```typescript [family.ts]
const room = base.channel(['room', 'room:{id}'], {
  capabilities: [emits({ message: t<{ text: string; from: string }>() })],
})

const handleSend = room.on('send', {
  input: v.object({ text: v.string() }),
  run(ctx, input) {
    ctx.channel.broadcast('message', {
      text: input.text,
      from: ctx.meta.username,
    })
  },
})
```

To address one instance, build a reference and pass it to `ctx.channels.get(...)`:

```typescript [target.ts]
const ref = room.at({ id: 'abc' }) // resolves room:abc
ctx.channels.get(ref).broadcast('message', { text: 'hi', from: 'system' })
```

See [Dynamic Families](/server/channels/dynamic-families) for the full family surface.

## Acting on a channel from the server

`ctx.channels.get(name)` — or `.get(ref)` for a family instance — returns a **channel handle**: the same room a member acts on, but reachable from any handler, lifecycle hook, or scheduled task. Passing a name you never declared with `base.channel()` throws `ChannelNotFound`. The handle exposes:

| Method                                | What it does                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `send(event, payload, options?)`      | Send a channel event to the current connection by default, or to `{ to }` — a `ConnectionRef`, `UserRef`, `TagRef`, or `TagGroupHandle`. Returns the delivered socket count.                                                                                                                                                                                                      |
| `broadcast(event, payload, options?)` | Push to every member. Excludes the caller by default; pass `{ includeSelf: true }` to include it.                                                                                                                                                                                                                                                                                 |
| `members()`                           | List the connections currently subscribed (`ConnectionInfo[]`).                                                                                                                                                                                                                                                                                                                   |
| `subscribe(ref, payload?)`            | Subscribe a connection from server code — runs the same `check` → `commit` → `onSubscribe` flow, is a no-op if it is already a member, and rejects if the gate throws.                                                                                                                                                                                                            |
| `kick(target, opts)`                  | Remove a user's subscribed connections. `target` is a `UserRef` (that user's member sockets), a `TagRef` (every socket under a tag key), or a tag group handle (every socket in the group). Each removed socket receives `__kicked__ { reason }`, then `__memberLeave__` / `__memberOffline__` goes to the rest. Pass `{ revoke: true }` to also drop the durable membership row. |

```typescript [admin.ts]
const handleModerate = base.on('kick-user', {
  input: v.object({ targetUserId: v.string() }),
  async run(ctx, input) {
    const lobby = ctx.channels.get('lobby')
    const target = ctx.users.get(input.targetUserId).ref()
    await lobby.kick(target, { reason: 'removed by a moderator', revoke: true })
  },
})
```

`kick(target, { revoke: false })` (the default) drops only the live sockets, auto-rejoining the user later; `kick(target, { revoke: true })` additionally deletes the durable membership so the user does not rejoin on their next connection. The full `kick` target rules and the `__kicked__` wire frame are covered in [Membership & Presence](/server/channels/membership-and-presence).

## Capabilities a channel may need

A channel keeps its membership across a reconnect by default, at no capability cost. A channel only pulls in extra capabilities when you use a feature beyond that, and assembly checks each one — a missing prerequisite is a build error that names exactly what to add:

| Feature                                                            | Needs                                                                                   |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| Channel streams (`.stream`, `.resumableStream`, `.recordedStream`) | The matching stream capability — `stream()`, `resumableStream()`, or `recordedStream()` |
| Channel `capabilities: [serverRequests(...)]`                      | root `serverRequests()`                                                                 |
| A custom `.replay`                                                 | `replay.custom()`                                                                       |
| `replay: true \| false`                                            | A built-in replay capability                                                            |
| `inbox()` in the channel's own `capabilities`                      | `channels()`, `sequence({ persist: true })`, and `dedup()` on the host                  |
| `readReceipts()` in the channel's own `capabilities`               | `inbox()` on the same channel                                                           |

A channels-only app pays for none of these — you add a capability only when a channel actually uses that feature. See [inbox](/server/capabilities/inbox) and [read receipts](/server/capabilities/read-receipts).
