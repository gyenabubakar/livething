`lastSeen()` keeps one durable row per user — the last time it was seen — and exposes it as `ctx.lastSeen`. By default it stamps on connect and disconnect only; switch to `track: 'activity'` and it also stamps on each real inbound message — protocol frames and app events, but not the transport keepalive pings — throttled per user so a chatty connection doesn't write on every frame.

```typescript [last-seen-server.ts]
import { define, t } from '@wskit/server'
import { lastSeen } from '@wskit/server/last-seen'

const base = define({
  upgrade: (request) => requireUsername(request),
  capabilities: [lastSeen()],
})

export const handleWhenSeen = base.on('when-seen', {
  input: v.object({ userId: v.string() }),
  run(ctx, input) {
    const at = ctx.lastSeen.at(input.userId)
    ctx.send('when-seen-result', {
      at,
      online: ctx.lastSeen.online(input.userId),
    })
  },
})
```

`lastSeen()` keeps its table in the server's own SQL storage, which every WSKit adapter provides automatically — there is nothing extra to list.

## How to enable

List `lastSeen()` once. With no options it stamps on connect and disconnect only:

```typescript [last-seen-default.ts]
const base = define({
  capabilities: [lastSeen()],
})
```

Pass `{ track: 'activity' }` to also stamp on inbound messages:

```typescript [last-seen-activity.ts]
const base = define({
  capabilities: [lastSeen({ track: 'activity', throttleMs: 30_000 })],
})
```

## Configuration

Every field on `LastSeenOptions` is optional.

| Option       | Type                         | Default        | What it does                                                                                                                                                                                                                           |
| ------------ | ---------------------------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `track`      | `'connection' \| 'activity'` | `'connection'` | `'connection'` stamps only on connect and disconnect. `'activity'` also stamps on each real inbound message — protocol frames and app events, but not transport keepalive pings — throttled per user to at most once per `throttleMs`. |
| `throttleMs` | `number`                     | `60_000`       | In `'activity'` mode, the minimum gap between two activity stamps for the same user. Ignored in `'connection'` mode.                                                                                                                   |

The stamp is cumulative — an out-of-order write (e.g. a delayed disconnect racing a fresh connect) never rolls a user's mark backwards; the stored value is always the highest timestamp seen for it.

## `ctx.lastSeen`

Listing `lastSeen()` adds a `lastSeen` member to every handler `ctx`:

::field-group
::field{name="at(userId)" type="(userId: string) => number | null"}
The last-seen timestamp (ms) for one user, or `null` if it has never been stamped.
::
::field{name="atMany(userIds)" type="(userIds: string[]) => Map<string, number>"}
Last-seen timestamps for many users in one read. Users never stamped are simply absent from the map.
::
::field{name="online(userId)" type="(userId: string) => boolean"}
Whether that user has a live connection on this instance right now — an in-memory check, not a storage read.
::
::

```typescript [check-many.ts]
export const handleRoster = base.on('roster', {
  input: v.object({ userIds: v.array(v.string()) }),
  run(ctx, input) {
    const seenAt = ctx.lastSeen.atMany(input.userIds)
    const rows = input.userIds.map((userId) => ({
      userId,
      online: ctx.lastSeen.online(userId),
      lastSeenAt: seenAt.get(userId) ?? null,
    }))
    ctx.send('roster-result', { rows })
  },
})
```

## It augments `ConnectionInfo` everywhere

With `lastSeen()` listed, every `ConnectionInfo` snapshot — from `ctx.connections.all()`, a channel handle's `members()`, and tag `connections()` — gains a `lastSeen` field alongside `id`, `userId`, and the rest. Without the capability, the field is simply absent from the returned objects. See [Connections](/server/context-and-storage/connections#connectioninfo) for the rest of the snapshot shape.

```typescript [roster-with-last-seen.ts]
const room = ctx.channels.get('lobby')
const roster = room.members().map((member) => ({
  userId: member.userId,
  lastSeen: member.lastSeen ?? null,
}))
```

## Filling `inbox().backlog()`'s `lastSeenAt`

When `lastSeen()` is listed alongside [`inbox()`](/server/capabilities/inbox), `handle.inbox()?.backlog()` fills each entry's `lastSeenAt` from this same table — so an observability read of who is behind on a channel also shows when that member was last seen. Without `lastSeen()`, `lastSeenAt` is absent from every entry. See [Inbox and read receipts](/server/inbox/overview) for the backlog query in full.

::note
`lastSeen()` and `inbox()` don't depend on each other — list either alone and it works. Listing both just lets the backlog read borrow the last-seen table instead of you joining the two yourself.
::
