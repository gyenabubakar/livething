`emits` declares the server→client, fire-and-forget events your server can push. Each event becomes something the client receives, and on the server it unlocks the three ways to push: `ctx.send` to the current connection, `ctx.broadcast` to many, and `ctx.connections.get(ref).send` to one specific connection addressed by its `ConnectionRef`.

## Declaring events

Call `emits({...})` from `@wskit/server` and list it in your capabilities. Each key is an event name; each value is a `t<Shape>()` marker that fixes the payload type:

```typescript [chat.ts]
import { define, emits, t } from '@wskit/server'

const base = define({
  env: t<Env>(),
  capabilities: [
    emits({
      message: t<{ text: string; from: string }>(),
      'user-joined': t<{ username: string }>(),
      'who-am-i-result': t<{ connectionId: string }>(),
    }),
  ],
})
```

The marker is **type-only**. Outgoing payloads are produced by your own server code, so WSKit does not validate them on the way out — the type just flows into `ctx.send`, `ctx.broadcast`, and the generated client. There is no schema to write here, only the shape.

## The contract slice

`emits` fills the client's `incoming` key — the events the client receives. This is the perspective flip: what the server _emits_ is what the client takes _in_. The declared events produce this slice of the client contract:

```typescript [chat-socket.ts]
interface ChatSocket {
  incoming: {
    message: { text: string; from: string }
    'user-joined': { username: string }
    'who-am-i-result': { connectionId: string }
  }
}
```

The client then listens with full typing, no hand-written types:

```typescript [app.ts]
socket.on('message', (data) => {
  // data: { text: string; from: string }
})
```

See [The Contract](/learn/the-contract) for the full picture of how the server description mirrors onto the client.

## Pushing events from a handler

With `emits` listed, your handlers get `ctx.send`, `ctx.broadcast`, and `ctx.connections.get(ref).send`, all typed to the events you declared:

- `ctx.send(event, payload)` pushes to the **current** connection.
- `ctx.broadcast(event, payload)` pushes to **every other** connection. The caller is excluded by default — pass `{ includeSelf: true }` to include it.
- `ctx.connections.get(ref).send(event, payload)` pushes to **one specific** connection by its `ConnectionRef`, and returns `false` when that socket is no longer live on this instance.

```typescript [handlers.ts]
const handleWhoAmI = base.on('who-am-i', {
  input: v.object({}),
  run(ctx) {
    ctx.send('who-am-i-result', { connectionId: ctx.connection.id })
  },
})

const handleDoBroadcast = base.on('do-broadcast', {
  input: v.object({ text: v.string() }),
  run(ctx, input) {
    // reaches everyone except the sender
    ctx.broadcast('message', { text: input.text, from: ctx.meta.username })
  },
})
```

To push to one specific socket, get a `ConnectionRef` — from `ctx.connection`, or any connection snapshot's `.ref()` — and hand it to `ctx.connections.get(ref)`:

```typescript [direct.ts]
const handleWhisper = base.on('whisper', {
  input: v.object({ to: v.string(), text: v.string() }),
  run(ctx, input) {
    const target = ctx.connections.all().find((c) => c.userId === input.to)
    if (!target) return
    const delivered = ctx.connections.get(target.ref()).send('message', {
      text: input.text,
      from: ctx.meta.username,
    })
    // delivered is false if that socket is gone on this instance
  },
})
```

All three are typed against the declared events. Calling `ctx.send('not-declared', ...)` is a compile error, and passing a payload that does not match the marker is a compile error too.

## Config field reference

| Field            | Value                          | Notes                                                                                                                                                                                                                                                                                                   |
| ---------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| event name (key) | a string, up to 128 characters | The wire name of the event. Quote it if it is hyphenated, e.g. `'user-joined'`. Cannot start or end with `__` (reserved for WSKit internals) or contain `::` (reserved for `ctx.matches` path keys). Checked when `define(...)` compiles your server, so a bad name fails at startup, not at send time. |
| payload (value)  | `t<Shape>()`                   | A type-only marker. No runtime validation runs on outbound payloads.                                                                                                                                                                                                                                    |

## Edge cases

**Hyphenated names need quotes.** A key with a hyphen or other non-identifier character must be a string literal:

```typescript [server.ts]
emits({
  'delivery-status': t<{ delivered: boolean }>(),
})
```

**Empty payload.** For an event that carries no data, declare it with an empty object marker:

```typescript [server.ts]
emits({
  ping: t<{}>(),
})
```

**Payload must be a plain object.** `ctx.send` and `ctx.broadcast` serialize the payload as JSON and reject anything that is not a plain object at runtime — an array, a string, or a number throws. Declare the marker as an object shape even for a single value:

```typescript [server.ts]
// Wrong: t<string[]>() compiles, but sending it throws at runtime.
emits({
  'bad-example': t<string[]>(),
})

// Right: wrap the value in an object.
emits({
  'user-list': t<{ users: string[] }>(),
})
```

**Reserved names throw at declaration.** A name that starts or ends with `__`, or contains `::`, throws when `define(...)` runs — before any client ever connects.

## Channels declare their own events

Top-level `emits` covers events on the main socket. A channel has its own contract and declares its own events through `capabilities: [emits(...)]`, not through a separate `outgoing` config field. See [Defining channels](/server/channels/defining) for that.
