A **server request** is a question your server asks a client and waits for the client's typed answer. `serverRequests(...)` declares the questions the server may ask.

Import it from `@livething/server/server-requests`:

```typescript [server.ts]
import { serverRequests } from '@livething/server/server-requests'
```

## Declare server-to-client requests

Pass a declaration map to `serverRequests({...})`. Each key is an event the server can ask:

```typescript [server.ts]
import { server, t } from '@livething/server'
import { serverRequests } from '@livething/server/server-requests'
import * as v from 'valibot'

const base = server({
  capabilities: [
    serverRequests({
      'ask-permission': {
        out: t<{ action: string }>(),
        in: v.object({ allowed: v.boolean() }),
      },
      'ping-ack': { out: t<{ note: string }>() },
      volunteer: {
        out: t<{ turn: number }>(),
        in: v.object({ ready: v.boolean() }),
      },
    }),
  ],
})
```

Every declaration is `{ out, in? }`. The `out` type is trusted because it comes from your server. Only the client's answer is validated.

| Declaration                   | Meaning                                                                                                                             |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `{ out: t<T>() }`             | An acknowledgement request. The server sends `T`, the client confirms receipt, and the server call resolves as `Promise<void>`.     |
| `{ out: t<T>(), in: schema }` | A two-way request. The server sends `out`; the client answers with `in`. An invalid answer rejects with `request-invalid-response`. |

::note
`serverRequests()` enables the outbound request runtime with no top-level declarations. Request names must be non-empty and cannot start or end with `__`.
::

### The contract slice

A declaration map fills the client contract's `serverRequests` key:

```typescript [user-socket.ts]
interface UserSocket {
  serverRequests: {
    'ask-permission': {
      payload: { action: string }
      response: { allowed: boolean }
    }
    'ping-ack': {
      payload: { note: string }
      response: void
    }
    volunteer: {
      payload: { turn: number }
      response: { ready: boolean }
    }
  }
}
```

## Ask one connection

Inside a handler, `ctx.request(event, payload)` asks the current connection and awaits its answer:

```typescript [handlers.ts]
const handleTrigger = base.on('trigger', {
  input: v.object({ action: v.string() }),
  async run(ctx, input) {
    const answer = await ctx.request('ask-permission', {
      action: input.action,
    })
    ctx.send('outcome', { allowed: answer.allowed })
  },
})
```

`answer` is typed from the declaration's `in` schema. Pass `{ timeout: 500 }` as the third argument to change the timeout; it is **10 000 ms** by default. A timeout rejects with `timeout`; a disconnected target rejects with `disconnected`; an undeclared event rejects immediately with `request-not-declared`.

To target a different connection, use `ctx.connections.get(ref).request(...)`.

## Ask everyone

`ctx.broadcastRequest(event, payload)` asks the other connections on this instance and resolves with the **first valid answer**. It returns `{ response, from }`:

```typescript [broadcast.ts]
const handleElect = base.on('elect', {
  input: v.object({ turn: v.number() }),
  async run(ctx, input) {
    const { response, from } = await ctx.broadcastRequest(
      'volunteer',
      {
        turn: input.turn,
      },
    )
    ctx.send('outcome', {
      from: from.userId,
      ready: response.ready,
    })
  },
})
```

Pass `{ timeout: 500 }` to set a timeout or `{ includeSelf: true }` to include the calling connection. Silence and invalid answers do not win the race.

You can broadcast to a channel with `ctx.channels.get(ref).broadcastRequest(...)`, a tag group with `ctx.tags.ephemeral(group).broadcastRequest(...)` or `.persistent(group)`, or one tag key with `.ref(key).broadcastRequest(...)`.

## Channel-scoped server requests

Put `serverRequests({...})` in a channel's `capabilities` list. The root still needs bare `serverRequests()` to install the shared outbound runtime:

```typescript [channel.ts]
const lobby = base.channel('lobby', {
  capabilities: [
    serverRequests({
      volunteer: {
        out: t<{ turn: number }>(),
        in: v.object({ ready: v.boolean() }),
      },
    }),
  ],
})
```

Inside that channel's handler, `ctx.channel.request(...)` asks the current member and `ctx.channel.broadcastRequest(...)` asks its members. Each channel keeps its declarations separate, so two channels may both declare `volunteer`.
