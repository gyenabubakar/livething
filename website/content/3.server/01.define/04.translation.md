Translation lets an existing WebSocket client talk to a WSKit server without changing that client first. It is useful when a team moves its server from a service such as Pusher to WSKit, but keeps the already-shipped client while it saves cost or gains control over its server.

Translation belongs to the **server only**. A [WSKit client](/client/overview) already speaks WSKit; when an app connects to a foreign service, that service's client SDK is usually the right tool.

## Add one translator

Import `translator` from `@wskit/server`, create a factory, and set it as `translate` in [`define`](/server/define/overview).

```typescript [server.ts]
import { define, t, translator } from '@wskit/server'

const legacy = translator(() => ({
  inbound(raw) {
    const frame = JSON.parse(raw)
    if (frame.type !== 'message') return null

    return JSON.stringify({ event: frame.name, payload: frame.body })
  },
  outbound(outgoing) {
    const frame = JSON.parse(outgoing)
    return JSON.stringify({
      type: 'message',
      name: frame.event,
      body: frame.payload,
    })
  },
}))

const base = define({
  env: t<Env>(),
  translate: legacy,
})
```

One [server definition](/server/define/overview) has zero or one translator. If an app must serve two foreign protocols, make two server definitions and route clients to the appropriate endpoint. WSKit does not try to guess a protocol from frames, and `translate` never accepts an array.

`translator()` always takes a function. WSKit calls that function once for every connection, so variables inside it belong to that one connection.

```typescript [state.ts]
const counted = translator(() => {
  let count = 0

  return {
    inbound(raw) {
      count += 1
      console.log(`this connection has sent ${count} frames`)
      return raw
    },
  }
})
```

## What each method does

| Method                | Direction                      | Return value                                                      |
| --------------------- | ------------------------------ | ----------------------------------------------------------------- |
| `inbound(raw)`        | Client to server               | A WSKit string, or `null` to keep the original string.            |
| `outbound?(outgoing)` | Server to client               | A foreign-protocol string, or `null` to keep the original string. |
| `hibernation?`        | When the connection hibernates | An object with both `serialize()` and `restore(state)`.           |

The factory, `inbound`, `outbound`, and both hibernation methods are synchronous. They must never return a Promise. `inbound` and `outbound` return a string or `null`; if you build an object, call `JSON.stringify` yourself. When `outbound` is omitted, server frames stay in the normal WSKit wire format.

## Pipeline order

Inbound translation runs first, before [WSKit's pipeline](/server/under-the-hood/pipeline-execution-order) checks for bare `ping` or `pong` strings and before it parses a WSKit JSON frame.

Outbound translation runs last. It sees the final serialized WSKit string, including protocol messages, [errors](/core/error-model), [replay](/server/replay/overview), [stream](/server/streams/overview) frames, and [pongs](/server/lifecycle-and-intercept/hooks).

::note
With Cloudflare [hibernation](/server/define/hibernation), WSKit disables the edge `ping` → `pong` auto-response when `translate` is configured. Heartbeat frames wake the Durable Object and pass through the translator, so map or preserve them when the foreign protocol uses heartbeats.
::

::translation-pipeline
::

This means a translator is a wire-format adapter, not an [`intercept`](/server/lifecycle-and-intercept/intercept) or a [`plugin`](/server/plugins/overview). It receives no [`ctx`](/server/context-and-storage/ctx), [storage](/server/context-and-storage/sql-and-kv), identity, or [`send()`](/server/context-and-storage/ctx#messaging) method, and it cannot register handlers or perform WSKit operations.

## Validate foreign JSON first

Set `input` when the foreign protocol sends JSON. WSKit parses and validates the raw frame before calling `inbound`, then gives `inbound` the schema's typed output, just as it does for [handler input](/server/handlers/overview). The validator must finish synchronously too; an async validator is a translator configuration error.

```typescript [validated.ts]
import { translator } from '@wskit/server'
import * as v from 'valibot'

const legacy = translator(() => ({
  input: v.object({ type: v.literal('message'), body: v.string() }),
  inbound(frame) {
    return JSON.stringify({ event: 'message', payload: { text: frame.body } })
  },
}))
```

If `input` JSON parsing or validation fails, WSKit closes the connection with [`CloseCodes.PROTOCOL_ERROR` (`1002`)](/core/close-codes). A translated endpoint has one declared foreign protocol, so malformed input must not fall through into the regular WSKit message pipeline. A failure inside your own `inbound` function is instead a translator runtime failure.

If the factory, translator methods, state serialization, or state restoration throws, WSKit closes that connection. Runtime failures are logged. Configuration mistakes, such as returning a Promise from a translator callback, are surfaced to the developer. A broken translator never falls back to sending an untranslated frame. During a broadcast, WSKit skips the failed recipient and continues delivering to healthy recipients.

## Hibernation state

With Cloudflare Durable Object [hibernation](/server/define/hibernation), closure variables disappear when the object is evicted. Use `serialize` and `restore` for the small connection-level state that your translator needs after wake.

```typescript [hibernation.ts]
const sequenced = translator(() => {
  let sequence = 0

  return {
    inbound(raw) {
      sequence += 1
      return raw
    },
    hibernation: {
      serialize() {
        return { sequence }
      },
      restore(state) {
        sequence = state?.sequence ?? 0
      },
    },
  }
})
```

`hibernation.serialize()` must return JSON-safe data and should only create a snapshot. It can run after inbound translation and immediately before a server frame is written, so it must not change the translator's state itself. `hibernation.restore()` runs before any frame is handled after a wake. The two methods are required together: saving state without restoring it, or restoring with no saved state, is not useful.

## Why there is no `observeHost()` grant

[`observeHost()`](/server/plugins/observe-host) protects a plugin that can both inspect host traffic and use powerful WSKit APIs such as [`ctx`](/server/context-and-storage/ctx), [storage](/server/context-and-storage/sql-and-kv), or [`send()`](/server/context-and-storage/ctx#messaging). A translator has no such APIs. Its whole WSKit surface is a string in and a string out, so it is configured directly on the host server rather than treated as a privileged plugin.

It is still installed code. Only use a translator package you trust, just as you would any other server dependency.
