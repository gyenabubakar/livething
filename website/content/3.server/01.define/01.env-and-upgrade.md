Two config fields decide how a connection starts: `env` types your platform bindings, and `upgrade` is the gate that runs during the WebSocket handshake. `upgrade` is where you authenticate the request, read your bindings, and decide whether to let the socket in.

## `env` — the platform bindings type

`env` takes a `t<Env>()` marker. It carries no runtime value — `t<T>()` is a type-only marker — but it sets the type of `ctx.env` in every handler and hook.

```typescript [env.ts]
import { define, t } from '@wskit/server'

interface Env {
  DB: D1Database
  API_KEY: string
}

const base = define({
  env: t<Env>(),
  capabilities: [],
})

const handleLookup = base.on('lookup', {
  run(ctx) {
    // ctx.env.DB      → D1Database
    // ctx.env.API_KEY → string
    ctx.env.DB.prepare('SELECT 1')
  },
})
```

The real bindings come from the adapter at runtime. On Cloudflare they are the Durable Object's `Env`; on Bun, Node, or Deno they are whatever the adapter passes through. `t<Env>()` only tells the type system what to expect.

::note
On Cloudflare you usually type `env` as the worker's generated `Env`. Where this section writes `t<Env>()` with a bare `Env`, that `Env` is your worker's binding type.
::

## `upgrade` — the auth gate

`upgrade` runs once, during the HTTP-to-WebSocket handshake, before any handler. It receives the raw `Request` — headers, URL, cookies, everything an HTTP request carries — and decides the fate of the connection.

```typescript [upgrade.ts]
import { define, t } from '@wskit/server'
import { RejectUpgrade } from '@wskit/server/errors'

const base = define({
  env: t<Env>(),
  async upgrade(request) {
    const token = request.headers.get('authorization')
    const user = await validateToken(token)
    if (!user) throw RejectUpgrade(4002, 'Invalid token')
    return {
      identity: user.id,
      meta: { userId: user.id, role: user.role },
    }
  },
  capabilities: [],
})
```

`upgrade` may be `async`. Return a value to **accept** the connection, or throw `RejectUpgrade(code, reason)` to **reject** it.

### Reading the request

The argument is a standard `Request`. Common things to pull from it:

```typescript [reading.ts]
async upgrade(request) {
  const url = new URL(request.url)
  const room = url.searchParams.get('room')          // query string
  const token = request.headers.get('authorization')  // header
  const cookie = request.headers.get('cookie')         // cookies

  // ... validate and return
}
```

A small, common pattern is to pull a username straight from the query string:

```typescript [username.ts]
import { RejectUpgrade } from '@wskit/server/errors'

async upgrade(request) {
  const username = new URL(request.url).searchParams.get('username')
  if (!username) throw RejectUpgrade(4001, 'Missing username')
  return { identity: username, meta: { username } }
}
```

::warning
The `env` bindings are **not** an argument to `upgrade` — it receives only the `Request`. If you need a binding to authenticate (a database, a secret), reach it from a closure or module scope, not from `ctx` (there is no `ctx` yet during the handshake).
::

## What `upgrade` returns

The accept value is `UpgradeReturn` — one required field and two optional ones.

::field-group
  ::field{name="identity" type="string"}
  Required. The stable per-user key for this socket. It is the row key for durable state, and the key channels use to re-attach the same user on reconnect. Maximum 256 characters — returning a longer one throws when the connection is accepted (it is a durable storage key, so it is capped rather than truncated). Use a stable ID (a user ID or ULID), not a token. This is the one field you almost always set.
  ::

  ::field{name="meta" type="TMeta"}
  Optional. Per-connection metadata, surfaced as `ctx.meta` in every handler. Its type flows straight into `ctx.meta`, so return `{ userId: 'u1' }` and `ctx.meta.userId` is a typed `string`. Defaults to `{}`.
  ::

  ::field{name="tags" type="{ ephemeral?: { group: key } }"}
  Optional. Initial ephemeral tags to attach before any handler runs. The keys are the ephemeral group names declared by the `tags(...)` capability, so this field is only useful with `tags()` listed. Persistent tags cannot be seeded here — add them at runtime with `ctx.tags.persistent(group).add(key)`.
  ::
::

```typescript [return.ts]
async upgrade(request) {
  const user = await authenticate(request)
  if (!user) throw RejectUpgrade(4003, 'Unauthorized')
  return {
    identity: user.id,
    meta: { userId: user.id, plan: user.plan },
    tags: { ephemeral: { role: user.role } },   // needs tags() with a 'role' group
  }
}
```

### `identity` is the durable key

`identity` is more than a label. It is the key WSKit uses to store per-user durable state, and to rejoin a returning user to the channels they belong to. Give the same person the same `identity` across reconnects and their durable memberships and stored state follow them. The reference for tags and channel rejoin lives in [Channels](/server/channels/overview) and the [tags capability](/server/capabilities/tags).

### `UpgradeFn` and `UpgradeReturn`, named

If you write the gate as a standalone function (handy for reuse across handlers), these are the shapes to match:

```typescript [shapes.ts]
import type { UpgradeFn, UpgradeReturn } from '@wskit/server'

// UpgradeReturn<TMeta> = { identity: string; meta?: TMeta; tags?: {...} }
// UpgradeFn<TMeta>     = (request: Request) => UpgradeReturn<TMeta> | Promise<...>

interface Upgrade extends UpgradeReturn<{ username: string }> {}

const requireUsername: UpgradeFn<{ username: string }> = (request) => {
  const username = new URL(request.url).searchParams.get('username')
  if (!username) throw RejectUpgrade(4001, 'Missing username')
  return { identity: username, meta: { username } }
}

const base = define({
  env: t<Env>(),
  upgrade: requireUsername,
  capabilities: [],
})
```

## Anonymous connections

`upgrade` is optional. Omit it — or return no `identity` — and the connection is still **accepted**, just anonymous:

- `identity` defaults to `''`
- `meta` defaults to `{}`
- `tags` defaults to none

```typescript [anonymous.ts]
const base = define({
  env: t<Env>(),
  capabilities: [],
  // no upgrade — every connection is accepted as anonymous
})
```

Anonymous sockets do not collapse onto one shared identity. Per-connection durable storage that needs a key (a per-user durable stream, for example) falls back to the connection ID when the identity is empty, so two anonymous connections never overwrite each other's rows. Storage that exists only to re-attach a returning user — durable channel memberships and persistent tags — behaves differently: it has no stable key to match an anonymous reconnect against, so the durable write is **skipped** for an empty identity rather than keyed on the connection ID. If you want every socket authenticated, supply an `upgrade` that throws `RejectUpgrade(...)` when credentials are missing.

## Rejecting the upgrade

Throw `RejectUpgrade(code, reason)` to refuse a connection. The handshake is rejected at the HTTP layer, and the `code` you pass decides how the client sees it.

```typescript [reject.ts]
import { RejectUpgrade } from '@wskit/server/errors'

async upgrade(request) {
  const token = request.headers.get('authorization')
  if (!token) throw RejectUpgrade(401, 'Missing credentials')         // HTTP 401
  const user = await validateToken(token)
  if (!user) throw RejectUpgrade(4002, 'Invalid token')               // WS close 4002
  if (user.banned) throw RejectUpgrade(403, 'Account suspended')      // HTTP 403
  return { identity: user.id, meta: { userId: user.id } }
}
```

### How the reject code is answered

The number you pass to `RejectUpgrade` is interpreted by its range:

| `code` you pass | What the client gets | When to use it |
| --- | --- | --- |
| `≥ 1000` (a WebSocket close code) | The handshake completes, then the socket is immediately closed with that code and reason. This is the **only** way a browser `WebSocket` can read the reason — via its `close` event. | When the client is a browser `WebSocket` and you want it to see *why*. |
| `400`–`599` (an HTTP status) | That HTTP status, with `reason` as the response body. | For a plain HTTP rejection a `fetch`/proxy can read. |
| anything else | Falls back to HTTP `403 Forbidden`. | A safe default. |

So `RejectUpgrade(4002, 'Invalid token')` lets a browser client read `'Invalid token'` off the close event, while `RejectUpgrade(401, 'Missing credentials')` returns a real HTTP 401. Pick the range that matches how your client connects.

::tip
WebSocket close codes in the **4000–4999** range are reserved for application use. Reach for those when you want a browser client to distinguish your reasons. See [Close codes](/core/close-codes) for the full map.
::

### The non-WebSocket case

A plain `GET` with no `Upgrade: websocket` header never reaches your `upgrade`. The adapter answers it with HTTP `426 Upgrade Required` first. So `upgrade` only ever runs for a genuine WebSocket handshake — you do not have to guard against ordinary HTTP traffic inside it.

## A scoped `upgrade`

A plugin can supply its own `upgrade` through the scoped builder. It runs before the app's upgrade, sees only the raw request (not the app's identity), and merges its `meta` into the connection. That variant is covered in [Plugins › Authoring](/server/plugins/authoring).
