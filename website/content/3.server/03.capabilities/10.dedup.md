When a client retries a send over a flaky network, the same message can arrive twice. Without protection, the handler runs twice — a double charge, a double post. **dedup** stops that. It stamps an ID on every outgoing message and remembers the most recent inbound IDs per connection, dropping any frame whose ID it has already seen.

## How it works

dedup acts in both directions:

- **Outgoing** — every server-to-client application message gets a unique `messageId` stamped into its `__wskit` envelope, so clients can drop duplicates from a replay or reconnect. Protocol frames (pings, subscribe acks, and the like) are skipped — they carry no `messageId`.
- **Incoming** — when a frame arrives carrying a `messageId` the connection has seen recently, dedup drops it before any handler runs.

Each connection keeps a small ring of recent IDs. The ring size — the `cap` — is how many IDs it remembers.

A frame with **no** `messageId` is never treated as a duplicate. It always dispatches. So dedup is at-least-once by default: a client opts into deduplication by attaching a stable ID to its retries, and an un-stamped send always goes through.

dedup adds nothing to the client contract. The `messageId` lives in the transport envelope, not in your typed payloads; `InferClient` is unchanged.

## Enable it

Import `dedup` from `@wskit/server/dedup` and list it in `capabilities`. The options object is optional.

::code-group

```typescript [socket.ts]
import { define, t } from '@wskit/server'
import { dedup } from '@wskit/server/dedup'

const base = define({
  env: t<Env>(),
  capabilities: [dedup()],
})
```

```typescript [socket.ts (custom ring size)]
import { define, t } from '@wskit/server'
import { dedup } from '@wskit/server/dedup'

const base = define({
  env: t<Env>(),
  capabilities: [dedup({ cap: 256 })],
})
```

::

## Configuration

| Option | Type | Required | Default | What it is |
|---|---|---|---|---|
| `cap` | `number` | no | `256` | How many recent inbound `messageId` values to remember per connection |

`cap` must be a positive integer if given — passing an invalid value throws immediately, at the `dedup()` call, not later at assemble. A larger ring catches retries spread over a longer window at the cost of a little more memory per connection; the default of `256` covers a few seconds of burst retries on a flaky link.

## Host-only :badge[host-only]

dedup is a **host-only** capability. It cannot be listed inside a plugin's scoped handler — only the top-level `define(...)` may enable it.

## Pairs with sequence and replay

dedup is often listed alongside [sequence](/server/capabilities/sequence), which numbers every outgoing message so the client can spot a gap. Together they give the client both halves of reliable delivery: dedup drops what arrived twice, sequence reveals what never arrived.

Built-in [replay](/server/capabilities/replay) also requires `dedup()` — the stamped `messageId` is what replay uses to skip messages the client already has. The three are usually listed together:

```typescript [reliable.ts]
import { define, t } from '@wskit/server'
import { dedup } from '@wskit/server/dedup'
import { sequence } from '@wskit/server/sequence'
import { replay } from '@wskit/server/replay'

const base = define({
  env: t<Env>(),
  capabilities: [
    dedup(),
    sequence({ persist: true }),
    replay.history(),   // built-in replay needs both of the above
  ],
})
```
