The `intercepts()` capability turns on **frame-level hooks** — code that runs for every inbound or outbound frame, around your handlers. List it to grant `base.intercept(...)`, the channel-scoped `channel.intercept(...)`, and the `ctx.matches` / `ctx.unsafeCast` frame guards. Import it from `@wskit/server/intercepts`:

```typescript [server.ts]
import { define, t } from '@wskit/server'
import { intercepts } from '@wskit/server/intercepts'

const base = define({
  env: t<Env>(),
  capabilities: [intercepts()],
})
```

## What it grants

| Surface | What it is |
|---|---|
| `base.intercept((ctx, frame) => …)` | The inbound hook — runs before validation and the handler. Inspect, rewrite, or drop a frame. |
| `channel.intercept((ctx, frame) => …)` | The same hook, scoped to one channel. |
| `ctx.matches(key, frame)` | A validating type guard — `true` when a frame matches a declared event **and** its payload passes the validator. |
| `ctx.unsafeCast(key, frame)` | A no-validation narrow — checks only that the key is a declared event. |

The hook mechanics — the `frame` shape, rewrite-vs-drop, channel ordering, `frame.owner`, and the nudge branch — live on the [Intercept](/server/lifecycle-and-intercept/intercept) page. This page covers **enabling** the capability and the two frame guards.

::note
The `outgoing` hook (`base.outgoing(...)`) is *not* gated by `intercepts()` — it is always available. Only the inbound `intercept` and the two frame guards need this capability.
::

## The frame guards: `ctx.matches` and `ctx.unsafeCast`

An intercept runs **before** validation, so `frame.payload` arrives typed `unknown`. These two `ctx` helpers check a frame against a declared event so you can narrow it:

| Method | Returns | What it does |
|---|---|---|
| `ctx.matches(key, frame)` | `boolean` | `true` when the frame's event and scope match the key **and** its payload passes the declared validator. A bad payload returns `false`. |
| `ctx.unsafeCast(key, frame)` | type guard | Checks only that `key` is a declared event; skips the payload validator. Use when your own logic already proved the shape. |

```typescript [matches.ts]
base.intercept((ctx, frame) => {
  // Runs the validator declared for 'send-message'. False if the payload is bad.
  if (ctx.matches('send-message', frame)) {
    const p = frame.payload as { text: string }
    if (containsProfanity(p.text)) return { ...p, text: mask(p.text) }
  }
})
```

Both throw if the key names no declared event — a typo is caught immediately, not silently ignored. Channel-scoped keys use the `@family::event` form. `matches` is a type guard and `unsafeCast` returns a narrowed frame, so after either one the `frame` is typed for that key (in practice the payload often stays `unknown`, so you still read it with a cast).

::caution
`ctx.matches` and `ctx.unsafeCast` are the one exception to the capability type-gate: they sit on every connection `ctx` **even without** `intercepts()`. But calling either one **throws at runtime** unless `intercepts()` is listed. List it whenever you narrow frames.
::

## The contract slice

`intercepts()` adds **nothing** to the client contract. Hooks are a server-side concern — they run at the transport layer, so `InferClient` is unchanged.
