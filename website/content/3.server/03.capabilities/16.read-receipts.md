Inbox already tracks who *received* each message, so the received cursor and its `receiversOf` query come with an inbox channel and need no opt-in — pushing the double-grey tick live to other members is a separate `broadcastReceipts` flag on `inbox()`. **readReceipts** adds the blue check on top: who has *read* a message, not just received it. A member advances a read cursor, and the channel learns who has read up to which message.

This page is the enable-and-configure reference. For how receipts behave on the wire — the `__received__` / `__read__` fan-out, `receiversOf` / `readersOf`, and the member cap — see [Receipts](/server/inbox/receipts).

## Requirements :badge[needs inbox()]

Read receipts build on inbox: they reuse the same per-member cursors, sequence numbers, and storage. So a channel with `readReceipts` must already be an inbox channel, and `inbox()` brings its own requirements — `channels()`, `persistence()`, `sequence({ persist: true })`, and `dedup()`. See [`inbox`](/server/capabilities/inbox) for that list.

::note
A read acknowledgement implies received: a `__read__` also settles that member's inbox rows up to the read mark. Marking a message read without having acked its delivery first is fine — inbox catches up.
::

## How to enable

List `readReceipts()` alongside `inbox()` — it takes no config — then switch it on per channel with `readReceipts: true`, next to `inbox: true`:

```typescript [receipts-server.ts]
import { define, t } from '@wskit/server'
import { channels } from '@wskit/server/channels'
import { dedup } from '@wskit/server/dedup'
import { inbox, readReceipts } from '@wskit/server/inbox'
import { persistence } from '@wskit/server/persistence'
import { sequence } from '@wskit/server/sequence'
import * as v from 'valibot'

const base = define({
  env: t<Env>(),
  upgrade: (request) => requireUsername(request),
  capabilities: [
    persistence(),
    channels(),
    sequence({ persist: true }),
    dedup(),
    inbox(),
    readReceipts(),
  ],
})

const chat = base.channel('chat', {
  persistent: true,
  inbox: true,
  readReceipts: true,
  outgoing: { emits: { 'room-msg': t<{ text: string; from: string }>() } },
})

export const handleSend = chat.on('send-room-msg', {
  input: v.object({ text: v.string() }),
  run(ctx, payload) {
    ctx.channel.broadcast('room-msg', { text: payload.text, from: ctx.meta.username })
  },
})
```

To tune the member cap, pass an options object instead of `true`:

```typescript [read-receipts-options-server.ts]
const chat = base.channel('chat', {
  persistent: true,
  inbox: true,
  readReceipts: { maxReceiptAudience: 512 },
  outgoing: { emits: { 'room-msg': t<{ text: string; from: string }>() } },
})
```

## Configuration

The only field on `ReadReceiptsOptions` is optional.

| Option | Type | Default | What it does |
|---|---|---|---|
| `maxReceiptAudience` | `number` | `256` | Only live-broadcast the read `__read__` frame while the channel has at most this many members. Above it the read cursor is still tracked and stays readable via `readersOf`, but no live tick fires. |

## Querying who has read

Inside a handler scoped to the channel, `ctx.channel.readReceipts.readersOf(seq)` returns the identities that have read up to a sequence number. These cursor surfaces attach at runtime and are not on the static ctx type yet, so the handler casts to reach them:

```typescript [readers-of-server.ts]
interface ChannelReceiptsCtx {
  readReceipts: { readersOf(seq: number): string[] }
}

export const handleAskRead = chat.on('ask-read', {
  input: v.object({ seq: v.number() }),
  run(ctx, input) {
    const receiptsCtx = ctx.channel as unknown as ChannelReceiptsCtx
    const identities = receiptsCtx.readReceipts.readersOf(input.seq)
    ctx.send('cursor-answer', { seq: input.seq, identities })
  },
})
```

## What it adds to the client contract

A channel whose contract has `readReceipts: true` gains `readers`, `onRead`, `markAsRead`, and `readersOf` on its client handle — `markAsRead(seq?)` advances the read cursor (omit `seq` to mark everything received so far), and `readersOf(seq)` queries who has read up to a message. As with inbox, the channel object must be passed to `base.assemble(...)` for `InferClient` to carry the flag. See [Receipts](/server/inbox/receipts) for the deep behaviour.
