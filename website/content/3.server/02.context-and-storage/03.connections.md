`ctx.send` and `ctx.broadcast` cover "this socket" and "everyone". This page covers the middle ground: reading **who** is connected, and sending to **one specific** connection that is not the caller.

Two pieces do the work:

- **`ConnectionInfo`** — a read-only snapshot of one live connection.
- **`ConnectionRef`** — an address for one connection. You build it from a snapshot and pass it to `ctx.connection(ref)` to send to that socket.

## Reading who is connected

`ctx.getConnections()` returns a snapshot array of every live connection on this instance. `ctx.connectionCount` is the same count as a number.

```typescript [members.ts]
base.on('list-members', {
  input: v.object({}),
  run(ctx) {
    const peers = ctx.getConnections()
    // peers[].meta is typed from your upgrade step — no cast needed.
    const usernames = peers.map((p) => p.meta.username)
    ctx.send('members-list-result', { members: usernames })
  },
})
```

The snapshot does not update — it is a point-in-time read. Call `getConnections()` again if you need fresh data.

## `ConnectionInfo`

Each entry from `getConnections()` (and from channel `members()` and tag `connections()`) is a `ConnectionInfo`:

::field-group
  ::field{name="id" type="string"}
  Unique ID of this connection. Same value as that connection's own `ctx.id`.
  ::
  ::field{name="identity" type="string"}
  The identity string the upgrade step returned for it — the per-user key.
  ::
  ::field{name="meta" type="Meta"}
  The metadata set during upgrade, typed from your upgrade step — `getConnections()` returns `ConnectionInfo<Meta>[]`, so reading a field needs no cast.
  ::
  ::field{name="tags" type="readonly TagRef[]"}
  Tag refs currently on this connection. Empty when no tag groups are declared.
  ::
  ::field{name="channels" type="readonly string[]"}
  Channel names this connection is currently subscribed to.
  ::
  ::field{name="latency" type="number | null"}
  Round-trip latency in ms, or `null` if not measured yet. Populated by `keepalive()`.
  ::
  ::field{name="quality" type="'excellent' | 'good' | 'degraded' | 'poor' | null"}
  Health label from the rolling latency average. `null` when hibernation is enabled, or before the first ping/pong has completed.
  ::
  ::field{name="bufferedAmount" type="number"}
  Bytes waiting to be sent to this connection. A high value means a slow client.
  ::
  ::field{name="ref()" type="() => ConnectionRef"}
  Build a `ConnectionRef` for this connection — pass it to anything that addresses one socket.
  ::
::

Reading the shape of a snapshot:

```typescript [snapshot.ts]
base.on('inspect-peers', {
  input: v.object({}),
  run(ctx) {
    const conns = ctx.getConnections()
    const first = conns[0]
    if (first) {
      ctx.log.info('peer snapshot', {
        id: first.id,
        identity: first.identity,
        channels: first.channels.length,
        tags: first.tags.length,
        latency: first.latency,
        quality: first.quality,
      })
    }
  },
})
```

::note
`getConnections()`, channel `members()`, and tag `connections()` all return `ConnectionInfo<Meta>`, where `Meta` is your upgrade type. So `p.meta.username` is typed just like your own `ctx.meta` — no cast needed.
::

## `ConnectionRef`

A `ConnectionRef` is an opaque address for one connection. You do not build it field-by-field — you get one from:

- **`ctx.self`** — the current connection.
- **`someConnectionInfo.ref()`** — any snapshot from `getConnections()`, channel `members()`, or tag `connections()`.

A ref is a plain address, not a live handle. It carries the connection's `id`, `identity`, and which instance owns it. Hold onto it and pass it wherever one socket is addressed — `ctx.connection(ref)`, `channelHandle.subscribe(ref)`, `channelHandle.kick(ref, reason)`.

```typescript [self-ref.ts]
base.on('join-lobby', {
  input: v.object({}),
  async run(ctx) {
    // ctx.self is this connection's ref.
    await ctx.channels.get('lobby').subscribe(ctx.self)
  },
})
```

## `ctx.connection(ref)` — addressing one socket

`ctx.connection(ref)` returns a handle to one specific connection. Its `send(event, payload)` delivers to **only** that socket and returns `false` if the connection is no longer live on this instance.

```typescript [send-to-one.ts]
base.on('whisper', {
  input: v.object({ toId: v.string(), text: v.string() }),
  run(ctx, input) {
    // Find the target snapshot, then address it by ref.
    const target = ctx.getConnections().find((c) => c.id === input.toId)
    if (!target) return

    const delivered = ctx.connection(target.ref()).send('message', {
      text: input.text,
      from: ctx.meta.username,
    })
    ctx.send('delivery-status', { delivered })
  },
})
```

### One connection vs broadcast

Three ways to send, each addressing a different set:

| You want to reach… | Use |
|---|---|
| The calling connection | `ctx.send(event, payload)` |
| One specific other connection | `ctx.connection(ref).send(event, payload)` |
| Every connection on the instance | `ctx.broadcast(event, payload, options?)` |

For sending to a **group** rather than one socket or everyone, use tags or channels instead: `ctx.tags.<kind>(group).ref(key).send(...)` sends to every connection holding a tag, and a channel handle's `broadcast(...)` sends to that channel's members. See [Tags](/server/capabilities/tags) and [Channels](/server/channels/overview).

### Asking one connection a question

With the `requests()` capability listed, the handle from `ctx.connection(ref)` also carries `request(...)` — ask that one connection a declared server→client request and await its typed answer.

```typescript [ask-one.ts]
base.on('ask-peer', {
  input: v.object({ toId: v.string() }),
  async run(ctx, input) {
    const target = ctx.getConnections().find((c) => c.id === input.toId)
    if (!target) return

    const answer = await ctx.connection(target.ref()).request(
      'confirm',
      { question: 'Accept invite?' },
      { timeout: 5_000 },
    )
    ctx.send('peer-answer', { ok: answer.ok })
  },
})
```

Without `requests()` listed, the handle has **only** `send` — the `request` arm is absent from the type, so calling it is a compile error. The full request/response model is on the [Requests](/server/capabilities/requests) page.

## In scheduled tasks

A scheduled task is not tied to one socket, so it has no `ctx.send` — but it still has `ctx.connection(ref)`, `ctx.getConnections()`, and `ctx.broadcast`. So a background job can read who is connected and send to one of them by ref:

```typescript [task.ts]
base.scheduled('nudge-idle', {
  run(ctx) {
    for (const conn of ctx.getConnections()) {
      if (conn.quality === 'poor') {
        ctx.connection(conn.ref()).send('hint', { text: 'Your connection looks slow.' })
      }
    }
  },
})
```

See [Scheduled](/server/capabilities/scheduled) for the task context in full.
