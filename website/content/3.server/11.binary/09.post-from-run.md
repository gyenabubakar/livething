This page builds on [Uploads](/server/binary/uploads) and [Upload, then post](/server/binary/upload-then-post).

Here one upload does both. The input carries the room and the text, and `run` posts the message itself when the file is stored. It checks that the user is in the room at the start, so a user who is not a member sends no bytes. It checks again at the end, because the user may have left the room while the file was still being sent. When the check fails, `run` throws, the client gets `Forbidden`, and `onDiscard` deletes the file.

`post-attachment` is `upload-attachment` with a room and a text in its input, and these lines around the same `writePieces` call:

<!-- docs-check: skip -->

```typescript [server/attachments.ts]
if (!(await isRoomMember(ctx.user.id, input.roomId))) {
  throw Forbidden({ reason: 'not a member of this room' })
}

// ...the attachment ID from the state, as in upload-attachment
const size = await writePieces(ctx.upload, attachmentId, pieces)

// The user may have left the room while the file was still being sent.
if (!(await isRoomMember(ctx.user.id, input.roomId))) {
  throw Forbidden({ reason: 'not a member of this room' })
}
```

After it saves the attachment's record with the room, it checks the signal and posts the message:

<!-- docs-check: skip -->

```typescript [server/attachments.ts]
// A cancel stops run only through its signal: do not post a cancelled file.
ctx.upload.signal.throwIfAborted()
ctx.channels
  .get('rooms', `room:${input.roomId}`)

    id: crypto.randomUUID(),
    text: input.text,
    files: [file],
    from: ctx.user.id,
    sentAt: Date.now(),

```

::code-collapse

```typescript [server/attachments.ts]
import * as v from 'valibot'
import { Forbidden } from '../shared/errors'
import {
  attachmentUploadState,
  discardAttachment,
  writePieces,
} from './attachment-files'
import { base } from './base'
import { isRoomMember, saveAttachment } from './helpers'

export const handlePostAttachment = base.binary.upload(
  'post-attachment',
  {
    input: v.object({
      roomId: v.string(),
      text: v.string(),
      fileName: v.string(),
      fileType: v.string(),
    }),
    state: attachmentUploadState,
    maxBytes: 512 * 1024 * 1024,
    async run(ctx, input, pieces) {
      if (!(await isRoomMember(ctx.user.id, input.roomId))) {
        throw Forbidden({ reason: 'not a member of this room' })
      }

      let attachmentId = ctx.upload.state?.attachmentId

      if (!attachmentId) {
        attachmentId = crypto.randomUUID()
        ctx.upload.saved(ctx.upload.savedThrough, {
          state: { attachmentId },
        })
      }

      const size = await writePieces(ctx.upload, attachmentId, pieces)

      // The user may have left the room while the file was still being sent.
      if (!(await isRoomMember(ctx.user.id, input.roomId))) {
        throw Forbidden({ reason: 'not a member of this room' })
      }

      const file = {
        attachmentId,
        fileName: input.fileName,
        fileType: input.fileType,
        size,
      }

      await saveAttachment({
        ...file,
        ownerId: ctx.user.id,
        roomId: input.roomId,
      })

      // A cancel stops run only through its signal: do not post a cancelled file.
      ctx.upload.signal.throwIfAborted()
      ctx.channels
        .get('rooms', `room:${input.roomId}`)
        .broadcast('files-posted', {
          id: crypto.randomUUID(),
          text: input.text,
          files: [file],
          from: ctx.user.id,
          sentAt: Date.now(),
        })

      return { info: { attachmentId } }
    },
    onDiscard(ctx) {
      return discardAttachment(ctx.upload)
    },
  },
)
```

::

An upload belongs to no channel, so `run` reaches the room with `ctx.channels.get(...)`, and checks membership with Huddle's own room list. A cancel does not throw in `run` by itself after the last piece: it only fires `ctx.upload.signal`. So `run` must check `ctx.upload.signal` before any side effect, such as posting a message, as `throwIfAborted()` does here. Then the message and the file come together: no member sees a message whose file is missing, and no file stays without its message.
