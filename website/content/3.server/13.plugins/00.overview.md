A **server plugin** is one part of a server (a _slice_) that you package so you can reuse it. It owns its own events, handlers, channels, streams, storage, and errors. It is also _namespaced_: LiveThing puts the plugin's ID in front of all these names, so they never clash with names in the host or in another plugin. You write a plugin like a small app, wrap it with `plugin(...)`, and the host lists it like any other capability.

A plugin is a feature you build once and use in many servers, for example a polls widget, a metrics counter, or a moderation engine. The host owns the platform, the transport, and the global engines. The plugin brings only its own slice. If a plugin needs configuration, such as a URL or a secret, write a function that takes the configuration as an argument and builds the plugin. The host then calls that function with its own values.

::note
The client has its own [plugins](/client/plugins/overview) too. They package client features you can reuse, such as analytics or support for an extra protocol. Client code gets a client plugin's API with `Plugin.use(socket)`. This chapter is about **server** plugins.
::

## The flow at a glance

A plugin goes through four steps, from writing it to running it inside a host.

::steps

### Write the slice

Create a _scoped builder_ with `server({ scope: 'plugin' })`. It is the same builder as a top-level server. It has the same `on` method, the same `request` and `channel` methods when you list their capabilities, and the same `ctx`. The difference is that it builds one slice, not a whole server.

```typescript [polls/polls-slice.ts]
import { emits, server, t } from '@livething/server'
import * as v from 'valibot'

export const h = server({
  scope: 'plugin',
  capabilities: [
    emits({
      'poll-updated': t<{
        pollId: string
        votes: Record<string, number>
      }>(),
    }),
  ],
})

export const vote = h.on('vote', {
  input: v.object({ pollId: v.string(), option: v.string() }),
  async run(ctx, input) {
    const votes =
      ((await ctx.kv.get(`poll:${input.pollId}`)) as
        | Record<string, number>
        | undefined) ?? {}

    votes[input.option] = (votes[input.option] ?? 0) + 1
    await ctx.kv.set(`poll:${input.pollId}`, votes)
    ctx.send('poll-updated', { pollId: input.pollId, votes })
  },
})
```

### Assemble it

Collect the handlers with `assemble(...)`, in the same way as a top-level server. You can also pass an optional `api`. The `api` is a set of functions that the host's handlers can call with `ctx.plugin(id)`. The `api` function receives the plugin's own scoped `ctx` for the current connection. Hooks are keys in `server({ scope: 'plugin', ... })`, so they do not go in `assemble`. Each `base.scheduled(...)` handler does go in `handlers`. The result is a scoped server definition. You cannot run it as a server on its own.

```typescript [polls/polls-definition.ts]
import { h, vote } from './polls-slice'

export const pollsDefinition = h.assemble({
  handlers: [vote],
  api(ctx) {
    return {
      async createPoll(question: string, options: string[]) {
        const pollId = crypto.randomUUID()
        await ctx.kv.set(
          `poll:${pollId}`,
          Object.fromEntries(options.map((option) => [option, 0])),
        )
        await ctx.kv.set(`poll-question:${pollId}`, question)
        return pollId
      },
      async results(pollId: string) {
        return (
          ((await ctx.kv.get(`poll:${pollId}`)) as
            | Record<string, number>
            | undefined) ?? {}
        )
      },
    }
  },
})
```

### Wrap it with `plugin(...)`

Give the slice an ID and wrap it. The ID has the form `author:name`. Each side of the colon can use only lowercase letters, digits, and hyphens. Any other ID throws an error. `plugin(...)` takes the server definition from the previous step and returns the value that the host imports.

```typescript [polls/index.ts]
import { plugin } from '@livething/server/plugins'
import { pollsDefinition } from './polls-definition'

export const Polls = plugin('acme:polls', {
  definition: pollsDefinition,
})
```

### The host lists `Plugin()`

The host calls the plugin like any other capability factory. LiveThing adds the plugin's events and handlers to the host server, under the plugin's namespace. Here is a version of Huddle with the polls plugin added. Its `base` lists `Polls()`, and its other capabilities are left out:

```typescript [server/huddle-definition.ts]
import { server } from '@livething/server'
import { Polls } from './polls'

const base = server({
  capabilities: [Polls()],
})
```
