You add your own admin operations with the `api` field of `assemble`. It is a factory: it receives the connectionless [admin context](/server/admin/context) and returns an object whose methods the outside caller can invoke through `service.admin()`.

```typescript [server.ts]
import { define, emits, t } from '@wskit/server'
import { channels } from '@wskit/server/channels'

const base = define({
  env: t<Env>(),
  capabilities: [channels(), emits({ 'room-archived': t<{ room: string }>() })],
})

export const handler = base.assemble({
  handlers: [
    /* your on / channel / request handlers */
  ],
  api: (ctx) => ({
    archiveRoom(room: string) {
      ctx.sql.exec('UPDATE rooms SET archived = 1 WHERE id = ?', room)
      ctx.broadcast('room-archived', { room })
    },
    liveCount() {
      return ctx.connectionCount
    },
  }),
})
```

The `api` factory runs once each time the surface is reached. Every method you return becomes a call on the admin surface. How you reach that surface depends on the runtime — in-process on Bun / Node / Deno, through the Durable Object stub on Cloudflare:

```typescript [bun-or-node.ts]
service.admin().archiveRoom('room:42')
const live = service.admin().liveCount()
```

```typescript [worker.ts]
const admin = await env.CHAT_ROOM.get(id).admin()
await admin.archiveRoom('room:42')
const live = await admin.liveCount()
```

On Cloudflare every call crosses a process boundary, so it returns a promise even when your method returns nothing. See [Reaching it](/server/admin/reaching-it) for what that boundary does and does not carry.

## The `ctx` is connectionless

The `ctx` your factory receives is the admin context — the whole-server view, with no current socket. `ctx.send`, `ctx.connection.id`, and `ctx.meta` are **not** on it; reaching for one is a compile error. What you get instead is `ctx.broadcast`, `ctx.connections`, `ctx.users`, `ctx.purgeUser`, `ctx.closeConnections`, `ctx.sql`, and the rest of the surface listed in [Admin Context](/server/admin/context).

Capability-owned members are gated here exactly as they are in your handlers: `ctx.channels` needs [`channels()`](/server/capabilities/channels) listed, and `ctx.schedule` / `ctx.cancelScheduled` need [`scheduled()`](/server/capabilities/scheduled). Without the capability the member is not on the type, so reading it is a compile error rather than a call that quietly does nothing.

```typescript
api: (ctx) => ({
  announce(text: string) {
    ctx.broadcast('announcement', { text }) // ✓ whole-server
    // @ts-expect-error — no current connection here
    ctx.send('announcement', { text })
  },
})
```

## Return types flow out

Whatever a method returns becomes the caller's result, and its type is inferred — you do not declare a response schema. A method that returns a value is a read; one that returns nothing is an action.

```typescript
api: (ctx) => ({
  // read — the return type flows to the caller
  bans() {
    return ctx.sql.exec<{ id: string }>('SELECT id FROM bans').toArray()
  },
  // action — returns nothing
  async purgeUser(id: string) {
    await ctx.purgeUser(id)
  },
})
```

::note
This is the **top-level** server's `api`. A plugin's `assemble` also takes an `api`, but a plugin's is per-connection — reached from a host handler with `ctx.plugin(id)`, not from the admin surface. See [Scoped context and API](/server/plugins/scoped-ctx).
::

## `purgeUser` cleans up whatever is durable

`ctx.purgeUser(id)` drops a user from every durable channel and persistent tag, then closes their live sockets. It needs no capability of its own: it cleans up whichever durable state actually exists for that user — a channel membership if [`channels()`](/server/capabilities/channels) is listed, a persistent tag row if [`tags(...)`](/server/capabilities/tags) is listed — and simply has nothing to do for the rest.
