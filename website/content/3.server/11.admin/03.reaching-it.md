The admin surface belongs to the **running service**. This is the object that holds your live connections, your storage, and the running engine. How your outside code reaches it depends on the runtime. The operations do the same things on every runtime.

## Cloudflare Durable Objects

Only a Worker can reach a Durable Object (DO), so the admin surface is an RPC method on the DO. RPC (remote procedure call) means calling a method that runs in another process. A **stub** is the object your Worker uses to call one Durable Object instance. Your Worker calls `admin()` on the stub, then calls the operation on the result:

```typescript [worker.ts]
export default {
  async fetch(request: Request, env: Env) {
    const url = new URL(request.url)

    if (url.pathname === '/webhooks/clerk') {
      const event = await verifyClerkWebhook(request)

      if (event.type === 'user.deleted') {
        const id = env.CHAT_DO.idFromName('global')
        const admin = await env.CHAT_DO.get(id).admin()
        await admin.purgeUser(event.data.id)
      }

      return new Response('ok')
    }

    // ...your normal WebSocket upgrade route
  },
}
```

Your Worker is already the place where HTTP requests enter your app. So your own auth checks (a webhook signature check, an IP allowlist, or any other check) protect the route before it calls `admin()`. LiveThing does not add its own auth layer. See [Auth is your boundary](#auth-is-your-boundary) below.

::warning
Export your Durable Object with a **class declaration**, not `export const`:

```typescript [worker.ts]
export class ChatRoom extends bind(chatDefinition) {}
```

`wrangler types` generates `DurableObjectNamespace<import("./worker").ChatRoom>`, which needs a **type** named `ChatRoom`. `export const ChatRoom = bind(chatDefinition)` exports only a value. So that reference finds no type, and the binding becomes `any` with no warning. TypeScript then checks none of your `stub.admin()`, `stub.shutdown()`, or `stub.fetch()` calls.
::

### What crosses the stub

A Worker and a Durable Object are separate processes, so a call between them is RPC. The arguments and the result are copied from one process to the other, and you can call only _methods_. So the admin context's grouped objects (`ctx.connections`, `ctx.users`, and `ctx.channels`) cannot be sent to the Worker as they are. On Cloudflare, each of their operations becomes a separate method on the admin object instead:

| Inside your `api`, in the DO          | On the Worker's stub                      |
| ------------------------------------- | ----------------------------------------- |
| `ctx.connectionCount`                 | `admin.connectionCount()`                 |
| `ctx.connections.all()`               | `admin.listConnections()`                 |
| `ctx.connections.get(ref).send(…)`    | `admin.sendToConnection(connectionId, …)` |
| `ctx.users.get(id).broadcast(…)`      | `admin.sendToUser(userId, …)`             |
| `ctx.users.get(id).close(…)`          | `admin.closeUser(userId, …)`              |
| `ctx.channels.get(name).broadcast(…)` | `admin.channelBroadcast(name, …)`         |
| `ctx.channels.get(name).members()`    | `admin.channelMembers(name)`              |
| `ctx.channels.get(name).kick(…)`      | `admin.channelKick(name, target, opts)`   |

`broadcast`, `purgeUser`, and `closeConnections` have the same names on the stub.

```typescript [worker.ts]
const admin = await env.CHAT_DO.get(id).admin()

const live = await admin.connectionCount()
await admin.sendToUser('user_9', 'notice', {
  text: 'your export is ready',
})
await admin.channelBroadcast('lobby', 'notice', {
  text: 'maintenance in 5m',
})

// A user ref is plain data when it crosses to the DO. `instance: undefined`
// means the DO that owns this admin surface. A ref that names a different
// instance is rejected.
await admin.channelKick(
  'lobby',
  { __livething: 'user-ref', id: 'user_9', instance: undefined },
  { reason: 'removed by a moderator', revoke: true },
)

// For a dynamic channel, pass its family and its instance name together.
await admin.channelBroadcast(
  { family: 'rooms', instance: 'rooms:42' },
  'notice',
  { text: 'closing' },
)
```

Because the values are copied, two more rules apply:

- Every call returns a promise, even when the operation returns nothing.
- `listConnections()` and `channelMembers()` return plain data. Each item has the same fields as a [`ConnectionInfo`](/server/context-and-storage/connections), but without its `ref()` method, because a method cannot be copied. To send to one of these connections, pass its `id` to `sendToConnection`. That method finds the connection inside the DO. It returns `false` when no live connection on that DO has this ID.

Storage and the other internal services (`sql`, `kv`, `schedule`) are not on the stub at all. Your `api` methods use them **inside** the Durable Object, where your code already runs.

## Node.js

`setup().bind(definition, options)` returns a WebSocket endpoint that runs in the same process as your HTTP server. Keep that endpoint, and call `admin()` on it from any other route. This example uses Express:

```typescript [server.ts]
import { setup } from '@livething/server-node'
import express from 'express'
import { definition } from './definition'

const app = express()
const { bind } = setup()
const chat = bind(definition, { sql: './data/chat.sqlite' })

app.post('/webhooks/clerk', async (req, res) => {
  const event = await verifyClerkWebhook(req)
  if (event.type === 'user.deleted') {
    const admin = await chat.admin()
    await admin.purgeUser(event.data.id)
  }
  res.send('ok')
})
```

There is no stub here. The engine is in the memory of the same process, so `chat.admin()` gives you the **whole admin context**. It is the same object your `api` methods see: `admin.connections.all()`, `admin.users.get(id).broadcast(…)`, `admin.connectionCount`. The separate method names in the table above exist only for Cloudflare's RPC. You do not use them here. The Bun and Deno adapters also give you the admin surface in the same process.

## Auth is your boundary

Admin operations do not go through the WebSocket protocol. They do not run `upgrade`, a channel's `check` / `commit` gate, or any other check that protects client traffic. The engine fully trusts your server code.

So **you must protect the routes that call `admin()`**. On Cloudflare, only your Worker can reach the DO. Your Worker route is where you verify the webhook signature or check the token. On Node, the call happens inside your own HTTP server, where your existing auth middleware already runs.
