An intercept often does work the handler then needs — verify a token, load a user, compute a permission. `ctx.provide` and `ctx.inject` pass that result down **without** a global, a re-fetch, or a cast. The store is per-frame: each message dispatch gets its own, and it is gone when the dispatch ends.

The flow is three steps:

::steps

### Make a key

`localKey<T>(name?)` returns a typed key. The type `T` is what the key carries; the optional name is only for debugging. Export it so the intercept and the handler import the same one.

```typescript [keys.ts]
import { localKey } from '@wskit/server'

export const AuthKey = localKey<{
  userId: string
  role: string
}>('auth')
```

### Provide in an intercept

`ctx.provide(key, value)` stores a value for this frame. The `value` must match the key's type — a wrong type is a compile error.

```typescript [intercept.ts]
// Unauthorized is your own typed error: error('unauthorized', ...). See Core.
base.intercept(async (ctx, frame) => {
  const auth = await verifyToken(ctx.meta.token)
  if (!auth) throw Unauthorized()
  ctx.provide(AuthKey, auth) // typed as { userId, role }
})
```

### Inject in a handler

`ctx.inject(key)` reads it back. The result is `T | undefined` — `undefined` when nothing was provided for that key on this frame.

```typescript [definition.ts]
base.on('admin-action', {
  input: v.object({ target: v.string() }),
  run(ctx, input) {
    const auth = ctx.inject(AuthKey) // { userId, role } | undefined
    // Forbidden is your own typed error: error('forbidden', ...). See Core.
    if (auth?.role !== 'admin')
      throw Forbidden({ reason: 'Not admin' })
    // ... do the admin work
  },
})
```

::

## The typing

The key's type parameter flows through both calls. `provide` only accepts a value of the key's type; `inject` returns that type or `undefined`.

```typescript [typing.ts]
const CountKey = localKey<number>('count')

ctx.provide(CountKey, 42) // ok
ctx.provide(CountKey, 'oops') // compile error — string is not number

const n = ctx.inject(CountKey) // number | undefined
const strict: number = ctx.inject(CountKey) // compile error — missing | undefined
```

Keys are identified by **object reference**, not by name. Two `localKey` calls with the same name are two different keys and never collide — which is why you export and import the one key rather than re-creating it.

```typescript [identity.ts]
const a = localKey<string>('user')
const b = localKey<string>('user') // different key, same name

ctx.provide(a, 'alice')
ctx.inject(a) // 'alice'
ctx.inject(b) // undefined — b is a different key
```

## Per-frame isolation

Each message dispatch starts with an empty store. A value you provide is visible to every **downstream** intercept and to the handler for that same frame — and to nothing else. The next message does not see it, and another connection's dispatch does not see it.

```typescript [isolation.ts]
const StepKey = localKey<number>('step')

base.intercept((ctx, frame) => {
  ctx.provide(StepKey, 1) // only this frame's handler can read this
})

base.on('do', {
  input: v.object({}),
  run(ctx) {
    ctx.inject(StepKey) // 1, for this frame only
  },
})
```

A re-`provide` for the same key overwrites the earlier value within the same dispatch.

## Intercept to handler, end to end

Here is a full server. One key, provided in the top-level intercept, read by both an `on` and a `request` handler:

::code-group

```typescript [keys.ts]
import { localKey } from '@wskit/server'

export const TopKey = localKey<{ tag: string }>('top')
```

```typescript [server.ts]
import { emits, server, t } from '@wskit/server'
import { clientRequests } from '@wskit/server/client-requests'
import { intercepts } from '@wskit/server/intercepts'
import * as v from 'valibot'
import { TopKey } from './keys.ts'

const base = server({
  upgrade: (request) => requireAuth(request),
  capabilities: [
    emits({ echoed: t<{ text: string }>() }),
    clientRequests(),
    intercepts(),
  ],
})

base.intercept((ctx) => {
  ctx.provide(TopKey, { tag: 'top' })
})

const handleEcho = base.on('echo', {
  input: v.object({ text: v.string() }),
  run(ctx, input) {
    const top = ctx.inject(TopKey)
    ctx.send('echoed', {
      text: `${input.text}:${top?.tag ?? 'none'}`,
    })
  },
})

const handleLookup = base.request('lookup', {
  input: v.object({ text: v.string() }),
  run(ctx, input) {
    const top = ctx.inject(TopKey)
    return { text: `${input.text}:${top?.tag ?? 'none'}` }
  },
})

export const definition = base.assemble({
  handlers: [handleEcho, handleLookup],
})
```

## Sharing across the top-level and channel intercept

The top-level intercept and a channel intercept run for the same frame share **one** store. A value the top-level intercept provides is readable in the channel intercept and in the channel handler.

```typescript [channel-share.ts]
import { emits, localKey, t } from '@wskit/server'

export const TopKey = localKey<{ tag: string }>('top')
export const ChannelKey = localKey<{ tag: string }>('channel')

base.intercept((ctx) => {
  ctx.provide(TopKey, { tag: 'top' })
})

const room = base.channel('room', {
  capabilities: [emits({ echoed: t<{ text: string }>() })],
})

room.intercept((ctx) => {
  ctx.provide(ChannelKey, { tag: 'channel' })
})

const handleRoomEcho = room.on('echo', {
  input: v.object({ text: v.string() }),
  run(ctx, input) {
    const top = ctx.inject(TopKey) // from the top-level intercept
    const chk = ctx.inject(ChannelKey) // from the channel intercept
    ctx.channel.send('echoed', {
      text: `${input.text}:${top?.tag ?? 'none'}:${chk?.tag ?? 'none'}`,
    })
  },
})
```

::note
`provide` and `inject` are on the connection `ctx` everywhere it appears, but they only carry data **within one frame's dispatch**. For state that outlives a frame — per-connection or per-user — use `ctx.meta`, `ctx.sql`, or `ctx.kv` instead. The `ctx` surface and storage are covered in [Context & Storage](/server/context-and-storage/ctx).
::
