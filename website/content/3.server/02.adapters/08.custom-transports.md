LiveThing ships two [transports](/server/adapters/transports): WebSocket, and server-sent events with POST requests. If your users are on a network that neither one reaches, you can build your own transport. A transport has two parts:

- **A client transport**, which you list in the [`transports`](/client/connecting/connect-options#transports) option of `connect()`, next to `websocket()` and `sse()`.
- **A server transport**, which you list in the `transports` option of the adapter's `bind()`, next to `websocket()` and `sse()`.

The engine does not change. It sends frames to a connection and gets frames from it, and it does not care how they travel. Your transport moves the same frames that WebSocket moves. This page builds a long-polling transport, because long polling is the transport people ask about most.

## Why LiveThing has no long polling

LiveThing has no built-in long polling, for these reasons:

- **Server-sent events reach the same networks.** Both are plain HTTP requests, so a proxy that blocks WebSocket lets both through.
- **Long polling is slower and costs more.** After every answer the client must send a new request, and messages that arrive in between wait on the server. One open stream has no such gap.
- **The gap makes order and memory harder.** The server keeps the messages for each client between polls, and must keep them in order when a poll fails.

Long polling helps in one case: a proxy that holds back a whole response until it ends, so a stream never arrives. We have not found data on how many networks do this. If yours does, build long polling as a custom transport with the example below.

## The server side

A server transport is a `ServerTransport` object with a `name`, a `handle()`, and an optional `check()`. The [complete example](#a-complete-long-polling-transport) at the end of this page has both sides. List it in `bind()` with the built-in transports. Its `name` must not be `websocket` or `sse`, and two transports cannot share a name:

```ts [huddle-server.ts]
import { setup, sse, websocket } from '@livething/server-node'
import { huddle } from './server/huddle-definition'
import { longPolling } from './server/long-polling'

const { bind } = setup()
const huddleEndpoint = bind(huddle, {
  sql: './data/huddle.sqlite',
  transports: [websocket(), sse(), longPolling()],
})
```

### `handle(request, endpoint)`

The adapter calls `handle()` for every request to the endpoint that is not a WebSocket upgrade. It gives you a standard Web `Request` and returns your `Response`, on Node, on Cloudflare and in a custom adapter alike.

- **Return `null` for a request that is not yours.** The adapter then offers the request to the next custom transport, in list order, and then to server-sent events. Without `sse()`, a request that nobody takes gets `426`. Mark your requests in a way you can check cheaply, such as a header, and return `null` before you read the body: the body can be read only once.
- **The response can stream.** On Node, the adapter writes the body as your stream produces it. A slow client slows the writes, so your stream's `desiredSize` shows it.
- **Watch `request.signal`.** It aborts when the client goes away, and on Node when the endpoint shuts down. A request you hold open, such as a poll, must stop waiting then. On Node, the shutdown ends every request still open.
- **A thrown error answers `500`.** The adapter logs it.

### `endpoint.authenticate(request)`

It runs the endpoint's origin check, then the server's [`authenticate`](/server/server/authenticate), and returns its decision. A request from an origin that is not allowed gets `{ reject: true, code: 403 }`. Pass the request you got, so the adapter keeps the client's IP address.

A decision with `reject: true` has a `code`. A code under `1000` is an HTTP status: answer with it. A code from `1000` is a close code: the client must get it as a close, as it would on a WebSocket.

### `endpoint.accept(connection, decision)`

It hands a connection to the engine and returns its `ConnectionHandle`. The `connection` is how the engine sends:

| Field                   | What it does                                                                                                                                                                   |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `send(frame)`           | Send one frame: `{ kind: 'text', text }` or `{ kind: 'bytes', bytes }`. Return `false` when the frame was not sent, so the engine does not count it as delivered. Never throw. |
| `close(code, reason)`   | Close the connection. Tell the client the code and the reason.                                                                                                                 |
| `bufferedAmount()`      | The bytes waiting to be sent.                                                                                                                                                  |
| `backpressureSupported` | `true` only when `bufferedAmount()` is the real number. The engine then paces streams and closes a client that reads too slowly with `1013`.                                   |
| `terminate()`           | Optional. Drop the connection at once, for a client that stopped reading.                                                                                                      |
| `secret`                | Optional. A secret the client sends to name its connection. The engine puts it in the first frame, `__connected__`, so your client transport reads it there.                   |
| `maxPostBytes`          | Optional. The largest request body you take, for the `__connected__` frame.                                                                                                    |

Report what the client does to the handle: `handleMessage(text)` for a text frame, `handleBinaryMessage(bytes)` for a [binary](/server/binary/overview) frame, and `handleClose(code, reason)` once when the connection ends, whichever side ended it. Call `handleClose` after your own `close()` too, as a WebSocket close event would.

### `check(definition)`

Optional. `bind()` calls it once at startup with the server definition. Throw to stop a startup that cannot work. A transport that cannot see a dead client by itself needs [`keepalive()`](/server/capabilities/keepalive), whose pings find out:

```ts [server/long-polling.ts]
import { hasCapability } from '@livething/server/adapters'
import type { ServerDefinition } from '@livething/server/adapters'

// Inside the transport object.
function check(definition: ServerDefinition) {
  if (!hasCapability(definition, 'keepalive')) {
    throw new Error(
      'longPolling() needs keepalive() in the server definition.',
    )
  }
}
```

### On Cloudflare

The Worker forwards each request to its Durable Object, as for server-sent events, and the object calls `handle()`. Every request of one connection must reach the same object, so route it by the URL, as the [Cloudflare setup](/server/adapters/transports#cloudflare) does. One transport object serves every object of the class in that isolate, so keep your state per connection, such as in a map by secret. An open request keeps the object awake, as an SSE stream does.

## The client side

A client transport is a `TransportFactory`: a `name` and an `open()` that starts one connection. The socket calls `open()` once for each try, with the URL, the `token` of this try, and the events to report:

| Event                           | When to call it                                                                                                                          |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `open()`                        | The server answered. The socket then waits for the `__connected__` frame.                                                                |
| `message(data)`                 | A frame arrived: a string, or an `ArrayBuffer` for binary.                                                                               |
| `close(code, reason, wasClean)` | The connection ended. Call it once. Use `1006` when it failed with no close code.                                                        |
| `error(event)`                  | Something failed. A `close` follows.                                                                                                     |
| `stable()`                      | Optional. The connection has carried data both ways, so [`reconnection()`](/client/primitives/reconnection) may forget its failed tries. |
| `unusable()`                    | Optional. The connection opened but cannot carry data. The socket skips this transport for 5 minutes. A `close` follows.                 |

The socket treats your transport like the built-in ones. [Failover](/client/connecting/connect-options#failover) moves on from it when it closes with `1006` before `__connected__`, a close with a code is final, and `socket.transport` shows its `name`.

`open()` returns a `Transport`:

| Member                  | What it does                                                                                                    |
| ----------------------- | --------------------------------------------------------------------------------------------------------------- |
| `name`                  | The same name as the factory.                                                                                   |
| `protocol`              | The subprotocol the server picked, or `''`.                                                                     |
| `webSocket`             | `null`. Only the WebSocket transport has one.                                                                   |
| `reportsStable`         | `true` when the transport calls `stable()` itself. When `false`, the connection counts as stable when it opens. |
| `isOpen()`              | Whether the connection is open.                                                                                 |
| `send(data)`            | Send a frame: a string, or a `Uint8Array` for binary. Keep the order.                                           |
| `sendControl(frame)`    | Send `'ping'` or `'pong'`.                                                                                      |
| `bufferedAmount()`      | The bytes waiting to be sent, for `socket.drain()`.                                                             |
| `close(code, reason)`   | Close the connection. The `close` event still fires.                                                            |
| `dispose(code, reason)` | Stop all events, then close. The socket calls it when it drops this try.                                        |

List the factory in `connect()`. The URL is the same for every transport:

```ts [client/connect-huddle.ts]
import { connect, sse, websocket } from '@livething/client'
import { longPolling } from './long-polling'

const huddleConnection = connect('https://huddle.example/huddle', {
  transports: [websocket(), sse(), longPolling()],
})
```

## A complete long-polling transport

LiveThing's own tests run this transport with the real client against a Node server: messages both ways, a broadcast to a client that is waiting, close codes from both sides, failover from a blocked WebSocket, and a shutdown while polls wait. It carries text frames only. Like WebSocket, it delivers each message at most once: a frame that was on its way when a poll failed is lost.

The client sends every request with a `LiveThing-Transport: long-polling` header. The first `GET` opens the connection. Each later `GET` carries the secret from `__connected__`, and waits up to 20 seconds for frames. A `POST` carries the client's frames, or its close.

On another origin, the browser sends a CORS preflight, an `OPTIONS` request, before each request with these headers. A preflight does not carry your headers. It names them in `Access-Control-Request-Headers`, so take an `OPTIONS` request whose `Access-Control-Request-Headers` includes `livething-transport`, and return `null` for any other `OPTIONS`, which belongs to server-sent events. Answer it with `204` and the headers of `corsHeaders(origin)` from `@livething/server/adapters`, plus `Access-Control-Allow-Methods: GET, POST` and an `Access-Control-Allow-Headers` that lists `Authorization`, `Content-Type`, `LiveThing-Transport` and `LiveThing-Secret`. Add `corsHeaders(origin)` to your other answers too.

```ts [server/long-polling.ts]
import { hasCapability } from '@livething/server/adapters'
import type {
  AuthDecision,
  ConnectionHandle,
  ServerTransport,
  TransportEndpoint,
} from '@livething/server/adapters'

const POLL_MS = 20_000

interface CloseInfo {
  code: number
  reason: string
}

interface Session {
  frames: string[]
  wake: (() => void) | null
  closed: CloseInfo | null
  handle: ConnectionHandle | null
}

interface ClientMessage {
  frames?: string[]
  close?: CloseInfo
}

export function longPolling(): ServerTransport {
  const sessions = new Map<string, Session>()

  function finish(secret: string, close: CloseInfo) {
    const session = sessions.get(secret)
    if (!session || session.closed) return

    session.closed = close
    session.wake?.()
    // Keep the session for one more poll, so the client reads the close.
    setTimeout(() => sessions.delete(secret), POLL_MS)
    void session.handle?.handleClose(close.code, close.reason)
  }

  async function poll(
    secret: string,
    session: Session,
    signal: AbortSignal,
  ) {
    if (
      session.frames.length === 0 &&
      !session.closed &&
      !signal.aborted
    ) {
      await new Promise<void>((resolve) => {
        function wake() {
          clearTimeout(timer)
          signal.removeEventListener('abort', wake)
          resolve()
        }

        const timer = setTimeout(wake, POLL_MS)
        signal.addEventListener('abort', wake)
        session.wake = wake
      })
      session.wake = null
    }

    if (session.closed) sessions.delete(secret)

    return Response.json({
      frames: session.frames.splice(0),
      close: session.closed,
    })
  }

  async function open(request: Request, endpoint: TransportEndpoint) {
    const decision: AuthDecision =
      await endpoint.authenticate(request)
    if (decision.reject) {
      const code = decision.code ?? 401
      if (code < 1000) {
        return new Response(decision.reason ?? null, { status: code })
      }

      return Response.json({
        frames: [],
        close: { code, reason: decision.reason ?? '' },
      })
    }

    const secret = crypto.randomUUID()
    const session: Session = {
      frames: [],
      wake: null,
      closed: null,
      handle: null,
    }

    sessions.set(secret, session)
    session.handle = endpoint.accept(
      {
        send(frame) {
          if (session.closed || frame.kind !== 'text') return false

          session.frames.push(frame.text)
          session.wake?.()
          return true
        },
        close: (code = 1000, reason = '') =>
          finish(secret, { code, reason }),
        bufferedAmount: () =>
          session.frames.reduce(
            (total, frame) => total + frame.length,
            0,
          ),
        backpressureSupported: false,
        secret,
      },
      decision,
    )

    return poll(secret, session, request.signal)
  }

  async function receive(
    secret: string,
    session: Session,
    request: Request,
  ) {
    const message = (await request.json()) as ClientMessage
    for (const frame of message.frames ?? []) {
      void session.handle?.handleMessage(frame)
    }

    if (message.close) finish(secret, message.close)

    return new Response(null, { status: 204 })
  }

  return {
    name: 'long-polling',
    check(definition) {
      if (!hasCapability(definition, 'keepalive')) {
        throw new Error(
          'longPolling() needs keepalive() in the server definition.',
        )
      }
    },
    async handle(request, endpoint) {
      const transport = request.headers.get('LiveThing-Transport')
      if (transport !== 'long-polling') return null

      const secret = request.headers.get('LiveThing-Secret')
      if (secret === null) return open(request, endpoint)

      const session = sessions.get(secret)
      if (!session) return new Response(null, { status: 404 })

      return request.method === 'POST'
        ? receive(secret, session, request)
        : poll(secret, session, request.signal)
    },
  }
}
```

The client side polls in a loop and sends its frames in order, one `POST` after another:

```ts [client/long-polling.ts]
import type {
  Transport,
  TransportFactory,
  TransportOpenOptions,
} from '@livething/client'

interface CloseInfo {
  code: number
  reason: string
}

interface PollAnswer {
  frames: string[]
  close: CloseInfo | null
}

export function longPolling(): TransportFactory {
  return { name: 'long-polling', open: openLongPolling }
}

function openLongPolling(options: TransportOpenOptions): Transport {
  const url = options.url.replace(/^ws/i, 'http')
  const abort = new AbortController()
  let state: 'connecting' | 'open' | 'closed' = 'connecting'
  let muted = false
  let secret: string | null = null

  let sending = Promise.resolve()

  function headers(): Record<string, string> {
    if (secret !== null) {
      return {
        'LiveThing-Transport': 'long-polling',
        'LiveThing-Secret': secret,
      }
    }

    return {
      'LiveThing-Transport': 'long-polling',
      ...(options.token === null
        ? {}
        : { Authorization: `Bearer ${options.token}` }),
    }
  }

  function end(info: CloseInfo, wasClean: boolean) {
    if (state === 'closed') return

    state = 'closed'
    abort.abort()
    if (!muted) options.events.close(info.code, info.reason, wasClean)
  }

  function read(frame: string) {
    if (secret === null && frame.startsWith('["__connected__"')) {
      secret = (JSON.parse(frame) as [string, { secret: string }])[1]
        .secret
    }

    if (!muted) options.events.message(frame)
  }

  async function pollLoop() {
    try {
      while (state !== 'closed') {
        const response = await fetch(url, {
          headers: headers(),
          signal: abort.signal,
        })
        if (!response.ok) {
          end(
            { code: 1006, reason: `HTTP ${response.status}` },
            false,
          )
          return
        }

        if (state === 'connecting') {
          state = 'open'
          if (!muted) options.events.open()
        }

        const answer = (await response.json()) as PollAnswer
        for (const frame of answer.frames) read(frame)

        if (answer.close) end(answer.close, true)
      }
    } catch (error) {
      if (state === 'closed') return

      if (!muted) options.events.error(error)
      end({ code: 1006, reason: '' }, false)
    }
  }

  function post(message: { frames?: string[]; close?: CloseInfo }) {
    sending = sending.then(async () => {
      try {
        const response = await fetch(url, {
          method: 'POST',
          headers: {
            ...headers(),
            'Content-Type': 'application/json',
          },
          body: JSON.stringify(message),
        })
        if (!response.ok) {
          end({ code: 1006, reason: 'POST failed' }, false)
        }
      } catch {
        end({ code: 1006, reason: 'POST failed' }, false)
      }
    })
  }

  function close(code = 1000, reason = '') {
    if (secret !== null && state === 'open') {
      post({ close: { code, reason } })
    }

    end({ code, reason }, true)
  }

  void pollLoop()

  return {
    name: 'long-polling',
    protocol: '',
    webSocket: null,
    reportsStable: false,
    isOpen: () => state === 'open',
    send(data) {
      if (typeof data !== 'string') {
        throw new Error('The long-polling transport sends text only.')
      }

      post({ frames: [data] })
    },
    sendControl: (frame) => post({ frames: [frame] }),
    bufferedAmount: () => 0,
    close,
    dispose(code, reason) {
      muted = true
      close(code, reason)
    },
  }
}
```

To carry [binary messages](/server/binary/overview), send a `bytes` frame as base64 text with a mark, as [server-sent events do](/learn/wire-protocol#over-server-sent-events), and turn it back into an `ArrayBuffer` on the client before `message()`.
