Koa handles normal HTTP requests. A WebSocket connection starts as an HTTP upgrade request. Node sends upgrade requests to the HTTP server's `upgrade` event, not to Koa's middleware. So create a Node HTTP server from `app.callback()` and bind LiveThing to that server's `upgrade` event.

```bash [pnpm]
pnpm add @livething/server @livething/server-node @livething/core koa
pnpm add -D @types/koa
```

Koa does not include TypeScript types, so the second command installs them.

```ts [huddle-server.ts]
import { createServer } from 'node:http'
import { setup } from '@livething/server-node'
import Koa from 'koa'
import { huddle } from './server/huddle-definition'

const app = new Koa()
app.use(async (context, next) => {
  if (context.path === '/health') {
    context.body = { ok: true }

    return
  }

  await next()
})

const httpServer = createServer(app.callback())

const { bind, ready } = setup()
const huddleEndpoint = bind(huddle, { sql: './data/huddle.sqlite' })

httpServer.on('upgrade', (request, socket, head) => {
  const url = new URL(request.url ?? '/', 'http://localhost')
  if (url.pathname === '/huddle') {
    huddleEndpoint.upgrade(request, socket, head)
    return
  }

  socket.destroy()
})

await ready()
httpServer.listen(3000)
```

Koa middleware does not run for an upgrade request. This includes router middleware and its route parameters. Match the WebSocket path in the `upgrade` listener yourself, as the example does. If you want the framework's router to handle WebSocket routes, use Hono, Fastify, or H3.

## Message size limit

`bind()` takes [`maxMessageBytes`](/server/adapters/node/node-http#message-size-limit), the largest message the endpoint accepts, in bytes. The default is 32 MiB. `bind()` creates the `ws` server and sets its `maxPayload` to the same value, so you set the limit in one place. A client message over it closes the socket with `1009`.

## Compression

`bind()` also takes `compression: true`, which turns on [WebSocket compression](/server/adapters/node/node-http#compression) (`permessage-deflate`) for the `ws` server it creates. It helps JSON and text a lot, but not bytes that are already compressed, such as images, audio and video. It costs CPU and memory for every connection, so it is off by default.

## Call the admin API from a route

The endpoint's [admin API](/server/admin/overview) runs in the same process as Koa, so a normal Koa middleware can use it. For example, Huddle's moderators post an announcement from an internal dashboard:

```ts [admin-announcements.ts]
import Koa from 'koa'
import { verifySession } from './auth'
import { huddleEndpoint } from './huddle-endpoint'

const app = new Koa()

app.use(async (context, next) => {
  if (
    context.method !== 'POST' ||
    context.path !== '/admin/announcements'
  ) {
    await next()
    return
  }

  const token = context.get('authorization').replace(/^Bearer /i, '')
  const user = await verifySession(token) // your auth
  if (user?.role !== 'admin') {
    context.status = 401
    return
  }

  let body = ''
  for await (const chunk of context.req) body += chunk
  const { text } = JSON.parse(body) as { text: string }

  const admin = await huddleEndpoint.admin()
  await admin.announce(text)
  context.status = 204
})
```

Add the middleware to the same `app` that serves your other routes. Here `huddleEndpoint` is the endpoint from `bind(huddle, ...)`, exported from its own module (`huddle-endpoint.ts`) so the upgrade listener and the middleware share it.

`announce` comes from Huddle's [admin `api`](/server/admin/authoring). The same object also has the built-in operations, such as `purgeUser` and `connectionCount`. An [admin call](/server/adapters/node/node-http#call-the-admin-api-from-your-app) skips every check that protects the socket side, so protect each admin route with your own auth.

Runtime configuration, client IP setup, storage, and shutdown work the same way as on [node:http](/server/adapters/node/node-http).
