Koa handles normal HTTP requests. A WebSocket connection starts as an HTTP upgrade request (a request that asks the server to switch the connection to the WebSocket protocol). Node sends upgrade requests to the HTTP server's `upgrade` event, not to Koa's middleware. So create a Node HTTP server from `app.callback()` and bind LiveThing to that server's `upgrade` event.

```bash [pnpm]
pnpm add @livething/server @livething/server-node @livething/core koa
```

```ts [koa.ts]
import { createServer } from 'node:http'
import { setup } from '@livething/server-node'
import Koa from 'koa'
import { huddle } from './server/definition'

const app = new Koa()
app.use(async (context, next) => {
  if (context.path === '/health') {
    context.body = { ok: true }
    return
  }

  await next()
})

const httpServer = createServer(app.callback())

const { bind, ready } = setup()
const huddleEndpoint = bind(huddle, { sql: './data/huddle.sqlite' })

httpServer.on('upgrade', (request, socket, head) => {
  const url = new URL(request.url ?? '/', 'http://localhost')
  if (url.pathname === '/ws') {
    huddleEndpoint.upgrade(request, socket, head)
    return
  }

  socket.destroy()
})

await ready()
httpServer.listen(3000)
```

Koa middleware does not run for an upgrade request. This includes router middleware and its route parameters. Match the WebSocket path in the `upgrade` listener yourself, as the example does. If you want the framework's router to handle WebSocket routes, use Hono, Fastify, or H3.

Runtime configuration, client IP setup, storage, the admin API, and shutdown work the same way as on [node:http](/server/adapters/node/node-http).
