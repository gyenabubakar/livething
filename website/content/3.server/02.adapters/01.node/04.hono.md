Use `@wskit/server-node/hono` when Hono owns route matching. The binding does not create or listen on a server.

```bash [pnpm]
pnpm add @wskit/server-node hono @hono/node-server
```

```ts [server.ts]
import { createAdaptorServer } from '@hono/node-server'
import { setup } from '@wskit/server-node/hono'
import { Hono } from 'hono'
import { chatHandler } from './handler'

const app = new Hono()
const { bind, ready, shutdown, websocket } = setup()
const chat = bind(chatHandler, {
  sql: './data/chat.sqlite',
})

app.get('/ws/:room', chat.upgrade)

await ready()

const server = createAdaptorServer({
  fetch: app.fetch,
  websocket,
})

server.listen(3000)
```

## Custom WebSocket server

If your application already uses `ws` and creates its Hono `WebSocketServer`, pass it to `setup()`. WSKit uses that exact server and does not close it:

```ts
import { WebSocketServer } from 'ws'

const webSocketServer = new WebSocketServer({ noServer: true })
const wskit = setup({ webSocketServer })
```

Hono owns `:room` matching and normal Hono middleware still runs before the endpoint. WSKit's `upgrade(request)` receives the final request URL, so read `room` from its pathname when the definition needs it:

```ts
upgrade(request) {
  const room = new URL(request.url).pathname.split('/').at(-1)
  return { userId: room ?? 'anonymous' }
}
```

Use `bind()` once per WSKit definition, then pass that endpoint's `upgrade` handler to its Hono route. A normal HTTP rejection from `upgrade(request)` becomes a Hono response before the handshake. When the client sent a WebSocket upgrade request, `@hono/node-server` preserves that response's status and headers but does not send its body. A WebSocket close-code rejection completes the handshake, then closes the socket.

## Client IP

Hono's Node server gives this binding the original Node request, so `clientIp` works the same way as it does with [`node:http`](/server/adapters/node/node-http#client-ip):

```ts
const chat = bind(chatHandler, {
  clientIp: { mode: 'direct' },
})
```

For a trusted proxy chain, use `mode: 'proxy'` and list its networks. The binding does not trust Hono request headers by itself.

Your application closes both pieces:

```ts
process.once('SIGTERM', async () => {
  await shutdown()
  server.close()
})
```

If an upgrade arrives in the short time between `shutdown()` starting and `server.close()`, the binding drops its socket without running `upgrade(request)`.
