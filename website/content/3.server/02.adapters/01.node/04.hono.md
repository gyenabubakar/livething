Use `@livething/server-node/hono` when Hono matches your routes. This binding does not create an HTTP server and does not start listening on a port. Your app does that with `@hono/node-server`.

```bash [pnpm]
pnpm add @livething/server @livething/server-node @livething/core hono @hono/node-server
```

```ts [huddle-server.ts]
import { createAdaptorServer } from '@hono/node-server'
import { setup } from '@livething/server-node/hono'
import { Hono } from 'hono'
import { huddle } from './server/huddle-definition'

const app = new Hono()

const { bind, ready, shutdown, websocket } = setup()
const huddleEndpoint = bind(huddle, {
  sql: './data/huddle.sqlite',
})

app.get('/huddle', huddleEndpoint.upgrade)

await ready()

const server = createAdaptorServer({
  fetch: app.fetch,
  websocket,
})

server.listen(3000)
```

`setup()` returns a `websocket` object. Pass it to `createAdaptorServer()` so that Hono's Node server can complete WebSocket handshakes.

## Server-sent events

With [`sse()`](/server/adapters/node/node-http#server-sent-events) in `transports`, also mount `huddleEndpoint.handle` on the same path, for every method. It serves the stream, the POSTs and the CORS preflight. A WebSocket upgrade passes through it to the next handler.

```ts [huddle-server.ts]
import { createAdaptorServer } from '@hono/node-server'
import {
  sse,
  websocket as websocketTransport,
} from '@livething/server-node'
import { setup } from '@livething/server-node/hono'
import { Hono } from 'hono'
import { huddle } from './server/huddle-definition'

const app = new Hono()
const { bind, ready, websocket } = setup()
const huddleEndpoint = bind(huddle, {
  sql: './data/huddle.sqlite',
  transports: [websocketTransport(), sse()],
})

app.get('/huddle', huddleEndpoint.upgrade)
app.all('/huddle', huddleEndpoint.handle)

await ready()
createAdaptorServer({ fetch: app.fetch, websocket }).listen(3000)
```

## Custom WebSocket server

If your app already creates a `WebSocketServer` from the `ws` package, pass it to `setup()`. LiveThing uses that server and does not close it. The `websocket` object that `setup()` returns then holds your server, so pass `websocket` to `createAdaptorServer()` in the same way:

```ts
import { setup } from '@livething/server-node/hono'
import { WebSocketServer } from 'ws'

const webSocketServer = new WebSocketServer({ noServer: true })
const { bind, ready, shutdown, websocket } = setup({
  webSocketServer,
})
```

## Message size limit

All Hono endpoints of one `setup()` share one `ws` server, and its `maxPayload` belongs to the whole server. So [`setup({ maxMessageBytes })`](/server/adapters/node/node-http#message-size-limit) sets it, for every endpoint. The default is 32 MiB. Each endpoint's own `maxMessageBytes` (also 32 MiB by default) must not be larger: `bind()` throws an error if it is, because the shared server would refuse those messages first. A message over the limit closes the socket with `1009`.

```ts [huddle-server.ts]
import { setup } from '@livething/server-node/hono'
import { huddle } from './server/huddle-definition'

const { bind } = setup({ maxMessageBytes: 64 * 1024 * 1024 })
const huddleEndpoint = bind(huddle, {
  sql: './data/huddle.sqlite',
  maxMessageBytes: 64 * 1024 * 1024,
})
```

When you pass your own `webSocketServer`, set its `maxPayload` yourself, and leave `maxMessageBytes` out of `setup()`: `setup()` throws if it gets both. LiveThing checks each endpoint's `maxMessageBytes` against your server's `maxPayload`. `maxMessageBytes` must be a whole number from 1 to `2147483647`, because `ws` keeps `maxPayload` as a 32-bit number.

## Compression

Compression also belongs to the shared `ws` server, so you turn it on in `setup()`, for every endpoint. `compression: true` turns on WebSocket compression (`permessage-deflate`) for messages of at least 1024 bytes. Pass `compression: { threshold }` to change that size, in bytes:

```ts [huddle-server.ts]
import { setup } from '@livething/server-node/hono'
import { huddle } from './server/huddle-definition'

const { bind } = setup({ compression: true })
const huddleEndpoint = bind(huddle, {
  sql: './data/huddle.sqlite',
})
```

[Compression](/server/adapters/node/node-http#compression) helps JSON and text a lot, but not bytes that are already compressed, such as images, audio and video. It costs CPU and memory for every connection, so it is off by default. When you pass your own `webSocketServer`, set `perMessageDeflate` on it instead: `setup()` throws if it gets both.

## Routes and rejections

Your normal Hono middleware runs before the endpoint. LiveThing's [`authenticate(request)`](/server/server/authenticate) receives the full request URL, so read the query string or headers from it when the definition needs them:

```ts [server/huddle-definition.ts]
import { server } from '@livething/server'
import { CloseCodes, RejectAuth } from '@livething/server/errors'
import { verifySession } from './auth'

const base = server({
  async authenticate(request) {
    const token = request.headers
      .get('Authorization')
      ?.replace('Bearer ', '')
    const user = await verifySession(token)
    if (!user) {
      throw RejectAuth(CloseCodes.AUTH_INVALID, 'invalid session')
    }

    return {
      userId: user.id,
      meta: { name: user.name, role: user.role },
    }
  },
})
```

Call `bind()` once for each LiveThing definition. Then pass that endpoint's `upgrade` handler to its Hono route.

The LiveThing route only handles WebSocket upgrade requests. A plain HTTP request to the same path goes to the next Hono handler, and your `authenticate` hook does not run. If no other handler matches, Hono answers `404`.

`authenticate(request)` can reject a connection in two ways:

- **HTTP rejection** (a status from `400` to `599`). The binding returns it as a Hono response, before the WebSocket handshake. When the client sent a WebSocket upgrade request, `@hono/node-server` sends the status and headers of that response, but not its body.
- **Close-code rejection** (a WebSocket close code). The binding completes the handshake, then closes the socket with that code.

## Call the admin API from a route

The endpoint's [admin API](/server/admin/overview) runs in the same process as Hono, so a normal Hono route can use it. For example, Huddle's moderators post an announcement from an internal dashboard:

```ts [huddle-server.ts]
import { setup } from '@livething/server-node/hono'
import { Hono } from 'hono'
import { verifySession } from './auth'
import { huddle } from './server/huddle-definition'

const app = new Hono()
const { bind } = setup()
const huddleEndpoint = bind(huddle, {
  sql: './data/huddle.sqlite',
})

app.post('/admin/announcements', async (context) => {
  const token = context.req
    .header('authorization')
    ?.replace(/^Bearer /i, '')
  const user = await verifySession(token) // your auth
  if (user?.role !== 'admin') return context.body(null, 401)

  const { text } = (await context.req.json()) as { text: string }

  const admin = await huddleEndpoint.admin()
  await admin.announce(text)

  return context.body(null, 204)
})
```

`announce` comes from Huddle's [admin `api`](/server/admin/authoring). The same object also has the built-in operations, such as `purgeUser` and `connectionCount`. An [admin call](/server/adapters/node/node-http#call-the-admin-api-from-your-app) skips every check that protects the socket side, so protect each admin route with your own auth.

## Client IP

Hono's Node server gives this binding the original Node request. So `clientIp` works the same way as it does with [`node:http`](/server/adapters/node/node-http#client-ip):

```ts
import { setup } from '@livething/server-node/hono'
import { huddle } from './server/huddle-definition'

const { bind } = setup()
const huddleEndpoint = bind(huddle, {
  clientIp: { mode: 'direct' },
})
```

If your app runs behind proxies you trust, use `mode: 'proxy'` and list their networks in `trustedProxies`. The binding does not trust forwarding headers from the request unless you configure proxy mode.

## Shutdown

LiveThing does not close your HTTP server. Your app stops both parts:

```ts
import { createAdaptorServer } from '@hono/node-server'
import { setup } from '@livething/server-node/hono'
import { Hono } from 'hono'
import { huddle } from './server/huddle-definition'

const app = new Hono()
const { bind, shutdown, websocket } = setup()
const huddleEndpoint = bind(huddle, {
  sql: './data/huddle.sqlite',
})
app.get('/huddle', huddleEndpoint.upgrade)

const server = createAdaptorServer({ fetch: app.fetch, websocket })

process.once('SIGTERM', async () => {
  await shutdown()
  server.close()
})
```

An upgrade can arrive after `shutdown()` starts but before `server.close()` runs. The binding closes the network socket of that upgrade and does not run `authenticate(request)`.
