---
title: SvelteKit
description: Share SvelteKit development and production Node servers with LiveThing.
---

SvelteKit does not route WebSocket upgrades through `+server` files. Attach LiveThing to Vite's Node server in development and use an `adapter-node` custom server in production.

## Install

```bash [pnpm]
pnpm add @livething/core @livething/server @livething/server-node sirv
pnpm add -D @sveltejs/adapter-node
```

`adapter-node` builds SvelteKit as a Node request handler. `sirv` serves the built browser files because the custom production server below replaces the adapter's normal server entry point.

Configure the adapter:

```js [svelte.config.js]
import adapter from '@sveltejs/adapter-node'

export default {
  kit: {
    adapter: adapter(),
  },
}
```

This produces `build/handler.js`, which the production server will import. If pnpm blocks native install scripts, allow `better-sqlite3` and `esbuild` through `pnpm.onlyBuiltDependencies` in `package.json`. LiveThing's default Node SQL provider uses `better-sqlite3` for durable data.

The finished server wiring uses these files:

```text
livething.js
server.js
src/lib/server/chat-definition.ts
svelte.config.js
vite.config.ts
```

`livething.js`, `server.js`, and the runtime values in `chat-definition.ts` are server-only. Client code may import the inferred client contract from `chat-definition.ts` with `import type`; TypeScript removes that import from the browser build.

## Create the shared LiveThing setup

```js [livething.js]
import { setup } from '@livething/server-node'
import { chatDefinition } from './src/lib/server/chat-definition.ts'

export const livething = setup()
export const chat = livething.bind(chatDefinition, {
  sql: './data/chat.sqlite',
})

export function handleLiveThingUpgrade(request, socket, head) {
  const url = new URL(
    request.url ?? '/',
    `http://${request.headers.host}`,
  )
  if (url.pathname !== '/ws') return false

  chat.upgrade(request, socket, head)
  return true
}
```

`chatDefinition` is the [server definition](/server/server/overview) that contains your chat event handlers. Keep that file in TypeScript so it can export `InferClient<typeof chatDefinition>` for your client. This root module is shared by the development config and the production server, so both use one endpoint shape and one `/ws` path. Each process still creates its own LiveThing runtime.

## Development server

SvelteKit uses Vite's Node HTTP server during development. A small Vite plugin starts the chat server and attaches its upgrade listener before Vite starts listening. Add it before `sveltekit()`:

```ts [vite.config.ts]
import { sveltekit } from '@sveltejs/kit/vite'
import { defineConfig } from 'vite'
import { handleLiveThingUpgrade, livething } from './livething.js'

export default defineConfig({
  plugins: [
    {
      name: 'livething-chat',
      async configureServer(vite) {
        if (!vite.httpServer) {
          throw new Error('Vite did not create an HTTP server')
        }

        await livething.ready()
        vite.httpServer.on('upgrade', handleLiveThingUpgrade)
        vite.httpServer.once('close', () => void livething.shutdown())
      },
    },
    sveltekit(),
  ],
})
```

The upgrade function returns `false` for every path except `/ws`, so Vite can still handle its own hot-update WebSocket. The `close` listener releases LiveThing's connections, timers, and storage when the development server stops.

## Production server

Build SvelteKit with `adapter-node`, then import its generated request handler into a server that your app owns. `sirv` tries the generated browser files first; when none matches, the request goes to SvelteKit's handler:

```js [server.js]
import { createServer } from 'node:http'
import sirv from 'sirv'
import { handler } from './build/handler.js'
import { handleLiveThingUpgrade, livething } from './livething.js'

const assets = sirv('build/client', { gzip: true })
const server = createServer((request, response) => {
  assets(request, response, () => handler(request, response))
})

server.on('upgrade', (request, socket, head) => {
  if (!handleLiveThingUpgrade(request, socket, head)) socket.destroy()
})

await livething.ready()
server.listen(
  Number(process.env.PORT ?? 3000),
  process.env.HOST ?? '0.0.0.0',
)

process.once('SIGTERM', async () => {
  await livething.shutdown()
  server.close()
})
```

There is no Vite hot-update socket in this production process, so the server closes any WebSocket upgrade that is not for `/ws`.

Point your `start` script at the custom server:

```json [package.json]
{
  "scripts": {
    "start": "node server.js"
  }
}
```

Run `pnpm dev` during development. Run `pnpm build` and `pnpm start` in production.
