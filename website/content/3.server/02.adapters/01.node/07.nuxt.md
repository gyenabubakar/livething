title: Nuxt
description: Run a LiveThing WebSocket endpoint inside a Nuxt 4 Node server.
---

Nuxt 4 uses Nitro 2 and H3 v1. Use LiveThing's H3 v1 binding so the same WebSocket route works in development and in the built Node server.

## Install

```bash [pnpm]
pnpm add @livething/core @livething/server @livething/server-node h3@^1.15.11 crossws@^0.3.5
```

Nuxt's Nitro 2 server uses H3 v1 for routing and CrossWS 0.3 for its WebSocket transport. That is why this guide uses LiveThing's `/h3/v1` binding instead of the H3 v2 binding.

Allow pnpm to install the native SQLite dependency:

```json [package.json]
{
  "pnpm": {
    "onlyBuiltDependencies": ["better-sqlite3", "esbuild"]
  }
}
```

## Enable WebSockets

Enable Nitro's WebSocket support in the Nuxt config:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    experimental: {
      websocket: true,
    },
  },
})
```

## Add the WebSocket route

Keep the LiveThing endpoint in the route that owns it. Nitro turns this file path into `/ws/chat`:

The example expects `server/chat-definition.ts` to export the [server definition](/server/server/overview) that contains your chat event handlers.

```ts [server/routes/ws/chat.ts]
import { setup } from '@livething/server-node/h3/v1'
import { chatDefinition } from '../../chat-definition'

const livething = setup()

const chat = livething.bind(chatDefinition, {
  sql: './data/chat.sqlite',
})

export const ready = livething.ready
export const shutdown = livething.shutdown
export default chat.upgrade
```

`setup()` creates the Node adapter, `bind()` connects your server definition to it, and `chat.upgrade` handles the WebSocket handshake. The SQLite file keeps LiveThing's durable data across server restarts.

The client connects to `/ws/chat`.

## Start and stop LiveThing with Nitro

Use a Nitro plugin for the chat server's startup and shutdown. It finishes initialization before requests arrive and releases the chat server's connections, timers, and storage when Nitro closes. The route handles WebSocket upgrades; this plugin only handles that server definition's lifecycle:

```ts [server/plugins/chat.ts]
import { ready, shutdown } from '../routes/ws/chat'

export default defineNitroPlugin(async (nitroApp) => {
  await ready()
  nitroApp.hooks.hook('close', shutdown)
})
```

Nuxt provides `defineNitroPlugin` as an auto-import, so no import is missing from this file.

Run `pnpm dev` during development. Build with `pnpm build`, then run the Node output:

```bash
HOST=0.0.0.0 PORT=3000 node .output/server/index.mjs
```

The H3 v1 binding does not support the `clientIp` option because H3 v1 does not give the route the original Node request. See [H3 on Node.js](/server/adapters/node/h3#h3-v1) for the other H3 v1 limits.
