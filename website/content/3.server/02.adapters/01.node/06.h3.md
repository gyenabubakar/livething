LiveThing has separate bindings for H3 v2 and H3 v1. Both let H3 match the route while CrossWS handles the WebSocket upgrade.

## H3 v2

Use `@livething/server-node/h3` with H3 v2 and CrossWS 0.4.

```bash [pnpm]
pnpm add @livething/server-node h3@^2.0.1-rc.31 crossws@^0.4.12
```

```ts [server.ts]
import { setup } from '@livething/server-node/h3'
import { serve } from 'crossws/server/node'
import { H3 } from 'h3/node'
import { chatDefinition } from './definition'

const app = new H3()

const { bind, ready, shutdown } = setup()
const chat = bind(chatDefinition, {
  sql: './data/chat.sqlite',
})

app.get('/ws/:room', chat.upgrade)

await ready()

const server = serve({
  fetch: app.fetch,
  websocket: {},
  hostname: '127.0.0.1',
  port: 3000,
})

process.once('SIGTERM', async () => {
  await shutdown()
  server.node?.server.close()
})
```

H3 matches `:room`. The definition can read the route from `new URL(request.url).pathname` inside `upgrade(request)`.

For an HTTP rejection, CrossWS sends the response before the WebSocket handshake. For a close-code rejection, it completes the handshake and then closes the socket.

### Client IP

The H3 v2 binding can access the original Node request, so it supports the same `clientIp` options as [`node:http`](/server/adapters/node/node-http#client-ip):

```ts
const chat = bind(chatDefinition, {
  clientIp: { mode: 'direct' },
})
```

For a trusted proxy chain, use `mode: 'proxy'` and list its networks.

## H3 v1

Use `@livething/server-node/h3/v1` with H3 v1 and CrossWS 0.3.

```bash [pnpm]
pnpm add @livething/server-node h3@^1.15.11 crossws@^0.3.5
```

```ts [server.ts]
import { createServer } from 'node:http'
import { setup } from '@livething/server-node/h3/v1'
import nodeWebSocketAdapter from 'crossws/adapters/node'
import { createApp, createRouter, toNodeListener } from 'h3'
import { chatDefinition } from './definition'

const app = createApp()
const router = createRouter()

const { bind, ready, shutdown } = setup()
const chat = bind(chatDefinition, {
  sql: './data/chat.sqlite',
})

router.get('/ws/:room', chat.upgrade)
app.use(router)

const websocket = nodeWebSocketAdapter(app.websocket)
const server = createServer(toNodeListener(app))
server.on('upgrade', websocket.handleUpgrade)

await ready()

server.listen(3000, '127.0.0.1')

process.once('SIGTERM', async () => {
  await shutdown()
  server.close()
})
```

H3 v1 gives the binding the request URL and headers, but not the original Node request. Because of that, this binding does not accept the `clientIp` option. Use another Node binding if the server must derive a trusted client IP from the socket or a proxy chain.

H3 v1 also does not report when a client leaves during async `upgrade(request)` work. LiveThing finishes that work and removes the connection when CrossWS reports the close. Keep upgrade checks short and safe to finish after a client leaves. Use the H3 v2 binding when upgrade cancellation is required.

## Server ownership

`setup()` does not create or listen on an HTTP server. Your application starts the server and closes it after `shutdown()` finishes. If an upgrade arrives after shutdown starts, the H3 v2 binding drops the socket and the H3 v1 binding returns HTTP 503.
