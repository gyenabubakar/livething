Use `@wskit/server-node/h3` when H3 owns matching and CrossWS owns the Node upgrade transport.

```bash [pnpm]
pnpm add @wskit/server-node h3 crossws
```

```ts [server.ts]
import { setup } from '@wskit/server-node/h3'
import { serve } from 'crossws/server/node'
import { H3 } from 'h3/node'
import { chatHandler } from './handler'

const app = new H3()
const { bind, ready, shutdown } = setup()
const chat = bind(chatHandler, {
  sql: './data/chat.sqlite',
})

app.get('/ws/:room', chat.upgrade)

await ready()

const server = serve({
  fetch: app.fetch,
  websocket: {},
  hostname: '127.0.0.1',
  port: 3000,
})
```

H3 matches `:room`. CrossWS resolves the route's WebSocket hooks from H3, then hands the peer to WSKit. The definition can read a route value from `new URL(request.url).pathname` in `upgrade(request)`.

For an HTTP-style rejection, CrossWS writes the rejection response before a WebSocket handshake. For a close-code rejection, it upgrades and immediately closes the peer.

## Client IP

On Node, H3 keeps the original Node request behind its Web API request. This binding uses that request, so `clientIp` works the same way as it does with [`node:http`](/server/adapters/node/node-http#client-ip):

```ts
const chat = bind(chatHandler, {
  clientIp: { mode: 'direct' },
})
```

For a trusted proxy chain, use `mode: 'proxy'` and list its networks. Configure this endpoint option instead of relying on H3's own proxy settings, so WSKit uses one explicit trust rule.

The server is still yours. Stop WSKit before its Node server:

```ts
process.once('SIGTERM', async () => {
  await shutdown()
  server.node?.server.close()
})
```
