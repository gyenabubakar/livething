Express handles normal HTTP routes. A WebSocket connection starts as an HTTP **upgrade** request: the client asks the server to switch the connection from HTTP to WebSocket. Express does not send upgrade requests through its routes or middleware. Node sends them to the `upgrade` event of the HTTP server instead. So you bind LiveThing to the Node HTTP server that runs your Express app, not to the Express app itself.

```bash [pnpm]
pnpm add @livething/server @livething/server-node @livething/core express
pnpm add -D @types/express
```

Express does not include TypeScript types, so the second command installs them.

```ts [huddle-server.ts]
import { createServer } from 'node:http'
import { setup } from '@livething/server-node'
import express from 'express'
import { huddle } from './server/huddle-definition'

const app = express()
app.get('/health', (_request, response) =>
  response.json({ ok: true }),
)

const httpServer = createServer(app)
const { bind, ready } = setup()
const huddleEndpoint = bind(huddle, { sql: './data/huddle.sqlite' })

httpServer.on('upgrade', (request, socket, head) => {
  const url = new URL(request.url ?? '/', 'http://localhost')
  if (url.pathname === '/huddle') {
    huddleEndpoint.upgrade(request, socket, head)
    return
  }

  socket.destroy()
})

await ready()
httpServer.listen(3000)
```

Express route parameters and middleware do not run for an upgrade request. Match the WebSocket path yourself inside the `upgrade` listener, as the example does. If you want to declare WebSocket routes with the framework's own router (with route parameters and middleware), use [Hono](/server/adapters/node/hono), [Fastify](/server/adapters/node/fastify), or [H3](/server/adapters/node/h3) instead.

## Call the admin API from a route

The endpoint's [admin API](/server/admin/overview) runs in the same process as Express, so a normal Express route can use it. For example, Huddle's moderators post an announcement from an internal dashboard:

```ts [admin-routes.ts]
import express from 'express'
import { verifySession } from './auth'
import { huddleEndpoint } from './huddle-endpoint'

export const adminRoutes = express.Router()

adminRoutes.post(
  '/announcements',
  express.json(),
  async (request, response) => {
    const token = request
      .header('authorization')
      ?.replace(/^Bearer /i, '')
    const user = await verifySession(token) // your auth
    if (user?.role !== 'admin') {
      response.sendStatus(401)
      return
    }

    const admin = await huddleEndpoint.admin()
    await admin.announce(request.body.text)
    response.sendStatus(204)
  },
)
```

Mount the router with `app.use('/admin', adminRoutes)`. Here `huddleEndpoint` is the endpoint from `bind(huddle, ...)`, exported from its own module (`huddle-endpoint.ts`) so the upgrade listener and the routes share it.

`announce` comes from Huddle's [admin `api`](/server/admin/authoring). The same object also has the built-in operations, such as `purgeUser` and `connectionCount`. An admin call skips every check that protects the socket side, so protect each admin route with your own auth. See [Call the admin API from your app](/server/adapters/node/node-http#call-the-admin-api-from-your-app).

Everything else works the same as on the [node:http](/server/adapters/node/node-http) page: adapter options, client IP setup, storage, and shutdown.
