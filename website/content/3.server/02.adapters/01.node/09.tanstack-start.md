description: Run a LiveThing WebSocket endpoint inside a TanStack Start Node server.

TanStack Start can run inside a Nitro 3 Node server. This is a Vite and Nitro integration, not a TanStack server function. A Nitro WebSocket route gives LiveThing the same `/ws/chat` endpoint in development and production.

## Install

```bash [pnpm]
pnpm add @livething/core @livething/server @livething/server-node h3@^2.0.1-rc.31 crossws@^0.4.12 nitro
```

Nitro provides the Node server, route files, and lifecycle hooks. H3 routes its HTTP and WebSocket requests, and CrossWS provides the WebSocket transport. If pnpm blocks native install scripts, allow `better-sqlite3` and `esbuild` through `pnpm.onlyBuiltDependencies` in `package.json`. LiveThing's default Node SQL provider uses `better-sqlite3` for durable data.

## Configure Nitro

Keep your existing TanStack Start and React plugins, then enable the Nitro Node server and WebSockets:

```ts [vite.config.ts]
import { tanstackStart } from '@tanstack/react-start/plugin/vite'
import react from '@vitejs/plugin-react'
import { nitro } from 'nitro/vite'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [tanstackStart(), react(), nitro()],
  nitro: {
    serverDir: './server',
    preset: 'node_server',
    features: {
      websocket: true,
    },
  },
})
```

Keep any other Vite plugins and TanStack Start options already in your project.

`serverDir` tells Nitro where the route and plugin files live, `node_server` builds a Node process, and `features.websocket` enables Nitro's WebSocket upgrade path.

## Add the LiveThing route

Keep the endpoint with the Nitro route that owns it. This file becomes `/ws/chat`:

The example expects `server/chat-definition.ts` to export the [server definition](/server/server/overview) that contains your chat event handlers.

```ts [server/routes/ws/chat.ts]
import { setup } from '@livething/server-node/h3'
import { chatDefinition } from '../../chat-definition'

const livething = setup()

const chat = livething.bind(chatDefinition, {
  sql: './data/chat.sqlite',
})

export const ready = livething.ready
export const shutdown = livething.shutdown
export default chat.upgrade
```

`setup()` creates the shared adapter, `bind()` connects the server definition, and `chat.upgrade` handles this route's WebSocket handshake. The SQLite file keeps LiveThing's durable data across server restarts. Use a Nitro plugin named after the chat server to start it before traffic arrives and close it when Nitro stops:

```ts [server/plugins/chat.ts]
import { definePlugin } from 'nitro'
import { ready, shutdown } from '../routes/ws/chat'

export default definePlugin(async (nitroApp) => {
  await ready()
  nitroApp.hooks.hook('close', shutdown)
})
```

The client connects to `/ws/chat`. `definePlugin` is a Nitro lifecycle hook, not an HTTP route. It makes the adapter ready before traffic arrives and releases its connections, timers, and storage when Nitro stops.

Run `pnpm dev` during development. Build and run the Node output with:

```bash
pnpm build
HOST=0.0.0.0 PORT=3000 node .output/server/index.mjs
```

This route is separate from TanStack Start's HTTP server functions. Those functions handle normal HTTP requests; Nitro and CrossWS handle the WebSocket upgrade.
