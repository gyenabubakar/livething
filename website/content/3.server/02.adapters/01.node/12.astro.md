---
title: Astro
description: Share Astro development and production Node servers with LiveThing.
---

Use an Astro integration hook in development and the Node adapter's middleware mode in production. Both let LiveThing attach to an HTTP server that the app owns.

## Install

```bash [pnpm]
pnpm astro add node
pnpm add @livething/core @livething/server @livething/server-node sirv
```

`astro add node` installs Astro's Node adapter and adds it to your config. `sirv` serves the built browser files from the custom production server below. If pnpm blocks native install scripts, allow `better-sqlite3` and `esbuild` through `pnpm.onlyBuiltDependencies` in `package.json`. LiveThing's default Node SQL provider uses `better-sqlite3` for durable data.

The finished server wiring uses these files:

```text
astro.config.mjs
livething.mjs
server.js
src/server/chat-definition.ts
```

`livething.mjs`, `server.js`, and the runtime values in `chat-definition.ts` run only on the server. Client code may import the inferred client contract from `chat-definition.ts` with `import type`; TypeScript removes that import from the browser build.

## Create the shared LiveThing setup

```js [livething.mjs]
import { setup } from '@livething/server-node'
import { chatDefinition } from './src/server/chat-definition.ts'

export const livething = setup()
export const chat = livething.bind(chatDefinition, {
  sql: './data/chat.sqlite',
})

export function handleLiveThingUpgrade(request, socket, head) {
  const url = new URL(
    request.url ?? '/',
    `http://${request.headers.host}`,
  )
  if (url.pathname !== '/ws') return false

  chat.upgrade(request, socket, head)
  return true
}
```

`chatDefinition` is the [server definition](/server/server/overview) that contains your chat event handlers. Node.js 24 can run this `.ts` module directly. This root module is shared by the Astro config in development and the custom Node server in production. Each process still creates its own LiveThing runtime.

Export the inferred contract beside the definition:

```diff [src/server/chat-definition.ts]
diff --git a/src/server/chat-definition.ts b/src/server/chat-definition.ts
--- a/src/server/chat-definition.ts
+++ b/src/server/chat-definition.ts
@@ -1,0 +1 @@
+import type { InferClient } from '@livething/server'
@@ -20,3 +21,5 @@
 export const chatDefinition = base.assemble({
   handlers: [handleSendMessage],
 })
+
+export type ChatClient = InferClient<typeof chatDefinition>
```

Client code imports only that type:

```ts [src/components/chat-client.ts]
import { client, connect } from '@livething/client'
import type { ChatClient } from '../server/chat-definition'

const socket = client<ChatClient>()(connect('wss://example.com/ws'))

socket.connect()
```

Because this is an `import type`, Astro does not include the server definition or `@livething/server` in the browser bundle.

## Development server

Add an Astro integration that attaches LiveThing before the development server starts listening. `astro:server:setup` gives the integration Vite's Node HTTP server. `astro:server:done` runs when that development server stops:

```js [astro.config.mjs]
import node from '@astrojs/node'
import { defineConfig } from 'astro/config'
import { handleLiveThingUpgrade, livething } from './livething.mjs'

const livethingIntegration = {
  name: 'livething',
  hooks: {
    'astro:server:setup': async ({ server }) => {
      if (!server.httpServer) {
        throw new Error('Astro did not create an HTTP server')
      }

      await livething.ready()
      server.httpServer.on('upgrade', handleLiveThingUpgrade)
    },
    'astro:server:done': () => livething.shutdown(),
  },
}

export default defineConfig({
  adapter: node({ mode: 'middleware' }),
  integrations: [livethingIntegration],
})
```

The upgrade function returns `false` for every path except `/ws`, so Astro and Vite can keep their own hot-update WebSocket behavior.

## Production server

Middleware mode writes an Astro request handler instead of starting a server. The generated `dist/server/entry.mjs` handles Astro requests. `sirv` tries the generated files in `dist/client` first, and other HTTP requests go to Astro. LiveThing attaches to that same Node server:

```js [server.js]
import { createServer } from 'node:http'
import sirv from 'sirv'
import { handler } from './dist/server/entry.mjs'
import { handleLiveThingUpgrade, livething } from './livething.mjs'

const assets = sirv('dist/client', { gzip: true })
const server = createServer((request, response) => {
  assets(request, response, () => handler(request, response))
})

server.on('upgrade', (request, socket, head) => {
  if (!handleLiveThingUpgrade(request, socket, head)) socket.destroy()
})

await livething.ready()
server.listen(
  Number(process.env.PORT ?? 3000),
  process.env.HOST ?? '0.0.0.0',
)

process.once('SIGTERM', async () => {
  await livething.shutdown()
  server.close()
})
```

There is no Vite hot-update socket in this production process, so the server closes any WebSocket upgrade that is not for `/ws`.

Add `"start": "node server.js"` to `package.json`. Run `pnpm dev` during development, then `pnpm build` and `pnpm start` for the production Node server.
