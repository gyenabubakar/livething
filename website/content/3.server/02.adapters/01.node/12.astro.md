---
title: Astro
description: Share Astro development and production Node servers with LiveThing.
---

In development, attach LiveThing with an Astro **integration**. An integration is an object in `astro.config.mjs` with hooks. Astro calls each hook at a fixed point, for example when the development server starts. In production, build Astro with its Node adapter in **middleware mode** and run it inside a Node server that your app owns. In both cases, LiveThing attaches to that HTTP server.

## Install

```bash [pnpm]
pnpm astro add node
pnpm add @livething/core @livething/server @livething/server-node sirv
```

`astro add node` installs Astro's Node adapter (`@astrojs/node`) and adds it to your config. The [development server](#development-server) section below sets its mode to `middleware`. `sirv` serves the built browser files from the custom production server below. If pnpm blocks native install scripts, allow `better-sqlite3` and `esbuild` through `pnpm.onlyBuiltDependencies` in `package.json`. LiveThing's default Node SQL provider uses `better-sqlite3` for durable data.

The finished server wiring uses these files:

```text
astro.config.mjs
livething.mjs
server.js
src/server/definition.ts
```

`livething.mjs`, `server.js`, and the runtime values in `definition.ts` run only on the server. The **client contract** is a TypeScript type that lists the events, requests, and streams your server offers. LiveThing infers (builds) it from your server definition. Client code may import that type from `definition.ts` with `import type`. TypeScript removes an `import type` from the built JavaScript, so no server code reaches the browser.

## Create the shared LiveThing setup

```js [livething.mjs]
import { setup } from '@livething/server-node'
import { huddle } from './src/server/definition.ts'

export const livething = setup()
export const huddleEndpoint = livething.bind(huddle, {
  sql: './data/huddle.sqlite',
})

export function handleLiveThingUpgrade(request, socket, head) {
  const url = new URL(
    request.url ?? '/',
    `http://${request.headers.host}`,
  )
  if (url.pathname !== '/ws') return false

  huddleEndpoint.upgrade(request, socket, head)
  return true
}
```

`huddle` is the [server definition](/server/server/overview) that contains your event handlers. Node.js 24 can run this `.ts` module directly, because Node.js removes the TypeScript types when it loads the file. The Astro config (in development) and the custom Node server (in production) both import this root module. Each process still creates its own LiveThing runtime.

Export the inferred contract beside the definition:

```diff [src/server/definition.ts]
diff --git a/src/server/definition.ts b/src/server/definition.ts
--- a/src/server/definition.ts
+++ b/src/server/definition.ts
@@ -1,0 +1 @@
+import type { InferClient } from '@livething/server'
@@ -20,3 +21,5 @@
 export const huddle = base.assemble({
   handlers: [handleSendMessage],
 })
+
+export type HuddleSocket = InferClient<typeof huddle>
```

Client code imports only that type:

```ts [src/components/socket.ts]
import { client, connect } from '@livething/client'
import type { HuddleSocket } from '../server/definition'

const socket = client<HuddleSocket>()(connect('wss://example.com/ws'))

socket.connect()
```

Because this is an `import type`, Astro does not include the server definition or `@livething/server` in the browser bundle.

## Development server

Astro's development server is a Vite server. Add an integration that attaches LiveThing before that server starts listening. Astro calls the `astro:server:setup` hook after it creates the Vite server and before the server listens. The hook receives the Vite server, and `server.httpServer` is its Node HTTP server. Astro calls `astro:server:done` after the development server closes:

```js [astro.config.mjs]
import node from '@astrojs/node'
import { defineConfig } from 'astro/config'
import { handleLiveThingUpgrade, livething } from './livething.mjs'

const huddleWebSocketIntegration = {
  name: 'livething-huddle',
  hooks: {
    'astro:server:setup': async ({ server }) => {
      if (!server.httpServer) {
        throw new Error('Astro did not create an HTTP server')
      }

      await livething.ready()
      server.httpServer.on('upgrade', handleLiveThingUpgrade)
    },
    'astro:server:done': () => livething.shutdown(),
  },
}

export default defineConfig({
  adapter: node({ mode: 'middleware' }),
  integrations: [huddleWebSocketIntegration],
})
```

Vite opens its own WebSocket to send code changes to the browser while you edit (hot updates). The upgrade function returns `false` for every path except `/ws`, so it does not touch that Vite WebSocket. The `astro:server:done` hook calls `livething.shutdown()`, which closes LiveThing's connections, timers, and storage.

## Production server

In middleware mode, `pnpm build` creates an Astro request handler but does not start a server. The generated `dist/server/entry.mjs` exports `handler`, which handles Astro requests. The browser files go to `dist/client`. In the server below, `sirv` tries those files first. When no file matches, the request goes to Astro. LiveThing attaches to the same Node server:

```js [server.js]
import { createServer } from 'node:http'
import sirv from 'sirv'
import { handler } from './dist/server/entry.mjs'
import { handleLiveThingUpgrade, livething } from './livething.mjs'

const assets = sirv('dist/client', { gzip: true })
const server = createServer((request, response) => {
  assets(request, response, () => handler(request, response))
})

server.on('upgrade', (request, socket, head) => {
  if (!handleLiveThingUpgrade(request, socket, head)) socket.destroy()
})

await livething.ready()
server.listen(
  Number(process.env.PORT ?? 3000),
  process.env.HOST ?? '0.0.0.0',
)

process.once('SIGTERM', async () => {
  await livething.shutdown()
  server.close()
})
```

There is no Vite hot-update socket in this production process, so the server closes any WebSocket upgrade that is not for `/ws`.

Add `"start": "node server.js"` to the `scripts` in `package.json`. Run `pnpm dev` during development. In production, run `pnpm build` and then `pnpm start`.
