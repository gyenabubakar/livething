Use `@wskit/server-node/fastify` with [`@fastify/websocket`](https://github.com/fastify/fastify-websocket). Register the plugin before routes, because it owns Fastify's upgrade hook.

```bash [pnpm]
pnpm add @wskit/server-node fastify @fastify/websocket
```

```ts [server.ts]
import websocket from '@fastify/websocket'
import { setup } from '@wskit/server-node/fastify'
import Fastify from 'fastify'
import { chatDefinition } from './definition'

const app = Fastify()
await app.register(websocket)

const { bind, ready, shutdown } = setup()
const chat = bind(chatDefinition, {
  sql: './data/chat.sqlite',
})

app.get('/ws/:room', chat.upgrade)

await ready()
await app.listen({ port: 3000 })
```

Fastify matches `:room`, runs its normal lifecycle hooks, and then hands an accepted socket to WSKit. Do not add `websocket: true`: the returned route object already supplies Fastify's `wsHandler` and normal HTTP handler. For information the WSKit definition needs, read the route part from `new URL(request.url).pathname` in `upgrade(request)`.

An HTTP rejection is sent by Fastify's `preHandler`, before the socket is accepted. A close-code rejection accepts the socket and closes it with that code.

## Client IP

This binding passes Fastify's original Node request to WSKit, so `clientIp` works the same way as it does with [`node:http`](/server/adapters/node/node-http#client-ip):

```ts
const chat = bind(chatDefinition, {
  clientIp: { mode: 'direct' },
})
```

For a trusted proxy chain, use `mode: 'proxy'` and list its networks. Configure this endpoint option instead of relying on Fastify's `request.ip`, so WSKit uses one explicit trust rule.

```ts
process.once('SIGTERM', async () => {
  await shutdown()
  await app.close()
})
```

If an upgrade arrives in the short time between `shutdown()` starting and `app.close()`, the binding drops its socket without running `upgrade(request)`.
