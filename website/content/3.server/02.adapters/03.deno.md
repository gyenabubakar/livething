LiveThing has no Deno adapter. Deno can run most Node.js code, so the [Node.js adapter](/server/adapters/node), `@livething/server-node`, runs on Deno with one change: you give it a `node:sqlite` database. Your definition and your `node:http` server stay the same.

::warning
Deno is not a supported runtime. LiveThing's CI runs the Node.js adapter on Node.js only. We ran LiveThing's end-to-end tests once on Deno 2.9, with a `node:http` server and a `node:sqlite` database, over WebSocket and server-sent events, and they passed. A later Deno or LiveThing release can still break it. The [Node frameworks](/server/adapters/node#frameworks) were not tried on Deno.
::

## Install

Install the packages from npm with `deno add`:

```bash [deno]
deno add npm:@livething/server npm:@livething/server-node npm:@livething/core
```

## Storage

On Node.js, the adapter stores `ctx.sql` and `ctx.kv` in SQLite through [better-sqlite3](https://github.com/WiseLibs/better-sqlite3) by default. Deno cannot load better-sqlite3: it is a native module built on an older Node API that Deno does not have. So on Deno, a file path or no `sql` option makes `bind()` throw.

Deno has its own SQLite in the `node:sqlite` module. Open a `DatabaseSync` and pass it as `sql`. The adapter keeps `ctx.kv` in the same database. better-sqlite3 is still installed with the adapter, but its native code never loads.

## The server

The entry file is the [node:http](/server/adapters/node#nodehttp) setup from the Node.js page, with two changes. `sql` is a `node:sqlite` database. And local imports end in `.ts`, because Deno does not guess file extensions. LiveThing does not close a database that you pass in, so close it after `shutdown()`. `node:sqlite` creates the file but not its folder, so create the `data` folder first.

```ts [huddle-server.ts]
import { createServer } from 'node:http'
import { DatabaseSync } from 'node:sqlite'
import { setup } from '@livething/server-node'
import { huddle } from './server/huddle-definition.ts'

const huddleDatabase = new DatabaseSync('./data/huddle.sqlite')
const { bind, ready, shutdown } = setup()
const huddleEndpoint = bind(huddle, { sql: huddleDatabase })

const app = createServer((request, response) => {
  response.statusCode = 404
  response.end()
})

app.on('upgrade', (request, socket, head) => {
  const url = new URL(
    request.url ?? '/',
    `http://${request.headers.host}`,
  )

  if (url.pathname === '/huddle') {
    huddleEndpoint.upgrade(request, socket, head)
    return
  }

  socket.destroy()
})

await ready()
app.listen(3000)

process.once('SIGTERM', async () => {
  await shutdown()
  huddleDatabase.close()
  app.close()
})
```

Run it with the permissions it needs: the network for the server, and the file system for the database.

```bash [deno]
deno run --allow-net --allow-read --allow-write --allow-env huddle-server.ts
```

Everything else on the [Node.js page](/server/adapters/node) applies: the options of `bind()`, server-sent events with `sse()` and `huddleEndpoint.handle`, the admin API, and shutdown. Like Node.js, Deno does not support hibernation.
