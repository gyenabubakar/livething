**Broadcasting** runs one generator and sends each of its chunks to many connections at the same time. This is called **fan-out**: one source, many receivers. Set `broadcast: true` on a stream. The server runs the generator once, on the connection that started the stream (the **creator**). Every connection in scope receives the same chunks. You write the same generator as for any other stream. The only change is who receives the chunks.

Broadcast is an option on a stream. It is not a third stream kind. It works on plain and recorded streams. This page covers the scope rules, durable broadcast, and channel-scoped broadcast. For how a client receives a broadcast (it only listens, with `onStream`), see [Broadcast (onStream)](/client/streams/broadcast-onstream).

## A plain broadcast stream

Add `broadcast: true`, and the generator's chunks go to every connection in scope. The **scope** is the set of connections that receive the chunks. For a top-level stream, the scope is every connection that is connected to the server. Here `tail-audit-log` is a broadcast, so every connection sees the same log lines. Huddle's own `tail-audit-log` does not have `broadcast: true`.

```ts [server/admin.ts]
import { server } from '@livething/server'
import { stream } from '@livething/server/streams'
import * as v from 'valibot'
import { auditLogEntries } from './audit-log'

const base = server({
  capabilities: [stream()],
})

export const handleTailAuditLog = base.stream('tail-audit-log', {
  input: v.object({}),
  broadcast: true,
  async *run(ctx) {
    for await (const entry of auditLogEntries(ctx.stream.signal)) {
      yield { line: entry.line }
    }
  },
})
```

One client starts the stream, and every connection in scope gets the chunks. Each chunk carries the same stream ID and the same sequence number for every receiver. So every subscriber sees the chunks in the same order. Each chunk is one frame: the creator and every subscriber get the same bytes, and the [`onOutgoing`](/server/lifecycle-and-intercept/outgoing) hook sees each chunk once.

## How a broadcast ends for subscribers

A **subscriber** is a connection in scope that receives the chunks but did not start the stream. When the generator finishes or throws, the server sends a **terminal frame** to every subscriber too. This frame carries the stream's event name, so each client knows which stream ended.

| Event                             | What subscribers see                                                    |
| --------------------------------- | ----------------------------------------------------------------------- |
| Generator completes               | A stream-end frame, sent to every subscriber.                           |
| Generator throws a defined error  | That error, as a terminal frame, sent to every subscriber.              |
| Generator throws an unknown error | `internal-error`, as a terminal frame, sent to every subscriber.        |
| Creator cancels the stream        | A stream-end frame. The stream is over for everyone.                    |
| A _subscriber_ cancels            | Only that subscriber stops. The stream keeps running for everyone else. |

The last two rows show who controls the run: the **creator**. A cancel from any other connection only removes that one subscriber.

```ts [server/admin.ts]
import * as v from 'valibot'
import { auditLogEntries } from './audit-log'
import { base } from './base'

export const handleTailAuditLogBoom = base.stream('tail-audit-log', {
  input: v.object({}),
  broadcast: true,
  async *run(ctx) {
    for await (const entry of auditLogEntries(ctx.stream.signal)) {
      yield { line: entry.line }
    }

    // The source ends early only when it loses its connection.
    // The creator and every subscriber get this terminal error.
    if (!ctx.stream.signal.aborted) {
      throw new Error('audit log source is unreachable')
    }
  },
})
```

## Durable broadcast

Recorded streams can broadcast too. One generator runs, and its chunks go to everyone in scope. The chunks are stored, so a **late joiner** first gets the chunks it missed from storage, then gets new chunks as they come.

The generator keeps running when the creator disconnects. Subscribers keep getting chunks, and the stream-end frame when the generator finishes. If the generator stops before it finishes (it throws, or the server restarts or is evicted while it runs), a subscriber that continues the stream gets the chunks it missed, then a terminal `StreamAborted` error with `reason: 'interrupted'`. So no subscriber is left waiting for an end that never comes.

A late joiner gets nothing from a durable broadcast until it continues the stream by its stream ID. On the client, it does this with [`continueStream`](/client/streams/durable-and-continue#reattaching-with-continuestream). Connections that were already in scope when the stream started get the chunks from the start.

This example uses a smaller server with a `rooms` channel and no `emits(...)`. The later examples on this page import Huddle's own `rooms`.

```ts [server/rooms.ts]
import { server } from '@livething/server'
import { channels } from '@livething/server/channels'
import { recordedStream } from '@livething/server/streams'
import * as v from 'valibot'
import { llm } from './llm'

const base = server({
  capabilities: [channels(), recordedStream()],
})

const rooms = base.channel(['rooms', 'room:{roomId}'], {})

// Recorded broadcast: late joiners get the stored chunks first, then new ones.
export const handleAskScout = rooms.recordedStream('ask-scout', {
  input: v.object({ prompt: v.string() }),
  broadcast: true,
  async *run(ctx, input) {
    const messages = [{ role: 'user', text: input.prompt }]
    for await (const piece of llm.stream({
      messages,
      signal: ctx.stream.signal,
    })) {
      yield { text: piece }
    }
  },
})
```

### A subscriber cancel doesn't stop the stream

On a durable broadcast, when a subscriber (not the creator) cancels, the server records that this user unsubscribed. The stream keeps running for everyone else. If the same user later tries to continue the stream, it gets `StreamAborted` with `reason: 'unsubscribed'`. The user chose to leave, so there is nothing to continue. A connection that leaves the stream's channel gets the same reason, because LiveThing stops the streams it ran there (see [Leaving the channel stops the stream](#leaving-the-channel-stops-the-stream)). See [abort reasons](/server/streams/config-and-lifecycle#abort-reasons).

## Steering a broadcast with a nudge

A **nudge** is a message the client sends into a running stream (see [Nudges](/server/streams/plain#nudges-steering-a-running-stream)). Only the creator can nudge a broadcast, because the generator runs on the creator's connection. A nudge from the creator changes the stream for every subscriber. For example, a `stop` nudge ends the stream for every subscriber, not only for the creator. This version of `ask-scout` reads only `stop`. Huddle's also reads `redirect`.

```ts [server/rooms.ts]
import * as v from 'valibot'
import { rooms } from './base'
import { llm } from './llm'

export const handleAskScoutNudged = rooms.recordedStream(
  'ask-scout',
  {
    input: v.object({ prompt: v.string() }),
    broadcast: true,
    nudges: { stop: null },
    async *run(ctx, input) {
      const messages = [{ role: 'user', text: input.prompt }]
      for await (const piece of llm.stream({
        messages,
        signal: ctx.stream.signal,
      })) {
        const recent = ctx.stream.nudges(yield { text: piece })
        if (recent.some((n) => n.event === 'stop')) return // ends for everyone
      }
    },
  },
)
```

## Channel-scoped broadcast

The place where you _declare_ a stream sets its scope. A top-level `base.stream` sends its chunks to every connection. A stream declared on a channel (created with `base.channel(...)`) sends its chunks only to that channel's members. Use this for a private room or a feed for one tenant.

```ts [server/rooms.ts]
import * as v from 'valibot'
import { rooms } from './base'
import { llm } from './llm'

export const handleAskScout = rooms.recordedStream('ask-scout', {
  input: v.object({ prompt: v.string() }),
  broadcast: true,
  async *run(ctx, input) {
    const messages = [{ role: 'user', text: input.prompt }]
    for await (const piece of llm.stream({
      messages,
      signal: ctx.stream.signal,
    })) {
      yield { text: piece }
    }
  },
})
```

Only connections subscribed to that channel receive the chunks. For a **durable** channel-scoped stream, a connection must be subscribed to the channel to continue the stream. See [Scoped Streams & Requests](/server/channels/scoped-streams-requests) for how channel membership controls access to a stream. The [Channels](/server/channels/overview) chapter explains channels: families like `room:{roomId}`, membership, and auth. Broadcast uses whatever scope the stream is declared in.

### Leaving the channel stops the stream

A channel-scoped stream is tied to the connection's membership in that channel. When the connection leaves the channel (it unsubscribes, is kicked, or is removed some other way), LiveThing stops every stream that connection runs in that channel. The stream's generator gets a `return()` call, so its `finally` block still runs. The owning connection, if still open, gets a terminal `stream-aborted` error with `reason: 'unsubscribed'`. For a broadcast stream, every other subscriber gets `__streamEnd__`. A recorded stream is also deleted from storage, so nobody can continue it after the leave. This always happens: a stream in a channel never keeps running for a connection that is no longer a member.

## Backpressure across many clients

**Backpressure** means slowing down the generator when clients cannot read chunks fast enough. `ctx.stream.drain()` works on a broadcast stream too. It waits for the **healthiest** receiver, never the slowest. So one slow client cannot stop the whole broadcast. That client falls behind and catches up later, or reaches its own buffer limits. On Cloudflare, the platform does not report how full a buffer is, so `drain()` resolves at once and does nothing, as on any other stream.
