A **stream** sends data to the client one chunk at a time instead of all at once: model tokens, query rows, a live feed. On the server you write an async generator and `yield` each chunk. The framework wires the rest — routing, backpressure, cancellation, and (for durable streams) resume after a drop.

This chapter is the deep one. For how a stream **capability** is registered (`stream()`, `resumableStream()`, `recordedStream()` in `define`), see [Stream capabilities](/server/capabilities/streams). For the basic "how do I write a stream handler method" intro, see [`base.stream`](/server/handlers/stream). Here you own the three stream kinds, durability, broadcast, and the full config.

## The three kinds

Every stream is an async generator, but they differ in what happens when the client disconnects and reconnects.

| Kind                    | Builder                | Survives a disconnect? | What is stored      | Reach for it when                                                                                                                                                   |
| ----------------------- | ---------------------- | ---------------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Plain (ephemeral)**   | `base.stream`          | No                     | Nothing             | The work is cheap to throw away — a live feed, a one-off render, anything the client can just re-request.                                                           |
| **Resumable (durable)** | `base.resumableStream` | Yes                    | Only the **cursor** | The source is re-runnable from a position — DB pagination, a file offset, a row ID. On resume the generator re-runs live from the saved cursor.                     |
| **Recorded (durable)**  | `base.recordedStream`  | Yes                    | Every **chunk**     | The source is one-shot and can't be replayed — LLM tokens, a push API. On resume the client gets the chunks it missed from a buffer; the generator does not re-run. |

The two durable kinds both need the [`persistence()`](/server/capabilities/persistence) capability. Plain streams need only `stream()`. List a durable builder without `persistence()` and `assemble(...)` throws at build time: `[wskit] The persistence() capability is required by ... but is not listed. Add persistence() to capabilities.`

::note
"Ephemeral" and "persistent" are the words that travel on the wire (the `streamKind` marker). Plain streams are `ephemeral`; both durable kinds are `persistent`.
::

## The same generator shape, three builders

All three builders take an event name and a config object with an async `run` generator. Each value the generator yields becomes one chunk on the wire.

```ts [stream-kinds.ts]
import { define, t } from '@wskit/server'
import { persistence } from '@wskit/server/persistence'
import { recordedStream, resumableStream, stream } from '@wskit/server/streams'
import * as v from 'valibot'

const Token = t<{ index: number }>()

const base = define({
  env: t<Env>(),
  capabilities: [stream(), persistence(), resumableStream(), recordedStream()],
})

// Plain: dies on disconnect.
const handleFeed = base.stream('feed', {
  input: v.object({ count: v.number() }),
  chunk: Token,
  async *run(_ctx, input) {
    for (let i = 0; i < input.count; i += 1) yield { index: i }
  },
})

// Resumable: re-runs from the saved cursor after a drop.
const handlePaginate = base.resumableStream('paginate', {
  input: v.object({}),
  chunk: Token,
  cursor: t<{ idx: number }>(),
  async *run(ctx) {
    const start = ctx.stream.cursor?.idx ?? 0
    for (let i = start + 1; i <= 100; i += 1) {
      yield ctx.stream.withCursor({ index: i }, { idx: i })
    }
  },
})

// Recorded: buffers chunks and replays the missed ones after a drop.
const handleTokens = base.recordedStream('tokens', {
  input: v.object({}),
  chunk: Token,
  async *run() {
    for (let i = 0; i < 100; i += 1) yield { index: i }
  },
})

export const handler = base.assemble(handleFeed, handlePaginate, handleTokens)
```

## The contract slice a stream adds

Every server-pushed stream — plain, resumable, or recorded — reaches the client the same way: `InferClient` puts them all in one flat `streams` map keyed by event name. Each entry pairs the `payload` that starts the stream with the `chunk` it yields, and carries a `kind` — `'ephemeral'` for a plain stream, `'persistent'` for the two durable kinds. Fields that carry no information are dropped: an empty `nudges`, and an undeclared `cursor`, are omitted; a resumable stream that declares a `cursor` keeps its type.

```ts [client-streams-view.ts]
// From a plain `feed`, a resumable `paginate` (with a cursor),
// and a recorded `tokens`:
type ClientStreams = {
  feed: {
    payload: { count: number }
    chunk: { index: number }
    kind: 'ephemeral'
  }
  paginate: {
    payload: {}
    chunk: { index: number }
    cursor: { idx: number }
    kind: 'persistent'
  }
  tokens: {
    payload: {}
    chunk: { index: number }
    kind: 'persistent'
  }
}
```

The client reads this merged map to type its `stream(...)`, `onStream(...)`, and `resumeStream(...)` calls — the `kind` is what gates resume-only methods to the durable streams. You never hand-write either shape; both are derived. See [`define`](/server/define/overview) for how the contract is materialized.

## Broadcasting is a behavior, not a fourth kind

Any of the three kinds can fan its chunks to many connections instead of one. Set `broadcast: true` and one generator runs once; its chunks go to every connection in scope. Scope follows where the stream is declared — a top-level stream fans out to every connection, a stream inside a `channel(...)` fans out to that channel's members.

```ts [broadcast.ts]
const handleLiveFeed = base.stream('live-feed', {
  input: v.object({ count: v.number() }),
  chunk: Token,
  broadcast: true,
  async *run(_ctx, input) {
    for (let i = 0; i < input.count; i += 1) yield { index: i }
  },
})
```

Broadcast works for durable kinds too. A **recorded** broadcast replays its chunk buffer to a late joiner so it catches up on what it missed, then follows live; a **resumable** broadcast stores only a cursor, so a late joiner sees just the chunks produced after it joined. See [Broadcast](/server/streams/broadcast) for the full picture.
