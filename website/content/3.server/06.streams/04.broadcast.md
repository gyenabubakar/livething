**Broadcasting** runs one generator and sends its chunks to many connections at once. Set `broadcast: true` on any stream and the creator runs the generator once; every connection in scope receives the same chunks. It is the same generator you already write — the only change is where the chunks go.

Broadcast is a flag, not a fourth kind. It works on plain, resumable, and recorded streams alike. This page covers the scope rules, durable broadcast, and channel-scoped broadcast. For how a client *consumes* a broadcast (listen-only via `onStream`), see [Broadcast (onStream)](/client/streams/broadcast-onstream).

## A plain broadcast stream

Add `broadcast: true` and the generator's chunks fan out to every connection in scope. A top-level stream's scope is "every connection on this socket."

```ts [broadcast.ts]
import { define, t } from '@wskit/server'
import { stream } from '@wskit/server/streams'
import * as v from 'valibot'

const Tick = t<{ index: number }>()

const base = define({
  env: t<Env>(),
  capabilities: [stream()],
})

export const handleStartBroadcast = base.stream('start-broadcast', {
  input: v.object({ count: v.number() }),
  chunk: Tick,
  broadcast: true,
  async *run(_ctx, input) {
    for (let i = 0; i < input.count; i += 1) {
      yield { index: i }
      await new Promise((r) => setTimeout(r, 10))
    }
  },
})
```

One client triggers it; everyone in scope gets the chunks. Each fanned-out chunk carries the same stream ID and sequence number, so every subscriber sees a consistent ordered run.

## How a broadcast ends for subscribers

When the generator finishes (or throws), the terminal frame fans out to every subscriber too, carrying the event name so each side knows which stream ended.

| Event | What subscribers see |
|---|---|
| Generator completes | A stream-end frame, fanned to every subscriber. |
| Generator throws a defined error | That error, terminal, fanned to every subscriber. |
| Generator throws an unknown error | `internal-error`, terminal, fanned to every subscriber. |
| Creator cancels the stream | Subscribers get a stream-end (the stream is over for everyone). |
| A *subscriber* cancels | Only that subscriber stops receiving — the stream keeps running for everyone else. |

That last row is the key asymmetry: the **creator** owns the run. A non-creator cancel just unsubscribes that one peer.

```ts [broadcast-error.ts]
export const handleBroadcastBoom = base.stream('broadcast-boom', {
  input: v.object({ count: v.number() }),
  chunk: Tick,
  broadcast: true,
  async *run(_ctx, input) {
    if (input.count < 0) {
      yield { index: 0 }
      // The terminal error fans to the creator AND every subscriber.
      throw new Error('broadcast boom')
    }
    for (let i = 0; i < input.count; i += 1) yield { index: i }
  },
})
```

## Durable broadcast

Durable streams broadcast too. One generator runs and its chunks fan to everyone in scope *and* are stored, so a **late joiner** — a client that connects after the stream started — catches up from storage and then follows live. Recorded broadcast replays buffered chunks to a late joiner; resumable broadcast brings a reconnecting subscriber back to live from its last cursor.

```ts [durable-broadcast.ts]
import { define, t } from '@wskit/server'
import { persistence } from '@wskit/server/persistence'
import { channels } from '@wskit/server/channels'
import { recordedStream, resumableStream } from '@wskit/server/streams'
import * as v from 'valibot'

const Empty = v.object({})
const TokenChunk = t<{ token: string }>()
const RowChunk = t<{ row: number }>()

const base = define({
  env: t<Env>(),
  capabilities: [persistence(), channels(), recordedStream(), resumableStream()],
})

const rooms = base.channel('rooms', {})

// Recorded broadcast — late joiners replay the buffer, then follow live.
export const handleFeed = rooms.recordedStream('feed', {
  input: Empty,
  chunk: TokenChunk,
  broadcast: true,
  maxChunks: 100,
  async *run() {
    for (let i = 1; i <= 5; i += 1) {
      yield { token: `t${i}` }
      await new Promise((r) => setTimeout(r, 250))
    }
  },
})

// Resumable broadcast — peers and late joiners see live chunks from where they joined.
export const handlePaginate = rooms.resumableStream('paginate', {
  input: Empty,
  chunk: RowChunk,
  broadcast: true,
  async *run(ctx) {
    const startAt = (ctx.stream.cursor as { idx: number } | null)?.idx ?? 0
    for (let i = startAt + 1; i <= 10; i += 1) {
      yield ctx.stream.withCursor({ row: i }, { idx: i })
      await new Promise((r) => setTimeout(r, 250))
    }
  },
})
```

The `paginate` example casts `ctx.stream.cursor` because it declares no `cursor` validator, so the cursor type stays `unknown`. Pass a `cursor` schema (or a `t<T>()` marker) to drop the cast — see [the cursor type on Resumable](/server/streams/durable-resumable#the-cursor-type-marker-vs-validator).

::note
For a **resumable** broadcast, peers and late joiners see only the chunks produced **after** they joined — there is no chunk buffer to replay from, because resumable stores only the cursor. A **recorded** broadcast does buffer chunks, so a late joiner replays the ones it missed first. Pick the kind by whether late joiners need the back-story or only the live tail.
::

### A subscriber cancel doesn't stop the stream

On a durable broadcast, when a non-creator subscriber cancels, the framework records that it unsubscribed but keeps the stream running for everyone else. If that same client later tries to resume the stream, it gets `StreamAborted` with `reason: 'unsubscribed'` — it opted out, so there is nothing to resume. See [abort reasons](/server/streams/config-and-lifecycle#abort-reasons).

## Steering a broadcast with a nudge

Because the generator runs on the creator's connection, a nudge sent by the creator steers the whole fan-out. A `stop` nudge ends the stream for every subscriber, not just the creator.

```ts [broadcast-nudge.ts]
export const handleFeedNudged = rooms.recordedStream('feed-nudged', {
  input: Empty,
  chunk: TokenChunk,
  broadcast: true,
  maxChunks: 100,
  nudges: { stop: Empty },
  async *run(ctx) {
    for (let i = 1; i <= 20; i += 1) {
      const recent = ctx.stream.nudges(yield { token: `t${i}` })
      if (recent.some((n) => n.event === 'stop')) return // ends for everyone
      await new Promise((r) => setTimeout(r, 100))
    }
  },
})
```

## Channel-scoped broadcast

Where you *declare* a stream sets its scope. A top-level `base.stream` fans out to every connection. A stream declared inside a `channel(...)` fans out only to that channel's members — a private room, a per-tenant feed.

```ts [channel-scoped.ts]
const room = base.channel(['rooms', 'room:{id}'], {})

export const handleRoomBroadcast = room.stream('start-room-broadcast', {
  input: v.object({ count: v.number() }),
  chunk: t<{ index: number }>(),
  broadcast: true,
  async *run(_ctx, input) {
    for (let i = 0; i < input.count; i += 1) {
      yield { index: i }
      await new Promise((r) => setTimeout(r, 10))
    }
  },
})

export const handler = base.assemble(handleRoomBroadcast)
```

Only connections subscribed to that channel receive the chunks. For a **durable** channel-scoped stream, a resuming connection must be subscribed to the channel to resume — see [Scoped Streams & Requests](/server/channels/scoped-streams-requests) for how channel membership gates a stream. The channel concepts (families like `room:{id}`, membership, auth) live in the [Channels](/server/channels/overview) chapter; broadcast just rides on top of whichever scope the stream is declared in.
