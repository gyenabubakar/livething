`emits` declares the server→client, fire-and-forget events your server can push. Each event becomes something the client receives, and on the server it unlocks the two ways to push: `ctx.send` to one connection and `ctx.broadcast` to many.

## Declaring events

Call `emits({...})` from `@wskit/server` and list it in your capabilities. Each key is an event name; each value is a `t<Shape>()` marker that fixes the payload type:

```typescript [chat.ts]
import { define, emits, t } from '@wskit/server'

const base = define({
  env: t<Env>(),
  capabilities: [
    emits({
      message: t<{ text: string; from: string }>(),
      'user-joined': t<{ username: string }>(),
      'who-am-i-result': t<{ connectionId: string }>(),
    }),
  ],
})
```

The marker is **type-only**. Outgoing payloads are produced by your own server code, so WSKit does not validate them on the way out — the type just flows into `ctx.send`, `ctx.broadcast`, and the generated client. There is no schema to write here, only the shape.

## The contract slice

`emits` fills the client's `incoming` key — the events the client receives. This is the perspective flip: what the server *emits* is what the client takes *in*. The declared events produce this slice of the client contract:

```typescript [chat-socket.ts]
interface ChatSocket {
  incoming: {
    message: { text: string; from: string }
    'user-joined': { username: string }
    'who-am-i-result': { connectionId: string }
  }
}
```

The client then listens with full typing, no hand-written types:

```typescript [app.ts]
socket.on('message', (data) => {
  // data: { text: string; from: string }
})
```

See [The Contract](/learn/core-model/the-contract) for the full picture of how the server description mirrors onto the client.

## Pushing events from a handler

With `emits` listed, your handlers get `ctx.send` and `ctx.broadcast`, both typed to the events you declared. `ctx.send(event, payload)` pushes to the current connection; `ctx.broadcast(event, payload)` pushes to everyone:

```typescript [handlers.ts]
const handleWhoAmI = base.on('who-am-i', {
  input: v.object({}),
  run(ctx) {
    ctx.send('who-am-i-result', { connectionId: ctx.id })
  },
})

const handleDoBroadcast = base.on('do-broadcast', {
  input: v.object({ text: v.string() }),
  run(ctx, input) {
    ctx.broadcast('message', { text: input.text, from: ctx.meta.username })
  },
})
```

Both are typed against the declared events. Calling `ctx.send('not-declared', ...)` is a compile error, and passing a payload that does not match the marker is a compile error too.

## Config field reference

| Field | Value | Notes |
|---|---|---|
| event name (key) | any string | The wire name of the event. Quote it if it is hyphenated, e.g. `'user-joined'`. |
| payload (value) | `t<Shape>()` | A type-only marker. No runtime validation runs on outbound payloads. |

## Edge cases

**Hyphenated names need quotes.** A key with a hyphen or other non-identifier character must be a string literal:

```typescript [server.ts]
emits({
  'delivery-status': t<{ delivered: boolean }>(),
})
```

**Empty payload.** For an event that carries no data, declare it with an empty object marker:

```typescript [server.ts]
emits({
  ping: t<{}>(),
})
```

## Channels declare their own events

Top-level `emits` covers events on the main socket. A channel has its own contract and declares its own events through `outgoing.emits`, not through this capability. See [Defining channels](/server/channels/defining) for that.
