A **channel** is a server-managed room. Connections subscribe to it, and a channel carries its own scoped events, its own gate, and its own lifecycle hooks. A chat lobby, a game table, a per-document session — each is a channel.

The `channels()` capability enables `base.channel(name, config)` and the `ctx.channels` accessor. Import it from `@wskit/server/channels`:

```typescript [server.ts]
import { channels } from '@wskit/server/channels'
```

## Defining a channel

List `channels()`, then declare a channel with `base.channel(name, config)`. A channel object exposes handler methods you build on. Here is a static `lobby` with an outgoing event, an auth gate, and a message handler:

```typescript [server.ts]
import { define, t } from '@wskit/server'
import { channels } from '@wskit/server/channels'
import * as v from 'valibot'

const base = define({
  env: t<Env>(),
  capabilities: [channels()],
})

const lobby = base.channel('lobby', {
  outgoing: {
    emits: { message: t<{ text: string; from: string }>() },
  },
  check(ctx) {
    if (ctx.meta.username === 'blocked-user') {
      throw new Error('blocked-user may not subscribe')
    }
  },
})

export const handleSay = lobby.on('say', {
  input: v.object({ text: v.string() }),
  run(ctx, input) {
    ctx.channel.broadcast('message', { text: input.text, from: ctx.meta.username })
  },
})
```

Inside a channel handler, `ctx.channel.broadcast(...)` pushes to every member, and `ctx.channel.send(...)` pushes to the one connection. For the deep authoring detail, see [Defining Channels](/server/channels/defining).

## The contract slice

`channels()` fills the client contract's `channels` key. Each channel carries its own nested mini-contract — the same `incoming` and `outgoing` keys again, scoped to that room:

```typescript [chat-socket.ts]
interface ChatSocket {
  channels: {
    lobby: {
      incoming: {
        message: { text: string; from: string }
      }
      outgoing: {
        say: { text: string }
      }
    }
  }
}
```

The flip is the same as for the top-level contract: the channel's `outgoing.emits` become the client's `incoming`, and the channel's handlers become the client's `outgoing`.

## Config at a glance

`base.channel(name, config)` accepts these config fields:

| Field | What it does |
|---|---|
| `subscribe` | Input schema for the subscribe payload. |
| `outgoing` | `{ emits, requests }` — the events and server-to-client requests this channel sends. |
| `check(ctx, input)` | Auth gate. Throw to reject the subscribe. |
| `commit(ctx)` | Runs after a subscribe is accepted. |
| `revalidate(ctx)` | Re-checks an existing membership. |
| `persistent` | Keep membership across reconnects (needs `persistence()`). |
| `replay` | `true`, `false`, or a config — re-send messages on reconnect. |
| `rateLimit` | Throttle how fast a member can send to this channel. |

On the returned channel object you bind handlers and lifecycle: `.on`, `.request`, `.stream` / `.resumableStream` / `.recordedStream`, `.subscribe`, `.unsubscribe`, `.sessionEnd`, `.intercept`, and `.replay`.

For the auth gate in depth, see [Auth Gate](/server/channels/auth-gate). For scoped streams and requests, see [Scoped Streams & Requests](/server/channels/scoped-streams-requests).

## Dynamic families

A channel can be a **family** — a pattern that spins up one channel per ID. Declare it with a `[family, template]` pair, then make a concrete reference with `.at(...)`:

```typescript [family.ts]
const room = base.channel(['room', 'room:{id}'], {
  outgoing: {
    emits: { message: t<{ text: string; from: string }>() },
  },
})

const handleSend = room.on('send', {
  input: v.object({ text: v.string() }),
  run(ctx, input) {
    ctx.channel.broadcast('message', { text: input.text, from: ctx.meta.username })
  },
})
```

To address one instance, build a reference and pass it to `ctx.channels.get(...)`:

```typescript [target.ts]
const ref = room.at({ id: 'abc' })       // resolves room:abc
ctx.channels.get(ref).broadcast('message', { text: 'hi', from: 'system' })
```

See [Dynamic Families](/server/channels/dynamic-families) for the full family surface.

## Capabilities a channel may need

A channel only pulls in extra engines when you use the matching feature, and assembly checks each one — a missing prerequisite is a build error that names exactly what to add:

- **Persistent membership** (`persistent: true`) needs `persistence()`.
- **Channel streams** (`.stream`, `.resumableStream`, `.recordedStream`) need the matching stream capability — `stream()`, `resumableStream()`, or `recordedStream()`.
- **Channel `outgoing.requests`** need `requests()`.
- **A custom `.replay`** needs `replay.custom()`; **`replay: true | false`** needs a built-in replay capability.

A channels-only app pays for none of these — you add a capability only when a channel actually uses that feature.
