A **family** is one channel declaration that matches many channel names. You do not declare a separate static channel for each room. Instead, you declare one **template**, such as `room:{roomId}`. Every name that matches the template becomes its own channel **instance**: a separate channel with its own members. All instances of a family share the same config, the same gate, and the same assembled handler values.

```typescript [server/rooms.ts]
import { emits, t } from '@livething/server'
import { base, Message } from './base'

const rooms = base.channel(['rooms', 'room:{roomId}'], {
  capabilities: [emits({ message: t<Message>() })],
})
```

Pass `rooms` to `assemble()` to turn on the family's config and hooks. To turn on a route, pass the handler value that `rooms.on(...)`, `rooms.request(...)`, or a stream method returns. A handler value also includes the family's config and hooks.

`rooms` is the **family key**. It is the identifier you pass to `ctx.channels.get('rooms', name)`. `room:{roomId}` is the template. LiveThing matches it against the name a client subscribes to. A client that subscribes to `room:general` joins the `room:general` instance. `room:design` is a different instance with different members.

The `[familyKey, template]` tuple is the only way to declare a family with `base.channel(...)`.

## The template grammar

A template is plain text plus `{name}` **captures**. A capture is a named part of the template that matches part of the channel name. LiveThing builds the matcher from the template itself, and you never write a regular expression (regex). Because of this, matching cannot become very slow on some inputs, which can happen with a badly written regex (this problem is called catastrophic backtracking).

| Template                 | Matches              | `params`                     |
| ------------------------ | -------------------- | ---------------------------- |
| `room:{roomId}`          | `room:general`       | `{ roomId: 'general' }`      |
| `org:{org}/thread:{tid}` | `org:acme/thread:42` | `{ org: 'acme', tid: '42' }` |

The rules:

- `{name}` captures one or more characters. The name must be a plain identifier: letters, digits, and underscores, and it cannot start with a digit.
- Two captures must have literal text between them. `{a}{b}` is rejected, but `{a}:{b}` is fine. This rule means a template with many captures can only split a name in one way.
- Braces are only for captures. A template cannot contain a literal `{` or `}`.
- Each capture name must be unique within a template.

A template with a mistake throws a clear error when you declare the channel. The mistakes are: a stray `{` or `}` that is not part of a capture, an empty `{}`, a bad name, a duplicate name, or two captures with no literal text between them. TypeScript also flags a stray brace before the code runs.

## Captures in the handler

Inside a family handler, `ctx.channel` tells you which instance the call came from. `ctx.channel.name` is the full matched name. `ctx.channel.family` is the family key. `ctx.channel.params` holds the captures, and their types come from the template.

```typescript [server/rooms.ts]
import * as v from 'valibot'
import { rooms } from './base'

const handleSendMessage = rooms.on('send-message', {
  input: v.object({ text: v.string() }),
  run(ctx, input) {
    ctx.channel.name // 'room:general'
    ctx.channel.family // 'rooms'
    ctx.channel.params.roomId // 'general' — typed string from {roomId}
    ctx.channel.broadcast('message', {
      id: crypto.randomUUID(),
      text: input.text,
      from: ctx.user.id,
      sentAt: Date.now(),
    })
  },
})
```

## Reaching one instance from outside

From any handler, `ctx.channels.get(family, name)` returns a handle for one instance. Pass the family key and the full matched name. In this example, a request handler answers with the member count of one room:

```typescript [server/rooms.ts]
import * as v from 'valibot'
import { base } from './base'

const handleRoomMemberCount = base.request('room-member-count', {
  input: v.object({ roomId: v.string() }),
  run(ctx, payload) {
    const handle = ctx.channels.get('rooms', `room:${payload.roomId}`) // e.g. 'room:general'
    return { count: handle.members().length }
  },
})
```

For a fully typed handle, pass the result of the family's `.at(params)` method instead of a raw string. `.at(...)` fills the template with the captures you give it. It returns a reference to that instance, and the handle you get from it is typed to the channel's events and requests:

```typescript [server/rooms.ts]
import * as v from 'valibot'
import { base, rooms } from './base'

const handleRoomNotice = base.on('room-notice', {
  input: v.object({ roomId: v.string(), text: v.string() }),
  run(ctx, payload) {
    const ref = rooms.at({ roomId: payload.roomId }) // typed reference to 'room:<roomId>'
    ctx.channels.get(ref).broadcast('message', {
      id: crypto.randomUUID(),
      text: payload.text,
      from: 'system',
      sentAt: Date.now(),
    })
  },
})
```

`.at(...)` exists only on family declarations. A static channel is already a single instance, so you pass it to `ctx.channels.get(...)` directly. Using `.at` on a static channel is a type error, and if you call it anyway, it throws. Calling `.at({})` without the captures the template needs is also a type error.

## Per-instance isolation

Each matched name is a fully separate channel. Members, broadcasts, and the gate belong to one exact instance. `room:general` never sees the members of `room:design`, and a broadcast to one never reaches the other. A static channel and a family are separate from each other in the same way. In this example, `announcements` also has an `announce` handler that an admin can call. In Huddle, only the server sends to `announcements`.

```typescript [server/rooms.ts]
import { emits, t } from '@livething/server'
import * as v from 'valibot'
import { base, Message } from './base'

const announcements = base.channel('announcements', {
  capabilities: [emits({ announcement: t<{ text: string }>() })],
})

const rooms = base.channel(['rooms', 'room:{roomId}'], {
  capabilities: [emits({ message: t<Message>() })],
})

// A broadcast in 'announcements' reaches only its members.
const handleAnnounce = announcements.on('announce', {
  input: v.object({ text: v.string() }),
  run(ctx, payload) {
    if (ctx.meta.role !== 'admin')
      throw new Error('only an admin may announce')
    ctx.channel.broadcast('announcement', { text: payload.text })
  },
})

// A broadcast in a 'rooms' instance reaches only that instance's members.
const handleSendMessage = rooms.on('send-message', {
  input: v.object({ text: v.string() }),
  run(ctx, payload) {
    ctx.channel.broadcast('message', {
      id: crypto.randomUUID(),
      text: payload.text,
      from: ctx.user.id,
      sentAt: Date.now(),
    })
  },
})
```

## Key collision rules

LiveThing finds a channel by the pair of family key and name. It never joins the two into one string. Because of this, two families stay separate even when joining their keys and names would give the same string. The two families below only show this. They are not part of Huddle, and the first one is not Huddle's `rooms`.

```typescript [server/rooms.ts]
import { emits, t } from '@livething/server'
import { base } from './base'
import type { Message } from './base'

// 'rooms' matches names like 'private-general'.
const rooms = base.channel(['rooms', 'private-{roomId}'], {
  capabilities: [emits({ message: t<Message>() })],
})

// 'rooms-private' matches names like 'general'.
const roomsPrivate = base.channel(['rooms-private', '{roomId}'], {
  capabilities: [emits({ message: t<Message>() })],
})
```

If a system built its lookup string as `key + '-' + name`, then `rooms` + `private-general` and `rooms-private` + `general` would both become `rooms-private-general`. LiveThing uses the pair, so the two families stay separate.

The first rule LiveThing checks when the server starts: **a family template must not match a static channel name.** If it did, one channel name could lead to two different channel declarations, and the result would depend on which one the lookup found first. When this happens, the server throws at startup. The error tells you to make the family template narrower or to rename the static channel.

```typescript [server/rooms.ts]
import { base } from './base'

// This pair fails at startup: the family 'room:{roomId}' matches the static
// name 'room:vip', so the same subscribe could resolve two ways.
base.channel('room:vip', {})
base.channel(['rooms', 'room:{roomId}'], {})
```

Two different families _may_ use the same template (for example, both use `room:{roomId}`). They stay separate because their family keys are different.

The second rule: **a static channel name must not be the same as a family key.** Static names and family keys are looked up in the same set of names. If you declare `base.channel('rooms', ...)` next to a family whose key is `'rooms'`, the server throws at startup and tells you to rename one of them.

Managing membership (subscribing a connection or kicking a member from server code) and the presence frames a channel broadcasts (messages that tell members who joined or left) work the same for **every** channel, not only families. They have their own page: [Membership & Presence](/server/channels/membership-and-presence).
