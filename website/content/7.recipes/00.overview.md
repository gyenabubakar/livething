The rest of the docs teach the pieces: [Start](/start/introduction) gets you running, [Learn](/learn/overview) walks each feature from both sides, and the [Server](/server/overview) and [Client](/client/overview) guides hold the per-package detail. **Recipes** put the pieces together, so you can see how the features combine and reuse the pattern in your own project.

Today, one part of Recipes is written: **Framework Hooks**. It has one page per UI framework ([React](/recipes/framework-hooks/react), [Vue](/recipes/framework-hooks/vue), [Svelte](/recipes/framework-hooks/svelte), [Solid](/recipes/framework-hooks/solid), [React Native](/recipes/framework-hooks/react-native)). Each page shows the few lines that bind the socket's reactive stores to that framework. The app recipes below are stubs for now. Each stub page has a title and a short description of what the recipe will cover, and no code yet.

## Why recipes

Learn shows one feature at a time, on its own. A real app is never one feature. A chat is rooms _and_ presence _and_ history _and_ auth, all at once; an AI app is streaming _and_ steering _and_ surviving a dropped connection. The gap between "I understand channels" and "I've built a chat" is what the app recipes are for.

::note
These pages assume you've met the building blocks already. If a capability or primitive is new to you, follow its link into [Learn](/learn/overview) for the concept, then come back.
::

## How to read them

If you have not bound the socket to your UI framework yet, start with your framework's page ([React](/recipes/framework-hooks/react), [Vue](/recipes/framework-hooks/vue), [Svelte](/recipes/framework-hooks/svelte), [Solid](/recipes/framework-hooks/solid), [React Native](/recipes/framework-hooks/react-native)). For worked examples of chat, streaming, presence, and auth today, read the [Learn](/learn/overview) pages: they all use Huddle, the same app.
