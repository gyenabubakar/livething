The socket is what `client<Contract>()(...)` returns. It has three layers:

1. **Connection methods** — the same on every socket, whatever the contract (`connect`, `getState`, the `on*` lifecycle listeners).
2. **Typed messaging** — `on()` and `send()`, which appear only when your contract declares `incoming` or `outgoing` events.
3. **Primitive methods** — each primitive you install (`requestResponse()`, `stream()`, `channels()`, …) adds its own methods on top.

This page is the flat index. Behavior lives on the owning page; here you get the signature and a link.

## Connection methods

Always present, from `SocketConnection`:

| Member | Signature | What it does |
|---|---|---|
| `connect` | `connect(): void` | Open the connection. Safe to call more than once. |
| `disconnect` | `disconnect(code?, reason?): void` | Close on purpose. Defaults to code `1000` and an empty reason. |
| `getState` | `getState(): ConnectionState` | The current [connection state](/client/overview#connection-states) — `'closed'`, `'connecting'`, `'open'`, or `'reconnecting'`. |
| `subscribe` | `subscribe(cb): () => void` | Run `cb` on every state change; read the value with `getState()`. Returns an unsubscribe. |
| `setDebug` | `setDebug(enabled): void` | Turn console logging on or off at runtime. |
| `protocol` | `readonly protocol: string \| null` | The subprotocol the server picked, or `null`. |
| `ws` | `readonly ws: WebSocket \| null` | The native `WebSocket`, or `null` when not connected. |

```typescript [app.ts]
socket.connect()
const stop = socket.subscribe(() => render(socket.getState()))
// later: stop()
socket.disconnect(1000, 'signed out')
```

## Lifecycle listeners

Each returns its own unsubscribe function, and each can have more than one listener:

| Listener | Fires | Callback gets |
|---|---|---|
| `onOpen(cb)` | every open — first connect and every reconnect | — |
| `onReconnect(cb)` | reconnects only, not the first connect | — |
| `onReconnectFailed(cb)` | once, when [`reconnection()`](/client/primitives/reconnection) gives up for good | — |
| `onClose(cb)` | every close, including ones that lead to a reconnect | `{ code, reason, wasClean }` |
| `onError(cb)` | a WebSocket-level error, or a typed server error no request, stream, or channel claimed | a DOM `Event` **or** a `WSKitError` |

```typescript [app.ts]
socket.onReconnectFailed(() => showPermanentDisconnectBanner())
socket.onClose(({ code, reason }) => log(`closed ${code}: ${reason}`))
socket.onError((err) => report(err)) // narrow: err instanceof Event vs a WSKitError
```

`onError` narrowing and the "who claims an error first" rules are on [onError Routing](/client/errors/onerror-routing).

## Typed messaging

Present only when your contract declares the matching events — [`Messaging`](/client/overview#the-messaging-interface):

| Member | Signature | Appears when | See |
|---|---|---|---|
| `on` | `on(event, handler): () => void` | the contract has `incoming` events | [Messaging](/client/overview#the-messaging-interface) |
| `send` | `send(event, payload): boolean` | the contract has `outgoing` events | [Messaging](/client/overview#the-messaging-interface) |

```typescript [app.ts]
const off = socket.on('order-update', (data) => updateOrder(data))
const accepted = socket.send('typing', { room: 'r-1' }) // true = accepted, not delivered
```

## Methods primitives add

Each of these exists only when its primitive is installed at socket creation. Leave the primitive out and the method isn't on the socket — and if your contract declares the matching key, TypeScript points you at the primitive to add.

| Method | Added by | See |
|---|---|---|
| `request(event, payload, options?)` | [`requestResponse()`](/client/primitives/request-response) | [requestResponse](/client/primitives/request-response) |
| `onRequest(event, handler)` | [`serverRequest()`](/client/primitives/server-request) | [serverRequest](/client/primitives/server-request) |
| `stream(event, payload, options?)` | [`stream()`](/client/primitives/stream) | [Stream Handle](/client/streams/stream-handle) |
| `resumeStream(event, streamId, options?)` | [`stream()`](/client/primitives/stream) | [Durable & Resume](/client/streams/durable-and-resume) |
| `onStream(event, handlers)` | [`stream()`](/client/primitives/stream) | [Broadcast (onStream)](/client/streams/broadcast-onstream) |
| `channel(family, id)` | [`channels()`](/client/primitives/channels) | [Channels](/client/channels/overview) |
| `getQuality()` · `getLatency()` · `onQualityChange(cb)` | [`keepalive()`](/client/primitives/keepalive) | [keepalive](/client/primitives/keepalive) |
| `intercept(fn)` | [`intercept()`](/client/primitives/intercept) | [intercept](/client/primitives/intercept) |

A plugin's own API isn't a socket method — reach it with `Plugin.use(socket)`. See [Plugins](/client/plugins).

## The channel handle

`socket.channel(family, id)` returns a handle that is itself a [Messaging](/client/overview#the-messaging-interface) object (`on` / `send`) plus room controls, and gains a scoped copy of any messaging primitive you installed:

| Member | What it does | See |
|---|---|---|
| `subscribe(payload?)` | Join the room; resolves when the server confirms | [Handles & Family](/client/channels/handles-and-family) |
| `unsubscribe()` | Leave; resolves on confirm, can reject with `Disconnected` | [Lifecycle Hooks](/client/channels/lifecycle-hooks) |
| `members` · `resyncMembers()` | The live roster and a re-sync request | [Presence Listeners](/client/channels/presence-listeners) |
| `onMemberJoin/Leave/Online/Offline`, `onSubscribed`, `onUnsubscribed`, `onKicked`, `onSubscriptionFailed` | Presence and lifecycle listeners | [Presence](/client/channels/presence-listeners), [Lifecycle](/client/channels/lifecycle-hooks) |
| `request(...)` · `stream(...)` · `resumeStream(...)` · `onStream(...)` | The same primitive methods, scoped to this room | the primitive's page |

## The stream handle

`await socket.stream(...)` resolves to a handle you iterate with `for await`:

| Member | What it does | See |
|---|---|---|
| `streamId` | The id grouping this run's chunks | [Stream Handle](/client/streams/stream-handle) |
| `active` | `true` while running, `false` once it ends, errors, or is cancelled | [Stream Handle](/client/streams/stream-handle) |
| `nudge(event, payload, options?)` | Send a message into the running server generator | [Nudges](/client/streams/nudges) |
| `cancel()` | Ask the server to stop; the loop exits without throwing | [Stream Handle](/client/streams/stream-handle) |
