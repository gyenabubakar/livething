Every LiveThing WebSocket frame is a JSON array with exactly three items:

```json
[event, payload, metadata]
```

- `event` is a string.
- `payload` is an object or `null` when there is no payload.
- `metadata` is a nested object or `null`; it is never omitted.

Metadata uses these groups:

```json
{
  "exchange": { "id": "request-42", "source": "client" },
  "channel": { "name": "room:general", "family": "rooms" },
  "delivery": { "id": "message-7", "seq": 12 },
  "stream": {
    "id": "scout-1",
    "event": "ask-scout",
    "durability": "persistent",
    "seq": 3,
    "nudgeId": "nudge-1",
    "terminated": false
  }
}
```

Use `exchange.id` for request matching, `channel` for channel routing, `delivery` for message IDs and delivery cursors, and `stream` for stream state. See [Wire Protocol](/learn/wire-protocol) for reserved events and examples.

## Binary frames

A server that lists [`binary()`](/server/capabilities/binary) also takes and sends binary WebSocket messages. One binary message holds one LiveThing message:

```text
[ magic:          4 bytes = 0x6C 0x74 0x62 0x66 ("ltbf") ]
[ version:        1 byte  = 0x01                         ]
[ envelopeLength: 4 bytes, unsigned, big-endian          ]
[ envelope:       envelopeLength bytes, UTF-8 JSON       ]
[ bytes:          all the remaining bytes                ]
```

- The **envelope** is a normal three-item frame: `[event, info, metadata]`. The info is in the payload's place, and it follows the same rules as a payload: an object, or `null`. The metadata groups are the same as above.
- The envelope is at most 64 KiB (65,536 bytes).
- The **bytes** are the application's own data. LiveThing never reads them. There can be zero bytes.

A binary `screen-frame` event that the server sends to a room looks like this:

```text
ltbf | 1 | length | ["screen-frame",{"from":"u_amara"},{"channel":{"name":"room:general","family":"rooms"},"delivery":{"id":"m-8","seq":3}}] | picture bytes
```

The server uses binary messages only for data events. Every framework event (`__subscribe__`, `__error__`, `__subscribeOk__` and the rest) is a text frame, in both directions. See [Wire Protocol](/learn/wire-protocol#binary-frames) for how the server checks a binary message.
