Most errors a client sees come from the server. Three come from the **client itself** — raised locally, never sent over the wire — when a call can't complete. Import them from `@wskit/client/errors`:

| Error          | Code           | When it fires                                                                                                                                          |
| -------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Timeout`      | `timeout`      | A `request()` (or a stream `nudge()`) got no reply in time, or a stream's per-chunk timeout elapsed                                                    |
| `Disconnected` | `disconnected` | The socket dropped while a `request()` was waiting, `disconnect()` was called mid-request, or a stream can't resume because reconnection was abandoned |
| `Dropped`      | `dropped`      | A buffered `request()` or `stream()` trigger was evicted before it could be sent — the buffer overflowed, or its TTL elapsed while offline             |

`Dropped` isn't request-only: [`buffering()`](/client/primitives/buffering) queues any promise-bearing outgoing frame, so a `stream()` trigger held while offline rejects the `stream()` promise with `Dropped` the same way if it's evicted or expires before the socket reconnects.

They're `WSKitError`s like any other, so you narrow them with `.matches()`:

```typescript [app.ts]
import { Disconnected, Dropped, Timeout } from '@wskit/client/errors'

try {
  await socket.request('slow-thing', {})
} catch (err) {
  if (Timeout.matches(err)) retry()
  else if (Disconnected.matches(err)) waitForReconnect()
  else if (Dropped.matches(err)) notifyNotSent()
}
```

## Narrowing any error on the client

A `catch` can receive a client-side error, a typed error from your server, or a framework error — all `WSKitError`s, all narrowed the same way. An [`onServerError`](/client/errors/onerror-routing) callback receives the server/framework side of that set. Match the specific ones you handle and let the rest fall through:

```typescript [app.ts]
import { Timeout } from '@wskit/client/errors'
import { NotFound } from '../server/errors' // your own, defined once and shared

try {
  const post = await socket.request('get-post', { id })
} catch (err) {
  if (NotFound.matches(err)) showMissing()
  else if (Timeout.matches(err)) retry()
  else throw err // not one we handle here
}
```

The `WSKitError` shape, the `error()` factory, and how `.matches()` works are covered once in the [Error Model](/core/error-model). The full catalog of framework errors your server can send — `RateLimited`, `ConnectionBusy`, `StreamAborted`, `ValidationFailed`, and the rest — is the [Built-in Errors](/core/builtin-errors) list. Both live in the [Core](/core/overview) section, since they're shared with the server.
