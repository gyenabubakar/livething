A **stream** is progressive, chunked data — LLM tokens, query rows, a live feed — sent piece by piece instead of all at once. The [`stream()`](/client/primitives/stream) primitive page is the quick reference. This chapter is the deep one: the handle and its iterator, nudging a running stream, durable auto-resume and cold resume, and listen-only broadcasts.

For the server half — writing the generator, recorded versus resumable streams — see [Streams](/server/streams/overview) in the Server section. Everything here is client-side.

## Two ways to consume a stream

There are two directions, and they use different methods:

- **You trigger it** — you call `stream(...)`, the server runs a generator just for you, and you read the chunks by iterating the handle you get back.
- **The server broadcasts it** — one stream fans out to many clients. You didn't start it, so you consume it with callbacks through `onStream(...)`.

A third method, `resumeStream(...)`, re-attaches to a durable stream you started earlier — after a reload, or in another tab.

| Method                                    | What it does                  | You get back            |
| ----------------------------------------- | ----------------------------- | ----------------------- |
| `stream(event, payload, options?)`        | Start a stream and iterate it | `Promise<StreamHandle>` |
| `onStream(event, handlers)`               | Listen to a broadcast stream  | an unsubscribe function |
| `resumeStream(event, streamId, options?)` | Cold-resume a durable stream  | `StreamHandle`          |

## The contract side

All three are typed from your contract's `streams` key. Each entry pairs the `payload` that starts the stream with the `chunk` shape it yields, plus a `kind` and an optional `nudges` map:

```typescript [ai-socket.ts]
interface AiSocket {
  streams: {
    'ask-ai': {
      payload: { prompt: string }
      chunk: { text: string }
      kind: 'ephemeral' // or 'persistent' for a durable stream
      nudges: { 'add-context': { context: string } } // optional mid-stream messages
    }
  }
}
```

`kind: 'persistent'` is what makes `resumeStream(...)` and automatic reconnect-resume type-check for that stream — see [Durable & Resume](/client/streams/durable-and-resume). `nudges` types the `nudge(...)` method on the handle — see [Nudges](/client/streams/nudges).

## Pair durable streams with keepalive

A resumable stream waits for its next chunk. If the connection half-dies — drops with no close frame — nothing in the stream itself can tell, and the iterator would wait forever. Only [`keepalive()`](/client/primitives/keepalive)'s pings notice a dead socket, and [`reconnection()`](/client/primitives/reconnection) brings it back so the stream can resume. Install both alongside `stream()` whenever you use persistent streams. (In debug mode, a persistent stream **started with `stream()`** without keepalive logs a warning — a cold `resumeStream()` doesn't emit this one, so don't rely on it there.)
