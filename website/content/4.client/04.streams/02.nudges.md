A **nudge** is a typed message you send _into_ a running stream. You use it to change what the stream does (for example, pause it or give it more context) without stopping the stream and starting a new one. `nudge(...)` is a method on the handle that `stream(...)` returns, so only the client that started the stream can nudge it.

```typescript [app.ts]
const tokens = await socket.stream('ask-ai', { prompt })

// a button handler that runs while a loop is still reading `tokens`:
async function onAddContext() {
  await tokens.nudge('add-context', { context: 'be brief' })
}
```

## Typed from the contract

The types of `nudge(event, payload)` come from the `nudges` map in the stream's contract entry. You can only send the nudges that the stream declares, and each payload must have the declared shape:

```typescript [ai-socket.ts]
interface AiSocket {
  streams: {
    'ask-ai': {
      payload: { prompt: string }
      chunk: { text: string }
      nudges: {
        pause: {}
        'add-context': { context: string }
      }
    }
  }
}
```

If a stream has no `nudges` in its contract, `nudge()` accepts no event names. Any call to it is a compile error.

## What a nudge resolves to

`nudge(...)` returns a promise. The promise depends on the server's confirmation (the server's reply that says it accepted the nudge):

- **Resolves** when the server confirms the nudge. The server confirms after it checks the payload and adds the nudge to the stream's queue of nudges.
- **Rejects** if the server refuses the nudge, or if `nudgeTimeout` passes with no confirmation. The server refuses a nudge when the event is not a declared nudge, when the payload fails validation, or with `NudgeOverflow` when too many nudges are waiting and the stream has not read them yet.
- **Rejects** with `Disconnected` if the socket is not open. It fails at once and does not wait for the timeout. A nudge that is still waiting for confirmation when the socket closes also rejects with `Disconnected`.

**A rejected nudge does not end the stream.** Only that one `nudge(...)` call failed, and the chunks keep coming. If the stream has already finished, `nudge(...)` sends nothing and resolves right away.

```typescript [app.ts]
try {
  await tokens.nudge('add-context', { context: 'be brief' })
} catch (err) {
  // the server refused this nudge, or it timed out; the stream is still running
  console.warn('nudge not applied', err)
}
```

## The nudge timeout

The `nudgeTimeout` option on the `stream()` primitive sets how long `nudge()` waits for confirmation, in milliseconds (default `10_000`). You can also set a different timeout for one call:

```typescript [app.ts]
const socket = client<AiSocket>()(
  connect('wss://example.com/ws'),
  stream({
    nudgeTimeout: 10_000, // how long nudge() waits for confirmation (default: 10_000)
  }),
)

// a longer timeout for one slow nudge:
await tokens.nudge('add-context', { context }, { timeout: 30_000 })
```

Set `nudgeTimeout: 0` (or `{ timeout: 0 }` on one call) to turn the confirmation timeout off. `nudge()` then waits with no time limit for the server to confirm, and it never rejects with `Timeout`.

## On a channel

A stream that you start on a channel handle also returns a handle with `nudge(...)`. It works the same way. On the wire, each nudge carries the channel name, so the server delivers it to the stream in that channel. The server refuses the nudge with `ChannelNotSubscribed` if you are no longer a member of the channel.

::note
You can only nudge streams that **you** started. A broadcast stream that you read with [`onStream()`](/client/streams/broadcast-onstream) has no handle, so you can't nudge it. For that stream you only listen; you did not start it.
::
