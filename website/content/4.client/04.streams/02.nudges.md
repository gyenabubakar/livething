A **nudge** is a typed message you send _into_ a running stream — to pause it, steer it, speed it up — without tearing it down and starting over. It lives on the handle `stream(...)` returned, so only the side that started the stream can nudge it.

```typescript [app.ts]
const tokens = await socket.stream('ask-ai', { prompt })

// a button handler, while the loop above is still consuming:
async function onAddContext() {
  await tokens.nudge('add-context', { context: 'be brief' })
}
```

## Typed from the contract

`nudge(event, payload)` is typed from the `nudges` map of the stream's contract entry — you can only send nudges the stream declared, with the right payload:

```typescript [ai-socket.ts]
interface AiSocket {
  streams: {
    'ask-ai': {
      payload: { prompt: string }
      chunk: { text: string }
      nudges: {
        pause: {}
        'add-context': { context: string }
      }
    }
  }
}
```

A stream with no `nudges` in its contract has no `nudge()` to call — it's a compile error.

## What a nudge resolves to

`nudge(...)` returns a promise tied to the server's acknowledgement:

- **Resolves** when the server confirms it received and applied the nudge.
- **Rejects** if the server refuses it, or if `nudgeTimeout` passes with no confirmation.
- **Rejects** with `Disconnected` if the socket isn't open — it fails fast rather than waiting out the timeout.

Crucially, **a rejected nudge does not end the stream** — only that one nudge call failed; the chunks keep flowing. And after the stream has already finished, `nudge(...)` resolves to a harmless no-op (it sends nothing).

```typescript [app.ts]
try {
  await tokens.nudge('add-context', { context: 'be brief' })
} catch (err) {
  // the server refused this nudge, or it timed out — the stream is still running
  console.warn('nudge not applied', err)
}
```

## The nudge timeout

How long `nudge()` waits for confirmation is the `nudgeTimeout` option on the primitive (default `10_000`), and you can override it per call:

```typescript [app.ts]
const socket = client<AiSocket>()(
  connect('wss://example.com/ws'),
  stream({
    nudgeTimeout: 10_000, // how long nudge() waits for confirmation (default: 10_000)
  }),
)

// override for one slow nudge:
await tokens.nudge('add-context', { context }, { timeout: 30_000 })
```

Set `nudgeTimeout: 0` (or `{ timeout: 0 }` on a single call) to turn the confirmation timeout off — `nudge()` then waits indefinitely for the server to confirm, and never rejects with `Timeout`.

## On a channel

A stream started on a channel handle returns a handle whose `nudge(...)` is scoped to that channel, exactly the same way — the nudge is tagged to the room on the wire.

::note
Nudges are for streams **you** started. A broadcast stream consumed with [`onStream()`](/client/streams/broadcast-onstream) has no handle and can't be nudged — you're a listener there, not the owner.
::
