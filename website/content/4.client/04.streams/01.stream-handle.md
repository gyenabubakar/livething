`socket.stream(event, payload, options?)` starts a stream and returns a **promise for a handle**. The promise resolves when the server accepts the stream. The handle is an **async iterable**: an object you read one chunk at a time with a `for await` loop.

```typescript [client/search.ts]
import { appendSearchHit } from './huddle-ui'
import { socket } from './socket'

const hits = await socket.stream('search-messages', {
  query: 'launch date',
})

for await (const chunk of hits) {
  appendSearchHit(chunk.hit) // chunk is typed from the stream's `chunk`
}
// the loop ended normally, so the stream finished
```

## When the promise settles

The promise from `stream(...)` is about _starting_ the stream, not finishing it:

- **Resolves** when the server confirms that it accepted the stream. This happens before any chunk arrives.
- **Rejects** if the server refuses the stream at the start. The usual reasons are:
  - `stream-id-collision`: the `streamId` you chose is already used by another running stream.
  - `stream-already-active`: another stream of the same event is already running on this connection. **By default**, a connection runs one stream per event name at a time. The server can allow more with `allowConcurrent: true` on the stream handler (see [server streams](/server/handlers/stream)). Then this error is not sent.
- **Rejects** with `Disconnected` if the socket is not open and cannot open. On a non-lazy socket that you have not `connect()`ed yet, the call rejects at once. A lazy socket (one that connects on first use) opens the connection for you. The promise also rejects with `Disconnected` if the connection closes before the server confirms.
- **Rejects** with `Timeout` if the server does not confirm within the `timeout` (the same limit as the per-chunk timeout, [below](#the-per-chunk-timeout)).
- **Rejects with a plain `TypeError`**, not a `LiveThingError`, if the payload can't be serialized (turned into text for the wire), for example because it has a circular reference. This error happens on the client before anything is sent. `.matches()` does not match it, but a `try/catch` catches it.

If you start a stream while the socket is still connecting, LiveThing holds the start message and sends it as soon as the socket opens. You don't need to wait for `open` yourself.

## Iterating

You read chunks with `for await`. The loop:

- **ends** when the server ends the stream. The `for await` loop finishes normally.
- **throws** on a terminal error (an error that ends the stream) or on a per-chunk timeout. Wrap the loop in `try/catch`.
- **cancels** the stream if you leave the loop with `break` or `return`.

```typescript [client/search.ts]
import { appendSearchHit, showToast } from './huddle-ui'
import { socket } from './socket'

const hits = await socket.stream('search-messages', {
  query: 'launch date',
})

let shown = 0
try {
  for await (const chunk of hits) {
    appendSearchHit(chunk.hit)
    if (++shown === 20) break // breaking cancels the stream for you
  }
} catch (err) {
  // a terminal server error, or a per-chunk timeout
  showToast('Search failed')
}
```

A thrown error is a `LiveThingError`. Use `.matches()` to check which error it is. A per-chunk timeout is `Timeout`. A disconnect that ends the stream is `Disconnected`. A server error is one of the errors your contract declares. `Forbidden` comes from `../shared/errors`, and Huddle's definition declares it:

```typescript [client/search.ts]
import { Disconnected, Timeout } from '@livething/client/errors'
import { Forbidden } from '../shared/errors'
import {
  appendSearchHit,
  showOfflineNotice,
  showToast,
} from './huddle-ui'
import { socket } from './socket'

const hits = await socket.stream('search-messages', {
  query: 'launch date',
})

try {
  for await (const chunk of hits) appendSearchHit(chunk.hit)
} catch (err) {
  if (Timeout.matches(err)) showToast('Search is slow')
  else if (Disconnected.matches(err)) showOfflineNotice()
  else if (Forbidden.matches(err))
    showToast(err.detail.reason) // a typed server error
  else showToast('Search failed')
}
```

Chunks go into a queue in the order they arrive, and your loop gets them one at a time. If a chunk arrives while your loop is still working on the previous one, the chunk waits in the queue. The client puts **no size limit** on this queue. If the server sends chunks much faster than your loop handles them, the chunks collect in memory. When the server is fast and your UI is slow, keep the loop body small: move slow work out of the loop, or skip some chunks, so the loop keeps up.

## The handle

```typescript [client/run-task.ts]
import { socket } from './socket'

const task = await socket.stream('run-task', {
  goal: 'Summarize this week',
  roomId: 'general',
})

task.streamId // the ID of this stream
task.active // true while the stream is running
await task.nudge('add-context', {
  text: 'the #design channel, not #general',
}) // a message into the running stream (see Nudges)
task.cancel() // ask the server to stop; the loop ends without throwing
```

- **`streamId`** is the ID that links all chunks of this stream. Set it yourself with the third argument ([below](#pinning-the-stream-id)), or read the generated one here.
- **`active`** is `true` while the stream runs. It becomes `false` when the stream ends, fails, or is cancelled.
- **`nudge(...)`** sends a message into the server's running stream generator. See [Nudges](/client/streams/nudges).
- **`cancel()`** asks the server to stop. The loop ends **without throwing**, unlike when an error happens. If the stream has already finished, `cancel()` does nothing. If the socket is reconnecting when you call `cancel()`, LiveThing sends the cancel when the connection opens again, and the loop ends then.

`cancel()` and `break` do the same thing. Leaving the loop with `break` calls `cancel()` for you.

## The per-chunk timeout

The `timeout` option limits how long `stream()` waits for the **next chunk**. It is not a limit on the whole stream. The timer starts again on every chunk. So a long stream that keeps sending chunks never times out. Only a _gap_ between chunks that is longer than the limit causes a timeout. When that happens, the loop throws `Timeout`.

```typescript [client/socket.ts]
import { binary, client, connect, stream } from '@livething/client'
import type { HuddleSocket } from '../server/huddle-definition'

export const socket = client<HuddleSocket>()(
  connect('wss://huddle.example.com/huddle'),
  binary(),
  stream({
    timeout: 30_000, // wait for the next chunk; starts again on each one (default: 30_000)
  }),
)
```

Set `timeout: 0` to turn the per-chunk timeout off. This also turns off the timeout for the server's start confirmation.

## Pinning the stream ID

By default, each stream gets a generated ID. To choose the ID yourself ("pin" it), pass `streamId` in the third argument. This is useful when you want a fixed ID that you can continue later, linked to something in your app such as a room. Only a durable stream can be continued, so pin a durable one like `ask-scout`. An ephemeral stream like `run-task` cannot be continued, even with a pinned ID.

```typescript [client/room.ts]
import { socket } from './socket'

const room = socket.channel('rooms', 'room:general')
await room.subscribe({})

const recap = await room.stream(
  'ask-scout',
  { prompt: 'Recap this week' },
  { streamId: 'scout-recap-general' },
)
```

A pinned `streamId` must be a non-empty string of at most **128 characters**. The client checks this before sending. An invalid ID rejects the `stream()` promise with `ValidationFailed`, and no message reaches the server.

A pinned ID lets you [reattach to](/client/streams/durable-and-continue) the same stream after a page reload. Reattaching connects again to a durable stream from a new page or tab.

## On a channel

With [`channels()`](/client/primitives/channels), a channel handle gets the same `stream(...)` method. It is scoped to that channel and typed from the channel's contract:

```typescript [client/room.ts]
import { appendScoutText } from './huddle-ui'
import { socket } from './socket'

const room = socket.channel('rooms', 'room:general')
await room.subscribe({})

const scoutReply = await room.stream('ask-scout', {
  prompt: 'What did I miss?',
})
for await (const chunk of scoutReply) appendScoutText(chunk.text)
```
