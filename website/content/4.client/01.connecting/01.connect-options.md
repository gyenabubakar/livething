`connect(url, options?)` takes three options. All of them are optional, and the defaults work for most apps.

```typescript [client/socket.ts]
connect('wss://example.com/huddle', {
  lazy: false, // open only when something needs the socket (default: false)
  idleTimeout: 10_000, // in lazy mode, close after this long with no use (default: 10s)
  protocols: ['huddle-v2'], // WebSocket subprotocols (default: none)
})
```

## `connect()` and `disconnect()`

Before the options, here are the two socket methods that open and close the connection:

- **`socket.connect()`** opens the connection. You can call it more than once. While the socket is already `open` or `connecting`, it does nothing.
- **`socket.disconnect(code?, reason?)`** closes the connection on purpose, and for good. It closes the WebSocket, stops any reconnection, clears the send buffer, and rejects pending requests. `code` defaults to `1000` (normal closure) and `reason` defaults to `''`. Both go to the native `WebSocket.close()` and show up in `onClose`.

Your `on()` handlers stay registered after a `disconnect()`. So when you call `connect()` again later, all your listeners still work. A `disconnect()` ends the session, so the next `connect()` counts as a _first_ connect, not a reconnect. `onReconnect` does not run for it.

## `lazy`

By default (`lazy: false`), the socket opens when you call `connect()`, and not before. Adding a listener with `on()` or calling `send()` does **not** open a non-lazy socket. You decide when it connects.

With `lazy: true`, the socket stays closed until some code needs the connection. Then it opens by itself. These calls count as "needing the connection":

- `on(...)`: adding a listener.
- `send(...)`: sending a message.
- Primitive calls that need a connection, such as `request(...)`, `channel(...).subscribe()`, or `stream(...)`.

```typescript [client/socket.ts]
import { binary, client, connect } from '@livething/client'
import { showToast } from './huddle-ui'
import type { HuddleSocket } from '../server/huddle-definition'

const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle', { lazy: true }),
  binary(),
)

// No connection yet. Nothing uses the socket.

socket.on('notification', (data) => showToast(data.title))
// The socket connects now, because it has a listener.
```

A `send()` on a closed lazy socket starts the connection, but that first message is not delivered, because the socket is not open yet. `send()` returns `false`. Add [`buffering()`](/client/primitives/buffering) to hold the message and send it when the socket opens. Calls that wait for an answer, such as `request(...)` and `stream(...)`, don't have this problem: they wait for the socket to open and then send.

Each listener counts as a **consumer**: something that keeps the connection open. Calling the unsubscribe function that `on()` returns removes that consumer. When no consumers are left and no operations are pending, the socket closes after [`idleTimeout`](#idletimeout). The next `on()` or `send()` opens it again. This keeps the connection closed (and saves battery on mobile) on pages that use the socket only now and then.

```typescript [client/socket.ts]
// With the lazy socket from above:
const stop = socket.on('notification', (data) =>
  showToast(data.title),
) // 1 consumer: connects
// ...
stop() // 0 consumers: the idle timer starts, and the socket closes after idleTimeout
```

A `send()` also counts as use. While the socket is open with no listeners, each `send()` starts the idle timer again from zero, so a socket that only sends stays open while it keeps sending.

The idle close is a normal `disconnect()`. `onClose` runs, and when the socket opens again later it is a first connect, so `onReconnect` does not run.

A `disconnect()` does **not** reset the consumer count. Your `on()` handlers stay registered after a disconnect, so they still count as consumers the next time you call `connect()`.

::note
**React strict mode.** In development, React 18 and later mount each component twice (mount, unmount, mount). A lazy socket handles this without closing. The unmount removes the listener, and the second mount adds it again right away, long before `idleTimeout` ends. So the idle close never happens. Production builds mount only once.
::

## `idleTimeout`

`idleTimeout` is how long a **lazy** socket stays open with nothing using it before it closes, in milliseconds. The default is `10_000` (10 seconds). It applies only in lazy mode. A non-lazy socket stays open until you call `disconnect()`.

Set it to `0` to turn off the idle close:

```typescript [client/socket.ts]
connect('wss://example.com/huddle', { lazy: true, idleTimeout: 0 })
// Opens on first use, then stays open. It never closes by itself.
```

`lazy: true` with `idleTimeout: 0` means "open when needed, then stay connected". Use it for a socket that your app needs only sometimes, when opening a new connection costs more than keeping one open.

## `protocols`

A **subprotocol** is a name for a message format that the client and server agree on when the WebSocket opens. The client offers a list of names, and the server picks one.

`protocols` is the list of subprotocols the client offers. LiveThing passes it directly to the native `WebSocket` constructor. Most apps don't need it. Use it when a gateway in front of your server expects a subprotocol, for example `huddle-v2`.

LiveThing does not choose between subprotocols. On Node, the server accepts the first name you offer. The Cloudflare adapter answers with no subprotocol, and a browser then fails the connection, so leave `protocols` off on Cloudflare.

```typescript [client/socket.ts]
import { binary, client, connect } from '@livething/client'
import type { HuddleSocket } from '../server/huddle-definition'

const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle', {
    protocols: ['huddle-v2'],
  }),
  binary(),
)

socket.connect()
// After the socket opens, read which one the server picked:
socket.protocol // 'huddle-v2', or null
```

`socket.protocol` is the subprotocol the server picked. It is `null` when you offered none, when the server picked none, or when the socket is not open.
