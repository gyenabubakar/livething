`connect(url, options?)` takes three options. All are optional, and the defaults suit most apps.

```typescript [app.ts]
connect('wss://example.com/ws', {
  lazy: false, // open only when something needs the socket (default: false)
  idleTimeout: 10_000, // in lazy mode, close after this long with no use (default: 10s)
  protocols: ['graphql-transport-ws'], // WebSocket subprotocols (default: none)
})
```

## `connect()` and `disconnect()`

Before the options, the two methods that drive the connection:

- **`socket.connect()`** opens the connection. It's safe to call more than once — while the socket is already `open` or `connecting`, it does nothing.
- **`socket.disconnect(code?, reason?)`** is a deliberate, full stop. It closes the WebSocket, stops any reconnection, clears the send buffer, and rejects pending requests. `code` defaults to `1000` (normal closure) and `reason` to `''`; both are passed through to the native `WebSocket.close()` and show up in `onClose`.

Your `on()` handlers survive a `disconnect()`, so calling `connect()` again later resumes with all listeners intact. Because `disconnect()` ends the session, the next `connect()` counts as a _first_ connect, not a reconnect — `onReconnect` doesn't fire on it.

## `lazy`

By default (`lazy: false`) the socket opens when you call `connect()`, and not before. Subscribing with `on()` or calling `send()` does **not** open a non-lazy socket on its own — you're in control of when it connects.

With `lazy: true`, the socket waits until something actually needs the connection, then opens it automatically. What counts as "needing it":

- `on(...)` — registering a listener.
- `send(...)` — handing the socket a message to deliver.
- Primitive operations that require a connection, such as `request(...)`, `channel(...).subscribe()`, or `stream(...)`.

```typescript [app.ts]
const socket = client<MySocket>()(
  connect('wss://example.com/ws', { lazy: true }),
)

// No connection yet — nothing is using the socket.

socket.on('notification', (data) => render(data))
// NOW it connects — there's a listener.
```

Each listener counts as a consumer that holds the connection open; the unsubscribe function releases it. When the count reaches zero and there are no pending operations, the socket closes after [`idleTimeout`](#idletimeout). The next `on()` or `send()` opens it again. This keeps the connection (and battery, on mobile) off pages where the socket is only needed now and then.

```typescript [app.ts]
const stop = socket.on('notification', render) // consumer +1 → connects
// ...
stop() // consumer 0 → idle timer starts → closes after idleTimeout
```

A `send()` keeps the socket up too: on a lazy socket with no listeners, sending opens it, and once the send settles the idle timer starts again. And `disconnect()` does **not** reset the consumer count — `on()` handlers survive a disconnect, so they still hold the socket the next time you `connect()`.

::note
**React strict mode.** In development, React 18+ double-mounts components, so a quick mount → unmount → mount can briefly close and reopen a lazy socket within the idle window. It's harmless — the socket reconnects and re-registers handlers on the second mount, and strict-mode double-mounting doesn't happen in production builds.
::

## `idleTimeout`

`idleTimeout` is how long a **lazy** socket stays open with nothing using it before it closes. The default is `10_000` (10 seconds). It only applies in lazy mode — a non-lazy socket stays open until you call `disconnect()`.

Set it to `0` to disable the idle close entirely:

```typescript [app.ts]
connect('wss://example.com/ws', { lazy: true, idleTimeout: 0 })
// Opens on first use, then stays open — never auto-closes.
```

`lazy: true` with `idleTimeout: 0` means "open on demand, then stay connected" — a good fit for an infrequently-used socket where reconnecting is more expensive than holding the connection open.

## `protocols`

`protocols` is the list of WebSocket subprotocols to offer during the handshake — passed straight to the native `WebSocket` constructor. Most apps don't need this; it's for servers that negotiate a subprotocol (for example `graphql-transport-ws`).

```typescript [app.ts]
const socket = client<MySocket>()(
  connect('wss://example.com/ws', {
    protocols: ['graphql-transport-ws', 'graphql-ws'],
  }),
)

socket.connect()
// After the socket is open, read which one the server chose:
socket.protocol // 'graphql-transport-ws' | 'graphql-ws' | null
```

`socket.protocol` is the subprotocol the server selected, or `null` when you offered none or the socket isn't open.
