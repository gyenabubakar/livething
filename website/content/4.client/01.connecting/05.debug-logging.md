Every socket has `setDebug(enabled)`. It turns console logging on or off. The logs show connection events, messages in and out, reconnection attempts, and more. Use it while you develop and test, and leave it off in production. It is off by default.

```typescript [client/socket.ts]
import { binary, client, connect } from '@livething/client'
import type { HuddleSocket } from '../server/huddle-definition'

export const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle'),
  binary(),
)

socket.setDebug(true)
```

A common pattern is to pass your build tool's development flag, so logging is on only in development builds. With Vite, that flag is `import.meta.env.DEV`:

```typescript [client/socket.ts]
socket.setDebug(import.meta.env.DEV)
```

Call it before `socket.connect()` if you want the first connect in the logs. You can also call it at any time while the app runs. This is useful when you want logs only while you look into a problem:

```typescript [client/socket.ts]
socket.setDebug(true) // start logging
socket.setDebug(false) // stop
```

## What it logs

With debug on, the socket logs things like:

- State changes, such as `closed → connecting`, and the URL it connects to, without its query string, hash or login details, since those can carry an auth token.
- Messages received (`received 'message'`) and sent (`send('send-message')`).
- A send that did not go out right away: `send('send-message') not sent — not connected`, `buffered 'send-message'`, or `send('__send-message') dropped — reserved event name`.
- Reconnection attempts, connection failures, and a [lazy](/client/connecting/connect-options#lazy) socket opening on first use or closing after `idleTimeout`.
- Ping and pong frames, a primitive that handled a message, and an intercept that dropped a message.
- Duplicate messages that were dropped, and server data that could not be parsed.
- Binary messages in and out, with the byte count in place of the bytes: `received binary 'avatar-preview' null <12345 bytes>`. See [binary](/client/primitives/binary).

The output is plain `console` lines that start with `[livething]`. For example:

```text
[livething] closed → connecting
[livething] connecting to wss://example.com/huddle
[livething] received 'message' { id: 'm-7', text: 'hi', from: 'u_100', sentAt: 1717000000000 }
[livething] buffered 'send-message'
[livething] dropped duplicate 'notification' (delivery id m-7)
```

The exact lines depend on which primitives you added to `client()`. Each primitive logs its own activity in the same way, with the same prefix. You cannot send the logs to another place or filter them by name. Debug output always goes to `console`, and the only setting is on or off.
