Frameworks such as Next.js, Nuxt, SvelteKit and TanStack Start use **server-side rendering (SSR)**: they run your components on the server first to build the HTML, then run them again in the browser. On the server, browser globals such as `window`, `document`, `navigator` and `WebSocket` do not exist. Code that uses them while a module loads will crash during SSR.

The LiveThing client does not use these globals when you import it, and it does not use them when you call `client(...)`. The `WebSocket` object is created only when the connection opens. So you can import `@livething/client` and create a socket in a module that also runs on the server. Nothing opens until you connect, in the browser.

```typescript [client/socket.ts]
import { binary, client, connect } from '@livething/client'
import type { HuddleSocket } from '../server/huddle-definition'

// Safe at module scope, also during SSR on Node. This opens no connection.
export const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle'),
  binary(),
)
```

[`binary()`](/client/primitives/binary) checks for `TextDecoder` when `client(...)` runs. Node, Bun, Deno and every browser have it, so this is safe during SSR too.

## Connect in the browser

You can create the socket anywhere. **Connecting** is the step that must run only in the browser. Call `socket.connect()` from a mount hook or an effect. A mount hook is a function your framework calls after the component appears on the page. It runs only in the browser, never during SSR.

::code-group

```tsx [React]
import { useEffect } from 'react'
import { socket } from './socket'

function App() {
  // useEffect runs only in the browser, so connect here.
  useEffect(() => {
    socket.connect()
    return () => socket.disconnect()
  }, [])
  // ...
}
```

```svelte [Svelte]
<script>
  import { onMount } from 'svelte'
  import { socket } from './socket'

  // onMount runs only in the browser, so connect here.
  onMount(() => {
    socket.connect()
    return () => socket.disconnect()
  })
</script>
```

```vue [Vue]
<script setup lang="ts">
import { onBeforeUnmount, onMounted } from 'vue'
import { socket } from './socket'

onMounted(() => socket.connect())
onBeforeUnmount(() => socket.disconnect())
</script>
```

::

A lazy socket (`connect(url, { lazy: true })`) opens by itself the first time something needs it, for example the first `on()` or `send()`. You do not call `connect()` yourself. Make sure that first use happens in the browser, not during render.

## Platform signals are SSR-safe too

[`platform()`](/client/platform/environments) takes an environment: the object that reports whether the page is visible and whether the device is online. The browser environment, `WebEnvironment`, reads `document`, `window` and `navigator` only inside its subscribe calls, never when you import it. Where those globals do not exist (SSR, Node, a runtime without a DOM), it reports no signals.

So you can add `platform({ environment: WebEnvironment })` to a socket at module scope. It starts to watch visibility and network changes only after the socket opens in the browser.

```typescript [client/socket.ts]
import { binary, client, connect, platform } from '@livething/client'
import { WebEnvironment } from '@livething/client/environment'
import type { HuddleSocket } from '../server/huddle-definition'

export const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle'),
  binary(),
  platform({ environment: WebEnvironment }),
)
```

## The one rule

Create the socket wherever you like, but do not **connect** during server render. An explicit `connect()`, or the first `on()` or `send()` on a lazy socket, belongs in code that runs only in the browser: a mount hook, an effect or an event handler. Until then, the socket does nothing.
