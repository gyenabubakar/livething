Every socket needs to know where to connect. You tell it with the `connect(...)` primitive. It is the only required argument to `client()`. This chapter covers how connecting works: the options you can set, a URL that can change, how to send auth data, and how to create a socket safely in server-rendered (SSR) code.

## The `connect` primitive

`connect(url, options?)` takes the server's WebSocket URL and a few options. In the example, `HuddleSocket` is Huddle's contract type, inferred from the server definition (see [Creating a socket](/client/overview#creating-a-socket)):

```typescript [client/socket.ts]
import { client, connect } from '@livething/client'
import type { HuddleSocket } from '../server/huddle-definition'

export const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle', { lazy: false }),
)

socket.connect()
```

`url` is a string, or a function that returns a string (sync or async). The function runs again on every connect and reconnect. So each attempt can use a different server. For example, you can move to a backup server when one is down (failover), or spread users across many servers (load balancing). See [Dynamic URL](/client/connecting/dynamic-url).

## What happens on connect

Calling `socket.connect()` moves the socket from `closed` to `connecting`. The socket moves to `open` when the WebSocket [handshake](/start/what-is-websocket) completes. (The handshake is the first HTTP request and response that turn the connection into a WebSocket.) Between `connecting` and `open`, the client does these steps:

1. **Resolves the URL.** If you passed a URL function, the client calls it. If the function is async, the client waits for its result.
2. **Adds query params.** Each [`query()`](/client/connecting/auth-and-query) primitive adds its params to the URL, one after another. This is how an auth token reaches the server.
3. **Opens the WebSocket.** It uses the final URL and any subprotocols you set. (A subprotocol is a name for a message format that the client and the server agree to use.)

Calling `connect()` again while the socket is `open` or `connecting` does nothing. You can call `disconnect()` at any time to stop the connection on purpose. If you call it while the URL or the query params are still resolving, the client cancels that attempt and ignores its result.
