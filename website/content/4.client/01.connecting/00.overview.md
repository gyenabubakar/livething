Every socket needs one thing: where to connect. That's the `connect(...)` primitive — the single required argument to `client()`. This chapter covers how connecting works: the options you can set, pointing at a URL that changes, attaching auth, and creating a socket safely on the server.

## The `connect` primitive

`connect(url, options?)` takes the URL and a few options:

```typescript [app.ts]
import { client, connect } from '@livething/client'
import type { MySocket } from './socket-types'

const socket = client<MySocket>()(
  connect('wss://example.com/ws', { lazy: false }),
)

socket.connect()
```

`url` is a string, or a function that returns one (sync or async) — the function runs again on every connect and reconnect, which is how failover and load balancing work. See [Dynamic URL](/client/connecting/dynamic-url).

## What happens on connect

Calling `socket.connect()` moves the socket from `closed` to `connecting`, then to `open` once the WebSocket handshake completes. In between, the client:

1. **Resolves the URL** — calls your URL function if you passed one, awaiting it if it's async.
2. **Appends query params** — any [`query()`](/client/connecting/auth-and-query) primitive adds its params to the resolved URL, in order. This is how an auth token reaches the server.
3. **Opens the WebSocket** — with the final URL and any subprotocols you set.

Calling `connect()` again while already open or connecting does nothing. Calling `disconnect()` at any point is a clean, deliberate stop — and if it happens while the URL or query is still resolving, that in-flight attempt is cancelled and its result discarded.
