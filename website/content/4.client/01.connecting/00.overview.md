Every socket needs to know where to connect. You tell it with the `connect(...)` primitive. It is the one argument that every `client()` call needs. (A server that sends binary messages, like Huddle's, also needs [`binary()`](/client/primitives/binary).) This chapter covers how connecting works: the options you can set, a URL that can change, how to send auth data, and how to create a socket safely in server-rendered (SSR) code.

## The `connect` primitive

`connect(url, options?)` takes the server's WebSocket URL and a few options. In the example, `HuddleSocket` is Huddle's contract type, inferred from the server definition (see [Creating a socket](/client/overview#creating-a-socket)):

```typescript [client/socket.ts]
import { binary, client, connect } from '@livething/client'
import type { HuddleSocket } from '../server/huddle-definition'

export const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle', { lazy: false }),
  binary(),
)

socket.connect()
```

`url` is a string, or a function that returns a string (sync or async). The function runs again on every connect and reconnect. So each attempt can use a different server. For example, you can move to a backup server when one is down (failover), or spread users across many servers (load balancing). See [Dynamic URL](/client/connecting/dynamic-url).

## What happens on connect

Calling `socket.connect()` moves the socket from `closed` to `connecting`. The socket moves to `open` when the WebSocket [handshake](/start/what-is-websocket) completes. (The handshake is the first HTTP request and response that turn the connection into a WebSocket.) Between `connecting` and `open`, the client does these steps:

1. **Resolves the URL.** If you passed a URL function, the client calls it. If the function is async, the client waits for its result. A URL function is also how an auth token reaches the server, in the query string (see [Auth & Query](/client/connecting/auth-and-query)).
2. **Opens the WebSocket.** It uses the URL and any subprotocols you set. (A subprotocol is a name for a message format that the client and the server agree to use.)

Calling `connect()` again while the socket is `open` or `connecting` does nothing. You can call `disconnect()` at any time to stop the connection on purpose. If you call it while the URL is still resolving, the client cancels that attempt and ignores its result.
