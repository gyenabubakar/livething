An open socket in a tab the user isn't looking at costs battery and server resources for nothing. **Background disconnect** closes the socket after the app has been hidden for a while, then reopens it the moment the user comes back — so a backgrounded tab goes quiet, and a returning one is live again without you writing any of it.

You turn it on with `backgroundDisconnectMs` on `platform()`:

```typescript [app.ts]
import {
  client,
  connect,
  platform,
  reconnection,
} from '@livething/client'
import { WebEnvironment } from '@livething/client/environment'

const socket = client<ChatSocket>()(
  connect('wss://example.com/ws'),
  reconnection(),
  platform({
    environment: WebEnvironment,
    backgroundDisconnectMs: 30_000, // disconnect 30s after the tab is hidden
  }),
)
```

## How it behaves

The number is a **grace period**, not an instant cutoff:

- When the app becomes hidden, a timer starts for `backgroundDisconnectMs`.
- If the app comes back **before** the timer fires, the timer is cancelled and nothing happens — a quick tab-switch never drops the socket.
- If the timer **does** fire while the socket is still open, the socket is suspended (closed deliberately, without counting as a reconnectable drop).
- When the app becomes visible again after that, the socket reopens automatically.

```typescript [app.ts]
// You write none of this — platform() does it:
// hidden ──30s──▶ suspend the socket
// visible ─────▶ reopen it
```

A short hide-and-return costs nothing; only a genuinely backgrounded tab gets disconnected, and returning to it brings the socket straight back.

## What you can observe

Background disconnect drives the same public events as any close and reopen, so anything you've already wired up sees it too:

| Moment           | Fires                                             | What you get                                                |
| ---------------- | ------------------------------------------------- | ----------------------------------------------------------- |
| Suspend on hide  | `socket.onClose(...)`                             | `{ code: 1000, reason: 'background', wasClean: true }`      |
| Reopen on return | `socket.onReconnect()`, then `open` + `reconnect` | channels rejoin and durable streams resume, before `onOpen` |

The return goes through the **reconnect** path, not a fresh first connect: every primitive's `onReconnect` runs — channels rejoin and resumable streams resume, exactly as after a network drop — so anything attached to `socket.onReconnect(...)` also fires on a return from background.

## Edge cases it handles for you

- **The socket already died on its own.** If a network blip closed the socket before the hidden timer fires, there's nothing to drop — `platform()` doesn't mark it as a background disconnect, so coming back to the tab won't try to reopen a socket it never closed (your `reconnection()`, if installed, handles that drop).
- **Starting hidden.** The environment reports the current visibility right away. That initial report doesn't start the disconnect timer — only an actual hide-while-running does — so opening a socket in an already-hidden tab doesn't immediately schedule a disconnect.
- **A manual `disconnect()` stops the watching.** If you call `socket.disconnect()` yourself, `platform()` detaches its visibility and network listeners — background disconnect (and network-aware reconnection) only start watching again after you call `connect()`.

## It needs visibility

Background disconnect relies on the visibility signal, so the environment must implement `onVisibilityChange`. Ask for `backgroundDisconnectMs` on an environment that can't see visibility and `platform()` throws a `LiveThingConfigError` at setup, rather than silently doing nothing:

```typescript [app.ts]
// throws LiveThingConfigError — this environment reports network but not visibility
platform({
  environment: networkOnlyEnvironment,
  backgroundDisconnectMs: 30_000,
})
```

Leave `backgroundDisconnectMs` off (or set it to `0`) and `platform()` just relays signals without ever dropping the socket for being hidden.

::note
Pair this with [`reconnection()`](/client/primitives/reconnection) so the reopen on return is smooth. The suspend-on-hide is deliberate and isn't itself treated as a drop to retry — it's the foreground signal that triggers the reopen.
::
