A socket can react to the world around it — go quiet when the tab is hidden, stop retrying while the device is offline, reconnect the moment either changes back. Those reactions need two signals from the host: whether the app is **visible**, and whether the network is **online**. The `platform()` primitive is how you supply them.

Platform awareness is fully **opt-in**. Nothing reads visibility or network state unless you add `platform()` with an environment — and the code that does isn't even in your bundle until you import it.

```typescript [app.ts]
import {
  client,
  connect,
  platform,
  reconnection,
} from '@livething/client'
import { WebEnvironment } from '@livething/client/environment'

const socket = client<ChatSocket>()(
  connect('wss://example.com/ws'),
  reconnection(),
  platform({
    environment: WebEnvironment, // where the signals come from
    backgroundDisconnectMs: 30_000, // drop the socket 30s after the tab is hidden
  }),
)
```

## Two signals, two behaviors

An **environment** is the source of the signals. It can report up to two things, and each one drives a different behavior:

| Signal         | Comes from           | Drives                                                                                                                    |
| -------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **visibility** | `onVisibilityChange` | [Background disconnect](/client/platform/background-disconnect) — drop the socket while hidden, reopen on return          |
| **network**    | `onNetworkChange`    | [Network-aware reconnection](/client/platform/network-aware) — pause retries while offline, retry the instant you're back |

Both are optional. An environment that reports only one signal enables only that behavior; the other simply stays off.

## The online store

`platform()` also adds `socket.online`, a [reactive store](/client/overview#reactive-stores) of a `boolean` — the network signal, ready to read in your UI. `socket.online.get()` reads it now, and `socket.online.subscribe(...)` runs when it flips. It changes only when the environment's `onNetworkChange` reports one, so an environment without that signal keeps it at its starting value.

```typescript [app.ts]
if (!socket.online.get()) showOfflineBadge()

socket.online.subscribe((online) => {
  online ? hideOfflineBadge() : showOfflineBadge()
})
```

Like every store on the socket, it binds to a framework with the same one-line adapter — see [Framework Hooks](/recipes/framework-hooks/react).

## The pieces

- An **environment** supplies the signals — use the ready-made [`WebEnvironment`](/client/platform/environments) in a browser, or write your own for React Native, Electron, or anywhere else.
- **`platform({ environment })`** wires those signals into the socket. On its own it just relays them; `backgroundDisconnectMs` turns on the hidden-tab disconnect.
- **`reconnection({ networkAware })`** picks up the network signal automatically when both primitives are installed — you don't connect them by hand.
