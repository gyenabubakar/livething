When the device is offline, a reconnection try cannot succeed. Each failed try also makes the next wait longer, because of backoff (the growing wait between tries). **Network-aware reconnection** uses the environment's network signal to stop tries while the device is offline. When the device is online again, the client tries at once.

This is the second behavior that `platform()` turns on. It needs two primitives: `platform()` supplies the network signal, and [`reconnection()`](/client/primitives/reconnection) uses it. Add both to the socket, and nothing else is needed.

```typescript [client/socket.ts]
import {
  client,
  connect,
  platform,
  reconnection,
} from '@livething/client'
import { WebEnvironment } from '@livething/client/environment'
import type { HuddleSocket } from '../server/definition'

export const socket = client<HuddleSocket>()(
  connect('wss://example.com/ws'),
  reconnection(), // networkAware is on by default
  platform({ environment: WebEnvironment }),
)
```

## What it does

When the network signal is present, `reconnection()` behaves like this:

- **The device goes offline.** If the socket then drops, `reconnection()` does not schedule a try. The socket stays in the `reconnecting` state and waits. No tries are used while the device is offline. If a try was already scheduled when the device went offline, that try is cancelled.
- **The device comes back online.** If the socket is in the `reconnecting` state, `reconnection()` opens it again at once. It does not wait for the timer. It also sets the attempt count back to 0, so if this try fails, the next wait starts again at about 1 second.

Because of this, a long time offline does not use up `maxAttempts`, and the socket reconnects as soon as the network returns.

## The `networkAware` option

`networkAware` is `true` by default. Set it to `false` if you want `reconnection()` to ignore the network signal and use only its timer. The client then keeps trying on schedule, whatever the environment reports.

```typescript [client/socket.ts]
const socket = client<HuddleSocket>()(
  connect('wss://example.com/ws'),
  reconnection({ networkAware: false }), // timer only, ignore online/offline
  platform({ environment: WebEnvironment }),
)
```

## It needs the signal

Network-aware reconnection only works when an environment reports network changes. This means you must add `platform()` with an environment that has `onNetworkChange`. The built-in `WebEnvironment` has it. Without that signal, `reconnection()` treats the device as always online and uses only its timer. `networkAware` then has no effect, and no error is thrown.

```typescript [client/socket.ts]
// no platform(), so no network signal: reconnection uses only its timer
client<HuddleSocket>()(
  connect('wss://example.com/ws'),
  reconnection(),
)
```

::note
`platform()` starts listening to the environment when you call `socket.connect()`, before the first connection attempt. At that moment the environment reports the current network state, not only later changes. So if the device is offline when the app starts, or when the socket drops, `socket.online` is `false` at once, and `reconnection()` waits for the network instead of using tries that cannot succeed. `platform()` stops listening on `disconnect()` and starts again on the next `connect()`.
::
