When the device goes offline, retrying the connection is pointless — every attempt is doomed until the network is back, and the backoff just grows while you wait. **Network-aware reconnection** uses the environment's online signal to pause retries while offline and fire one off the instant you're back online.

It's the second behavior `platform()` enables, and it works hand-in-hand with [`reconnection()`](/client/primitives/reconnection): `platform()` supplies the network signal, and `reconnection()` consumes it. You just install both.

```typescript [app.ts]
import {
  client,
  connect,
  platform,
  reconnection,
} from '@wskit/client'
import { WebEnvironment } from '@wskit/client/environment'

const socket = client<ChatSocket>()(
  connect('wss://example.com/ws'),
  reconnection(), // networkAware is on by default
  platform({ environment: WebEnvironment }),
)
```

## What it does

With the online signal flowing, `reconnection()` changes its behavior around the network:

- **Goes offline while connected** → when the socket drops, instead of scheduling a retry it sits in the `reconnecting` state and waits, spending no attempts on a connection that can't succeed.
- **Comes back online** → it resets the backoff and reopens **immediately**, without waiting out the current timer. Because the attempt counter is reset, the delay starts fresh from the base again rather than from wherever the backoff had climbed.

So a long offline stretch doesn't burn through your retry budget, and reconnection is snappy the moment the network returns.

## The `networkAware` option

`networkAware` is on by default. Set it to `false` to make `reconnection()` ignore the network signal and rely only on its timer — useful if you want retries to keep ticking regardless of what the platform reports:

```typescript [app.ts]
const socket = client<ChatSocket>()(
  connect('wss://example.com/ws'),
  reconnection({ networkAware: false }), // timer-only; ignore online/offline
  platform({ environment: WebEnvironment }),
)
```

## It needs the signal

Network-aware behavior only does something when an environment actually reports network changes — that means `platform()` installed with an environment whose `onNetworkChange` is implemented (the built-in `WebEnvironment` does). Without that signal, `reconnection()` assumes it's always online and runs on its timer alone, so `networkAware` has nothing to act on.

```typescript [app.ts]
// no platform() → no online signal → reconnection runs timer-only
client<ChatSocket>()(connect('wss://example.com/ws'), reconnection())
```

::note
The online signal is reported as soon as the environment binds, so a socket that starts offline knows it right away — `reconnection()` waits for the network instead of immediately throwing attempts at a dead link.
::
