`setup(socket)` receives a **`PluginSocket`** — an object with the same verbs the app socket has (`on`, `send`, `request`, `channel`, `stream`, `onStream`, `resumeStream`, `onRequest`), but typed to the plugin's own contract and scoped to its namespace. You write **plain names** — `socket.on('welcome', ...)`, `socket.send('hello', ...)` — and the framework adds the `__<id>::` prefix on the wire for you. See [Namespacing and matching](/client/plugins/namespacing-and-matching) for how that prefix works.

Every example below shares one contract:

```typescript [feed-wire.ts]
import type { SocketContract } from '@wskit/client'

interface FeedWire extends SocketContract {
  incoming: { welcome: { name: string } }
  outgoing: { hello: { name: string } }
  clientRequests: {
    echo: { payload: { text: string }; response: { echoed: string } }
  }
  streams: { feed: { payload: { from: number }; chunk: { row: number } } }
  serverRequests: {
    'device-info': { payload: {}; response: { platform: string } }
  }
}
```

A verb only exists on `socket` when the plugin's contract declares the matching section — a `FeedWire` with no `serverRequests` gets no `onRequest` at all, and calling it would be a compile error, not a runtime one. Each verb also needs its primitive registered on the host `client()`; see [Declaring primitive dependencies](/client/plugins/defining#declaring-primitive-dependencies) for the full list.

## Messaging: `on` and `send`

A contract with `incoming` gets `socket.on(...)`; one with `outgoing` gets `socket.send(...)`. Both need no dependency — they work with no primitives registered at all.

```typescript [feed-plugin.ts]
import { plugin } from '@wskit/client'
import type { FeedWire } from './feed-wire'

export const Feed = plugin<FeedWire, { hello(name: string): boolean }>()({
  id: 'e2e:feed',
  setup(socket) {
    // 'welcome' arrives on the wire as __e2e:feed::welcome
    socket.on('welcome', (message) => console.info('got', message.name))

    return {
      api: () => ({
        // 'hello' goes out as __e2e:feed::hello; true if sent or buffered
        hello: (name) => socket.send('hello', { name }),
      }),
    }
  },
})
```

`socket.on(...)` **holds the socket open** while it's registered, the same way the top-level `on()` does — a lazy socket a receive-only plugin drives doesn't idle-close out from under it (see [`idleTimeout`](/client/connecting/connect-options#idletimeout)). It returns an unsubscribe function that releases that hold.

`socket.send(...)` returns `true` if the message was handed to the socket or buffered, `false` if it was dropped before going anywhere — the same meaning as the top-level `send()`.

## `request` — needs `clientRequests`

A contract with the `clientRequests` contract key gets `socket.request(...)`, typed from the plugin's own `clientRequests` map. It needs the `clientRequests()` primitive registered on the host.

```typescript [feed-plugin.ts]
import { clientRequests, plugin } from '@wskit/client'
import type { FeedWire } from './feed-wire'

export const Feed = plugin<FeedWire, { echo(text: string): Promise<string> }>()(
  {
    id: 'e2e:feed',
    dependencies: [clientRequests],
    setup(socket) {
      return {
        api: () => ({
          // sent as __e2e:feed::echo; resolves with the typed response
          echo: async (text) => (await socket.request('echo', { text })).echoed,
        }),
      }
    },
  },
)
```

It settles the same way the top-level [`request()`](/client/primitives/client-requests) does — resolving with the typed response, rejecting with a typed `WSKitError`, `Timeout`, or `Disconnected`. A declared error the server throws reaches the caller as its **plain** code, with the plugin's prefix already stripped — see [Plugin errors](/client/plugins/errors).

## `stream`, `onStream`, `resumeStream` — need `stream`

A contract with `streams` gets all three: `socket.stream(...)` to trigger and iterate, `socket.onStream(...)` to listen to a broadcast stream, `socket.resumeStream(...)` to cold-resume a durable one. They need the `stream` primitive registered on the host, and they work exactly like their top-level counterparts — plain names in, `__<id>::` prefix on the wire.

```typescript [feed-plugin.ts]
import { plugin, stream } from '@wskit/client'
import type { StreamHandle } from '@wskit/client'
import type { FeedWire } from './feed-wire'

interface FeedApi {
  streamFeed(): Promise<StreamHandle<{ row: number }>>
}

export const Feed = plugin<FeedWire, FeedApi>()({
  id: 'e2e:feed',
  dependencies: [stream],
  setup(socket) {
    return {
      api: () => ({
        // triggers __e2e:feed::feed and returns a handle to iterate
        streamFeed: () => socket.stream('feed', { from: 0 }),
      }),
    }
  },
})
```

The handle `socket.stream(...)` resolves to is the same `StreamHandle` the top-level socket returns — `for await` to read chunks, and `handle.nudge(event, payload)` to send a mid-stream message if the stream declares `nudges`, all namespaced under the plugin automatically. The mechanics of the handle, cold resume, and nudging are covered in full in the [Streams chapter](/client/streams/overview) — see [Nudges](/client/streams/nudges) for the nudge details specifically. This page only covers that the three methods exist on the scoped socket, typed the same way.

## `onRequest` — needs `serverRequests`

A contract with the `serverRequests` contract key gets `socket.onRequest(...)`, so the server can ask this plugin a question. It needs the `serverRequests()` primitive registered on the host.

```typescript [feed-plugin.ts]
import { plugin, serverRequests } from '@wskit/client'
import type { FeedWire } from './feed-wire'

export const Feed = plugin<FeedWire>()({
  id: 'e2e:feed',
  dependencies: [serverRequests],
  setup(socket) {
    // answers a request the server sent to __e2e:feed::device-info
    socket.onRequest('device-info', () => ({ platform: 'web' }))

    return { api: () => ({}) }
  },
})
```

It behaves like the top-level [`onRequest()`](/client/primitives/server-requests): the return value (sync or async) becomes the reply, and it returns an unsubscribe function.

## `channel`

A contract with a `channels` section gets `socket.channel(...)` — the same fixed, dynamic-member, and family forms the top-level socket has, typed from the plugin's own channels and reached with plain names. It needs the `channels` primitive registered on the host. This page only lists that it exists; for the three forms, sending and receiving on a plugin channel, and owning a dynamic family from inside a plugin, see [Plugin channels & dynamic families](/client/plugins/dynamic-families).

## The raw message handlers

On top of the verbs above, every plugin socket — whatever its contract — carries the raw message handlers and tools from `PluginBase`, whether or not the plugin declares any wire sections at all.

### `onIncoming` and `onOutgoing`

These see every raw frame moving through the plugin's own namespace, before (`onIncoming`) or on the way to (`onOutgoing`) the wire. Return the message, maybe changed, to pass it on; throw `Block` to drop an incoming frame or cancel an outgoing one.

```typescript [feed-plugin.ts]
import { plugin } from '@wskit/client'
import { Block } from '@wskit/client/errors'
import type { FeedWire } from './feed-wire'

export const Feed = plugin<FeedWire>()({
  id: 'e2e:feed',
  setup(socket) {
    socket.onIncoming((message) => {
      if (message.event === '__e2e:feed::spam') throw Block // drop it
      return message // pass it on unchanged
    })

    socket.onOutgoing((message) => ({
      ...message,
      payload: { ...(message.payload as object), tracedAt: Date.now() },
    }))

    return { api: () => ({}) }
  },
})
```

By default these handlers see **only this plugin's own namespaced frames** — never the app's, never another plugin's. Wrap the plugin in `observeHost(...)` to widen that; see [Observing host traffic](/client/plugins/observe-host).

Each handler can be registered **once** — a second `socket.onIncoming(...)` call in the same `setup` throws:

```
[wskit] plugin 'e2e:feed' registered onIncoming() twice — use a single callback.
```

### `onOpen` and `onReconnect`

`onOpen` runs on every open (the first connect and every reconnect); `onReconnect` runs only on reconnects. Both return an array of `{ event, payload }` frames to send right away, or nothing — and both take plain names, which the framework namespaces before sending.

```typescript [feed-plugin.ts]
import { plugin } from '@wskit/client'
import type { FeedWire } from './feed-wire'

export const Feed = plugin<FeedWire>()({
  id: 'e2e:feed',
  setup(socket) {
    socket.onOpen(() => [{ event: 'hello', payload: { name: 'alice' } }]) // every open
    socket.onReconnect(() => [{ event: 'resync', payload: {} }]) // reconnects only

    return { api: () => ({}) }
  },
})
```

### `onClose`

`onClose(code, reason, suspended)` runs on every close. `suspended` is `true` for a platform pause that will resume the **same session** — a mobile app backgrounded, for instance — not a real end, so a handler should skip teardown in that case.

```typescript [feed-plugin.ts]
import { plugin } from '@wskit/client'
import type { FeedWire } from './feed-wire'

export const Feed = plugin<FeedWire>()({
  id: 'e2e:feed',
  setup(socket) {
    socket.onClose((code, reason, suspended) => {
      if (suspended) return // a pause, not a real close — keep in-memory state as is
      console.info('feed plugin closed', code, reason)
    })

    return { api: () => ({}) }
  },
})
```

## The tools

The rest of `PluginBase` is small tools you call yourself, from inside `setup` or from inside a hook, rather than callbacks the framework fires:

| Tool                  | What it does                                                                              |
| --------------------- | ----------------------------------------------------------------------------------------- |
| `generateId(prefix?)` | Make a unique ID that shares the socket's own counter, so it never clashes with anything. |
| `hasPrimitive(tag)`   | Whether a primitive with this tag is installed, e.g. `hasPrimitive('channels')`.          |
| `ensureConnected()`   | Open the connection now if it's lazy and hasn't connected yet.                            |
| `state`               | The connection state as a [reactive store](/client/overview#reactive-stores).             |

```typescript [feed-plugin.ts]
import { plugin } from '@wskit/client'
import type { FeedWire } from './feed-wire'

export const Feed = plugin<FeedWire, { sessionId: string }>()({
  id: 'e2e:feed',
  setup(socket) {
    const sessionId = socket.generateId('feed-session')

    socket.state.subscribe((state) => console.info('feed sees', state))

    if (socket.hasPrimitive('keepalive')) console.info('keepalive is installed')
    socket.ensureConnected()

    return { api: () => ({ sessionId }) }
  },
})
```

`state` is the store itself, not a method — read it with `socket.state.get()` and watch it with `socket.state.subscribe(...)`, the same pair the app socket's own `state` uses. There is no `getState()` on the plugin socket.
