A plugin's errors work like the [client's own error model](/core/error-model), with one difference: everything a plugin sends or throws travels under its namespace on the wire (`__<id>::room-full`), and the framework strips that prefix before handing the error to code, on both sides described below.

## The scoped `onError`

If a plugin's contract declares an `errors` section, the socket `setup` receives gets an `onError` method. It is only present then — a plugin with no `errors` section has no `onError` to call.

```typescript [room-plugin.ts]
import { clientRequests, plugin } from '@wskit/client'

interface RoomWire {
  errors: {
    'room-full': { limit: number }
  }
  clientRequests: {
    join: { payload: { room: string }; response: { ok: true } }
  }
}

interface RoomApi {
  join(room: string): Promise<{ ok: true }>
}

export const Room = plugin<RoomWire, RoomApi>()({
  id: 'acme:room',
  dependencies: [clientRequests],
  setup(socket) {
    socket.onError((err) => {
      switch (err.code) {
        case 'room-full':
          console.warn('room is full, capacity', err.detail.limit)
          break
      }
    })

    return {
      api: () => ({
        join: (room: string) => socket.request('join', { room }),
      }),
    }
  },
})
```

`err` is a real [`WSKitError`](/core/error-model) — `err instanceof WSKitError` holds — built as a typed union, one member per error the plugin's contract declares. `switch (err.code)` narrows `err.detail` to that case's shape, the same way `.matches()` does for a plain `WSKitError`. The code you see is the **plain** name you declared (`'room-full'`), not the namespaced wire code (`__acme:room::room-full`) — the framework strips the plugin's prefix before calling your handler.

`onError` returns an unsubscribe function, and you can call it more than once to add several listeners, just like the app socket's own `onError`.

### What reaches it

The scoped `onError` only fires for a server-pushed error that lands in the plugin's namespace **unclaimed** — one that no `request`, `stream`, or `channel` subscribe in that namespace was waiting for. An error a request rejects with, or a channel subscribe fails with, goes to that call instead (see [below](#a-thrown-error-reaches-the-caller-plain)), never to `onError`.

### With no handler registered

A plugin with an `errors` section but no `onError` call still owns those errors — they don't leak into the app as ordinary frames. Instead, an unclaimed one surfaces through the app socket's own [`onError`](/client/errors/onerror-routing), with the namespaced code **kept** (`__acme:room::room-full`, not `room-full`), so it stays unambiguous next to every other error passing through that catch-all.

## A thrown error reaches the caller plain

When a server plugin throws a declared error from inside a request handler, a stream, or a channel's `subscribe` check, the client sees it as the **plain** code — the same code the plugin author declared on the server, with no namespace prefix. This is the request/stream/channel promise or loop, so it follows the normal routing for [that kind of call](/client/errors/onerror-routing), not the scoped `onError` above.

```typescript [room-plugin.ts]
import { WSKitError } from '@wskit/client/errors'

// The server's request handler throws its declared `room-full` error for
// this room. On the wire it left as `__acme:room::room-full`; the promise
// here rejects with the plain `room-full`.
try {
  await room.join('lobby')
} catch (err) {
  if (err instanceof WSKitError && err.code === 'room-full') {
    showFullRoomNotice()
  }
}
```

The same stripping happens for a channel subscribe that a plugin's `check` rejects: the subscribe promise rejects with the plain code, not the namespaced one.

```typescript [room-plugin.ts]
// The server's channel `check` throws its declared `room-full` for a
// blocked member. The subscribe rejection carries the plain code.
try {
  await room.channel('lobby').subscribe()
} catch (err) {
  if (err instanceof WSKitError && err.code === 'room-full') {
    showFullRoomNotice()
  }
}
```

Either way, the plugin author writes and matches one plain code, `'room-full'`, on both sides — the `__<id>::` prefix is wire plumbing the framework adds and removes, never something application code names.
