When the socket is down and [buffering](/client/primitives/buffering) is on, the messages you `send()` are queued and flushed on reconnect. **TTL** (time-to-live) is how long a queued _channel_ message is allowed to wait before it's considered stale and dropped instead of sent. You set it on the `channels()` primitive.

::note
TTL only does something when [`buffering()`](/client/primitives/buffering) is enabled — it's the lifetime of a buffered message. With no buffering, a `send()` on a disconnected channel isn't queued, so there's nothing for a TTL to expire.
::

## Why expire channel messages

Some channel events are only useful for a moment. A `typing` indicator sent while you were disconnected is worthless thirty seconds later — you don't want it flushed on reconnect and shown long after the person stopped typing. A `chat` message, on the other hand, you'd want delivered no matter how long the gap. TTL lets you say which is which.

## One TTL for every channel event

Pass a number and it applies to every channel event. A buffered message older than that on flush is dropped:

```typescript [app.ts]
import { buffering, channels, client, connect } from '@wskit/client'

const socket = client<ChatSocket>()(
  connect('wss://example.com/ws'),
  channels({ ttl: 5_000 }), // buffered channel events live 5s
  buffering({ enabled: true }),
)

// sent while offline: flushed on reconnect only if the gap was under 5s
room.send('say', { text: 'hello' })
```

## Per-event TTL

Pass a map to give each event its own lifetime. This is the common case — short-lived signals expire fast, real messages don't:

```typescript [app.ts]
channels({
  ttl: {
    'start-typing': 5_000,
    'stop-typing': 5_000,
  },
})
```

An event **not** in the map gets no TTL — it never expires by time and waits in the buffer until it's flushed (or evicted by the buffer's size limit). So with the map above, a buffered `start-typing` older than 5 seconds is dropped on flush, while a `message` (absent from the map) is always delivered:

```typescript [app.ts]
room.send('start-typing', { who: 'Ada' }) // dropped if the gap exceeds 5s
room.send('message', { text: 'important' }) // no TTL — always flushed
```

## Per-call override

A `ttl` in the third argument to `send()` beats whatever the primitive is configured with — global number or map alike. Use it for a one-off:

```typescript [app.ts]
channels({ ttl: 10_000 })

// this one message overrides the 10s default with 100ms
room.send('cursor-move', { x, y }, { ttl: 100 })
```

The resolution order is: the per-call `ttl` if you passed one, otherwise the channel's configured TTL (the number, or the map entry for that event), otherwise none.

::note
A buffered message that later expires by TTL is dropped on flush. The `send()` call that queued it still returned `true` at the time — the message was accepted into the buffer; the drop happens later. A `ttl` of `0` is **not** an instant drop — it means _no expiry_, the same as leaving TTL unset, so that message waits in the buffer until it's flushed.
::

## Separate from top-level buffering

Channel TTL is independent of the `ttl` on [`buffering()`](/client/primitives/buffering), which governs **top-level** events (the ones you send straight on the socket). They're separate on purpose: a chat room's events and your top-level events usually want different lifetimes, so each is tuned where it belongs.

```typescript [app.ts]
const socket = client<ChatSocket>()(
  connect('wss://example.com/ws'),
  channels({ ttl: { 'start-typing': 5_000 } }), // channel events
  buffering({ enabled: true, ttl: 30_000 }), // top-level events
)
```
