When the socket is down and [buffering](/client/primitives/buffering) is on, the messages you `send()` go into a queue (the buffer). The client sends them when it reconnects. This sending of the queue is called the **flush**. **TTL** (time-to-live) is the longest time, in milliseconds, that a queued _channel_ message may wait. If it waits longer, the client drops it at flush time and never sends it. You set the channel TTL on the `channels()` primitive.

::note
TTL only works when [`buffering()`](/client/primitives/buffering) is enabled, because it is the lifetime of a buffered message. Without buffering, a `send()` on a disconnected channel is not queued, so there is nothing for a TTL to drop.
::

## Why expire channel messages

Some channel events are useful only for a short time. Say you send a `start-typing` event while you are offline. Thirty seconds later it is wrong: if the client sends it on reconnect, other people see you typing long after you stopped. A `send-message` event (a chat message) is different. You want it delivered even after a long gap. TTL lets you decide which events expire and which ones wait.

The examples on this page use the `HuddleSocket` contract from the [channels primitive](/client/primitives/channels#the-contract-side) page. Its `rooms` channel family has the outgoing events `send-message` and `start-typing`.

## One TTL for every channel event

Pass a number, and it applies to every channel event. At flush time, the client drops any buffered message that is older than this number:

```typescript [client/room.ts]
import {
  buffering,
  channels,
  client,
  connect,
} from '@livething/client'
import type { HuddleSocket } from '../server/huddle-definition'

export const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle'),
  channels({ ttl: 5_000 }), // buffered channel events live 5 seconds
  buffering({ enabled: true }),
)

const room = socket.channel('rooms', 'room:general')

// sent while offline: sent on reconnect only if it waited less than 5 seconds
room.send('send-message', { text: 'hello' })
```

## Per-event TTL

Pass a map (an object with one number per event name) to give each event its own lifetime. This is the most common setup: short signals expire fast, and real messages do not expire:

```typescript [client/room.ts]
channels({
  ttl: {
    'start-typing': 5_000,
  },
})
```

An event that is **not** in the map gets no channel TTL. If `buffering()` has no `ttl` of its own, that event never expires by time. It waits in the buffer until the flush, or until the buffer is full and drops its oldest message. With the map above, a buffered `start-typing` older than 5 seconds is dropped at flush time. A `send-message` (not in the map) is always sent:

```typescript [client/room.ts]
room.send('start-typing', {}) // dropped if it waited more than 5 seconds
room.send('send-message', { text: 'important' }) // no TTL, always sent
```

## Per-call override

A `ttl` in the third argument of `send()` replaces the TTL from `channels()`, both the single number and the map. Use it for one message:

```typescript [client/room.ts]
channels({ ttl: 10_000 })

// this message uses 1 second instead of the 10-second default
room.send('start-typing', {}, { ttl: 1_000 })
```

The client picks the TTL in this order:

1. The `ttl` you passed to `send()`, if any.
2. The TTL from `channels()`: the number, or the map entry for that event.
3. The `ttl` from [`buffering()`](/client/primitives/buffering#message-ttl), if any.
4. Otherwise, no TTL.

::note
When a buffered message expires, the client drops it at flush time. The `send()` call that queued it still returned `true`, because at that moment the buffer accepted the message. The drop happens later.

A `ttl` of `0` does **not** drop the message at once. It means _no expiry_, the same as no TTL, so the message waits in the buffer until the flush.
::

## Channel TTL and buffering TTL

[`buffering()`](/client/primitives/buffering) has its own `ttl`. It is for **top-level** events (the events you send directly on the socket, not in a channel). You set the two separately, because channel events and top-level events often need different lifetimes:

```typescript [client/socket.ts]
export const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle'),
  channels({ ttl: { 'start-typing': 5_000 } }), // channel events
  buffering({ enabled: true, ttl: 30_000 }), // top-level events
)
```

The `buffering()` TTL is also the fallback for channel events. A channel event with no TTL from `send()` or `channels()` uses the `buffering()` TTL. In the example above, `start-typing` uses 5 seconds. A channel `send-message` event is not in the `channels()` map, so it uses the 30 seconds from `buffering()`. If you want `send-message` to wait with no time limit, leave out the `ttl` on `buffering()`, or give `send-message` a `ttl` of `0` in the `channels()` map.
