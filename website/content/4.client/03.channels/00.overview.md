A **channel** is a server-managed room: a named group of connections that share messages. The [`channels()`](/client/primitives/channels) primitive page is the quick reference — get a handle, subscribe, send. This chapter is the deep one: every handle shape, every presence and lifecycle callback, and how buffered channel events expire.

For the server half — declaring channels, the auth gate, scoped features — see [Channels](/server/channels/overview) in the Server section. Everything here is client-side.

## A channel handle

`socket.channel(...)` returns a **handle**. A handle is a [Messaging](/client/overview#the-messaging-interface) object — the same `on()` / `send()` as the socket — plus the room controls: subscribing, leaving, membership, and presence.

```typescript [app.ts]
import { channels, client, connect } from '@wskit/client'
import type { ChatSocket } from '../server/chat'

const socket = client<ChatSocket>()(connect('wss://example.com/ws'), channels())

const room = socket.channel('rooms', 'room-42')
await room.subscribe()

room.on('message', (data) => append(data)) // Messaging
room.send('say', { text: 'hi' }) // Messaging
room.members.get() // room control (a reactive store)
room.onMemberJoin((id, m) => addAvatar(m)) // room control
```

Everything a handle exposes is typed from one entry of your contract's `channels` key.

## The contract behind a handle

Each channel is a contract inside the contract. A handle's `on()`, `send()`, and (with their primitives) `request()`/`stream()` are typed from _that channel's_ nested events — and a `'dynamic'` marker is what decides whether you address it by one name or by family-plus-name:

```typescript [chat-socket.ts]
interface ChatSocket {
  channels: {
    general: {
      // a fixed channel — addressed as channel('general')
      incoming: {
        message: { text: string; from: string }
      }
      outgoing: {
        say: { text: string }
      }
    }
    rooms: {
      addressing: 'dynamic' // a family — addressed as channel('rooms', 'room-42')
      incoming: {
        message: { text: string; from: string }
      }
      outgoing: {
        say: { text: string }
      }
    }
  }
}
```

The same event name (`message`) means whatever each channel declares — top-level events and other channels never collide with it.
