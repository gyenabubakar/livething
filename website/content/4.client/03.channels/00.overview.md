A **channel** is a room that the server manages: a named group of connections that share messages. The [`channels()`](/client/primitives/channels) primitive page is the short reference. It shows how to get a handle, subscribe and send. This chapter gives the full details: every kind of handle, every presence and lifecycle callback, and how buffered channel events expire. (**Presence** means knowing which members are in a channel and which of them are online right now.)

For the server side (declaring channels, the auth gate and scoped features), see [Channels](/server/channels/overview) in the Server section. Everything on these pages is about the client.

## A channel handle

`socket.channel(...)` returns a **handle**. A handle is the object you use to work with one channel. It is a [Messaging](/client/overview#the-messaging-interface) object, so it has the same `on()` and `send()` methods as the socket. It also has the room controls: subscribing, leaving, membership, and presence.

```typescript [client/room.ts]
import { channels, client, connect } from '@livething/client'
import type { HuddleSocket } from '../server/huddle-definition'

export const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle'),
  channels(),
)

const room = socket.channel('rooms', 'room:general')
await room.subscribe({})

room.on('message', (data) => append(data)) // Messaging
room.send('send-message', { text: 'hi' }) // Messaging
room.members.get() // room control (a reactive store)
room.onMemberJoin((memberId, member) => addAvatar(memberId, member)) // room control
```

Every method and store on a handle gets its types from one entry in the `channels` key of your contract.

## The contract behind a handle

Each channel has its own small contract inside your contract. A handle's `on()` and `send()` get their types from _that channel's_ events. So do `request()` and `stream()` when you add their primitives.

The `addressing` field decides how you name the channel. Without `'dynamic'`, the entry is one fixed channel, and you get it by its name. With `addressing: 'dynamic'`, the entry is a **family**: a group of channels that share one contract and differ only by name. You get one channel of a family with the family key plus the channel name:

```typescript [socket-types.ts]
interface HuddleSocket {
  channels: {
    rooms: {
      addressing: 'dynamic' // a family, addressed as channel('rooms', 'room:general')
      incoming: {
        message: {
          id: string
          text: string
          from: string
          sentAt: number
        }
      }
      outgoing: {
        'send-message': { text: string }
      }
    }
    dms: {
      addressing: 'dynamic' // another family, addressed as channel('dms', 'dm:u_100+u_200')
      incoming: {
        message: {
          id: string
          text: string
          from: string
          sentAt: number
        }
      }
      outgoing: {
        'send-message': { text: string }
      }
    }
  }
}
```

The same event name (`message`) has the type that each channel declares for it. `rooms` and `dms` both use it here, and they never clash: a room's `message` and a DM's `message` are still two separate events. A top-level event with the same name would also be separate.

::note
A handle can also make channel **requests** and use channel **streams**, but only when you also add their primitives: [`clientRequests()`](/client/primitives/client-requests), [`serverRequests()`](/client/primitives/server-requests) and [`stream()`](/client/primitives/stream). Those pages document them. This chapter covers only what `channels()` adds by itself.
::
