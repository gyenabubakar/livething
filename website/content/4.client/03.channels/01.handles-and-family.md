A handle is how you address a channel from the client. There are two shapes of channel — a **fixed** channel with one known name, and a **dynamic family** that covers many rooms following a pattern — and the contract decides which `channel(...)` call you use.

## Getting a handle

`socket.channel(...)` returns a handle right away — before any subscription is confirmed. You can register listeners on it immediately; they stay dormant until the channel becomes active.

```typescript [app.ts]
const general = socket.channel('general') // a fixed channel
const room = socket.channel('rooms', 'room-42') // one room in a dynamic family
```

Which form you use is typed from the contract. A channel marked `addressing: 'dynamic'` needs the family key **and** a name; any other channel is fixed and takes just its name. Pass the wrong shape — a name to a family, or two arguments to a fixed channel — and it's a compile error.

## Fixed channels

A fixed channel has a name you know at build time — `general`, `announcements`, `support`. You declared each one by name on the server, so each is its own key in the contract:

```typescript [app.ts]
const announcements = socket.channel('announcements')

announcements.on('post', (data) => showPost(data))
await announcements.subscribe()
```

## Dynamic families

A family is one declaration that covers many rooms — `room-42`, `room-alpha`, one per document or game or conversation. You address a single room with the family key plus its name:

```typescript [app.ts]
const room = socket.channel('rooms', 'room-42')

await room.subscribe()
room.send('say', { text: 'hello' })
```

Each concrete room is its own subscription with its own members — `channel('rooms', 'room-42')` and `channel('rooms', 'room-7')` are fully independent. They just share one event contract, because they came from one server declaration.

## The family handle

When you want to act on the **whole** family at once — listen across every room, or see which rooms are active — use `socket.channel.family(key)`. It returns a callable handle: call it with a name to get one room, or use its family-level methods.

```typescript [app.ts]
const rooms = socket.channel.family('rooms')

// one room, same as socket.channel('rooms', 'room-42')
rooms('room-42').send('say', { text: 'hi' })

// listen across every room — the second arg tells you which one fired
rooms.on('message', (data, channelName) => append(channelName, data))

// family lifecycle, across every room
rooms.onSubscribed((channelName, source) => openTab(channelName))
rooms.onUnsubscribed((channelName) => closeTab(channelName))

// the rooms currently active in this family
rooms.list() // e.g. ['room-42', 'room-7']
```

`family.on(event, handler)` fires for that event on any room in the family, so a single handler can drive a multi-room UI without you tracking each room yourself. `list()` returns only the **active** rooms — ones with a confirmed subscription right now.

## Handle identity

Handles are cached by channel, so asking for the same channel twice gives you the **same object**:

```typescript [app.ts]
socket.channel('rooms', 'room-42') === socket.channel('rooms', 'room-42') // true
socket.channel.family('rooms')('room-42') === socket.channel('rooms', 'room-42') // true
```

That means you don't have to hold a handle in a variable to keep your listeners — `socket.channel('general').on(...)` registered in one place and `socket.channel('general').send(...)` called in another both hit the one underlying channel. The family handle is cached the same way: `socket.channel.family('rooms')` returns the same family handle each time.

## Listeners before subscribing

Because a handle exists before its subscription, the usual order is: get the handle, attach listeners, then subscribe. Listeners attached early simply wait — they activate the moment the channel does, so you never miss the first message after a join.

```typescript [app.ts]
const room = socket.channel('rooms', 'room-42')

room.on('message', (data) => append(data)) // dormant for now
room.onMemberJoin((id, m) => addAvatar(m)) // dormant for now

await room.subscribe() // both become live here
```

What you **can't** do before subscribing is `send()` — that throws until the channel is active. The subscription lifecycle and that guard are covered in [Lifecycle Hooks](/client/channels/lifecycle-hooks).
