A handle is the object you use to work with one channel from the client. There are two kinds of channel. A **fixed** channel has one known name. A **dynamic family** is one declaration that covers many rooms whose names follow a pattern. The contract decides which `channel(...)` call you use for each one.

## Getting a handle

`socket.channel(...)` returns a handle at once, before the server confirms any subscription. You can add listeners to it right away. They receive nothing until the channel becomes active (the server has confirmed your subscription). The examples on this page use the `socket` from the [overview](/client/channels/overview#a-channel-handle).

```typescript [client/room.ts]
const announcements = socket.channel('announcements') // a fixed channel
const room = socket.channel('rooms', 'room:general') // one room in a dynamic family
```

The contract sets which form you use. A channel with `addressing: 'dynamic'` in the contract is a family. It needs the family key **and** a room name. When you build the client contract from your server code with `InferClient`, every family declared on the server gets this marker automatically. Any other channel is fixed and takes only its name. If you use the wrong form, TypeScript reports a type error. For example, passing only a family key, or passing two arguments to a fixed channel, does not compile.

## Fixed channels

A fixed channel has a name you know when you write the code, such as `general`, `announcements` or `support`. You declared each one by name on the server, so each one is its own key in the contract:

```typescript [client/room.ts]
const announcements = socket.channel('announcements')

announcements.on('announcement', (data) => showToast(data.text))
await announcements.subscribe()
```

## Dynamic families

A family is one declaration that covers many rooms, for example one room per team channel (`room:general`, `room:design`). To address one room, pass the family key and the room name:

```typescript [client/room.ts]
const room = socket.channel('rooms', 'room:general')

await room.subscribe({})
room.send('send-message', { text: 'hello' })
```

Each room in a family is a separate subscription with its own members. `channel('rooms', 'room:general')` and `channel('rooms', 'room:design')` do not affect each other. They share one set of event types, because they come from one server declaration.

## The family handle

Sometimes you want to work with the **whole** family at once. For example, you want to listen to every room, or see which rooms are active. Use `socket.channel.family(key)` for this. It returns a family handle that you can call like a function. Call it with a room name to get the handle for that room, or use its family-level methods:

```typescript [client/room.ts]
import { socket } from './socket'

const rooms = socket.channel.family('rooms')

// one room, the same as socket.channel('rooms', 'room:general')
rooms('room:general').send('send-message', { text: 'hi' })

// listen to every room; the second argument is the room the event came from
rooms.on('message', (data, channelName) =>
  appendToRoom(channelName, data),
)

// lifecycle events for every room in the family
rooms.onSubscribed((channelName) => openTab(channelName))
rooms.onUnsubscribed((channelName) => closeTab(channelName))

// the rooms in this family that are active right now
rooms.list() // e.g. ['room:general', 'room:design']
```

`rooms.on(event, handler)` runs for that event on any room in the family. One handler can update a UI that shows many rooms, and you do not need to track each room yourself. `onSubscribed` also passes a second argument, `source`: `'client'` when your code subscribed, or `'server'` when the server subscribed this connection. `list()` returns only the **active** rooms, which are the rooms with a confirmed subscription right now.

## Handle identity

The client keeps one handle per channel and reuses it. When you ask for the same channel twice, you get the **same object**:

```typescript [client/room.ts]
socket.channel('rooms', 'room:general') ===
  socket.channel('rooms', 'room:general') // true

socket.channel.family('rooms')('room:general') ===
  socket.channel('rooms', 'room:general') // true
```

So you do not need to keep a handle in a variable to keep your listeners. You can call `socket.channel('announcements').on(...)` in one file and `socket.channel('announcements').subscribe()` in another file. Both calls use the same channel. The family handle is reused in the same way: `socket.channel.family('rooms')` returns the same family handle each time.

## Listeners before subscribing

A handle exists before its subscription. So the usual order is: get the handle, add listeners, then subscribe. Listeners you add early receive events as soon as the channel is active. You do not miss the first message after you join.

```typescript [client/room.ts]
const room = socket.channel('rooms', 'room:general')

room.on('message', (data) => appendMessage(data)) // receives nothing yet
room.onMemberJoin((memberId, member) =>
  addAvatar(memberId, member.meta),
) // receives nothing yet

await room.subscribe({}) // both listeners receive events from here
```

You **can't** call `send()` before the channel is active. It throws a `ChannelNotSubscribed` error until the server confirms the subscription. [Lifecycle Hooks](/client/channels/lifecycle-hooks) covers the subscription lifecycle and this check.
