A channel handle tracks who is in the room. It has a live **roster** that you can read at any time. It also has four listeners that run as people come and go. The listeners form **two pairs**, and each pair answers a different question. This page explains the difference. The examples use `room`, a handle for Huddle's `room:general` channel in the `rooms` family (see the [overview](/client/channels/overview#a-channel-handle)).

## The roster

`channel.members` is a [reactive store](/client/overview#reactive-stores) of a `ReadonlyMap`. Read the map now with `channel.members.get()`. The map's keys are **member IDs**:

- On a persistent channel (`membership: 'persistent'` on the server), a signed-in member's ID is their **user ID** (the `userId` the server returned from its `authenticate` step). It stays the same when the member reconnects, and a user with several tabs open is one member.
- On an ephemeral channel (the default), or for an anonymous connection, the member ID is the **connection ID**. Every socket gets a new one.

Each value has two fields:

- `meta`: the metadata the server attached to the member's connection in `authenticate`.
- `online`: `true` while the member has a live connection in the channel.

```typescript [client/room.ts]
const room = socket.channel('rooms', 'room:general')

for (const [memberId, member] of room.members.get()) {
  console.log(memberId, member.meta, member.online)
}
```

The roster does not include you. It is filled from one sync message. When the channel has presence, the server sends that message right after it confirms your subscribe, as a separate message. `subscribe()` resolves on the confirmation, so right after `await room.subscribe()` the roster can still be empty. To react when it fills, watch the store (see below) or use the listeners. If a member has no metadata, its `meta` is an empty object. It is never missing.

Because `members` is a store, you can also watch it. `channel.members.subscribe(...)` gives you a new snapshot every time the roster changes. So a member list can re-render from one subscription, without the join and leave callbacks:

```typescript [client/room.ts]
room.members.subscribe((members) =>
  renderRoster([...members.values()]),
)
```

A member is added on a join and removed on a leave. Each sync from the server replaces the whole list. When a member goes online or offline, only its `online` field changes: the member stays in the roster, and the store publishes a new snapshot. The roster is also emptied when you leave the channel, and when your own socket drops (it fills again after the reconnect).

The server sends changes in [batches](/server/channels/membership-and-presence#how-changes-are-sent): during a burst of joins, one frame can hold many changes. The client applies the whole batch, publishes one new snapshot, and then runs the listeners in the order of the changes. So a listener reads the roster as it is after the whole batch, and a list rendered from the store re-renders once per batch, not once per change. On a channel with `presence: false` on the server, the roster stays empty and no presence listener runs.

On a persistent channel, the roster also lists members who are offline right now (`online: false`), so an offline member does not disappear from the list. A member leaves the roster only when they really leave the channel.

After a reconnect, the server sends a fresh sync and the listeners run only for what changed while you were away. `onMemberJoin` runs for members that are new to the roster, and `onMemberLeave` runs for members that are gone. `onMemberOnline` and `onMemberOffline` run for members whose `online` value changed.

::note
Presence messages (the first sync, join and leave, and online and offline) are used only while the channel is **active**. If one arrives while an `unsubscribe()` is in progress, or after the channel became inactive, the client ignores it. It writes an info-level log line and does nothing else. The roster and the listeners never change for an inactive channel.
::

## The subscription status

Next to the roster, `channel.status` is a [reactive store](/client/overview#reactive-stores) of the subscription's current state:

```typescript [client/room.ts]
room.status // ReadableStore<'subscribing' | 'subscribed' | 'unsubscribed' | 'failed'>
```

| Value          | Meaning                                                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `subscribing`  | a `subscribe()` or a rejoin after a reconnect is in progress, waiting for the server to confirm                                |
| `subscribed`   | active: `send()` works                                                                                                         |
| `unsubscribed` | not in the room (never joined, left, or kicked)                                                                                |
| `failed`       | a subscribe or a rejoin was refused (see [`onSubscriptionFailed`](/client/channels/lifecycle-hooks#onsubscriptionfailederror)) |

Use it when you only want to show a "joining…" spinner. You don't need the four [lifecycle hooks](/client/channels/lifecycle-hooks) for that:

```typescript [client/room.ts]
room.status.subscribe((status) => {
  if (status === 'subscribing') showSpinner()
  else hideSpinner()
})
```

The lifecycle hooks (`onSubscribed`, `onUnsubscribed`, `onKicked`, `onSubscriptionFailed`) are still there when you want to react to one change. Use `status` when you want the current value shown in your UI.

## Two pairs of listeners

```typescript [client/room.ts]
room.onMemberJoin((memberId, member) =>
  addAvatar(memberId, member.meta),
)
room.onMemberLeave((memberId) => removeAvatar(memberId))

room.onMemberOnline((memberId) => showOnlineDot(memberId))
room.onMemberOffline((memberId) => hideOnlineDot(memberId))
```

Each one returns a function that removes the listener. The two pairs are **not** interchangeable.

### Join / leave: group membership

`onMemberJoin` and `onMemberLeave` track who _belongs to the room_. They run only when membership really changes: someone subscribes, unsubscribes, or is kicked or removed by the server.

On a [persistent channel](/client/primitives/channels#membership-and-presence), a disconnect is not a leave. When the member reconnects, join does not run either, because the member never left the group, and the member keeps the same member ID. A user who opens a second tab does not join again either: it is still one member. The exception is an anonymous connection: it has no user ID to keep its seat, so its disconnect is a leave.

On an ephemeral channel (the default), a disconnect is a leave, and the rejoin after the reconnect is a new join with a new member ID.

If the server kicks a member, you see a leave. A kick ends the membership for good, so the member does not come back on reconnect. You see a join again only if their client subscribes again.

Use this pair to keep the list of who is in the room, for example an avatar strip or a participant count.

### Online / offline: reachable right now

`onMemberOnline` and `onMemberOffline` track whether a member is _reachable right now_. Online runs when a member gets their first live connection in the channel, for example after a join or a reconnect. Offline runs when their last live connection goes away, for example a disconnect, or right after a leave. A user with two tabs open goes offline only when both tabs are closed.

Online and offline never add or remove entries in the `channel.members` roster. They only change the member's `online` field. So you can draw "online dots" either from these two callbacks or from `member.online` in the `channel.members` store.

A short way to remember both: **join/leave is about the guest list. Online/offline is about who is in the building right now.**

## When your own socket reconnects

When your socket drops, the client empties the roster but remembers who was in it. No listeners run for the other members at this point. After the reconnect, the server sends the snapshot again, and the listeners run only for the real differences:

- a member who is still there with the same online state: nothing runs
- a member who is new: `onMemberJoin`, then `onMemberOnline` if they are online
- a member whose online state changed while you were away: `onMemberOnline` or `onMemberOffline`
- a member who is gone: `onMemberLeave`, then `onMemberOffline` if they were online before

```typescript [client/room.ts]
room.onMemberJoin((id, member) => addAvatar(id, member.meta)) // only new members
room.onMemberLeave((id) => removeAvatar(id)) // only members who left
room.onMemberOnline((id) => showOnlineDot(id)) // a member became reachable
room.onMemberOffline((id) => hideOnlineDot(id)) // a member stopped being reachable
```

With this setup, an avatar list built on join and leave doesn't blink off and on each time your network drops for a moment. A list rendered from the `members` store is different: it is empty until the new snapshot arrives.

::note
If a listener throws an error, the client catches it and reports it. The other listeners for the same event still run, so one broken callback doesn't stop the rest of your presence UI from updating.
::
