`readReceipts()` is the read half of receipts — the blue check. [`inbox()`](/client/primitives/inbox) gives you *received* receipts (the double-grey check) for free; this primitive adds the read side: `markAsRead(seq?)` to advance your own read cursor, `readers` to watch who has read what, and `readersOf(seq)` to ask the server authoritatively. The channel must opt in on the server with [`readReceipts`](/server/capabilities/read-receipts).

```typescript [app.ts]
import { client, connect, channels, inbox, readReceipts, dedup, reconnection } from '@wskit/client'
import type { ReceiptsClient } from '../server/receipts'

const socket = client<ReceiptsClient>()(
  connect('wss://example.com/ws'),
  channels(),
  inbox(),
  readReceipts(),
  dedup(),
  reconnection({ maxDelay: 400 }),
)
```

## Where it sits in the stack

Read receipts build on inbox, so add `readReceipts()` **after** [`channels()`](/client/primitives/channels) **and** [`inbox()`](/client/primitives/inbox). Read implies received: marking a message read also settles it as received on the server, so a member's received cursor never lags behind its read cursor.

## The read surface

On a channel whose contract sets `readReceipts: true`, the handle gains four members. They mirror inbox's received surface, one column over.

### `readers` — the live read store

`channel.readers` is a [reactive store](/client/overview#reactive-stores) of every member's read cursor, fed by the `__read__` frames the server fans out. Its snapshot is a `CursorList` (`ReadonlyMap<identity, number>`) mapping each member to its `readThrough`, dropping any member who has read nothing yet — so every entry is a member to show the blue check for. It is cleared when you leave the channel.

```typescript [app.ts]
chat.readers.subscribe(() => {
  for (const [identity, readThrough] of chat.readers.get()) {
    showBlueCheck(identity, readThrough)
  }
})
```

### `markAsRead(seq?)` — advance your read cursor

`channel.markAsRead(seq)` tells the server you have read everything up to `seq`. Omit `seq` to mark **everything received so far** — the common case for "the user is looking at the thread." It is fire-and-forget: the server advances your read cursor and, on a broadcasting channel, tells the other members.

```typescript [app.ts]
const chat = socket.channel('chat')

chat.on('room-msg', (msg) => appendMessage(msg.text))

// User opened the thread — mark it all read.
chat.markAsRead()
```

Because a read mark also settles delivery, calling `markAsRead()` covers the received cursor too.

### `onRead(cb)` — one member's read cursor advanced

`channel.onRead(cb)` fires each time a member's read cursor moves forward, with that member's identity and new cursor. It returns an unsubscribe.

```typescript [app.ts]
const stop = chat.onRead((identity, readThrough) => {
  markRead(identity, readThrough)
})
```

### `readersOf(seq)` — ask the server who read it

`readers` and `onRead` reflect the live fan-out, which the server caps by member count. For the authoritative answer, `channel.readersOf(seq)` asks the server which identities have read up to at least `seq`, and resolves to that list. Like `receiversOf`, only a member may query — a non-member's request is dropped silently.

```typescript [app.ts]
const identities = await chat.readersOf(1)
renderReadBy(identities.slice().sort().join('|'))
```

## Options

`readReceipts({ timeout })` sets how long a `readersOf` query waits for the server's answer before rejecting, in milliseconds. The default is `10_000` (10s). Override a single call with `readersOf(seq, { timeout })`.

```typescript [app.ts]
readReceipts({ timeout: 5_000 })
```

::note
`readers`, `onRead`, `markAsRead`, and `readersOf` are **type-gated by the contract**. They appear on a channel handle only when its server config sets `readReceipts: true` — and for that flag to reach the client type, the handler's channel object must be passed to `base.assemble(...)`. A channel with only `inbox: true` has the received surface but no read surface.
::

For the server half — the read cursor, the `__read__` fan-out, and `readersOf` — see [Receipts](/server/inbox/receipts) in the Server section.
