`serialization()` is the surface for **binary** messages. A binary message carries raw bytes instead of text. Apps use binary formats such as [Protocol Buffers](https://protobuf.dev) or [MessagePack](https://msgpack.org) to make messages smaller than JSON. You give `serialization()` two things that always go together: the format the bytes arrive in, and a **decoder** (a function that turns the bytes into a normal message).

::warning
**LiveThing rejects binary messages today.** The client handles text (JSON) messages only. When a binary message arrives, the client rejects it before this decoder runs and reports an error to [`onError`](/client/errors/onerror-routing). There is no way to send binary messages either. The options below show the planned shape of this primitive.
::

```typescript [client/socket.ts]
import { client, connect, serialization } from '@livething/client'
import { decode } from '@msgpack/msgpack'
import type { HuddleSocket } from '../server/huddle-definition'

export const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle'),
  serialization({
    binaryType: 'arraybuffer',
    parseBinary(data) {
      // Planned shape: bytes that hold a MessagePack-encoded notification.
      // LiveThing's server sends JSON text today.
      return {
        event: 'notification',
        payload: decode(new Uint8Array(data)),
      }
    },
  }),
)
```

In this example, `decode` comes from the [`@msgpack/msgpack`](https://github.com/msgpack/msgpack-javascript) package. It turns MessagePack bytes back into the `{ title, body }` object of a `notification`.

## Options

`binaryType` and `parseBinary` are a **linked pair**. TypeScript does not let you set one without the other. `binaryType` also decides the type of the value that `parseBinary` receives:

- `binaryType: 'arraybuffer'` → `parseBinary(data: ArrayBuffer)`. An `ArrayBuffer` is a fixed block of bytes that you can read right away.
- `binaryType: 'blob'` → `parseBinary(data: Blob)`. A `Blob` is a file-like object. You read its bytes later, with an async call such as `blob.arrayBuffer()`.

`parseBinary` returns one of two things:

- `{ event, payload }`: the client routes the message to your `on()` handlers, like any other message. You can also add an optional `metadata` field.
- `null`: the client ignores that message.

This decoder returns `null` for bytes that it cannot read as a notification:

```typescript [client/socket.ts]
import { serialization } from '@livething/client'
import { decode } from '@msgpack/msgpack'

serialization({
  binaryType: 'arraybuffer',
  parseBinary(data) {
    try {
      return {
        event: 'notification',
        payload: decode(new Uint8Array(data)),
      }
    } catch {
      return null
    }
  },
})
```

`serialization()` only changes how binary messages are read. Text messages always use the built-in JSON format, `{ event, payload }`.
