`inbox()` is the client half of guaranteed per-member delivery. On the server an [inbox channel](/server/capabilities/inbox) writes a durable copy of every broadcast for each member and holds it until that member confirms it arrived. `inbox()` is what sends that confirmation: as inbox messages arrive it tracks the highest sequence per channel, sends a `__received__` acknowledgement, and re-acks on reconnect — so the server can drop your held copy and never re-deliver it. Without it, guaranteed delivery never settles.

```typescript [app.ts]
import { client, connect, channels, inbox, dedup, reconnection } from '@wskit/client'
import type { ChatSocket } from '../server/chat'

const socket = client<ChatSocket>()(
  connect('wss://example.com/ws'),
  channels(),
  inbox(),
  dedup(),
  reconnection(),
)
```

## It needs `dedup()`, and comes after `channels()`

`inbox()` depends on [`dedup()`](/client/primitives/dedup); building the socket without it throws when you call `client()(...)`. The reason: on reconnect the server drains your held rows and re-delivers any it hadn't seen an ack for, and some of those also arrived live before the drop. `dedup()` throws the repeats away so your `on()` handlers run once per message.

Add it **after** [`channels()`](/client/primitives/channels). Inbox is channel-scoped, and the order lets a reconnect's channel auto-rejoin reach the server before inbox re-acks that channel. Pairing with [`reconnection()`](/client/primitives/reconnection) makes sense too, since the re-ack runs on reconnect.

## It learns which channels are inbox-backed

You don't tell the client which channels have an inbox. When you subscribe, the server's `__subscribeOk__` carries an `inbox` flag, and `inbox()` reads it — from then on it acks that channel and only that channel. A plain channel with no inbox is never acked.

So the auto-acknowledgement is invisible in your code. You subscribe and read messages the normal way:

```typescript [app.ts]
const chat = socket.channel('chat')

await chat.subscribe()
chat.on('room-msg', (msg) => appendMessage(msg.text))
```

Every `room-msg` that arrives advances the acked cursor for `chat`; the `__received__` frame goes out on its own. If you drop and reconnect, the client re-sends the high-water mark so the server can settle anything that was still held.

## The received surface

On a channel whose contract sets `inbox: true`, the handle gains three received-receipt members. They read the `__received__` frames the server fans out — the double-grey check — into a local view of who has received what. Those frames only arrive when the **server** channel enables `broadcastReceipts`; without it, `receivers` and `onReceived` stay quiet, though `receiversOf` still answers from the stored cursor. (Who has *read* a message is the separate [`readReceipts()`](/client/primitives/read-receipts) surface.)

### `receivers` — the reactive store

`channel.receivers` is a [reactive store](/client/overview#reactive-stores) of every member's received cursor, keyed by identity. Its snapshot is a `CursorList` (`ReadonlyMap<identity, number>`) mapping each member to its `receivedThrough` — the highest sequence that member has confirmed receiving — dropping any member still at `0`, so every entry is a member to show the grey double-check for.

```typescript [app.ts]
chat.receivers.subscribe(() => {
  for (const [identity, receivedThrough] of chat.receivers.get()) {
    markReceived(identity, receivedThrough)
  }
})
```

The store is **cleared when you leave the channel** — an `__unsubscribeOk__` or a `__kicked__` empties it, so a rejoin starts from a clean slate rather than showing stale cursors.

### `onReceived(cb)` — one member's cursor advanced

`channel.onReceived(cb)` fires each time a member's received cursor moves forward, with that member's identity and new cursor. It returns an unsubscribe.

```typescript [app.ts]
const stop = chat.onReceived((identity, receivedThrough) => {
  markReceived(identity, receivedThrough)
})
```

### `receiversOf(seq)` — ask the server who got it

`receivers` and `onReceived` reflect the live fan-out, which the server caps by member count. For the authoritative answer, `channel.receiversOf(seq)` asks the server directly and resolves to the identities that have received up to at least `seq`:

```typescript [app.ts]
const identities = await chat.receiversOf(1)
renderReceivedBy(identities.slice().sort().join('|'))
```

Only a member of the channel may query; a non-member's request is dropped silently on the server. Because inbox owns this query, `receiversOf` works with `inbox()` alone — you do not need `readReceipts()` for it.

## Options

`inbox({ timeout })` sets how long a `receiversOf` query waits for the server's answer before rejecting, in milliseconds. The default is `10_000` (10s). Override a single call with `receiversOf(seq, { timeout })`.

```typescript [app.ts]
inbox({ timeout: 5_000 })
```

## A realistic construction

Here is the full stack from the receipts fixture — `channels()`, `inbox()`, and `dedup()`, with read receipts added on top (see [Read receipts](/client/primitives/read-receipts)):

```typescript [app.ts]
import { channels, client, connect, dedup, inbox, readReceipts, reconnection } from '@wskit/client'
import type { ReceiptsClient } from '../server/receipts'

const socket = client<ReceiptsClient>()(
  connect('wss://example.com/ws'),
  channels(),
  inbox(),
  readReceipts(),
  dedup(),
  reconnection({ maxDelay: 400 }),
)
```

::note
The received surface is **type-gated by the contract**. A channel gets `receivers`, `onReceived`, and `receiversOf` only when its server config sets `inbox: true` — for the flag to reach the client type, the handler's channel object must be passed to `base.assemble(...)`. A plain channel handle has none of these members.
::

::tip
The double-grey check only tells you a message was **received**. For the blue check — who has **read** it — add [`readReceipts()`](/client/primitives/read-receipts). And if the channel bounds its held rows and a member falls behind, the server signals a hole with `__gap__` on reconnect; to react to it, add [`replay()`](/client/primitives/replay), which owns `onGap`. An inbox-only client silently drops the gap frame.
::

For the server half — held rows, the `__received__` fan-out and its member cap, and `receiversOf` — see [Receipts](/server/inbox/receipts) in the Server section.
