`channels()` adds `socket.channel(...)`. It returns a handle for a **channel**, which is a room that the server manages. A channel handle is a [Messaging](/client/overview#the-messaging-interface) object, so it has the same `on()` and `send()` methods as the socket. It also has the room controls: subscribing, leaving, membership, and presence (which members are online right now). This page is the client-side reference. For the server side, see [Channels](/server/channels/overview) in the Server section.

```typescript [app.ts]
import { channels, client, connect } from '@livething/client'
import type { ChatSocket } from '../server/chat'

const socket = client<ChatSocket>()(
  connect('wss://example.com/ws'),
  channels(),
)
```

## The contract side

`channel(...)` gets its types from the `channels` key of your contract. Each entry is one channel (or one family of channels) with its own **nested** contract. It has its own `incoming` and `outgoing`, and it can also have `subscribePayload`, `clientRequests`, `serverRequests`, and `streams`. These work the same way as at the top level. `addressing` tells the client whether the entry is one fixed channel (`'static'`) or a **dynamic family**, which is a group of channels that share one contract and differ only by name (`'dynamic'`).

`InferClient` is the type that builds a client contract from your server code. This is the shape that it creates for a chat server with one fixed `general` channel and a `rooms` family:

```typescript [socket-types.ts]
interface ChatSocket {
  channels: {
    general: {
      addressing: 'static'
      incoming: {
        message: { text: string; from: string }
      }
      outgoing: {
        say: { text: string }
      }
    }
    rooms: {
      addressing: 'dynamic'
      subscribePayload: { token: string }
      incoming: {
        message: { text: string; from: string }
      }
      outgoing: {
        say: { text: string }
        'start-typing': {}
        'stop-typing': {}
      }
    }
  }
}
```

So in `socket.channel('rooms', 'room-42').on('message', …)` and `.send('say', …)`, the types come from _that channel's_ `incoming` and `outgoing`. The same event name can mean different things in different channels.

## Getting a handle

`socket.channel(name)` returns a handle at once, before the server confirms any subscription. You can add listeners to it right away. They do nothing until the channel becomes active.

```typescript [app.ts]
const general = socket.channel('general') // a fixed channel
const room42 = socket.channel('rooms', 'room-42') // one channel in a dynamic family
```

The channel name (and, for a family, the family key) is typed from your contract's `channels`. If you don't know the channel names in a family ahead of time, use [family handles](#family-handles).

## Subscribing and leaving

You must call `subscribe()` before you can `send()` on a channel.

```typescript [app.ts]
const room = socket.channel('rooms', 'room-42')

await room.subscribe({ token: 'abc' }) // resolves when the server confirms

room.on('message', (data) => appendMessage(data))
room.send('say', { text: 'hello' })

await room.unsubscribe()
```

- **`subscribe(data?)`** resolves when the server confirms the join. It rejects if the server refuses the join (for example, an auth failure) or if the connection drops before the server replies. When the server channel declares a `subscribe` schema for the join payload, the contract has a `subscribePayload` for that channel, and `subscribe(data)` **requires** that typed payload. Without a schema, the payload is optional and untyped. You can add `on()` listeners before you subscribe. They start to work when the channel becomes active. You can't `send()` until the channel is active: `send()` throws. This check happens even when [buffering](/client/primitives/buffering) is installed, so the message is not buffered.
- **`unsubscribe()`** marks the channel inactive at once, so a `send()` after it throws right away. The promise it returns resolves only when the server confirms the leave. The client sends the leave again after each reconnect until the server confirms it. So a leave that was lost when the connection dropped still completes.

::tip
You can pass `subscribe()` a **function** instead of a value. The client calls it for the first subscribe. On an **ephemeral** channel (a channel whose server definition sets `membership: 'ephemeral'`), the client also subscribes again after every reconnect, and it calls your function again each time to get a new payload. Use this to send a new short-lived token for the channel each time.

```typescript [app.ts]
await room.subscribe(() => ({ token: getRoomToken() }))
```

Channels are **persistent** by default. On a persistent channel, the server itself adds you back to the channel after a reconnect, so the client does not subscribe again and does not call your function. If the channel has a `revalidate` function, the server runs it to check the membership again. See [Auth Gate](/server/channels/auth-gate).
::

## Membership and presence

`channel.members` is the current list of members, as a [reactive store](/client/overview#reactive-stores). Four listeners tell you about changes:

```typescript [app.ts]
room.members.get() // ReadonlyMap<memberId, { meta, online }>

room.onMemberJoin((memberId, member) =>
  addAvatar(memberId, member.meta),
)
room.onMemberLeave((memberId) => removeAvatar(memberId))
room.onMemberOnline((memberId) => showDot(memberId))
room.onMemberOffline((memberId) => hideDot(memberId))
```

A **member ID** is the user's ID on a persistent channel (so it stays the same across reconnects and tabs), and the connection ID on an ephemeral channel or for an anonymous connection.

`channel.status` is a second store. Its value is `'subscribing' | 'subscribed' | 'unsubscribed' | 'failed'`. Use it to show a "joining…" message from the current value, instead of using the lifecycle listeners below.

The two pairs of listeners answer different questions:

- **`onMemberJoin` / `onMemberLeave`** tell you who is _in the group_. They fire only when membership really changes: a first subscribe, a leave, a kick, or a removal by the server. What a disconnect does depends on the channel type:
  - On a **persistent** channel (the default), a disconnect does not fire them. When the member reconnects, they don't fire either, because the member never left the group. An anonymous connection is the exception: its disconnect is a leave.
  - On an **ephemeral** channel, a disconnect is a real leave. It fires `onMemberLeave`, and the member's next subscribe after a reconnect fires `onMemberJoin` again, with a new member ID.
- **`onMemberOnline` / `onMemberOffline`** tell you whether a member can be _reached right now_. Online fires when a member gets their first live connection in the channel. Offline fires when their last live connection goes away. Use them for "online dot" UIs. They never add or remove members; they only change `member.online`. On a persistent channel, a member who is offline stays in the list with `online: false`.

`member.meta` is the member's metadata, which the server set during `upgrade`. The member list is filled from one sync message that the server sends right after you subscribe. `channel.resyncMembers()` asks the server to send that list again. It sends the request and returns at once, with nothing to await. Use it when you think the list is out of date.

## Channel lifecycle

Four more listeners tell you about the channel's own state, separate from other members:

- **`onSubscribed((source) => …)`**: the channel became active for you. `source` is `'client'` (the client sent the join) or `'server'` (the server added you, for example when it adds you back to a persistent channel after a reconnect).
- **`onUnsubscribed(() => …)`**: the channel is no longer active on your side. This happens when you call `unsubscribe()`, when the server kicks you, or when the socket closes for good (you call `disconnect()`, or reconnecting fails).
- **`onKicked((reason) => …)`**: the server removed you from the channel. `onUnsubscribed` fires right after it.
- **`onSubscriptionFailed((error) => …)`**: the server refused a rejoin after a reconnect (for example, your permissions changed while you were away). The channel becomes inactive, so `send()` throws until you call `subscribe()` again. Check `error` with `.matches()` to see why. A refused `subscribe()` call rejects its promise instead of firing this listener.

Each listener returns a function that removes it.

## Family handles

Sometimes you don't know the channel names in a dynamic family ahead of time. `socket.channel.family(key)` returns a handle for the whole family. You can call the handle like a function to get one channel. Its listeners fire for every channel in the family:

```typescript [app.ts]
const rooms = socket.channel.family('rooms')

rooms.on('message', (data, channelName) => append(channelName, data)) // channelName tells you which
rooms.onSubscribed((channelName, source) => openTab(channelName))
rooms.list() // the channel names that are active now

rooms('room-42').send('say', { text: 'hi' }) // one specific channel
```

`socket.channel('rooms', 'room-42')` and `socket.channel.family('rooms')('room-42')` return the same handle.

## Scoped requests and streams

When you also install [`clientRequests()`](/client/primitives/client-requests), [`serverRequests()`](/client/primitives/server-requests), or [`stream()`](/client/primitives/stream), the channel handle gets the matching methods: `room.request(...)`, `room.onRequest(...)`, and `room.stream(...)`. Each one is typed from that channel's own contract, and its messages are marked with the channel on the wire.

## Options

`channels({ ttl })` sets the **time-to-live (TTL)** for buffered channel events. The TTL is how long a buffered event may wait to be sent before the client drops it. Pass one number for all channel events, or a map with one number per event. It is separate from the top-level `ttl` on [`buffering()`](/client/primitives/buffering), because channel events and top-level events often need different times.

```typescript [app.ts]
channels({
  ttl: { 'start-typing': 5_000, 'stop-typing': 5_000 },
})
```
