A **ping** is a small frame one side sends to ask "are you still there?". A **pong** is the reply. The time between sending a ping and getting its pong is the **round-trip latency**.

`keepalive()` makes the client send its own pings, measure round-trip latency, and close a connection that stops answering. It is opt-in. Without it, the client still **replies** to the server's pings. That reply is built into the socket, so the server does not drop you for being idle. But the client sends no pings of its own and measures no latency.

```typescript [client/socket.ts]
import { client, connect, keepalive } from '@livething/client'
import type { HuddleSocket } from '../server/definition'

export const socket = client<HuddleSocket>()(
  connect('wss://example.com/ws'),
  keepalive({ interval: 30_000, maxMissedPongs: 2 }),
)
```

## The quality API

Connection quality only has a value when something measures pongs. So the quality [stores](/client/overview#reactive-stores) belong to this primitive. They are added to the socket only when you install `keepalive()`:

```typescript [client/socket.ts]
socket.quality // ReadableStore<'excellent' | 'good' | 'degraded' | 'poor' | 'disconnected'>
socket.latency // ReadableStore<number | null>: last round-trip in ms, null when not measured

const stop = socket.quality.subscribe((quality) => {
  updateIndicator(quality, socket.latency.get())
})
```

`socket.quality.get()` returns `'disconnected'` whenever the socket is not open. After the socket opens, it stays `'disconnected'` until the first pong arrives. There is no guessed value at open. The store publishes only when the tier changes.

The tier comes from the average latency of the last 5 pongs, so one slow pong does not change it. The latency cut-offs that decide the tier come from the [`quality()`](/client/primitives/quality) primitive. Install it to change them.

`socket.latency` is set on every pong to that pong's round-trip time. It is `null` before the first pong, after a missed pong, and after the socket closes.

## Missed-pong detection

Each ping expects a pong. The client counts misses in a row:

- **1 missed pong** sets the quality to `'poor'` as an early warning, and sets `socket.latency` to `null`.
- **`maxMissedPongs` misses** (default `2`) mean the connection is dead, even though the WebSocket has not closed. This is called a **half-open** connection: the socket still looks open in code, but no data gets through. The client closes it with close code `IDLE` (`4004`). Because the other side no longer answers, the browser may not get a reply to that close, and then `onClose` receives `1006` (the connection ended without a clean close) instead of `4004`. If [`reconnection()`](/client/primitives/reconnection) is installed, the client then reconnects.

This is why durable streams and long-lived sockets should use `keepalive()`. Without it, nothing checks that the other side still answers, so a half-open connection can stay open and nobody notices.

You can react to the early `'poor'` warning, to the close, or to both:

```typescript [client/socket.ts]
import { CloseCodes } from '@livething/core'

// Warn the user when quality drops, before the client closes the connection.
socket.quality.subscribe((quality) => {
  if (quality === 'poor') showWeakConnectionBanner()
})

// The close reaches onClose with code 4004 (IDLE), or 1006 when the
// other side never answered the close.
socket.onClose((event) => {
  if (event.code === CloseCodes.IDLE || event.code === 1006) {
    // The socket looked open but stopped answering. reconnection() opens a new one.
    console.warn('connection stopped answering, reconnecting')
  }
})
```

## Options

```typescript [client/socket.ts]
keepalive({
  interval: 30_000, // how often to ping, in ms; 0 turns pinging off (default: 30_000)
  maxMissedPongs: 2, // misses before the client closes the socket (default: 2)
})
```

## The other direction

Pings go both ways. The server can send its own pings, and the client answers them automatically. If the server lists the [`keepalive()`](/server/capabilities/keepalive) capability, it closes any connection that sends nothing for longer than its idle timeout, with close code `IDLE`. Any frame from the client resets that timer: a normal message or the automatic pong. LiveThing's client sends the pong for you. A client you write yourself in another language must also answer pings, or the server closes it as dead.

The server does not always run that idle check. [Hibernation](/server/server/hibernation) is a Cloudflare Durable Objects mode where the server object is removed from memory while it has no work, and the socket stays open. Under hibernation the server runs no idle timer, so it never closes a quiet client. The server keepalive page explains this in its hibernation section. If you need to detect a dead connection, keep `keepalive()` installed on the client. Then the client finds its own half-open connection and does not depend on the server.
