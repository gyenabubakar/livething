`keepalive()` makes the client send its own pings, measure round-trip latency, and close a connection that stops answering. It's opt-in. Without it, the client still **replies** to the server's pings — that's built into the socket itself, not something you opt into, so the server won't drop you for being idle — but it sends none of its own and measures no latency.

```typescript [app.ts]
import { client, connect, keepalive } from '@wskit/client'
import type { MySocket } from './socket-types'

const socket = client<MySocket>()(
  connect('wss://example.com/ws'),
  keepalive({ interval: 30_000, maxMissedPongs: 2 }),
)
```

## The quality API

Because connection quality only means anything once something is measuring pongs, the quality [stores](/client/overview#reactive-stores) live here — they're added to the socket only when you install `keepalive()`:

```typescript [app.ts]
socket.quality // ReadableStore<'excellent' | 'good' | 'degraded' | 'poor' | 'disconnected'>
socket.latency // ReadableStore<number | null> — last round-trip in ms, null if not measured yet

const stop = socket.quality.subscribe((quality) => {
  updateIndicator(quality, socket.latency.get())
})
```

`socket.quality.get()` returns `'disconnected'` whenever the socket isn't open, and stays `'disconnected'` until the first pong measures a real tier — there's no optimistic value at open. It publishes only when the tier actually changes. `socket.latency` updates on every pong and is `null` until the first measurement. The latency cut-offs that decide the tier come from the [`quality()`](/client/primitives/quality) primitive — install it to tune them.

## Missed-pong detection

Each ping expects a pong. The library tracks consecutive misses:

- **1 missed pong** degrades the quality to `'poor'` as an early warning.
- **`maxMissedPongs` misses** (default `2`) means the connection is effectively dead even though the WebSocket hasn't formally closed — a "half-open" connection. The client force-closes it with close code `IDLE` (4004) and, if [`reconnection()`](/client/primitives/reconnection) is installed, reconnects.

This is why durable streams and long-lived sockets want `keepalive()`: without it, a half-open connection can sit unnoticed, because nothing is checking that the other end still answers.

You can react to either signal — the early `'poor'` warning or the force-close:

```typescript [app.ts]
import { CloseCodes } from '@wskit/core'

// Warn the user as quality slips, before the connection is given up on.
socket.quality.subscribe((quality) => {
  if (quality === 'poor') showWeakConnectionBanner()
})

// The force-close comes through onClose as code 4004 (IDLE).
socket.onClose((event) => {
  if (event.code === CloseCodes.IDLE) {
    // The socket looked alive but stopped answering; reconnection() takes it from here.
    console.warn('connection went silent — reconnecting')
  }
})
```

## Options

```typescript [app.ts]
keepalive({
  interval: 30_000, // how often to ping, in ms; 0 turns pinging off (default: 30_000)
  maxMissedPongs: 2, // misses before the socket is force-closed (default: 2)
})
```

## The other direction

Keepalive runs both ways. The server may send _its_ own pings, and the client answers them automatically — any inbound frame counts, so a normal message or that automatic pong keeps you alive. If the server has the [`keepalive()`](/server/capabilities/keepalive) capability listed and the client goes silent past its idle timeout, the **server** closes the socket with `IDLE`. The library handles the reply for you; a hand-written client in another language must do the same, or it'll be dropped for looking dead.

That server-side idle close is not guaranteed, though. A server running under [hibernation](/server/server/hibernation) never arms an idle timer at all — see the keepalive capability's hibernation notes. Do not rely on the server to catch a silent client; if that matters to you, keep the client-side `keepalive()` above installed so the client detects its own half-open connection instead of waiting on the server.
