`clientRequests()` adds `socket.request(...)`. It sends a message and returns a promise. The promise resolves with the server's reply to that exact message. Use it when you need an answer. Use `send()` when you only need to send the message and do not wait for any answer (this is often called "fire-and-forget"). For the server half, see [clientRequests](/server/capabilities/client-requests).

```typescript [app.ts]
import { client, clientRequests, connect } from '@livething/client'
import type { ApiSocket } from '../server/api'

const socket = client<ApiSocket>()(
  connect('wss://example.com/ws'),
  clientRequests(),
)
socket.connect()

const balance = await socket.request('get-balance', {
  userId: '123',
})
// balance: { balance: number; currency: string }, typed from the contract
console.log(`${balance.balance} ${balance.currency}`)
```

Internally, each request carries a unique ID in `metadata.exchange.id`. This ID is called the **correlation ID**. The server copies it onto its reply, and the primitive uses it to find the promise that the reply belongs to. The payload you send and the response you get are both typed from the `clientRequests` map in your contract.

## The contract side

`request()` is typed from the `clientRequests` map in your socket contract. Each entry pairs the `payload` you send with the `response` you get back:

```typescript [socket-types.ts]
interface ApiSocket {
  clientRequests: {
    'get-balance': {
      payload: { userId: string }
      response: { balance: number; currency: string }
    }
    'create-post': {
      payload: { title: string; body: string }
      response: { id: string }
    }
  }
}
```

With `@livething/server`, `InferClient` builds this map from your server code, so you don't write it yourself. Then `socket.request('get-balance', …)` suggests the event name in your editor, checks the payload, and gives the resolved value its type.

## How the promise settles

```typescript [app.ts]
import { Timeout } from '@livething/client/errors'
import { Forbidden, QuotaExceeded } from '../server/errors'

try {
  const post = await socket.request('create-post', {
    title: 'Hi',
    body: '…',
  })
  // resolved: `post` is { id: string }
  router.push(`/posts/${post.id}`)
} catch (err) {
  if (Forbidden.matches(err))
    showToast(err.detail.reason) // typed server error
  else if (QuotaExceeded.matches(err))
    showUpgrade(err.detail) // another typed error
  else if (Timeout.matches(err)) showToast('Server took too long')
  else throw err
}
```

The promise settles in one of these ways:

- **Resolves** with the typed response when the server replies. If the server handler returns nothing, it resolves with no value (a [void acknowledgement](#acknowledgement-requests)).
- **Rejects with a typed `LiveThingError`** if the server answers with one of your declared errors. Use `.matches()` to check which error it is, then read `err.detail`.
- **Rejects with `Timeout`** if no reply arrives before the timeout ends.
- **Rejects with `Disconnected`** if the connection closes while the request waits for its reply. This happens when you call `disconnect()`, and also when the connection drops.
- **Rejects with `Dropped`** if the request was buffered (see [below](#when-the-socket-isnt-open)) and then removed before it could be sent. This happens when the buffer is full, or when the request's TTL (time to live, the longest time a message may wait in the buffer) ends. `Dropped`, `Timeout` and `Disconnected` are all imported from `@livething/client/errors`.
- **Rejects with `internal-error`** if the server handler throws something that is not one of your declared errors.
- **Rejects at once with `ValidationFailed`** if the event name is empty, reserved, or longer than 128 characters. Reserved names are `ping`, `pong`, and any name that starts or ends with `__`. This check runs on the client, so no frame is sent.

## Acknowledgement requests

Sometimes you don't need a value back. You only want to know that the server **received and handled** your message. This is an _acknowledgement_ request. On the server, the handler returns nothing. On the client, `request()` resolves with `undefined`. You `await` it only to know that the server finished.

```typescript [socket-types.ts]
interface ApiSocket {
  clientRequests: {
    // `response: void` means an acknowledgement. There is no value to read.
    'mark-seen': {
      payload: { messageId: string }
      response: void
    }
  }
}
```

```typescript [app.ts]
// Resolves after the server has handled the message.
await socket.request('mark-seen', { messageId: 'm-42' })
console.log('the server marked the message as seen')
```

This is how it differs from `send()`. `send()` returns `true` when the message is accepted, which means it was passed to the socket or buffered. It never tells you that the server got the message. An acknowledgement request resolves only **after** the server handler ran. So awaiting it confirms that the message arrived and was processed, even when you need no data back.

```typescript [app.ts]
// `typing` is a message handler on the server, so the client uses send()
socket.send('typing', { roomId: 'room-1' }) // true = accepted, not delivered

// `mark-seen` is a request handler on the server, so the client uses request()
await socket.request('mark-seen', { messageId: 'm-42' }) // resolves = the server handled it
```

## Concurrent requests

Each request has its own correlation ID. So you can have many requests waiting at the same time, and each one resolves on its own:

```typescript [app.ts]
const [profile, balance] = await Promise.all([
  socket.request('get-profile', { userId: '123' }),
  socket.request('get-balance', { userId: '123' }),
])
```

## Timeout

By default, a request waits 10 seconds for a reply. Set a different default for all requests with the primitive option. Set it for one call with the third argument:

```typescript [app.ts]
const socket = client<ApiSocket>()(
  connect('wss://example.com/ws'),
  clientRequests({ timeout: 5_000 }), // default for every request
)

// a longer wait for one slow call
const report = await socket.request(
  'build-report',
  { range: '1y' },
  { timeout: 30_000 },
)
```

## When the socket isn't open

`request()` needs a socket that is open or connecting:

- On a **lazy** socket (one created with `connect(url, { lazy: true })`), calling `request()` opens the connection. The request is sent when the connection is open.
- While the socket is **connecting** or **reconnecting**, the client holds the frame and sends it, in order, when the connection opens. If that connection attempt fails, the request rejects with `Disconnected`. With [`buffering()`](/client/primitives/buffering) installed, the request goes into the buffer like any other send.
- On a socket that is **not lazy** and that you haven't opened with `connect()` yet (state `closed`), `request()` rejects at once with `Disconnected`. It does not wait until the timeout. Call `connect()` first, or use a lazy socket.

## On a channel

With [`channels()`](/client/primitives/channels) installed, channel handles also get a `request()` method. It is typed from that channel's contract, and the request is sent to that channel:

```typescript [app.ts]
const room = socket.channel('rooms', 'room-1')
await room.subscribe()
const history = await room.request('get-history', {
  before: 'msg-100',
})
```

Call `await room.subscribe()` first. If you call `room.request()`, `room.send()` or `room.stream()` before the channel is active, it **throws `ChannelNotSubscribed` right away**. This is a thrown error, not a rejected promise. So a `.catch()` on the request does not catch it. Use `try`/`catch` around the call, or subscribe first.

For the other direction, where the server asks _you_ a question and waits for your answer, see [`serverRequests()`](/client/primitives/server-requests).
