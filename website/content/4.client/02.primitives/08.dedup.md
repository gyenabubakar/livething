`dedup()` drops a message you have already received. When a connection drops, the server can send again the messages you missed (a catch-up). A few messages can then arrive twice: once before the drop, and once in the catch-up. `dedup()` throws away the second copy, so your `on()` handlers run once per message.

`dedup()` adds no methods to the socket. It checks each incoming message before your handlers get it. For this to work, the server must add an ID to each message. To turn that on, see [dedup](/server/capabilities/dedup) in the Server section.

```typescript [client/socket.ts]
import { client, connect, dedup } from '@livething/client'
import type { HuddleSocket } from '../server/huddle-definition'

export const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle'),
  dedup(),
)
```

## How it works

Each message from the server can carry a delivery ID in `metadata.delivery.id`. The primitive keeps a list of the delivery IDs it has seen recently:

- If a message has an ID that is still in the list, `dedup()` drops it. When [debug logging](/client/connecting/debug-logging) is on, it logs each dropped message to the console.
- If a message has a new ID, `dedup()` adds the ID to the list and the message goes through.
- A message **without** a delivery ID is never dropped. It always goes through.

The list uses a **sliding window**. An ID stays in the list until `windowMs` milliseconds have passed since that ID last arrived. Each repeat of an ID resets its timer. So an ID that keeps arriving again stays in the list until the repeats stop.

The list has no fixed size limit. Its size depends on time: it holds about as many IDs as the number of different messages you receive in `windowMs`. Old IDs are removed when the next message with a delivery ID arrives. A connection that receives no messages keeps its list as it is until the next message comes.

## Options

```typescript [client/socket.ts]
import { dedup } from '@livething/client'

dedup({
  windowMs: 60_000, // how long to remember an ID after it last arrived (default: 60_000)
})
```

`windowMs` must be a finite number above `0`. Any other value throws a `LiveThingConfigError` when you call `dedup()`.

Set `windowMs` a good amount larger than the longest time you expect the socket to stay disconnected. If the socket is disconnected for longer than the window, the IDs of the messages it received before the drop leave the list. Repeats of those messages in the catch-up then go through. The default of 60 seconds works for apps that reconnect quickly.

A larger `windowMs` means a larger list. If your app receives a very large number of different messages, do not make `windowMs` larger than your catch-up needs.

[`replay()`](/client/primitives/replay) and [`inbox()`](/client/primitives/inbox) both need `dedup()`, because the server can send them copies of messages you already have. If you add either one without `dedup()`, the `client()` call fails to compile. When TypeScript cannot be sure (see [Primitives](/client/primitives/overview) for the cases), and in plain JavaScript, `client()` throws an error when it builds the socket.
