`dedup()` drops a message you've already seen. When a connection drops and the server replays what you missed, a few messages can arrive twice — once before the drop, once in the catch-up. This throws away the repeat, so your `on()` handlers run once per message. It adds no methods; it works through the pipeline. For the server half — tagging messages with IDs — see [dedup](/server/capabilities/dedup) in the Server section.

```typescript [app.ts]
import { client, connect, dedup } from '@wskit/client'
import type { MarketSocket } from './socket-types'

const socket = client<MarketSocket>()(connect('wss://example.com/ws'), dedup())
```

## How it works

The primitive keeps a set of recently-seen `__wskit.messageId` values. A message whose ID is still remembered is silently dropped; a new ID is remembered and passes through. Messages **without** a `messageId` are never deduplicated — they always go through.

It's a **sliding window**: an ID is remembered until it has gone unseen for `windowMs`. Every repeat refreshes that timer, so an ID that keeps being replayed stays remembered until it goes quiet. Memory is bounded by time, not a fixed count — the set holds roughly your distinct-ID rate times `windowMs`, and a quiet connection prunes down to nothing.

## Options

```typescript [app.ts]
dedup({
  windowMs: 60_000, // how long to remember an id after it was last seen (default: 60_000)
})
```

Set `windowMs` comfortably larger than your longest expected reconnect gap. If you're disconnected longer than the window, the duplicate IDs from the overlap will have expired and won't be caught — so the default of 60 seconds suits apps that reconnect quickly. For a very high sustained rate of distinct IDs, keep `windowMs` no larger than your catch-up window needs.

`dedup()` is also a requirement of [`replay()`](/client/primitives/replay), which is what makes catch-up safe to repeat.
