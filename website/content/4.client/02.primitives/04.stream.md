`stream()` adds the methods for reading server streams. A stream is data that the server sends in many small pieces (chunks), for example the words of Scout's reply or a page of chat history. For the server half (writing the generator that produces the chunks), see [Streams](/server/streams/overview) in the Server section. For the full client API, see the [Streams chapter](/client/streams/overview).

```typescript [client/scout.ts]
import { client, connect, stream } from '@livething/client'
import type { HuddleSocket } from '../server/huddle-definition'

export const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle'),
  stream(),
)
```

## The contract side

The three methods are typed from the `streams` key of your contract. Each entry has:

- `payload`: the data that starts the stream.
- `chunk`: the shape of each piece the stream sends.
- `kind`: `'ephemeral'` (a one-time stream that ends if the connection drops) or `'persistent'` (a durable stream that the server keeps, so the client can resume it).
- `nudges` (optional): a map of messages you can send into a running stream.

```typescript [socket-types.ts]
interface HuddleSocket {
  streams: {
    'search-messages': {
      payload: { query: string }
      chunk: { hit: Message }
      kind: 'ephemeral'
    }
    'export-room': {
      payload: { roomId: string }
      chunk: { messages: Message[] }
      kind: 'persistent'
    }
    'tail-audit-log': {
      payload: {}
      chunk: { line: string }
      kind: 'ephemeral'
      nudges: {
        stop: undefined
        'set-level': { level: 'info' | 'warn' | 'error' }
      }
    }
  }
}
```

With `@livething/server`, `InferClient` produces this map for you, so you don't write it by hand. A server `stream` becomes `kind: 'ephemeral'`. A server `resumableStream` or `recordedStream` becomes `kind: 'persistent'`.

`payload` types the second argument to `stream(...)`, and `chunk` types each value you get in the `for await` loop. `kind: 'persistent'` is what allows `resumeStream(...)` for that stream. An `'ephemeral'` stream can't be passed to `resumeStream(...)`.

The primitive adds three methods, all typed from your contract's `streams`.

## `stream(event, payload, options?)`: start and read a stream

`stream(...)` starts a stream and returns a promise for a **handle**. The handle is an object you read with `for await`. The promise resolves when the server accepts the stream. It rejects if the server refuses the stream, if the connection closes first, or if the server doesn't answer within `timeout` (see [Options](#options)).

```typescript [client/scout.ts]
const hits = await socket.stream('search-messages', {
  query: 'launch date',
})

for await (const chunk of hits) {
  appendHit(chunk.hit) // chunk is typed from the stream's `chunk`
}
// the loop ended normally, so the stream finished
```

The loop **ends** when the stream completes. It **throws** on a terminal error (an error that ends the stream) or on a per-chunk timeout, so wrap it in `try/catch` to handle those. If you leave the loop with `break` or `return`, the stream is cancelled for you.

The optional third argument sets the stream ID yourself (`{ streamId: 'export-room-general' }`) instead of letting LiveThing generate one. A fixed ID is useful when you want to resume the same stream after a page reload.

### The handle

```typescript [client/admin.ts]
const log = await socket.stream('tail-audit-log', {})

log.nudge('set-level', { level: 'error' }) // message into the running stream
log.cancel() // ask the server to stop; the loop ends without throwing
log.streamId // the ID shared by all chunks of this stream
log.active // true while the stream is still running
```

`nudge(event, payload, options?)` sends a message _into_ the running server generator, for example to change which lines it sends. It returns a promise:

- It resolves when the server confirms the nudge.
- It rejects if the server refuses the nudge or if `nudgeTimeout` passes.
- If the stream finishes before the server confirms, it resolves when the stream ends normally or is cancelled, and rejects with the error that ended the stream.

A rejected nudge does **not** end the stream. Only the client that started the stream can nudge it. After a stream has finished, `nudge()` and `cancel()` do nothing (`nudge()` resolves without sending anything).

::note
Chunks wait in a queue, in order, until your `for await` body reads them. The client puts no limit on the size of this queue. If your loop is much slower than the server, chunks build up in memory. When the server is fast and your UI is slow, keep the loop body short: move slow work out of the loop, or skip some chunks (for example, render only the latest one).
::

## `onStream(event, handlers)`: listen only (broadcasts)

When the server broadcasts a stream to many clients, your client did not start it. Scout's reply to `ask-scout` in a room works this way: everyone in the room gets the same chunks, not only the person who asked. You read it with callbacks instead of a `for await` loop:

```typescript [client/room.ts]
const unsubscribe = room.onStream('ask-scout', {
  onChunk(chunk, streamId) {
    appendScoutText(chunk.text)
  },
  onEnd(streamId, finalSeq) {
    markScoutReplyDone()
  },
  onError(err, streamId) {
    showScoutError(err)
  },
  onTimeout(streamId) {
    showScoutStalled()
  },
})
```

The callbacks run for every stream with that event name. If several streams with the same name run at the same time, use `streamId` to tell them apart. On a broadcast, a terminal error reaches every subscriber, so `onError` runs for all of them. Call `unsubscribe()` to stop listening.

## `resumeStream(event, streamId, options?)`: resume by hand

`resumeStream(...)` connects to a **durable** stream again by its ID. Use it after a page reload, or to join a broadcast stream when you already have its ID. It only accepts streams whose `kind` is `'persistent'`. Passing an ephemeral stream is a compile error.

```typescript [client/room.ts]
const resumed = socket.resumeStream('export-room', savedStreamId, {
  lastKnownSeq: 12,
})
for await (const chunk of resumed)
  appendExportedMessages(chunk.messages)
```

Each chunk has a sequence number (`seq`). `lastKnownSeq` is the highest sequence number you already received. The server sends only the chunks after it.

## Durable streams resume automatically

A `'persistent'` stream (a server `resumableStream` or `recordedStream`) resumes by itself when the socket reconnects. The **same `for await` loop keeps receiving chunks**, starting after the last chunk it received. You don't write any reconnect code, and you don't call `resumeStream()`:

```typescript [client/room.ts]
// `export-room` is a persistent stream. If the socket drops and then
// reconnects while the export is running, this loop keeps receiving chunks.
const pages = await socket.stream('export-room', {
  roomId: 'room:general',
})
for await (const chunk of pages) {
  appendExportedMessages(chunk.messages)
}
markExportDone()
```

This works only with two other primitives installed:

- [`reconnection()`](/client/primitives/reconnection), so the socket reconnects after a drop. Without it, the loop throws `Disconnected`.
- [`keepalive()`](/client/primitives/keepalive), so the client notices a half-open connection (a connection that stopped working without closing). Without it, the loop can wait forever.

Use `resumeStream()` only for a _cold_ resume: when the handle in memory is gone, for example after a page reload or in a second browser tab.

## Options

```typescript [client/socket.ts]
stream({
  timeout: 30_000, // wait for the NEXT chunk; restarts on every chunk, it is not a total limit (default: 30_000)
  nudgeTimeout: 10_000, // how long nudge() waits for the server to confirm (default: 10_000)
})
```

`timeout` also limits how long `stream(...)` waits for the server to accept the stream. Set `timeout: 0` to turn the per-chunk timeout off. You set `timeout` only here, on the primitive. You can change the nudge timeout for one call with `nudge(event, payload, { timeout })`. `nudgeTimeout: 0` (or `{ timeout: 0 }` on one call) turns off the nudge timeout in the same way, so `nudge()` waits with no time limit.

## On a channel

With [`channels()`](/client/primitives/channels) installed, channel handles also get `stream(...)`, `onStream(...)`, and `resumeStream(...)`. These methods work on that channel only and are typed from the channel's contract. This is how `room.onStream('ask-scout', ...)` above reaches only the room's own broadcast, and not another room's.
