`query()` adds query parameters to the connection URL each time the socket connects. Since a browser can't set custom headers on a WebSocket, this is the usual way to pass an auth token. It adds no methods — it rewrites the URL during connect. The [Auth & Query](/client/connecting/auth-and-query) page covers the auth side; this is the primitive reference.

```typescript [app.ts]
import { client, connect, query } from '@wskit/client'
import type { MySocket } from './socket-types'

const socket = client<MySocket>()(
  connect('wss://example.com/ws'),
  query(() => ({ token: getAuthToken(), client: 'web' })),
)
// wss://example.com/ws?token=eyJhbG...&client=web
```

## The params function

`query(fn)` takes a function that returns a `Record<string, string>`, or a `Promise` of one. The key things to know:

- **It runs on every connect and reconnect.** A token refreshed between attempts is picked up automatically — there's nothing to invalidate.
- **It may be async.** The client awaits it before opening the socket, so you can refresh a token inside it.
- **Params are appended after the URL is resolved.** If a [dynamic URL](/client/connecting/dynamic-url) already carries a query string, the params are added with `&` rather than replacing it.
- **A disconnect mid-resolution cancels the attempt.** If you `disconnect()` while an async `query()` is still resolving, the resolved params are discarded and no socket opens.

```typescript [app.ts]
query(async () => {
  let token = getStoredToken()
  if (isExpired(token)) token = await refreshToken()
  return { token }
})
```

If the function throws or its promise rejects, the attempt ends through the normal connection-failure path: the error is reported to `socket.onError`, and [`reconnection()`](/client/primitives/reconnection) retries it if installed.

For cookie-based auth (no `query()` needed) and the server side, see [Auth & Query](/client/connecting/auth-and-query).
