`query()` adds query parameters to the connection URL each time the socket connects. Query parameters are the `?key=value` pairs at the end of a URL. A browser can't set custom headers on a WebSocket, so this is the usual way to send an auth token. `query()` adds no methods to the socket. It only changes the URL before each connection attempt. This page is the reference for the primitive. The [Auth & Query](/client/connecting/auth-and-query) page explains how to use it for authentication.

```typescript [client/socket.ts]
import { client, connect, query } from '@livething/client'
import type { HuddleSocket } from '../server/huddle-definition'

export const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle'),
  query(() => ({ token: getSessionToken(), client: 'web' })),
)
// wss://example.com/huddle?token=eyJhbG...&client=web
```

## The params function

`query(fn)` takes a function that returns a `Record<string, string>` (an object with string keys and string values), or a `Promise` of one. This function works as follows:

- **It runs on every connect and reconnect.** If your app refreshes the token between two attempts, the next attempt uses the new token. You don't need to clear or reset anything.
- **It can be async.** The client waits for its promise before it opens the socket, so you can refresh a token inside it.
- **The client adds the params after it resolves the URL.** If a [dynamic URL](/client/connecting/dynamic-url) already has a query string, the client adds the params to it with `&`. It does not replace the existing ones.
- **A disconnect cancels the attempt.** If you call `disconnect()` while an async `query()` function is still running, the client ignores the params it returns and does not open a socket.

```typescript [client/socket.ts]
query(async () => {
  let token = getStoredToken()
  if (isExpired(token)) token = await refreshToken()
  return { token }
})
```

If the function throws, or its promise rejects, the connection attempt fails in the normal way. The error goes to your `socket.onError` callbacks. If you installed [`reconnection()`](/client/primitives/reconnection), it schedules another attempt, and that attempt calls your function again.

Auth with cookies needs no `query()`. For cookie auth and for reading the token on the server, see [Auth & Query](/client/connecting/auth-and-query).
