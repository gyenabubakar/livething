`quality()` sets the latency cut-offs that decide which connection-quality tier you're in. It only configures thresholds — it adds no methods, and it's only useful alongside [`keepalive()`](/client/primitives/keepalive), which does the measuring and exposes the `socket.quality` and `socket.latency` stores.

```typescript [app.ts]
import { client, connect, keepalive, quality } from '@wskit/client'
import type { MySocket } from './socket-types'

const socket = client<MySocket>()(
  connect('wss://example.com/ws'),
  keepalive(),
  quality({ thresholds: { excellent: 30, good: 100, degraded: 300 } }),
)
```

## The tiers

Quality comes from a rolling average of recent ping/pong latency. The thresholds (in ms) split it into tiers:

| Tier           | Default                         | Meaning               |
| -------------- | ------------------------------- | --------------------- |
| `excellent`    | < 50ms                          | fast                  |
| `good`         | 50–150ms                        | fine                  |
| `degraded`     | 150–500ms                       | sluggish              |
| `poor`         | > 500ms, or after a missed pong | bad                   |
| `disconnected` | —                               | the socket isn't open |

The three thresholds must **ascend** — `excellent` < `good` < `degraded`. They aren't validated, so a non-ascending set (say `good` below `excellent`) silently makes some tiers unreachable rather than erroring.

The latency tiers come from a rolling average of the last few pings, so they move smoothly; the jump to `'poor'` on a missed pong is immediate, not averaged.

## Reading it in your UI

The values live in the [stores](/client/overview#reactive-stores) [`keepalive()`](/client/primitives/keepalive) adds — `socket.quality` and `socket.latency`. A connection-status dot is the typical use:

```typescript [app.ts]
const dotColor = {
  excellent: 'green',
  good: 'green',
  degraded: 'amber',
  poor: 'red',
  disconnected: 'grey',
}

socket.quality.subscribe((quality) => {
  setDotColor(dotColor[quality])
  const latency = socket.latency.get() // null until the first pong, and again after a missed one
  setTooltip(latency === null ? 'measuring…' : `${latency}ms`)
})
```

Both are reactive stores, so binding them to a framework is the same one-line adapter you use for connection state — see [Framework Hooks](/recipes/framework-hooks/react).

## Options

```typescript [app.ts]
quality({
  thresholds: { excellent: 50, good: 150, degraded: 500 }, // ms cut-offs (these are the defaults)
})
```

You give the three boundaries; `poor` is everything past `degraded`, and `disconnected` is what `socket.quality` reads whenever the socket isn't open.

::note
Each side computes quality independently, so the client and server may disagree on the same connection — the bundled `@wskit/server` uses its own cut-offs. These tiers are a UI convenience, not a wire contract; don't treat them as a shared protocol value.
::

Without `keepalive()` the client sends no pings, so there's nothing to measure and these thresholds have nothing to act on. Add `keepalive()` to make quality live, and use `quality()` only when the defaults don't fit your app.
