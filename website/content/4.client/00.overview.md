`@livething/client` is the typed WebSocket client. You give it a contract type and a URL, and you get back a **socket** — an object with typed `on()` and `send()`, connection control, lifecycle callbacks, and whatever extra methods the primitives you added bring along.

The [Learn](/learn/the-contract) section is the tutorial — it teaches each feature from both sides at once. This **Client** section is the per-package guide: it goes deep on the client half — every connection option, every primitive, every method — for when you need the details.

## Creating a socket

You build a socket in two calls. The first names the contract; the second takes `connect(...)` and the primitives you want:

```typescript [app.ts]
import {
  channels,
  client,
  connect,
  reconnection,
} from '@livething/client'
import type { ChatSocket } from '../server/chat'

const socket = client<ChatSocket>()(
  connect('wss://example.com/ws'),
  channels(),
  reconnection({ maxAttempts: Infinity }),
)
```

The split into two calls is deliberate. TypeScript can't infer some type arguments while you write others by hand, so naming the contract in the first call frees the second call to infer the primitives — that's what types `socket.channel(...)` from your contract. The order of the primitives doesn't matter; they're sorted by their dependencies before they run.

`connect(...)` is the one required argument. Everything else is opt-in: a primitive you don't pass simply isn't on the socket.

## What every socket has

These methods are on the socket no matter which primitives you add:

| Method                        | What it does                                                                                                                                                                                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `connect()`                   | Opens the connection. Safe to call more than once — a no-op while already open or connecting.                                                                                                                                                            |
| `disconnect(code?, reason?)`  | Closes on purpose. A full stop: no reconnection, the send buffer is cleared, pending requests reject. `code` defaults to `1000`, `reason` to `''`; an invalid code or oversized reason safely becomes a normal (`1000`) close and reports a local error. |
| `state`                       | A [reactive store](#reactive-stores) of the current [connection state](#connection-states). Read it with `socket.state.get()`; watch it with `socket.state.subscribe(...)`.                                                                              |
| `onOpen(callback)`            | Runs on every open — the first connect and every reconnect.                                                                                                                                                                                              |
| `onReconnect(callback)`       | Runs only on reconnects, not the first connect.                                                                                                                                                                                                          |
| `onReconnectFailed(callback)` | Runs once when reconnection gives up for good.                                                                                                                                                                                                           |
| `onClose(callback)`           | Runs on every close, including ones that lead to a reconnect. The callback gets `{ code, reason, wasClean }`.                                                                                                                                            |
| `onError(callback)`           | Runs on a WebSocket-level failure or anything local code throws: handlers, interceptors, primitives, plugins, and connection setup.                                                                                                                      |
| `onServerError(callback)`     | Runs for an unclaimed server error, including codes this client does not know yet. Use the code overload for declared detail types.                                                                                                                      |
| `setDebug(enabled)`           | Turns console logging on or off at runtime.                                                                                                                                                                                                              |
| `protocol`                    | The subprotocol the server picked, or `null`.                                                                                                                                                                                                            |
| `ws`                          | The native `WebSocket`, or `null` when not connected.                                                                                                                                                                                                    |

Each `on*` callback returns an unsubscribe function. `onError` receives `unknown`: a DOM `Event` for a WebSocket failure, or any value thrown by local setup, handlers, primitives, interceptors, plugins, or an invalid `disconnect(...)` code. `onServerError` receives a `LiveThingError`; its broad overload accepts codes added by a newer server, while `onServerError('known-code', ...)` keeps the declared detail type. A claimed server error still rejects the request, stream, or channel operation that was waiting for it. With no matching server-error listener, the error is rethrown to the host's global handler. The full error model is in the [Errors chapter](/client/errors/overview).

The socket also carries the **Messaging** methods — `on(event, handler)` to listen and `send(event, payload)` to send — which appear only when your contract declares `incoming` or `outgoing` events, respectively. See [the Messaging interface](#the-messaging-interface) below.

## Reactive stores

Every live value on the socket — the connection state, the connection quality, a channel's roster — is exposed as a small **reactive store**. LiveThing is framework-agnostic, so instead of one binding per value it gives you one shape for all of them:

```typescript [store.ts]
interface ReadableStore<T> {
  get(): T
  subscribe(listener: (value: T) => void): () => void
}
```

- **`get()`** reads the current value. The reference stays the same until the value actually changes, so you can compare snapshots by identity.
- **`subscribe(listener)`** runs `listener` with the new value on every change, and returns a function that removes it. It does **not** fire right away — read the starting value with `get()`.

`ReadableStore` is exported from `@livething/client`. This is exactly the shape React's `useSyncExternalStore`, a Svelte store, a Vue `ref`, and a Solid signal want, so binding any store to a framework is one small adapter you write once and reuse for every value — see [Framework Hooks](/recipes/framework-hooks/react).

You'll meet these stores through the socket: `socket.state` here, plus `socket.quality` / `socket.latency` from [`keepalive()`](/client/primitives/keepalive), `socket.reconnection` from [`reconnection()`](/client/primitives/reconnection), `socket.online` from [`platform()`](/client/platform/overview), and `channel.members` / `channel.status` on a [channel handle](/client/channels/presence-listeners).

## Connection states

A socket is always in exactly one of four states:

- **`closed`** — not connected, and not trying to be.
- **`connecting`** — opening a connection (resolving the URL, then the handshake).
- **`open`** — connected and ready to send and receive.
- **`reconnecting`** — the connection dropped and the client is waiting to retry. Only reached when the [`reconnection()`](/client/primitives/reconnection) primitive is installed.

The state lives in the `socket.state` store: read it now with `socket.state.get()`, or watch it with `socket.state.subscribe(...)`.

```typescript [app.ts]
render(socket.state.get())

const stop = socket.state.subscribe((state) => render(state))
// later: stop()
```

## The Messaging interface

`on()` and `send()` make up the **Messaging** interface — the pair of methods for receiving and sending typed events:

```typescript [app.ts]
// Listen — returns an unsubscribe function
const stop = socket.on('notification', (data) => {
  // data is typed from your contract's `incoming`
})

// Send — returns true if sent or buffered, false if dropped
socket.send('mark-read', { id: '123' })
```

Which of the two you get depends on your contract: `on()` exists only when the contract has `incoming` events, and `send()` only when it has `outgoing` events. Try to `send()` on a contract that declares nothing outgoing and it's a compile error — there's nothing to send.

A `true` from `send()` means "accepted" — handed to the socket or placed in the buffer — not "the server got it." When you need delivery confirmation, use a [request](/client/primitives/client-requests) instead.

Channel handles returned by the `channels` primitive are Messaging objects too, so the same `on()` / `send()` work scoped to a room.

## Primitives add the rest

Beyond the base above, each primitive you install adds its own methods, typed from your contract:

- [`channels()`](/client/primitives/channels) adds `socket.channel(...)`.
- [`clientRequests()`](/client/primitives/client-requests) adds `socket.request(...)`.
- [`serverRequests()`](/client/primitives/server-requests) adds `socket.onRequest(...)`.
- [`stream()`](/client/primitives/stream) adds `socket.stream(...)`, `socket.onStream(...)`, and `socket.resumeStream(...)`.
- [`keepalive()`](/client/primitives/keepalive) adds the `socket.quality` and `socket.latency` stores.
- [`reconnection()`](/client/primitives/reconnection) adds the `socket.reconnection` store.
- [`platform()`](/client/platform/overview) adds the `socket.online` store.

If you don't install a primitive, its methods aren't on the socket — and if your contract declares the matching key, TypeScript points you at the primitive to add.
