`@livething/client` is the typed WebSocket client. You give it a contract type and a URL. (The contract is the type that lists every event, channel, request and stream your server supports.) You get back a **socket**. A socket is an object with typed `on()` and `send()` methods, methods to open and close the connection, and lifecycle callbacks. It also has the extra methods of every primitive you add. (A primitive is a client feature, such as channels or reconnection, that you pass to `client()`.)

The [Learn](/learn/the-contract) section is the tutorial. It teaches each feature on the server and the client together. This **Client** section is the guide for the client package only. It covers every connection option, every primitive and every method in detail.

## Creating a socket

You build a socket with two calls. The first call names the contract. The second call takes `connect(...)` and the primitives you want:

```typescript [client/socket.ts]
import {
  channels,
  client,
  connect,
  reconnection,
} from '@livething/client'
import type { HuddleSocket } from '../server/huddle-definition'

export const socket = client<HuddleSocket>()(
  connect('wss://example.com/huddle'),
  channels(),
  reconnection({ maxAttempts: Infinity }),
)
```

There are two calls for a reason. TypeScript cannot infer some type arguments of a function when you write the others by hand. So you name the contract in the first call, and TypeScript infers the primitives in the second call. This is how `socket.channel(...)` gets its types from your contract. The order of the primitives does not matter. `client()` sorts them by their dependencies before they run.

`connect(...)` is the only required argument. Everything else is optional. A primitive you don't pass is not on the socket.

## What every socket has

These methods and properties are on every socket, whatever primitives you add:

| Method                        | What it does                                                                                                                                                                                                                                                                                                                   |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `connect()`                   | Opens the connection. You can call it more than once. It does nothing while the socket is already open or connecting.                                                                                                                                                                                                          |
| `disconnect(code?, reason?)`  | Closes the connection on purpose. After this, the socket does not reconnect, the send buffer is cleared, and pending requests reject. `code` defaults to `1000` and `reason` to `''`. If the code is not valid or the reason is longer than 123 bytes, the socket closes with a normal `1000` close and reports a local error. |
| `state`                       | A [reactive store](#reactive-stores) of the current [connection state](#connection-states). Read it with `socket.state.get()`. Watch it with `socket.state.subscribe(...)`.                                                                                                                                                    |
| `onOpen(callback)`            | Runs on every open: the first connect and every reconnect.                                                                                                                                                                                                                                                                     |
| `onReconnect(callback)`       | Runs only on reconnects, not on the first connect.                                                                                                                                                                                                                                                                             |
| `onReconnectFailed(callback)` | Runs once, when reconnection stops trying.                                                                                                                                                                                                                                                                                     |
| `onClose(callback)`           | Runs on every close, including a close that is followed by a reconnect. The callback gets `{ code, reason, wasClean }`.                                                                                                                                                                                                        |
| `onError(callback)`           | Runs on a WebSocket failure, or when your local code throws: handlers, interceptors, primitives, plugins and connection setup.                                                                                                                                                                                                 |
| `onServerError(callback)`     | Runs for a server error that no request, stream, channel or plugin handled, including error codes this client does not know. Use the overload that takes a code to get the declared detail type.                                                                                                                               |
| `setDebug(enabled)`           | Turns console logging on or off while the app runs.                                                                                                                                                                                                                                                                            |
| `protocol`                    | The subprotocol the server picked, or `null`. (A subprotocol is a name the client and server agree on during the WebSocket handshake.)                                                                                                                                                                                         |
| `ws`                          | The native `WebSocket` object, or `null` when not connected.                                                                                                                                                                                                                                                                   |

Each `on*` callback method returns an unsubscribe function. Call it to remove the callback.

`onError` receives a value of type `unknown`. For a WebSocket failure it is a DOM `Event`. Otherwise it is the value that local setup, a handler, a primitive, an interceptor or a plugin threw, or the error from an invalid `disconnect(...)` code.

`onServerError` receives a `LiveThingError`. It has two overloads:

- `onServerError(callback)` accepts every code, including codes that only a newer server version sends.
- `onServerError('known-code', callback)` runs only for that code, and keeps the declared detail type.

A server error that belongs to a waiting request, stream or channel operation rejects that operation. It does not reach `onServerError`. If no `onServerError` listener matches an error, the client rethrows it to the host's global error handler (for example `window.onerror`). The [Errors chapter](/client/errors/overview) explains the full error model.

The socket also has the **Messaging** methods: `on(event, handler)` to listen and `send(event, payload)` to send. `on()` exists only when your contract declares `incoming` events, and `send()` only when it declares `outgoing` events. See [the Messaging interface](#the-messaging-interface) below.

## Reactive stores

A **reactive store** is a value you can read now and watch for changes. The socket gives every live value as a store: the connection state, the connection quality, a channel's member list. LiveThing does not depend on any UI framework, so it uses one shape for all of these values:

```typescript [store.ts]
interface ReadableStore<T> {
  get(): T
  subscribe(listener: (value: T) => void): () => void
}
```

- **`get()`** reads the current value. It returns the same object reference until the value changes, so you can compare two snapshots with `===`.
- **`subscribe(listener)`** runs `listener` with the new value on every change. It returns a function that removes the listener. It does **not** run the listener right away, so read the starting value with `get()`.

`ReadableStore` is exported from `@livething/client`. This shape connects easily to React's `useSyncExternalStore`, a Svelte store, a Vue `ref` and a Solid signal. You write one small adapter for your framework once, and use it for every store. See [Framework Hooks](/recipes/framework-hooks/react).

These are the stores on the socket:

- `socket.state`, described on this page.
- `socket.quality` and `socket.latency`, from [`keepalive()`](/client/primitives/keepalive).
- `socket.reconnection`, from [`reconnection()`](/client/primitives/reconnection).
- `socket.online`, from [`platform()`](/client/platform/overview).
- `channel.members` and `channel.status`, on a [channel handle](/client/channels/presence-listeners).

## Connection states

A socket is always in one of four states:

- **`closed`**: not connected, and not trying to connect.
- **`connecting`**: opening a connection. First it resolves the URL, then it does the WebSocket handshake.
- **`open`**: connected and ready to send and receive.
- **`reconnecting`**: the connection dropped and the client is waiting to try again. The socket only enters this state when the [`reconnection()`](/client/primitives/reconnection) primitive is installed.

The state is in the `socket.state` store. Read the current state with `socket.state.get()`, or watch it with `socket.state.subscribe(...)`:

```typescript [client/socket.ts]
render(socket.state.get())

const stop = socket.state.subscribe((state) => render(state))
// later: stop()
```

## The Messaging interface

`on()` and `send()` together are the **Messaging** interface: the two methods for receiving and sending typed events.

```typescript [client/socket.ts]
// Listen. Returns an unsubscribe function.
const stop = socket.on('notification', (data) => {
  // data is typed from your contract's `incoming`
})

// Send. Returns true if sent or buffered, false if dropped.
socket.send('rename', { name: 'Ada' })
```

Your contract decides which of the two methods you get. `on()` exists only when the contract has `incoming` events. `send()` exists only when it has `outgoing` events. If the contract declares no `outgoing` events, calling `send()` is a compile error.

When `send()` returns `true`, the message was accepted: it went to the WebSocket or into the send buffer. It does not mean the server received it. When you need to know that the server received a message, use a [request](/client/primitives/client-requests) instead.

The channel handles that the `channels` primitive returns also have the Messaging interface. The same `on()` and `send()` work on them, but only for that channel.

## Primitives add the rest

Each primitive you install adds its own methods on top of the base socket. Their types come from your contract:

- [`channels()`](/client/primitives/channels) adds `socket.channel(...)`.
- [`clientRequests()`](/client/primitives/client-requests) adds `socket.request(...)`.
- [`serverRequests()`](/client/primitives/server-requests) adds `socket.onRequest(...)`.
- [`stream()`](/client/primitives/stream) adds `socket.stream(...)`, `socket.onStream(...)` and `socket.resumeStream(...)`.
- [`keepalive()`](/client/primitives/keepalive) adds the `socket.quality` and `socket.latency` stores.
- [`reconnection()`](/client/primitives/reconnection) adds the `socket.reconnection` store.
- [`platform()`](/client/platform/overview) adds the `socket.online` store.

If you don't install a primitive, its methods are not on the socket. If your contract declares the matching section (for example `channels`) but the primitive is missing, TypeScript shows an error that names the primitive to add.
