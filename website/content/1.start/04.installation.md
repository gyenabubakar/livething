LiveThing is split across a few packages. You install the client where your UI lives, and the server plus one platform adapter where your backend lives. Both share `@livething/core`, which the commands below include for you.

## The packages

| Package                        | Where it runs                                   | What it is                                                                                       |
| ------------------------------ | ----------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `@livething/client`            | Browser, React Native, Node, Bun, Deno, Workers | The typed client socket                                                                          |
| `@livething/server`            | Your backend                                    | The server framework (`server`, capabilities, `InferClient`)                                     |
| `@livething/server-cloudflare` | Cloudflare Durable Objects                      | Platform adapter                                                                                 |
| `@livething/server-bun`        | Bun                                             | Platform adapter                                                                                 |
| `@livething/server-node`       | Node.js                                         | Platform adapter                                                                                 |
| `@livething/server-deno`       | Deno                                            | Platform adapter                                                                                 |
| `@livething/core`              | Shared                                          | Wire protocol, errors, `CloseCodes` — the shared peer dependency, included in the commands below |

::note
`@livething/core` is a peer dependency of both `@livething/client` and `@livething/server`. The commands below install it explicitly, so it works the same on npm, pnpm, yarn, and bun.
::

## Client

Install in the project that holds your UI:

::code-group

```bash [npm]
npm install @livething/client @livething/core
```

```bash [pnpm]
pnpm add @livething/client @livething/core
```

```bash [bun]
bun add @livething/client @livething/core
```

```bash [yarn]
yarn add @livething/client @livething/core
```

::

## Server

Install `@livething/server` plus the adapter for your platform. Pick one adapter.

### Cloudflare Durable Objects

::code-group

```bash [npm]
npm install @livething/server @livething/server-cloudflare @livething/core
```

```bash [pnpm]
pnpm add @livething/server @livething/server-cloudflare @livething/core
```

```bash [bun]
bun add @livething/server @livething/server-cloudflare @livething/core
```

```bash [yarn]
yarn add @livething/server @livething/server-cloudflare @livething/core
```

::

The Cloudflare adapter requires a `compatibility_date` of `2026-04-07` or later in your `wrangler.jsonc`:

```jsonc [wrangler.jsonc]
{
  "compatibility_date": "2026-04-07",
}
```

### Bun, Node.js, and Deno

Install `@livething/server` plus your runtime's adapter — `@livething/server-bun`, `@livething/server-node`, or `@livething/server-deno`. The server code you write is identical to the Cloudflare block above; only the adapter package changes.

```bash [npm]
npm install @livething/server @livething/server-node @livething/core
```

Swap `@livething/server-node` for `@livething/server-bun` or `@livething/server-deno`, and use your runtime's own installer (`bun add`, `deno add`) if you prefer.

## Schemas

LiveThing validates payloads with any [Standard Schema](https://standardschema.dev) validator — valibot, Zod, ArkType, and others. The examples in these docs use [valibot](https://valibot.dev), which `@livething/server` already depends on:

::code-group

```bash [npm]
npm install valibot
```

```bash [pnpm]
pnpm add valibot
```

```bash [bun]
bun add valibot
```

```bash [yarn]
yarn add valibot
```
