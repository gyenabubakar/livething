The [Quickstart](/start/quickstart) built a typed broadcast. This page adds two things to it. First, an `upgrade` hook checks who the user is before the connection opens. Second, you add **one channel**. A channel is a room that the server manages: clients join it, and it has its own typed events. On this page you see the shared types at work: a channel you declare on the server appears on the client with full types, and you write no extra code for that.

The app stays small: one channel, and no streams or replay. It uses the same adapter as the Quickstart. Only the channel and the auth hook are new.

::callout{icon="i-ph-package-duotone" to="/start/installation"}
You need no new packages. The server `channels()` capability is part of `@livething/server`, under the `@livething/server/channels` subpath. The client `channels()` primitive is part of `@livething/client`.
::

## The server

Two things are new compared to the Quickstart: an `upgrade` hook that checks the handshake, and a `channels()` capability with one `lobby` channel. You build the server in three parts, all in the same `chat.ts` file.

::steps{level="3"}

### Check who is connecting

The `upgrade` hook (the [upgrade gate](/server/server/upgrade)) runs during the HTTP handshake, before the WebSocket opens. It receives the standard `Request`. To accept the connection, return `{ userId, meta }`. To reject it, throw `RejectUpgrade(code, reason)`.

- `userId` is the stable ID of the user behind this connection. LiveThing uses it to recognize the same user when they reconnect.
- `meta` is data for this connection. Every handler can read it as `ctx.meta`.

A browser cannot set custom headers on a WebSocket request, so the client sends its token in the URL query string. The hook reads it from there. `4002` is the LiveThing close code for an invalid token (`CloseCodes.AUTH_INVALID`).

Listing the `channels()` capability turns on channels for this server.

```typescript [chat.ts]
import { emits, server, t } from '@livething/server'
import { channels } from '@livething/server/channels'
import { RejectUpgrade } from '@livething/server/errors'
import * as v from 'valibot'
import type { InferClient } from '@livething/server'

const base = server({
  async upgrade(request) {
    const token = new URL(request.url).searchParams.get('token')
    const user = await validateToken(token)
    if (!user) throw RejectUpgrade(4002, 'Invalid token')
    return {
      userId: user.id, // the stable ID of this user
      meta: { userId: user.id }, // available as ctx.meta in every handler
    }
  },
  capabilities: [channels()],
})
```

### Declare the channel

`base.channel('lobby', ...)` defines the channel. It takes three settings:

- `subscribe` is a schema. It validates the payload a client sends when it joins.
- `check` runs when a client tries to join. Throw an error in it to reject the join.
- `capabilities: [emits(...)]` declares the events the server can broadcast to the channel.

```typescript [chat.ts]
const lobby = base.channel('lobby', {
  subscribe: v.object({ inviteToken: v.string() }),
  capabilities: [
    emits({
      'lobby-message': t<{ text: string; from: string }>(),
    }),
  ],
  check(ctx, input) {
    // input is the validated subscribe payload: { inviteToken: string }
    // A plain throw rejects the join. The client receives the code
    // 'internal-error'. To send your own error code, use a typed error
    // from the errors() capability.
    if (!validInvite(input.inviteToken)) {
      throw new Error('Bad invite')
    }
  },
})
```

### Handle channel messages

`lobby.on(...)` defines a handler for a message that a client sends to the channel. Inside it, `ctx.channel.broadcast(...)` sends only to the members of this channel. Then call `assemble` to build the server definition, and export the inferred type.

```typescript [chat.ts]
export const handleSay = lobby.on('say', {
  input: v.object({ text: v.string() }),
  run(ctx, input) {
    // ctx.meta.userId comes from the upgrade hook.
    // includeSelf also sends the event to the member who sent the message.
    ctx.channel.broadcast(
      'lobby-message',
      { text: input.text, from: ctx.meta.userId },
      { includeSelf: true },
    )
  },
})

// handleSay belongs to the lobby channel, so passing handleSay also adds lobby.
// Passing the channel object itself adds only its settings and lifecycle
// hooks, not its message handlers.
export const definition = base.assemble({ handlers: [handleSay] })
export type ChatSocket = InferClient<typeof definition>
```

::

::note
`validateToken` and `validInvite` stand for your own logic. This page is about the shapes: what `upgrade` returns and what `check` receives.
::

## The client

The client side follows the server. Add the `query()` primitive to send the token, and the `channels()` primitive to use channels. Get a handle (an object for one channel) with `socket.channel('lobby')`. Call `subscribe()` with the typed payload to join. Then listen for events and send messages.

```typescript [app.ts]
import { channels, client, connect, query } from '@livething/client'
import type { ChatSocket } from '../server/chat'

const socket = client<ChatSocket>()(
  connect('ws://localhost:3000/ws/chat'),
  query(() => ({ token: getAuthToken() })), // adds ?token=... to the URL
  channels(),
)

socket.connect()

const lobby = socket.channel('lobby')

// You can add listeners before the server confirms the subscribe
lobby.on('lobby-message', (data) => {
  // data has the type { text: string; from: string }, taken from the server channel
  console.log(`${data.from}: ${data.text}`)
})

// subscribe() needs the typed payload, because the server channel declares a `subscribe` schema
await lobby.subscribe({ inviteToken: 'abc-123' })

// After the subscribe, you can send. The payload type comes from the channel's `say` handler input
lobby.send('say', { text: 'hello lobby' })
```

`getAuthToken` stands for your own code that returns the user's token.

## See the shared types

Every type on the client side comes from the one `InferClient` type:

- **The channel name.** `socket.channel('lobby')` autocompletes `'lobby'`. If you misspell it, you get a compile error.
- **The subscribe payload.** The server channel declares `subscribe: v.object({ inviteToken: v.string() })`, so `lobby.subscribe(...)` **requires** `{ inviteToken: string }`. If you leave out the field, you get a compile error.
- **The channel event.** `lobby.on('lobby-message', ...)` gives `data` the type `{ text: string; from: string }`. This is the exact shape that the channel's `emits(...)` declares.
- **The message you send.** The payload of `lobby.send('say', ...)` must match the input schema of the server's `lobby.on('say', ...)` handler.

If you change any of these shapes on the server, the client code that uses them shows type errors. You define the contract once, and the compiler checks both sides against it.
