The [Quickstart](/start/quickstart) gave you a typed broadcast. Now we'll build slightly up: gate the connection with an `upgrade` auth hook, and add **one channel** — a server-managed room with its own typed event. This is the page where the shared types really click: a channel you declare on the server appears, fully typed, on the client with no extra work.

We'll keep it focused — one channel, no streams or replay. It still uses the same adapter as the Quickstart; only the new capability and the auth hook are added.

::callout{icon="i-ph-package-duotone" to="/start/installation"}
Same packages as the Quickstart, plus nothing new — `channels` ships inside `@wskit/server` under the `@wskit/server/channels` subpath.
::

## The server

Two things change from the Quickstart: an `upgrade` hook that authenticates the handshake, and a `channels()` capability with one `lobby` channel. We'll build it in three parts — all in the same `chat.ts`.

::steps{level="3"}

### Gate the connection

The `upgrade` hook runs during the HTTP handshake. Return `{ userId, meta }` to accept the connection; throw `RejectUpgrade(code, reason)` to reject it. `userId` is the durable key for the connection, and `meta` flows into `ctx.meta` in every handler. Listing the `channels()` capability turns on rooms.

```typescript [chat.ts]
import { define, emits, t } from '@wskit/server'
import { channels } from '@wskit/server/channels'
import { RejectUpgrade } from '@wskit/server/errors'
import * as v from 'valibot'
import type { InferClient } from '@wskit/server'

const base = define({
  async upgrade(request) {
    const token = request.headers.get('authorization')
    const user = await validateToken(token)
    if (!user) throw RejectUpgrade(4002, 'Invalid token')
    return {
      userId: user.id, // durable key for this connection
      meta: { userId: user.id }, // flows into ctx.meta everywhere
    }
  },
  capabilities: [channels()],
})
```

### Declare the channel

`base.channel('lobby', ...)` defines the room. Its `subscribe` schema validates the join payload, `check` runs the auth gate on entry (throw to reject), and its `capabilities: [emits(...)]` declares the events the channel can broadcast.

```typescript [chat.ts]
const lobby = base.channel('lobby', {
  subscribe: v.object({ inviteToken: v.string() }),
  capabilities: [
    emits({ 'lobby-message': t<{ text: string; from: string }>() }),
  ],
  check(ctx, input) {
    // input is the validated subscribe payload: { inviteToken: string }
    // A plain throw rejects the subscribe; use a typed error (the errors()
    // capability) when you want the client to catch it.
    if (!validInvite(input.inviteToken)) {
      throw new Error('Bad invite')
    }
  },
})
```

### Handle channel messages

A channel handler is bound with `lobby.on(...)`. Inside it, `ctx.channel.broadcast(...)` is scoped to the channel's members only. Then `assemble` the server and export the inferred type.

```typescript [chat.ts]
export const handleSay = lobby.on('say', {
  input: v.object({ text: v.string() }),
  run(ctx, input) {
    // ctx.meta.userId comes from the upgrade hook
    ctx.channel.broadcast('lobby-message', {
      text: input.text,
      from: ctx.meta.userId,
    })
  },
})

// handleSay already carries its channel, so passing it pulls `lobby` in too.
// (Pass the channel object itself only when it has no message handlers —
// for example a channel that's just lifecycle hooks.)
export const handler = base.assemble({ handlers: [handleSay] })
export type ChatSocket = InferClient<typeof handler>
```

::

::note
`validateToken` and `validInvite` are stand-ins for your own logic. The shapes — what `upgrade` returns, what `check` receives — are what matter here.
::

## The client

The channel side mirrors the server. Add the `channels()` primitive, grab a handle with `socket.channel('lobby')`, `subscribe()` with the typed payload, then listen and send.

```typescript [app.ts]
import { channels, client, connect } from '@wskit/client'
import type { ChatSocket } from '../server/chat'

const socket = client<ChatSocket>()(connect('wss://example.com/ws'), channels())

socket.connect()

const lobby = socket.channel('lobby')

// Listeners can be registered before the subscribe is confirmed
lobby.on('lobby-message', (data) => {
  // data is typed { text: string; from: string } — straight from the server channel
  console.log(`${data.from}: ${data.text}`)
})

// subscribe() requires the typed payload, because the server channel declared a `subscribe` schema
await lobby.subscribe({ inviteToken: 'abc-123' })

// Now you can send — typed against the channel's `say` handler input
lobby.send('say', { text: 'hello lobby' })
```

## Watch the shared types click

Everything on the client side came from that one `InferClient` type:

- **The channel name.** `socket.channel('lobby')` autocompletes `'lobby'`. Misspell it and it's a compile error.
- **The subscribe payload.** Because the server channel declared `subscribe: v.object({ inviteToken: v.string() })`, `lobby.subscribe(...)` **requires** `{ inviteToken: string }`. Drop the field and the compiler stops you.
- **The channel event.** `lobby.on('lobby-message', ...)` types `data` as `{ text: string; from: string }` — the exact shape the server's `emits(...)` capability declared.
- **The outgoing channel event.** `lobby.send('say', ...)` is typed against the server's `lobby.on('say', ...)` input schema.

Change any of those shapes on the server and the client call sites light up. That's the whole idea — one contract, both ends, kept honest by the compiler.
