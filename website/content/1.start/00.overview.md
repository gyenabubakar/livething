LiveThing is a typed WebSocket framework. Its two main packages are `@livething/server` and `@livething/client`. They share one **contract**: the list of events your app sends and receives, with the exact type of each **payload** (the data that a message carries). You write your events once on the server. TypeScript infers the contract from that code, and the client uses the same types. You never copy types from one side to the other.

## LiveThing in 30 seconds

You create a server base with `server(...)` and store it in a variable, for example `base`. Next you create **handlers**, the functions that run when a message arrives, and pass them to `base.assemble(...)`. From the result, you export one type with `InferClient`. The client imports that type. After that, `socket.on()`, `socket.send()`, requests and channels are all typed on both sides. If you write a wrong event name or a wrong payload shape, TypeScript shows a compile error. You find the mistake while you write code, not when the app runs.

Every feature is opt-in on both sides. On the server, a feature is a **capability** that you list. On the client, a feature is a **primitive** that you pass. Your bundle only contains the features you import. A minimal client is about **5.24 KB** after minifying (removing spaces and shortening names) and gzip compression (a standard way to make files smaller for download).
