WSKit is a typed WebSocket framework. It comes as two packages — `@wskit/server` and `@wskit/client` — built around **one shared contract**. You write the contract once on the server, and the client gets the same types automatically.

## Two packages, one contract

On the server you declare what your app can send and receive. On the client you don't redeclare any of it — you import a single type and the whole API becomes typed.

The bridge is `InferClient`. On the server you write:

```typescript
import type { InferClient } from '@wskit/server'

export const handler = base.assemble({
  handlers: [
    /* ...handlers */
  ],
})
export type ChatSocket = InferClient<typeof handler>
```

On the client you consume that type:

```typescript
import { client, connect } from '@wskit/client'
import type { ChatSocket } from '../server/chat'

const socket = client<ChatSocket>()(connect('wss://example.com/ws'))
socket.connect()

socket.on('message', (data) => {
  // data is fully typed — inferred straight from the server
})
```

The contract **mirrors** across the wire. The server's `emits` (server → client events) become the client's `incoming`. The server's `base.on` handlers become the client's `outgoing`. The same flip applies to requests, server-initiated requests, streams, channels, and errors. `incoming` and `outgoing` are always read from the point of view of whoever holds the type.

## Opt-in features

WSKit ships almost nothing by default. Features are added explicitly:

- **Server capabilities** — you list them in `define({ capabilities: [...] })`. Each one is imported from its own subpath (for example `channels()` from `@wskit/server/channels`). Listing a capability pulls its engine code into the bundle; leaving it out costs nothing.
- **Client primitives** — you pass them to `client()`. For example `reconnection()` for automatic reconnect, `channels()` for rooms, `keepalive()` for pings. A primitive you don't pass simply doesn't exist on the socket.

This is why the minimal client is about **4.5 KB gzipped** — the build ships one file per module, so importing only what you use tree-shakes the rest away.

## Where it runs

The server is built to run anywhere a WebSocket does, and you swap platforms by changing one import — each platform has its own adapter, like `@wskit/server-cloudflare` for Cloudflare Durable Objects.

The client works in any environment with a `WebSocket` — browsers, React Native, Node.js, Bun, Deno, and Cloudflare Workers.

## What type safety buys you

Because the contract is inferred, not hand-copied, the two sides can never drift:

- Calling `socket.on()` with an event the server doesn't emit is a compile error.
- Sending the wrong payload shape is a compile error.
- Renaming an event on the server flags every stale call site on the client.
- Autocomplete works for every event name and payload field, on both sides.

You declare your events once and let the compiler keep both ends honest.
