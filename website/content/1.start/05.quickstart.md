This is the smallest real LiveThing app: a server that emits one event and handles one incoming event, an adapter entry, the inferred type, and a client that listens and sends. No channels, no auth, no streams — just the contract flowing end to end.

We'll use the Cloudflare Durable Objects adapter here. The server code is identical on every platform; only the adapter entry changes.

::callout{icon="i-ph-package-duotone" to="/start/installation"}
Make sure you've installed `@livething/client`, `@livething/server`, `@livething/server-cloudflare`, and `valibot` first — see [Installation](/start/installation).
::

::steps{level="3"}

### Create the server

The contract has two events: the server **emits** `message` (server → client), and it **handles** `send-message` (client → server). The `emits({...})` capability turns on `ctx.send` / `ctx.broadcast`; the values are `t<Shape>()` type markers.

```typescript [chat.ts]
import { emits, server, t } from '@livething/server'
import * as v from 'valibot'
import type { InferClient } from '@livething/server'

const base = server({
  capabilities: [
    emits({
      message: t<{ text: string; from: string }>(),
    }),
  ],
})

export const handleSendMessage = base.on('send-message', {
  input: v.object({ text: v.string(), from: v.string() }),
  run(ctx, input) {
    // Fan out to every connection. Typed against the emits() declaration.
    ctx.broadcast('message', {
      text: input.text,
      from: input.from,
    })
  },
})

export const definition = base.assemble({
  handlers: [handleSendMessage],
})

// This single type is the whole client contract.
export type ChatSocket = InferClient<typeof definition>
```

`base.on('send-message', ...)` returns an incoming handler value. Its `input` schema validates the client's payload before `run` sees it. `base.assemble(...)` collects the handler values you list into the `ServerDefinition` the adapter runs.

### Add the adapter entry

The adapter connects your server definition to the platform. On Cloudflare it returns a Durable Object class:

```typescript [index.ts]
import { bind } from '@livething/server-cloudflare'
import { definition } from './chat'

export class ChatRoom extends bind(definition) {}
```

That's the entire backend. Wire `ChatRoom` up as a Durable Object in your `wrangler.jsonc` (and remember the `compatibility_date` of `2026-04-07` or later).

### Connect from the client

Import the inferred `ChatSocket` type — nothing is redeclared. `client<ChatSocket>()` returns a factory you call with your primitives; the only required one is `connect`.

```typescript [app.ts]
import { client, connect } from '@livething/client'
import type { ChatSocket } from '../server/chat'

const socket = client<ChatSocket>()(
  connect('wss://your-worker.example.com'),
)

socket.connect()

// `data` is typed { text: string; from: string } — inferred from the server's emits()
socket.on('message', (data) => {
  console.log(`${data.from}: ${data.text}`)
})

// Typed against the server's send-message handler input
socket.send('send-message', { text: 'hello', from: 'gyen' })
```

## Watch the types flow

The contract mirrors across the wire, so the names flip:

- The server **emits** `message` → the client **receives** it with `socket.on('message', ...)`.
- The server **handles** `send-message` → the client **sends** it with `socket.send('send-message', ...)`.

Try it: rename `message` to `chat` in the server's `emits({...})`. The client's `socket.on('message', ...)` immediately becomes a type error, because `InferClient` re-derived the contract. You never edited the client by hand — the compiler caught the drift for you.
