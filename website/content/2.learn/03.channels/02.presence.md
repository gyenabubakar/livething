Once people are in a room, you usually want to *show* them — a list of who's here, an avatar that dims when someone's connection drops, a "3 people typing" indicator. That's **presence**: the channel keeps track of its members, and both sides can read the roster and react as it changes.

There's an important distinction baked into presence: being a **member** of a channel is not the same as being **online** right now. This page makes that difference clear and shows how to use both.

## Member vs online

- **Membership** is whether a connection belongs to the channel. You become a member when you subscribe, and you stay one until you unsubscribe or are removed. This is the "who's in this room" set.
- **Online** is whether a member's connection is currently live. A member can briefly go *offline* — their laptop slept, the network blipped — without leaving the room. When they reconnect, they're online again, still a member the whole time.

Why split them? Because a momentary drop shouldn't kick someone out of a room. Presence lets you show "still here, just reconnecting" instead of yanking them from the member list every time the wifi hiccups.

## Reading members on the server

Inside any channel handler, `ctx.channel.members()` returns the current roster — an array of connection info, including each member's `meta` (the per-connection data you set in `upgrade`):

```typescript [chat.ts]
const handleWhoIsHere = room.on('who-is-here', {
  input: v.object({}),
  run(ctx) {
    const names = ctx.channel.members().map((m) => m.meta.username)
    ctx.send('roster', { names })
  },
})
```

This is also how `commit` can enforce capacity — `ctx.channel.members().length` tells you how full the room is before you let one more in, as you saw in [Subscribing](/learn/channels/subscribing).

::note
As with any handler, a channel handler like `handleWhoIsHere` only takes effect once it's passed to `base.assemble(...)` (which pulls its channel in too). These snippets leave that line out to stay focused — see [The Contract](/learn/core-model/the-contract).
::

The server also drives presence changes directly: `room.subscribe(...)` and `room.unsubscribe(...)` lifecycle hooks fire as people join and leave, and you can broadcast a system message from them:

```typescript [chat.ts]
room.subscribe((ctx) => {
  ctx.channel.broadcast('system', { text: `${ctx.meta.username} joined` })
})

room.unsubscribe((ctx) => {
  ctx.channel.broadcast('system', { text: `${ctx.meta.username} left` })
})
```

## Reading presence on the client

On the client, the channel handle keeps a live `members` map and gives you callbacks for every presence change. The map is keyed by connection id, and each member carries its `meta`:

```typescript [app.ts]
const room = socket.channel('room')
await room.subscribe()

// A live snapshot of who's in the room.
for (const [connectionId, member] of room.members) {
  console.log('here:', member.meta)
}
```

### The four presence callbacks

The split between membership and online state shows up directly in the callbacks:

| Callback | Fires when |
|---|---|
| `onMemberJoin` | Someone subscribes to the channel (a real join) |
| `onMemberLeave` | Someone unsubscribes or is removed (a real leave) |
| `onMemberOnline` | An existing member's connection comes back |
| `onMemberOffline` | An existing member's connection drops, but they stay a member |

```typescript [app.ts]
room.onMemberJoin((connectionId, member) => {
  addToRoster(connectionId, member.meta)
})

room.onMemberLeave((connectionId) => {
  removeFromRoster(connectionId)
})

room.onMemberOffline((connectionId) => {
  dimAvatar(connectionId) // still a member, just away
})

room.onMemberOnline((connectionId, member) => {
  brightenAvatar(connectionId)
})
```

Use **join/leave** to add and remove people from your visible roster, and **online/offline** to show a presence dot or grey out an avatar without removing anyone.

## The initial roster

When you subscribe, the server sends the full current member list so your `members` map starts populated — you don't have to wait for `onMemberJoin` events to trickle in. If you ever need to re-fetch the roster (say after a long offline stretch), call `room.resyncMembers()` and the server re-sends it.

## What flows between them

| Server | Client |
|---|---|
| `ctx.channel.members()` | `room.members` (live map) |
| a subscribe (join) | `onMemberJoin` |
| an unsubscribe / removal | `onMemberLeave` |
| a connection drop / return | `onMemberOffline` / `onMemberOnline` |

Presence is automatic once channels are on — you don't declare anything extra. The roster and callbacks are simply there on the channel handle.
