A **frame** is one message as it travels over the WebSocket. LiveThing uses the same small JSON frame for every message, both for your app's events and for the framework's own events:

```json
[
  "message",
  {
    "id": "m_8f2a",
    "text": "hello",
    "from": "maya",
    "sentAt": 1767225600000
  },
  null
]
```

Every frame is a JSON array with exactly three items:

1. the event name, a string;
2. the payload (the data that the message carries), or `null` when the event has no payload;
3. the metadata, a nested object or `null`.

The third item is never left out. When a frame has no metadata, the third item is `null`. An empty object `{}` is not allowed. Because a frame is plain JSON, a client in another language can use the protocol with a normal WebSocket and a JSON parser.

## Metadata

Metadata holds the framework details that LiveThing needs to handle a frame. With these details, LiveThing can route the frame (send it to the right channel or stream), match a reply to its request, deliver messages in order, and continue a stream after a disconnect. The details are in groups, one group per feature:

```json
{
  "exchange": { "id": "request-42", "source": "server" },
  "channel": {
    "name": "room:42",
    "family": "rooms",
    "unsubscribeId": "leave-1",
    "membership": "persistent",
    "inbox": true,
    "readReceipts": true
  },
  "delivery": { "id": "message-7", "seq": 12 },
  "stream": {
    "id": "ask-scout-1",
    "event": "ask-scout",
    "durability": "persistent",
    "seq": 3,
    "nudgeId": "nudge-1",
    "terminated": false
  }
}
```

This example shows every field at once. A real frame includes only the groups and fields that its message needs. Unknown groups and unknown fields are not allowed.

| Group      | Fields                                                                   | Use                                                            |
| ---------- | ------------------------------------------------------------------------ | -------------------------------------------------------------- |
| `exchange` | `id`, `source`                                                           | Match a reply to its request                                   |
| `channel`  | `name`, `family`, `unsubscribeId`, `membership`, `inbox`, `readReceipts` | Send a frame to a channel and describe that channel            |
| `delivery` | `id`, `seq`                                                              | Give a message an ID and a number, to order it and drop copies |
| `stream`   | `id`, `event`, `durability`, `seq`, `nudgeId`, `terminated`              | Group the frames of one stream and continue it                 |

Some fields need a short explanation:

- `exchange.source` is the side that started the request: `"client"` or `"server"`. The reply carries the same value.
- `channel.family` is the family key of a dynamic channel. A dynamic channel is one declaration that covers many rooms, such as `rooms` for `room:42`. See [Channels](/learn/channels).
- `channel.unsubscribeId` is the ID of a leave request. The server's confirmation carries the same ID.
- `channel.membership` is `"persistent"` when the server stores the membership and puts the client back into the channel after a reconnect. It is `"ephemeral"` when the client must join again itself.
- `channel.inbox` and `channel.readReceipts` are `true` when the channel uses the inbox or read receipts feature. An inbox tracks which messages each user has received, and read receipts track which messages each user has read.
- `delivery.seq` is the delivery number. The client uses it to put channel and replay messages in order and to drop duplicate copies (a message that arrives twice). A message sent to many connections carries the same `delivery.seq` and `delivery.id` for every recipient. Stream chunks carry `stream.seq` and no `delivery.seq`.
- `stream.seq` is the chunk number. A client uses it to continue a stream from the last chunk it received.
- `stream.durability` is `"persistent"` when the server stores the stream, so the stream can continue after a disconnect. It is `"ephemeral"` for a plain stream.
- `stream.nudgeId` is the ID of a nudge. A nudge is a small message that the client sends into a running stream to control it, for example to pause an AI reply. See [Streaming](/learn/streaming).
- `stream.terminated` appears on a stream error. `false` means the error did not end the stream, for example when one nudge fails.

## Reserved events

Framework events have names that start and end with two underscores, such as `__error__`. For this reason, your own event names cannot start or end with `__`.

Most reserved events travel in one direction. Four go both ways, with a different payload in each direction: `__received__`, `__read__`, `__receivedQuery__` and `__readQuery__` (they appear in both tables). `memberId` in a presence payload is the user ID when the channel is persistent and the connection has signed in, otherwise it is the connection ID.

### Client to server

| Event                | Payload                                            | Meaning                                                                                                                                           |
| -------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `__subscribe__`      | the subscribe payload the channel expects, or none | Join a channel                                                                                                                                    |
| `__unsubscribe__`    | none                                               | Leave a channel                                                                                                                                   |
| `__replay__`         | `{ lastKnownSeq?, resume? }`                       | Ask for the messages missed since delivery number `lastKnownSeq` (or from the start). `resume` lists up to 8 resume tokens of earlier connections |
| `__streamCancel__`   | none                                               | Stop a running stream                                                                                                                             |
| `__continueStream__` | `{ lastKnownSeq? }`                                | Continue a stored stream after a reconnect, from chunk number `lastKnownSeq`                                                                      |
| `__received__`       | `{ receivedThrough }`                              | Tell the server this user received the channel's messages up to that delivery number                                                              |
| `__read__`           | `{ readThrough }`                                  | Tell the server this user read the channel's messages up to that delivery number                                                                  |
| `__receivedQuery__`  | `{ seq }`                                          | Ask which users received the message with that delivery number                                                                                    |
| `__readQuery__`      | `{ seq }`                                          | Ask which users read the message with that delivery number                                                                                        |

### Server to client

| Event               | Payload                                      | Meaning                                                                                                                                                                                                                              |
| ------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `__subscribeOk__`   | `{ seq? }`                                   | Confirms a join. When replay is on, `seq` is where catch-up starts for a member that has seen no message in the channel                                                                                                              |
| `__unsubscribeOk__` | `{}`                                         | Confirms a leave                                                                                                                                                                                                                     |
| `__streamOk__`      | `{}`                                         | Confirms a stream started                                                                                                                                                                                                            |
| `__nudgeOk__`       | `{}`                                         | Confirms a nudge (a small message a client sends into a running stream to control it)                                                                                                                                                |
| `__streamEnd__`     | `{}`                                         | The stream finished                                                                                                                                                                                                                  |
| `__error__`         | `{ code, detail? }`                          | A typed error. With `stream.terminated: true` it ends the stream; `stream-aborted` with `reason: 'interrupted'` ends a recorded stream that was cut off                                                                              |
| `__kicked__`        | `{ reason }`                                 | The server removed this connection from a channel                                                                                                                                                                                    |
| `__gap__`           | `{ missedThrough }`                          | Some missed messages were already deleted, so they cannot be sent again. `missedThrough` is the last deleted delivery number                                                                                                         |
| `__resume__`        | `{ token, seq? }`                            | Sent first when replay is on. `token` is this connection's secret resume token: a later `__replay__` shows it to get back the messages sent to this connection. `seq` marks where the connection started, as a first catch-up cursor |
| `__memberJoin__`    | `{ memberId, meta? }`                        | A member joined the channel                                                                                                                                                                                                          |
| `__memberLeave__`   | `{ memberId, meta? }`                        | A member left the channel                                                                                                                                                                                                            |
| `__memberOnline__`  | `{ memberId, meta? }`                        | A member's connection came online (presence)                                                                                                                                                                                         |
| `__memberOffline__` | `{ memberId }`                               | A member's connection went offline (presence)                                                                                                                                                                                        |
| `__memberSync__`    | `{ members: { memberId, meta?, online }[] }` | The full list of the channel's members. `online` is `false` for a persistent-channel member with no live connection right now                                                                                                        |
| `__received__`      | `{ userId, receivedThrough }`                | Tells every member that `userId` received the channel's messages up to that delivery number                                                                                                                                          |
| `__read__`          | `{ userId, readThrough }`                    | Tells every member that `userId` read the channel's messages up to that delivery number                                                                                                                                              |
| `__receivedQuery__` | `{ userIds }`                                | The users who received the queried message                                                                                                                                                                                           |
| `__readQuery__`     | `{ userIds }`                                | The users who read the queried message                                                                                                                                                                                               |

## Sending frames

A client sends the same three-item shape:

```json
["send-message", { "text": "hi" }, null]
```

A request adds its ID inside `metadata.exchange`:

```json
[
  "get-profile",
  { "userId": "u_amara" },
  { "exchange": { "id": "request-42", "source": "client" } }
]
```

To join a channel, a client puts the channel name inside `metadata.channel.name`. For a dynamic channel, it also adds the family key in `metadata.channel.family`. If the channel expects data when a client joins, that data goes in the payload.

```json
["__subscribe__", null, { "channel": { "name": "room:42" } }]
```

When a frame is not valid JSON or is not a three-item array, the server drops it. When the frame has the right shape but its metadata or payload is wrong, the server replies with an `__error__` frame whose code is `validation-failed`.

Every frame is a text frame. LiveThing does not support binary frames. If a client sends one, the server closes the connection with close code `1003` (`UNSUPPORTED_DATA`). See [Close codes](/core/close-codes).

The `@livething/client` package builds and reads these frames for TypeScript apps. A client in another language only needs to send and read the three-item JSON array.
