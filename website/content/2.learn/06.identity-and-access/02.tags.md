Sometimes you need to reach a *set* of connections, not just one and not everyone — "send this to every admin," "kick all of this user's open tabs," "notify everyone on team 42." **Tags** make that possible: you label connections, and then you can address every connection sharing a label as a single group. Tags are a server-side capability; the client just experiences the results.

A tag is two parts: a **group** (the kind of label, like `user` or `role`) and a **key** (the value, like a specific user id or `admin`). A connection can carry many tags.

## Ephemeral vs persistent

There are two kinds of tag, and the difference is how long they last:

- **Ephemeral tags** live for the connection. They vanish when the connection closes. Use them for live, session-scoped grouping — "this socket belongs to user X right now."
- **Persistent tags** are stored and survive reconnects. Use them for durable grouping that should outlast a single connection.

You declare which groups exist, of each kind, up front.

## Declaring tag groups

The `tags()` capability takes a builder that lists your groups. The builder gives you `ephemeral` and `persistent` factories; each group has a name and a type (or schema) for its key:

```typescript [chat.ts]
import { define, t } from '@wskit/server'
import { tags } from '@wskit/server/tags'
import * as v from 'valibot'

const base = define({
  env: t<Env>(),
  capabilities: [
    tags((ephemeral, persistent) => [
      ephemeral('user', t<string>()),
      // a schema-backed group validates the key on add
      ephemeral('role', v.picklist(['admin', 'member', 'guest'])),
      persistent('favorite', t<string>()),
    ]),
  ],
})
```

A group declared with a schema (like `role` above) validates its key when you add it — try to tag a connection with an unknown role and it's rejected. Declaring groups up front is also what makes the tag API type-safe: you can only reference groups you declared.

## Adding and removing tags

Inside a handler, `ctx.tags` is scoped to the current connection. Pick a group, then `add` or `remove` a key:

::note
The handlers in these snippets are trimmed for focus. As always, a handler only takes effect once you pass it to `base.assemble(...)` — see [The Contract](/learn/core-model/the-contract).
::

```typescript [chat.ts]
const handleSetRole = base.on('set-role', {
  input: v.object({ role: v.picklist(['admin', 'member', 'guest']) }),
  run(ctx, input) {
    ctx.tags.ephemeral('role').add(input.role)
  },
})
```

You can also attach a tag the moment a connection opens, by returning a `tags` field from the [upgrade gate](/learn/identity-and-access/authentication) — handy for tagging by user id on connect:

```typescript [chat.ts]
async upgrade(request) {
  const user = await authenticate(request)
  return {
    identity: user.id,
    meta: { userId: user.id },
    tags: { ephemeral: { user: user.id } }, // tagged on connect
  }
}
```

## Addressing a group

The point of tags is reaching everyone who shares one. From a group, `.ref(key)` gives you a handle to all connections with that exact tag, and you can send to them, count them, or list them:

```typescript [chat.ts]
const handleNotifyAdmins = base.on('notify-admins', {
  input: v.object({ text: v.string() }),
  run(ctx, input) {
    // send an event to every connection tagged role:admin
    ctx.tags.ephemeral('role').ref('admin').send('admin-notice', { text: input.text })

    // or inspect the group
    const adminConnections = ctx.tags.ephemeral('role').ref('admin').connections()
    console.log(`${adminConnections.length} admins online`)
  },
})
```

This is the power of tags: one `send` reaches every connection with the tag, wherever they are, with no manual bookkeeping of who's who.

A common real use is multi-tab: a single user often has several sockets open. Tag each by `user`, and `ctx.tags.ephemeral('user').ref(userId)` addresses *all* of that user's tabs at once — perfect for "log out everywhere" or pushing an update to every device.

You can also use a tag reference with channel operations — for example, kicking everyone with a given tag out of a channel — by passing the ref where a target is expected:

```typescript [chat.ts]
await ctx.channels.get('room').kick(
  ctx.tags.ephemeral('user').ref(bannedUserId),
  'banned',
)
```

## What the client sees

Tags are entirely a server-side organizing tool — there's no `tags()` primitive on the client, and nothing for the client to configure. The client simply receives whatever the server sends to its group: an `admin-notice` event arrives through a normal `socket.on('admin-notice', ...)` listener, exactly like any other event. The grouping logic stays on the server, where it belongs.

## The mental model

- **Declare** your tag groups (ephemeral or persistent) in `tags()`.
- **Tag** connections with `ctx.tags.<kind>(group).add(key)` — or at the upgrade gate.
- **Address** a group with `ctx.tags.<kind>(group).ref(key)` to send, count, or list.

Tags turn "which sockets belong together?" from a problem you track by hand into a label the framework manages.
