Real networks are messy. Connections drop when a laptop sleeps, a phone changes towers, a proxy times out an idle socket, or you ship a deploy. A WebSocket app that ignores all this works perfectly on your machine and falls apart for users. **Reliability** is the set of primitives that keep a connection healthy and your data consistent through all that mess.

These features are largely client-side, because the client is where the unreliable network bites hardest. A couple have a server half too. You add only the ones you need.

## What can go wrong, and what handles it

| Problem | Feature |
|---|---|
| The socket drops and stays dead | [Reconnection](/learn/reliability/reconnection) — retry with backoff |
| An idle socket gets silently killed by a proxy | [Keepalive](/learn/reliability/keepalive-and-quality) — pings and missed-pong detection |
| The user sends things while offline | [Buffering](/learn/reliability/buffering) — queue and flush on reconnect |
| Messages were missed during the gap | [Replay](/learn/reliability/replay-and-dedup) — catch up after reconnect |
| The same message arrives twice | [Deduplication](/learn/reliability/replay-and-dedup) — drop the duplicate |

Each is an opt-in primitive (and, for replay and keepalive, a matching server capability). Leave one out and you don't pay for it; add it and the socket gains that resilience.

## How they work together

They're designed to compose. A typical resilient client stacks several:

```typescript [app.ts]
import { client, connect, reconnection, keepalive, buffering } from '@wskit/client'

const socket = client<AppSocket>()(
  connect('wss://example.com/ws'),
  reconnection(), // get back after a drop
  keepalive(),    // notice a dead socket fast
  buffering(),    // don't lose sends while offline
)
```

The story they tell together: **keepalive** notices a socket has silently died and closes it, **reconnection** brings it back, **buffering** holds anything you tried to send during the gap and flushes it on return, and **replay** plus **dedup** make sure you catch up on what you missed without processing anything twice.
