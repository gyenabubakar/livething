A raw WebSocket that drops stays dropped — `onclose` fires and that's it. For a real app, that's not acceptable: a brief network blip shouldn't end the session. The `reconnection()` primitive makes the client reconnect automatically after an unexpected drop, with sensible backoff so you don't hammer the server. This is a client-only feature; the server doesn't need to know.

## Turning it on

Add the primitive and the socket reconnects on its own:

```typescript [app.ts]
import { client, connect, reconnection } from '@wskit/client'
import type { AppSocket } from '../server/app'

const socket = client<AppSocket>()(
  connect('wss://example.com/ws'),
  reconnection(),
)
socket.connect()
```

That's the whole setup. When the socket drops unexpectedly, the client moves to the `reconnecting` state and starts retrying. On success it goes back to `open` and your `onOpen` callback fires — which is exactly why `onOpen` runs on every reconnect, not just the first connect.

## Backoff and jitter

Reconnection doesn't retry instantly and forever — that would stampede your server when many clients drop at once (say, after a deploy). Instead it backs off:

- **Exponential backoff.** The wait between attempts doubles each time — roughly 1s, 2s, 4s, 8s — up to a ceiling.
- **Jitter.** Each wait is randomly nudged so a thousand clients that dropped together don't all retry on the same tick. They spread out instead of arriving in a thundering herd.

The defaults are tuned for a typical app, with a maximum delay of 30 seconds between attempts and 10 attempts before it gives up. You can change them:

```typescript [app.ts]
reconnection({
  maxAttempts: Infinity, // never stop trying
  maxDelay: 10_000,      // cap each wait at 10s
})
```

Setting `maxAttempts: Infinity` keeps retrying forever — appropriate for an always-on app. When attempts run out, the client gives up and your `onReconnectFailed` callback fires.

## Close-code awareness

Not every disconnect should be retried. If the server closed the connection because the user was *banned*, reconnecting just gets them banned again. Reconnection looks at the close code to decide whether a retry makes sense, and you can steer that:

```typescript [app.ts]
reconnection({
  // never retry these close codes
  nonRetryableCodes: [4009 /* banned */, 4002 /* auth invalid */],

  // or decide case by case
  shouldReconnect(code, reason) {
    if (code === 4001) return false // auth expired — re-auth instead
    // return undefined to fall through to the defaults
  },
})
```

`shouldReconnect` returning `true` or `false` settles it; returning `undefined` falls through to `nonRetryableCodes` and the built-in defaults. This is how you separate "the network hiccuped, come back" from "the server said no, stay gone."

::tip
The named close codes — `CloseCodes.BANNED`, `CloseCodes.AUTH_INVALID`, and so on — come from `@wskit/core`, so you can write `nonRetryableCodes: [CloseCodes.BANNED]` instead of memorizing numbers.
::

## Network awareness

By default, reconnection pauses its retries while the device reports it's offline, and resumes the moment it's back online — so you don't burn through your attempt budget retrying into a network that isn't there. On platforms that expose connectivity status, this happens automatically.

## What it does and doesn't do

Reconnection brings the *socket* back. It does **not**, on its own, re-subscribe your channels or replay missed messages — those are separate concerns handled by their own features:

- Channel subscriptions re-establish through the [channels](/learn/channels/subscribing) primitive, which re-subscribes on reconnect (and can re-run a function payload for a fresh token).
- Durable streams auto-resume — see [Durable Streams](/learn/streaming/durable).
- Missed messages catch up through [Replay](/learn/reliability/replay-and-dedup).

Reconnection is the foundation those build on: first you get the socket back, then the other features restore what was happening on it.

For the full option list and backoff details, see the [Client reconnection reference](/client/primitives/reconnection).
