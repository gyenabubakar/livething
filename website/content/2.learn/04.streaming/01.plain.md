A plain stream is the simplest kind: the server produces a sequence of chunks, the client consumes them as they arrive, and nothing is stored — if the connection drops, the stream is gone. This is the right default for most streaming, because most of the time a lost stream just gets re-requested. Let's build one end to end.

## Server: a generator that yields

Turn on the `stream()` capability, then declare a stream with `base.stream(...)`. The heart of it is an **async generator** — a `run` function written with `async *` — that `yield`s each chunk:

```typescript [ai.ts]
import { define, t } from '@wskit/server'
import { stream } from '@wskit/server/streams'
import * as v from 'valibot'

const base = define({
  env: t<Env>(),
  capabilities: [stream()],
})

export const handleTokens = base.stream('start-tokens', {
  input: v.object({ prompt: v.string() }),
  chunk: t<{ token: string }>(),
  async *run(ctx, input) {
    for (const word of input.prompt.split(' ')) {
      yield { token: word + ' ' }
    }
  },
})

export const handler = base.assemble(handleTokens)
```

Three pieces define the stream:

- **`input`** — a schema for the payload that starts the stream, validated like any handler input.
- **`chunk`** — a type marker for the shape of each chunk you yield.
- **`run`** — the async generator. Each `yield` sends one chunk to the client. When the generator finishes, the stream ends cleanly.

Because `run` is `async`, you can `await` between yields — call an LLM, read a database page, wait on a timer. The client receives each chunk the moment you yield it.

## Client: a `for await` loop

On the client, add the `stream()` primitive. Call `socket.stream(name, payload)` to start a stream; it returns a handle you iterate with `for await`:

```typescript [app.ts]
import { client, connect, stream } from '@wskit/client'
import type { AiSocket } from '../server/ai'

const socket = client<AiSocket>()(
  connect('wss://example.com/ws'),
  stream(),
)
socket.connect()

const tokens = await socket.stream('start-tokens', { prompt: 'hello there friend' })

for await (const chunk of tokens) {
  // chunk: { token: string }
  process.stdout.write(chunk.token)
}
// loop ends when the server's generator finishes
```

The loop runs until the server's generator finishes, then exits. The payload you pass and the chunk type you receive are both typed from the server's declaration.

## Stopping early

You don't have to consume a whole stream. Two ways to stop:

- **Break out of the loop.** `break`ing (or `return`ing) out of the `for await` cancels the stream for you — the client tells the server to stop, and the server's generator is cleaned up.
- **Call `cancel()`.** The handle has a `cancel()` method if you want to stop without being in the loop.

```typescript [app.ts]
for await (const chunk of tokens) {
  render(chunk.token)
  if (userClickedStop) break // cancels the stream
}
```

On the server, a cancelled stream surfaces through `ctx.stream.signal` — an `AbortSignal` that fires when the client cancels, disconnects, or the server shuts down. You can also wrap your generator's loop in a `try/finally` to run cleanup when it's stopped for any reason:

```typescript [ai.ts]
async *run(ctx, input) {
  try {
    for (const word of input.prompt.split(' ')) {
      if (ctx.stream.signal.aborted) return
      yield { token: word + ' ' }
    }
  } finally {
    // runs whether the stream finished or was cancelled
    releaseResources()
  }
}
```

## When the server errors

If your generator throws, the stream ends with an error rather than a clean finish. On the client, the error surfaces out of the `for await` loop, so a `try/catch` around the loop catches it — and if you threw a registered typed error, you can `.matches()` it just like any other ([Errors](/learn/messaging/errors)):

```typescript [app.ts]
try {
  for await (const chunk of tokens) {
    render(chunk.token)
  }
} catch (err) {
  // the stream failed partway through
}
```

## What flows between them

| Server | Client |
|---|---|
| `base.stream('start-tokens', { run })` | `await socket.stream('start-tokens', payload)` |
| each `yield` | one iteration of `for await` |
| generator finishes | loop ends |
| generator throws | loop throws |
| client cancels | `ctx.stream.signal` aborts |

That's a complete plain stream. The variants ahead — nudges, durable, broadcast — all keep this same generator-and-loop core; they add capabilities on top.

For backpressure handling, concurrency options, and the full `ctx.stream` surface, see the [Server streams reference](/server/capabilities/streams) and the [Client stream reference](/client/primitives/stream).
