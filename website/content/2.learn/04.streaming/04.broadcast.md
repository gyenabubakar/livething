Every stream so far has been one-to-one: a client starts it, and that client consumes its chunks. A **broadcast stream** is one-to-many: the server produces a single stream and fans its chunks out to *every* listener at once. Instead of each client triggering its own generator, one generator's output reaches everyone watching.

This is the shape you want for a shared live feed — a sports ticker, a collaborative cursor feed, a "server is processing" progress bar that the whole room watches together.

## Server: mark it broadcast

A broadcast stream is declared like any other, with one extra flag: `broadcast: true`. The generator is the same — you just yield chunks, and the framework delivers each one to all current listeners:

```typescript [feed.ts]
import { define, t } from '@wskit/server'
import { stream } from '@wskit/server/streams'
import * as v from 'valibot'

const base = define({
  env: t<Env>(),
  capabilities: [stream()],
})

export const handleFeed = base.stream('start-broadcast', {
  input: v.object({ count: v.number() }),
  chunk: t<{ index: number }>(),
  broadcast: true,
  async *run(_ctx, input) {
    for (let i = 0; i < input.count; i++) {
      yield { index: i }
      await new Promise((r) => setTimeout(r, 1000))
    }
  },
})

export const handler = base.assemble(handleFeed)
```

At the top level, `broadcast: true` fans the stream out to every connection. Scoped to a channel — `room.stream('feed', { broadcast: true, ... })` — it fans out to that room's members only, which is usually what you want for a shared room feed.

## Client: listen, don't iterate

Because a broadcast stream isn't *yours* — it's a shared feed you're tuning into — you consume it differently. Instead of `socket.stream(...)` and a `for await` loop, you use `socket.onStream(name, handlers)`: a callback-based subscription that fires for every chunk that arrives:

```typescript [app.ts]
import { client, connect, stream } from '@wskit/client'
import type { FeedSocket } from '../server/feed'

const socket = client<FeedSocket>()(
  connect('wss://example.com/ws'),
  stream(),
)
socket.connect()

const stop = socket.onStream('start-broadcast', {
  onChunk(chunk, streamId) {
    // chunk: { index: number }
    render(chunk.index)
  },
  onEnd(streamId, finalSeq) {
    markComplete()
  },
  onError(error, streamId) {
    showError(error)
  },
})

// later, to stop listening:
stop()
```

The handlers:

- **`onChunk(chunk, streamId)`** — a chunk arrived. Typed from the server's `chunk`.
- **`onEnd(streamId, finalSeq?)`** — the stream finished.
- **`onError(error, streamId)`** — the stream errored. Every subscriber is notified.
- **`onTimeout(streamId)`** — no chunk arrived within the expected window.

`onStream(...)` returns an unsubscribe function. The `streamId` lets you tell apart multiple broadcasts of the same event, if more than one is running.

## How it differs from a regular stream

The distinction is worth being precise about:

| | Regular stream | Broadcast stream |
|---|---|---|
| Client API | `socket.stream(...)` + `for await` | `socket.onStream(...)` + callbacks |
| Who consumes | the client that started it | every listener |
| Generators running | one per client | one, shared |
| Resume | yes (if durable) | listen-only; not resumed by a subscriber |

A regular stream is a private activity you drive and consume. A broadcast stream is a public feed you tune into — you don't start it or own it, you just listen while it's live, and stop when you're done.

## What flows between them

| Server | Client |
|---|---|
| `base.stream('feed', { broadcast: true })` | `socket.onStream('feed', handlers)` |
| each `yield` | `onChunk(chunk, streamId)` |
| generator finishes | `onEnd(streamId)` |
| generator throws | `onError(error, streamId)` — to every listener |

Broadcast streams pair naturally with channels: a channel-scoped broadcast stream is a feed for one room, reaching exactly its members.
