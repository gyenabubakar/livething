The Start section gave you a working app. This section explains the ideas underneath it — the small set of concepts that every other feature in WSKit is built on. Learn these four pages and the rest of the framework stops feeling like magic.

The whole point of the **Learn** section is to teach the two packages — `@wskit/server` and `@wskit/client` — as one system. They aren't two separate libraries that happen to talk to each other; they're two halves of a single contract. Every page in this section shows you the server half and the client half of a feature side by side, because that's how you actually build with WSKit.

## What this section covers

::card-group

The single inferred type that flows from server to client, and the perspective flip that makes the client's view the mirror of the server's.

The matched opt-in pair: server capabilities and client primitives. Why a feature always has two halves, and how you only pay for what you import.
::
::card{title="Connection Lifecycle" icon="i-ph-arrows-clockwise-duotone" to="/learn/core-model/connection-lifecycle"}
The life of a connection — upgrade, connect, the message pipeline, disconnect — and the connection states the client moves through.

::card{title="Wire Protocol" icon="i-ph-broadcast-duotone" to="/learn/core-model/wire-protocol"}
The JSON envelope both sides speak: `event`, `payload`, and the `__wskit` metadata that carries routing and correlation.

Once these click, every feature page that follows is just "here's the server capability, here's the client primitive, here's what flows between them."
